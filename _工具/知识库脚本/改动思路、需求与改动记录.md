# 知识库节头脚本·改动版本记录

## v1.1｜2026-08-05

### 用户提出的问题

节头写入“出处＋文档定位＋使用边界”时，出处可以从文件名取得，但脚本本身不理解文档，必须明确它如何知道“文档定位”和“使用边界”，不能依赖模糊猜测。

### 改动需求

1. 把实际写入的文档定位和使用边界明确放进代码，能够直接审查。
2. 不允许脚本根据相似文件名或未知目录自行猜测。
3. 新文档没有规则时停止写入，先补定位与边界规则。
4. 只能修改三区副本，不能因参数误填污染一区、二区。
5. 剥离用于对账时不得直接修改三区原文件。
6. 修复首次静态审查发现的代码围栏、旧标签残留、非原子写入和末尾换行还原问题。

### 改动思路

脚本只负责机械执行，不承担语义判断。代码顶部建立两级白名单：

- `EXACT_RULES`：总纲、三份世界观、项目索引、西七洞等根级文件逐文件指定。
- `DIRECTORY_RULES`：策划案、细节设定、龙马项目文档、项目遗留按目录指定。

每条规则同时保存 `location`（文档定位）和 `boundary`（使用边界）。运行时先用完整相对路径匹配精确规则，再匹配目录规则；无规则即全批退出。这样脚本“知道”的唯一来源就是可审查的规则表，不从正文、basename 相似性或 AI 推断取得。

### 实际改动内容

1. 将定位与边界集中为 `HeaderRule`，补全总纲、细节设定、西七洞和索引的边界句。
2. 精确文件规则改用相对根目录的完整路径，避免归档世界观旧稿被误标为现行世界观。
3. 当前三区的 43 个 Markdown 均能落入明确规则；不再存在“警告后跳过并继续写”的路径。
4. 根目录锁定为 `E:\works\mortal-cultivation-war3\docs\修仙项目`；其它根目录直接拒绝。
5. 改成两阶段处理：先读取并计算全部结果，通过后才写入；未知规则、编码错误均在写入前终止。
6. 注入采用同目录临时文件＋原子替换；批处理中途失败时尝试恢复本轮已写文件。
7. `--strip` 改为只向 `--output` 空目录生成无节头副本，不再原地剥离三区。
8. 代码围栏按反引号/波浪线种类和长度配对；围栏内部不识别标题，也不删除同形节头示例。
9. 修复文件末尾是无换行二级/三级标题时，注入再剥离不能逐字还原的问题。
10. README 按新规则、命令和安全边界同步更新。

### 验证状态

- 按用户要求，未运行 `inject_headers.py`，未对三区 Markdown 做注入或剥离。

## v1.2｜2026-08-05

### 用户提出的问题

1. 文档定位和使用边界应写在《项目索引》，不应成为代码内部的第二份项目语义。
2. 脚本由 AI 执行；停止时必须留下明确的机器事实，执行 AI 再向 thoth 报告。
3. 脚本不得编写处理建议。
4. `西七洞.md` 不进入三区。

### 改动需求

1. 三份《项目索引》保持逐字一致，并共同承载知识库节头规则。
2. 注入前校验三份索引 SHA-256 一致。
3. 脚本从索引表读取“文档定位＋使用边界”，代码内不保留具体项目规则。
4. 停止时 stdout 和 JSON 日志只记录事实：状态、退出码、错误码、停止阶段、原因、涉及路径和统计。
5. 日志明确标记必须由执行 AI 向 thoth 报告，但不生成处理建议。
6. 西七洞在一区、二区标为 `[①→②]`，从三区目录树和知识库规则中移除。

### 改动思路

《项目索引》决定“写什么”，脚本只决定“如何校验并安全写入”。索引内用 `KB_HEADER_RULES_BEGIN/END` 包住严格四列表格；脚本先核对三份索引一致，再解析表格。任何格式错误、索引不一致、规则覆盖缺口、编码错误或写入异常均整批停止并记事实日志。

### 实际改动内容

1. 一区《项目索引》新增“知识库节头规则”表，并同步为二区、三区完全相同的副本。
2. 西七洞路由改为只到二区，三区树不再列出。
3. 删除代码内部 `EXACT_RULES`、`DIRECTORY_RULES` 及全部具体定位、边界文本。
4. 新增三索引一致性校验、索引表解析、格式校验、重复路径校验和规则覆盖校验。
5. 新增 `logs/inject_headers_时间.json` 与 `logs/latest.json`；日志只记事实字段。
6. stdout 固定输出 `STOP/OK`、错误码、阶段、退出码、事实详情与日志路径。
7. 日志设置 `ai_report_required=true`，执行 AI 必须把事实结果报告给 thoth。
8. `--strip` 保持不修改三区原件，也不依赖索引语义。
9. `项目索引.md` 作为配置输入，不参与节头注入，保证三份索引运行前后始终逐字一致。
