# NPC系统策划案
## 1. 系统职责
NPC有两个方向：自身行为和交互。自身行为管理驻留、行走、范围游走、路点巡逻；交互分功能交互与说话交互。移动参数配主表，功能定义配交互配置，文字/语音及其事件配说话配置。

一个NPC最多提供一个业务功能，不保留综合服务菜单或多个功能选项。一个NPC可以没有业务功能，只提供默认对白与事件说话；可以关联多个任务，此时由唯一的任务面板功能承接。

普通服务NPC不包含战斗、任务剧情编排、教学引导、陪同路线等需求。继续、返回、关闭、接取与交付按钮属于对应界面的流程控制，不作为公共业务功能逐个配表。

## 2. 人物身份与移动
每个NPC有稳定编号、姓名和职能称谓，称谓与姓名按显示需要组合。基础配置包含场景、刷新区域、模型、缩放、初始朝向和交互距离；内部名称和策划说明不导出。

场景激活时生成NPC，卸载时移除；重复生成须识别同一人物，防止旧交互误用新单位。同局人物为共享世界对象，玩家的对白和任务状态分别展示，不直接改写共享人物状态。

移动模式包括驻留、游走和巡逻。游走引用区域，巡逻按主表路点顺序及循环/往返方式移动；到点停留、单段超时均用毫秒。移动不改变NPC逻辑身份。

交互开始暂停当前移动并面向玩家，结束后恢复原行为。暂停、朝向与恢复属于交互基础响应；多人同时交互时NPC面向谁尚待确定。

## 3. 功能交互
主表选择一个公共功能并填对应业务ID。交互配置统一定义执行方式、使用面板、子页及业务ID类型，不在两处维护同一面板关系。

| 功能 | 承接 |
| --- | --- |
| 强化、炼化、法宝打造/养炼、仓库、炼丹、制符 | 直接打开原系统面板和必要子页，内部操作继续由原系统负责 |

| 功能 | 承接 |
| --- | --- |
| 商店交易 | 打开交易系统面板；商品目录及交易规则由交易系统拥有 |

| 功能 | 承接 |
| --- | --- |
| 传送 | 打开独立传送面板，使用本NPC引用的区域目的地方案 |

| 功能 | 承接 |
| --- | --- |
| 调用技能、施加BUFF | NPC简易面板显示必要说明、资格与办理按钮；引用具体效果，不限定治疗或增益 |

| 功能 | 承接 |
| --- | --- |
| 单个任务 | NPC简易面板完整显示任务正文、目标、奖励、进度、状态和对应按钮 |

| 功能 | 承接 |
| --- | --- |
| 任务面板 | 同一NPC有多个任务时点击直接打开任务面板，支持不同任务类别，不限定宗门子页 |

仅使用单个NPC简易面板或对应独立功能面板，不使用A/B双框、吸附或联动拖动。原系统面板沿用自己的拖动、关闭和布局，不新增“返回NPC/结束交谈”。功能打开应定位到对应内容，已打开的面板不能因此被关闭。

交互发起和实际办理时核对NPC有效性、场景、存活、距离及业务资格。提交后关闭窗口不撤销操作，不提前判定成功；错误、取消和结果未知分别按真实业务结果处理，不重复扣费或发奖。

## 4. 任务服务
任务系统拥有任务正文、目标、进度、奖励、存档及操作许可。NPC只提供入口与人物表现，不复制任务目录或另做一套任务状态。

单任务的未接取、进行中、可完成、已完成、办理中和失败状态在一个简易面板内显示。多任务直接由任务面板列出及办理，不在NPC简易面板再列多条交付选项。

接取按任务接取NPC配置判断，交付按任务指定NPC和交付方式判断；提交、重试和奖励资格由任务业务规则拥有。接取人和交付人可以不同。两种交付都检查目标、提交物和奖励状态；只有要求当面的任务才额外要求指定NPC的有效交互。“任务进行中”不等于“可交付”。

任务交付方式按每个任务分别配置，与“单任务简易面板/多个任务面板”的呈现方式独立：

| 交付方式 | 条件满足后的办理 | 提示 |
| --- | --- | --- |
| 必须当面交付 | 在指定交付NPC的有效交互中办理；从普通任务菜单不能远程交付 | 不满足当面条件时显示“须到【NPC姓名】处当面交付” |

| 交付方式 | 条件满足后的办理 | 提示 |
| --- | --- | --- |
| 允许面板交付 | 可从任务面板直接提交并领奖，不要求入口NPC上下文或处于NPC交互范围 | 显示“可直接交付”，不能套用当面交付提示 |

NPC姓名由交付NPC编号关联NPC主表npc_name取得；需要显示职能称谓时按统一名称组合规则处理。编号只供配置关联和内部判断，玩家可见提示、任务面板说明和对白不直接显示NPC编号。姓名缺失应作为配置问题处理，不用编号替代姓名。目标未完成、提交物不足、办理中和已交付分别显示对应原因；两种方式都保留业务资格与防重复领奖检查。

当面交付按任务自己的交付方式与指定NPC判断，不依赖额外的NPC对白节点确认，不在NPC表增加重复交付开关。

从NPC打开任务面板时，只有当前交互的指定NPC可以办理当面交付。走远、换场景、死亡或NPC失效后，不能继续以原交互资格交付。从普通任务菜单打开时不能办理要求当面完成的交付。关闭或重开窗口不等于完成任务，提交前按最新状态复核。

任务交付必须同时满足任务进度、提交物、奖励资格及防重复领奖条件；仅指定NPC编号不能替代实际交互资格。

任务NPC对话目标的param为0时，NPC须提供不依赖对白节点的通用交互完成确认；NPC身份、双方存活、场景与距离合法且玩家主动确认完成交互后，才产生目标事实。没有对白的NPC也须支持。仅选中、走近、打开、关闭面板或导航到达不算；随机说话不决定任务是否完成，也不能因面板刷新重复推进。param非0时须实际完成指定节点，缺失时不能用通用确认绕过。

通用交互完成确认使用哪一控件、在单功能直开流程中的具体承接位置尚待确定；不能把打开原功能面板直接算作确认完成。既有任务若仍引用旧节点参数，须另行核定参数迁移。

## 5. 传送
NPC引用一个传送方案，方案按顺序列目标区域ID。区域拥有名称、所属场景、矩形落点、min_level和completed_quest_id；方案不重复配置这些条件，不另造相同身份的传送点表。

列表同级分页、不滚动，页数由有效且实际显示的目的地计算，不固定示例页数。目标必须属于本方案，点击后按当前真实资格再检查，不能相信旧面板状态。方案引用落点区域本身，不擅自沿其teleport_target再跳一次。

显示资格与传送准入分开。最低等级和前置任务不自动代表隐藏规则；独立展示等级、费用及实际安全落点在对应业务资料中核定。没有真实区域配置及地图制作验证时，不宣称传送可运行。

## 6. 说话交互
### 6.1 统一点击与随机
“点击交互”是唯一的点击说话触发，编号2。不再分别用打开交谈、打开功能面板触发两遍。一次有效点击同时按主表功能打开对应界面，并从本次说话候选中随机播放一条，业务派发不受随机文案改变。

主表默认对白是点击交互的默认候选；额外挂载的点击说话与其合并，满足本次参数和冷却后等概率随机选择一条。只有默认对白就播放默认对白。文字和语音都为空的说话行不加入候选；任务正文和功能面板内容不参加随机。

同一NPC挂同一事件多条说话，固定随机一条，不连续全播。事件结果必须来自真实办理事实，传送成功、技能/BUFF成功、任务结果、强化/炼化/打造/炼丹/制符结果均不由点击意图推定。

### 6.2 文字、语音与触发
文字与语音可分别提供。文字呈现包括面板、头顶气泡、主画面；仅语音允许不显示文字。主画面文字锚定玩家界面，不随NPC世界位置移动，不依赖NPC面板保持打开。个人传音的语音应保持离开NPC后仍可听。

事件参数一格一个值，由对话功能字典说明命名空间。距离事件填距离，任务事件可填任务ID，传送结果可填区域ID，点击交互不另填面板ID。没有共用条件字典；需要本次交互后才触发的说话，使用本行布尔开关，不免除业务系统本身的资格判断。

时长与冷却统一毫秒。0冷却表示不限制，0持续时长沿语音或项目统一文字默认时长。同一NPC、同一事件玩家、同一事件身份共享冷却起点；每条候选按自身冷却时长判断本次能否播放，播放后该事件身份的冷却重新起算。主表默认点击对白按0冷却处理。

### 6.3 离开
离开时触发新告别、已有内容继续、已有内容停止是三种分别配置的情况。新告别由走出配置范围或交谈结束事件触发；播放中的内容由leave_policy决定继续或停止。走出配置范围的边界取本条距离参数，已播内容停止的边界取NPC交互距离。

个人传音面向本次事件玩家。不同事件竞争、多人可见范围、气泡与音频的相互覆盖关系尚待确定，不从网页演示推定全局广播或新内容必定覆盖旧内容。

## 7. 配置与资源
配置范围为NPC主表、交互配置、传送方案、说话配置、对话功能。音频管理是策划台账，不作为程序配置导出。

主表可挂说话ID1～9，每个说话ID对应一条记录。未配置填0；记录的NPC归属由挂载关系决定。策划辅助列只保留说明行，不导出。

真实技能/BUFF/部分单任务内容ID、目的地区域和正式音频仍须按内容确定，不能捏造ID补齐。商店目录、服务费用和资格归相应业务系统，不在NPC表重复结算。

## 8. 待定事项
通用交互完成确认的控件及其在单功能直开流程中的位置待定；仅打开功能面板不算完成。多人共享朝向仲裁、个人传音与气泡共享边界、独立展示等级及费用待定；真实业务ID、传送区域与音频不得用示例替代。
