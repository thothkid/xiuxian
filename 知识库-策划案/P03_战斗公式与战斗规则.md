# 战斗公式与战斗规则
战斗的伤害通道、结算顺序、伤害公式、命中与暴击判定、攻击事件幂等规则、死亡与复活流程，以及可执行的验收值。具体系数以配置表与系统参数为准。

## 两条伤害通道
| 通道 | 攻方属性 | 守方属性 | 用途 |
|---|---|---|---|
| 物理 | `atk` | `def` | 普攻、肉身攻击、明确标为物理的神通 |
| 术法 | `matk` | `resist` | 明确标为术法的神通与法宝效果 |

## 法力不是伤害通道
法力字段 `mp` 是施展神通消耗的蓝条资源，不是伤害通道。攻击、防御均为单值，公式不读取攻击上下限、法术攻击上下限、物防上下限或法防上下限。

## 结算顺序
伤害严格按以下顺序结算：校验攻方、目标、距离、存活状态、冷却和法力；支付本次神通法力消耗，支付失败则不生成攻击事件；执行命中判定；按伤害通道读取攻防单值；计算神通倍率与固定伤害；计算通用增伤、减伤和护盾；计算境界压制或破压制；计算暴击；钳制并取整，扣除生命；生成唯一战斗日志、飘字和死亡事件。

## 万分比解释规则
百分比统一按万分比整数解释：
```text
pct_value = stored_value / 10000
```
同一修饰项不得在属性系统和伤害公式中重复计算。

## 基础伤害公式
物理基础伤害与术法基础伤害各自取攻减防，下限为 1：
```text
base_damage = max(attacker.atk - defender.def, 1)        // 物理
base_damage = max(attacker.matk - defender.resist, 1)    // 术法
```

## 神通倍率与固定值
```text
ability_damage = base_damage × ability_coefficient + ability_fixed
```

## 通用增减伤
```text
modified_damage = ability_damage × max(0, 1 + damage_bonus - damage_reduction)
```

## 境界修正
```text
realm_delta = attacker.realm_id - defender.realm_id
realm_modifier = clamp(1 + realm_delta × configured_step + anti_suppression, configured_min, configured_max)
suppressed_damage = modified_damage × realm_modifier
```

## 暴击与最终值
```text
critical_damage = suppressed_damage × critical_multiplier   // 仅暴击时
final_damage = max(round(critical_damage), 1)
```

## 伤害公式的边界
`configured_step`、`configured_min`、`configured_max` 必须来自系统参数，不在代码写死。PvE 与 PvP 使用不同的境界修正参数，PvP 系数默认更弱。破压制只能修正境界系数，不得直接抹除全部境界差。减伤可实际降低基础伤害，但最终有效命中仍至少造成 1 点伤害，免疫是独立判定。护盾在生命值之前吸收伤害。

## 命中与暴击公式
```text
hit_chance = clamp(base_hit + attacker.hit - defender.dodge, hit_min, hit_max)
crit_chance = clamp(attacker.crit - defender.crit_resist, 0, crit_max)
```

## 命中与暴击的边界
命中、闪避、暴击和免暴均使用万分比。必中、不可暴击、免疫等是显式标签，不通过极端百分比暗示。命中失败不造成伤害；是否返还法力由神通自身配置明确。

## 攻击事件幂等
每次攻击生成唯一 `combat_event_id`，该 ID 只被接受一次。动画事件、弹道到达和范围命中都必须携带同一事件 ID，重复到达只记录重复事件、不重复结算。多段神通使用 `combat_event_id + hit_index` 标识每一段，持续伤害使用 `combat_event_id + tick_index` 标识每一跳。

## 攻击结算的基本规则
每次有效普攻至少造成 1 点伤害。死亡单位不再接受攻击、移动或交互指令。单次攻击只结算一次，动画事件重复回调不得重复扣血。击杀行为不直接发放修为。

## 死亡与复活流程
```text
hp <= 0
→ 进入死亡状态
→ 清理当前攻击与受控状态
→ 等待配置时长
→ 在当前场景指定安全复活点复活
```

复活恢复比例、保护时间和是否保留 Buff 由系统参数配置。没有指定安全复活点时，场景不得通过加载校验。

## 基础伤害验收值
| 攻击 | 防御 | 期望伤害 |
|---:|---:|---:|
| 10 | 5 | 5 |
| 5 | 5 | 1 |
| 3 | 10 | 1 |

## 修饰与境界验收值
| 场景 | 输入 | 期望 |
|---|---|---|
| 无修饰 | 基础伤害 100 | 100 |
| 增伤 20% | 基础伤害 100，增伤 2000 | 120 |
| 增伤 20% 且减伤 30% | 基础伤害 100 | 90 |
| 高一大境界 | 基础伤害 100，境界步长 10% | 110 |
| 低一大境界 | 基础伤害 100，境界步长 10% | 90 |
| 重复事件 | 同一事件 ID 到达两次 | 只扣一次生命 |
验收时应从配置读取系数并计算期望值，不把表中示例系数写入代码。

## 已废弃的战斗口径
天运取攻击上限、天佑取防御上限已废弃。物理与法术上下限随机取值已废弃。「法术威力」作为所有伤害的无基准乘数已废弃。角色死亡后在未配置的位置原地或随机复活已废弃。技能、法术和法力不得混作同一概念。
