# 掉落规则与配置字段
> 定位：定义掉落方案的抽取规则、配置字段语义、产物与交接边界。方案 ID、具体数值和候选物品以实际配置表为准。

## 一、方案与目标
一个掉落方案选择一种抽取方式，最多配置 32 个掉落槽。单个槽位的目标可以是固定物品或装备 ID、按大类／子类／档位筛出的随机目标，或另一个掉落方案。三种目标可以在同一方案内混合；目标类型与抽取方式是两个不同维度。

槽位 id 有值时，优先按该 ID 所指目标处理，不再同时做分类随机；该 ID 究竟指固定物品／装备还是子方案，须无歧义判定。分类目标从可掉落的物品／装备配置中筛出候选：装备必须填写大类和档位，子类可留空表示不限；物品必须填写大类，子类和档位可留空表示不限。筛选后候选数必须在 1 至 100 之间。槽位命中后，每件等概率选一个候选，允许选到同一个候选；没有候选或超过 100 个候选均为配置错误。

子方案目标被抽中时，再按子方案自己的抽取方式和槽位配置结算。外层只把“抽中子方案槽位”视为本层一次命中；子方案产生多少件产物由子方案独立决定，不把子方案的槽位展开到外层抽取池。应识别并拒绝自身引用与循环嵌套，避免无限递归。

掉落槽位的固定目标与子方案目标必须能无歧义区分，不得凭可能重叠的数字ID猜测目标类型。

## 二、三种抽取方式
方案的 drop_type 选择以下三种方式之一，同一次结算只执行选中的方式：

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按概率 | 每个可用槽独立判定一次；可零槽、单槽或多槽同时命中；若命中槽数超过配置的最大掉落数，从命中槽中随机保留最大掉落数个 | 最小掉落数无效；最大掉落数用于命中后的截断 |

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按权重可重复 | 先在最小／最大掉落数之间等概率取一个整数 N，再从本方案所有可用槽组成的同一个池中按权重抽 N 次；权重换算规则待裁定 | 抽中过的槽仍留在池中 |

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按权重不可重复 | 同样先取 N，再按权重抽取；每抽中一个槽，将该槽从本层池中移除，并按剩余权重继续抽 | 本层槽位最多命中一次；池空即停止 |

按概率方式中，prob 是该槽的单次命中概率，以一亿为 100%；一个槽的判定不影响其他槽。按权重方式中，prob 是该槽在本方案抽取池中的权重，0 权重槽不会命中。总权重是否必须等于一亿、抽取区间是否固定为一亿，现行表格说明互相矛盾；在策划裁定前，不以“按实际权重和归一”或“未满一亿可抽空”作为已定规则。

“共用一个池”只指同一个方案当前这一层的权重抽取：固定 ID、分类随机、子方案三个目标槽都按各自 prob 参与同一次选槽。子方案被选中以后，其内部另按自己的模式和权重结算。按概率方式没有共用权重池，每个槽只看自己的命中概率。

两种权重方式用最小／最大掉落数决定本层抽取次数，不约束最终产物件数。按概率方式不读取最小掉落数；各槽独立判定后，若命中槽数超过已配置的最大掉落数，就从命中槽中等概率随机保留指定数量的槽，再按这些槽的 num 生成产物。最大掉落数未配置时不截断；不能把最大掉落数误用为每槽的产物数量上限。

## 三、命中后的产物数量
固定目标与分类目标的 num 是该槽每次命中后要给出的固定产物数量，不是方案的抽取次数，也不是方案中填了多少槽。

- 固定 ID：本层命中一次，产出该 ID 的 num 件。
- 分类随机：本层命中一次，从符合大类／子类／档位的候选中独立等概率抽 num 次，每次产出一件；候选可重复。
- 子方案：本层命中后执行子方案。子方案槽位 num 对子方案执行次数的影响待需求确认；在该口径确定前，不得将它当作固定物品数量，也不得静默忽略。

按权重可重复时，同一固定 ID 或分类槽被多次命中，每次都独立按上述数量规则产出；按权重不可重复只保证本层同一槽不再命中，不限制不同槽给出同一物品，也不改变子方案自身的重复规则。

同类产物落地前是否合并尚未确定，不能作为已确定的掉落处理规则。

## 四、配置表字段
D掉落方案.xlsx 的 drop_config 每一行定义一个方案；drop_items 是本方案最多 32 个掉落槽。字段语义如下，具体物理列名和类型以配置表与导表结构为准。

| 方案字段 | 策划含义 |
|---|---|
| id | 掉落方案的唯一 ID，供怪物或子方案引用 |

| 方案字段 | 策划含义 |
|---|---|
| drop_type | 本方案选择的三种抽取方式 |

| 方案字段 | 策划含义 |
|---|---|
| min_drop_number | 两种权重方式的本层抽取次数下限；按概率方式无效 |

| 方案字段 | 策划含义 |
|---|---|
| max_drop_number | 两种权重方式的本层抽取次数上限；按概率方式用于命中槽数的随机截断，留空时不截断 |

| 方案字段 | 策划含义 |
|---|---|
| drop_number | 仅供策划统计已填写的掉落槽数，服务器结算不得读取或以它限制结果 |

| 方案字段 | 策划含义 |
|---|---|
| drop_items | 本方案配置的掉落槽集合 |

| 方案字段 | 策划含义 |
|---|---|
| time_limit_id | 表中预留的时间限制引用；具体生效条件尚待单独明确，不从字段名推断规则 |

| 槽位配置 | 策划含义 |
|---|---|
| id | 固定物品／装备 ID 或子方案 ID；必须能无歧义判别目标类型 |

| 槽位配置 | 策划含义 |
|---|---|
| name | 策划识别用名称，不作为目标匹配条件 |

| 槽位配置 | 策划含义 |
|---|---|
| main_class、sub_class、lv | 分类随机的大类、子类、档位筛选条件；id 有值时优先处理 ID 目标 |

| 槽位配置 | 策划含义 |
|---|---|
| prob | 按概率时为以一亿为 100% 的独立命中率；按权重时为槽位权重，换算规则待裁定 |

| 槽位配置 | 策划含义 |
|---|---|
| num | 固定 ID 的件数或分类随机的独立选取次数；子方案语义待确认 |

表格中给策划看的内部名、编号、方案说明、掉落物名称与权重验算等辅助列，不代替上述运行规则。特别是 drop_number 只用于策划核对填写数量。

## 五、校验与边界
- 方案 ID 必须唯一，引用的物品／装备和子方案必须存在；子方案引用不得成环。
- 权重方式须满足 0 ≤ min_drop_number ≤ max_drop_number。若抽取次数大于可选槽数，权重不可重复方式在池空时停止。
- 按概率方式的 prob 应处于 0 至一亿；权重方式参与抽取的槽 prob 必须大于 0，抽取次数为正时池内至少有一个可选槽。
- 固定目标与分类随机槽的 num 为正整数；分类筛选后不得为空。子方案槽的 num 校验随其语义一起确定。
- 不设置独立“保底槽”或 guaranteed 字段。需要必得时，在适用的概率方案里配置 100% 命中，或通过方案组合表达；不得偷偷占用权重方式的抽取次数。
- 不设计掉落概率衰减规则。

## 六、产出与其他系统的边界
怪物境界、品质、来源和首领职能可以选择不同掉落方案；原生、魔化、造物只作为选择方案的条件，不自动绑定固定掉落。物品的“功能_随机产出”也可以引用掉落方案，由该物品配置调用次数；每次调用仍按所引用方案的规则结算。掉落目标自身的品质以其物品／装备配置为准，不在掉落时临时改写。怪物死亡与掉落不直接增加修为。

同一次死亡或掉落结算重复到达时不得重复发放。地面掉落记录所有者及保护起止时间：保护期内只有所有者或允许的队伍成员可拾取，结束后转为公开拾取。普通物品通过点击拾取；灵石自动进入钱包，不占背包格。范围自动拾取为预留能力，不作为已开放功能；启用时与手动拾取遵守相同背包规则。背包容量与整笔失败边界由背包规则定义。

## 待定的掉落口径
权重抽取的总权重要求与取点区间尚待裁定，不把实际权重和归一或未满一亿可抽空视为已定规则。子方案槽位num是否控制子方案执行次数尚待确认；time_limit_id的具体生效条件尚待明确。
