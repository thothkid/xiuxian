# P08 掉落系统策划案
## 一、方案与目标
一个掉落方案选择一种抽取方式，最多配置 32 个掉落槽。单个槽位的目标可以是固定物品或装备 ID、按大类／子类／档位筛出的分类目标，或另一个掉落方案。三种目标可以在同一方案内混合；目标类型与抽取方式是两个不同维度。

一、方案与目标：槽位 id 有值时，优先按该 ID 所指目标处理，不再同时做分类筛选；该 ID 究竟指固定物品／装备还是子方案，须无歧义判定。分类目标从可掉落的物品／装备配置中筛出候选：装备必须填写大类和档位，子类可留空表示不限；物品必须填写大类，子类和档位可留空表示不限。

两种分类产出模式使用相同的筛选条件。

方案级“分类全量产出”（all_candidates）默认关闭。关闭时为分类随机：筛选后候选数必须在 1 至 100 之间，槽位每次命中后独立等概率选取 num 次，每次产出一件，允许重复选中同一候选。没有候选或超过 100 个候选均为配置错误。

开启分类全量产出时，分类槽每次命中后给出全部匹配候选，每种候选各 num 件；候选数可以超过 100，但不得为空。开关只作用于本方案这一层的分类槽，不影响固定 ID 的件数或子方案的调用次数；子方案使用自己的开关，不继承父方案设置。

分类全量产出不是第四种抽取方式，也不代表槽位必定命中：仍先按本方案的抽取方式、prob 和最大掉落数确定命中槽，再按各槽的分类产出模式与 num 生成产物。

子方案目标被抽中时，再按子方案自己的抽取方式和槽位配置结算。外层只把“抽中子方案槽位”视为本层一次命中；子方案产生多少件产物由子方案独立决定，不把子方案的槽位展开到外层抽取池。应识别并拒绝自身引用与循环嵌套，避免无限递归。

固定物品、装备与子方案的 ID 必须唯一指向一种目标。目标不存在，或同一个 ID 同时指向多类目标，均为配置错误；不得按查询先后顺序猜测目标类型。

## 二、三种抽取方式
方案的 drop_type 选择以下三种方式之一，同一次结算只执行选中的方式：

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按概率 | 每个可用槽独立判定一次；可零槽、单槽或多槽同时命中；若命中槽数超过配置的最大掉落数，从命中槽中随机保留最大掉落数个 | 最小掉落数无效；最大掉落数用于命中后的截断 |

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按权重可重复 | 先在最小／最大掉落数之间等概率取一个整数 N，再从本方案所有可用槽组成的同一个池中，按当前正权重总和计算比例，抽 N 次 | 抽中过的槽仍留在池中 |

| 方式 | 本层如何抽取 | 次数 |
|---|---|---|
| 按权重不可重复 | 同样先取 N，再按权重抽取；每抽中一个槽，将该槽从本层池中移除，并按剩余权重继续抽 | 本层槽位最多命中一次；池空即停止 |

二、三种抽取方式：按概率方式中，prob 是该槽的单次命中概率，以一亿为 100%；一个槽的判定不影响其他槽。按权重方式中，prob 是该槽在本方案抽取池中的相对权重，0 权重槽不会命中。每次按当前池中所有正权重槽的实际权重总和归一，不要求总和等于一亿，不因总和不足一亿而产生空结果。

例如权重为 1 和 3 的两个槽，单次抽中概率分别为四分之一和四分之三。不可重复方式移除已命中槽后，按剩余正权重重新计算比例。

“共用一个池”只指同一个方案当前这一层的权重抽取：固定 ID、分类目标、子方案三个目标槽都按各自 prob 参与同一次选槽。子方案被选中以后，其内部另按自己的模式和权重结算。按概率方式没有共用权重池，每个槽只看自己的命中概率。

二、三种抽取方式：两种权重方式用最小／最大掉落数决定本层抽取次数，不约束最终产物件数；最大掉落数为 0 时抽取零次。按概率方式不读取最小掉落数；各槽独立判定后，若命中槽数超过已配置的最大掉落数，就从命中槽中等概率随机保留指定数量的槽，再按这些槽的 num 生成产物。

概率方式最大掉落数留空（导出为 0）时不截断；不能把最大掉落数误用为每槽的产物数量上限。

## 三、命中后的产物数量
num 的含义由目标类型和分类全量产出开关共同决定，不是本层方案的抽取次数，也不是方案中填了多少槽。

三、命中后的产物数量：固定 ID：本层命中一次，产出该 ID 的 num 件。

三、命中后的产物数量：分类随机（全量开关关闭）：本层命中一次，从符合大类／子类／档位的候选中独立等概率抽 num 次，每次产出一件；候选可重复。

三、命中后的产物数量：分类全量（全量开关开启）：本层命中一次，给出全部符合条件的候选，每种各 num 件。候选有几种，总产物数量就是几种乘以 num。

三、命中后的产物数量：子方案：本层命中一次后，独立执行所引用子方案 num 次，num 必须为正整数。每次都按子方案自己的抽取方式重新结算，不是抽一次再复制结果，也不是给子方案的最终产物数量设上限。例如 num 为 3，就是独立执行子方案 3 次；父层仍只计一次槽命中。

按权重可重复时，同一固定 ID 或分类槽被多次命中，每次都独立按上述数量规则产出；按权重不可重复只保证本层同一槽不再命中，不限制不同槽给出同一物品，也不改变子方案自身的重复规则。

同类产物落地前合并暂缓，不作为本次掉落规则的实现与验收条件。

## 四、配置表字段
D掉落方案.xlsx 的 drop_config 每一行定义一个方案；drop_items 是本方案最多 32 个掉落槽。字段语义如下，具体物理列名和类型以配置表与导表结构为准。

| 方案字段 | 策划含义 |
|---|---|
| id | 掉落方案的唯一 ID，供怪物或子方案引用 |

| 方案字段 | 策划含义 |
|---|---|
| drop_type | 本方案选择的三种抽取方式 |

| 方案字段 | 策划含义 |
|---|---|
| all_candidates | 分类全量产出，默认关闭；开启后本层分类槽每种候选各给 num 件，不影响固定 ID 和子方案的数量规则 |

| 方案字段 | 策划含义 |
|---|---|
| min_drop_number | 两种权重方式的本层抽取次数下限；按概率方式无效 |

| 方案字段 | 策划含义 |
|---|---|
| max_drop_number | 两种权重方式的本层抽取次数上限，为 0 时抽取零次；按概率方式用于命中槽数的随机截断，留空或 0 时不截断 |

| 方案字段 | 策划含义 |
|---|---|
| drop_number | 仅供策划统计已填写的掉落槽数，不参与结算，不限制掉落结果 |

| 方案字段 | 策划含义 |
|---|---|
| drop_items | 本方案配置的掉落槽集合 |

| 槽位配置 | 策划含义 |
|---|---|
| id | 固定物品／装备 ID 或子方案 ID；必须能无歧义判别目标类型 |

| 槽位配置 | 策划含义 |
|---|---|
| name | 策划识别用名称，不作为目标匹配条件 |

| 槽位配置 | 策划含义 |
|---|---|
| main_class、sub_class、lv | 分类目标的大类、子类、档位筛选条件，随机与全量模式共用；id 有值时优先处理 ID 目标 |

| 槽位配置 | 策划含义 |
|---|---|
| prob | 按概率时为以一亿为 100% 的独立命中率；按权重时为槽位的相对权重，按当前池内正权重总和归一 |

| 槽位配置 | 策划含义 |
|---|---|
| num | 固定 ID 的件数、分类随机的独立选取次数、分类全量中每种候选的件数，或子方案的独立执行次数；均为正整数 |

表格中给策划看的内部名、编号、方案说明、掉落物名称与权重验算等辅助列，不代替上述运行规则。特别是 drop_number 只用于策划验收填写数量。

## 五、校验与边界
五、校验与边界：方案 ID 必须唯一，引用的物品／装备和子方案必须存在；子方案引用不得成环。

五、校验与边界：权重方式须满足 0 ≤ min_drop_number ≤ max_drop_number。若抽取次数大于可选槽数，权重不可重复方式在池空时停止。

五、校验与边界：按概率方式的 prob 应处于 0 至一亿；权重方式参与抽取的槽 prob 必须大于 0，抽取次数为正时池内至少有一个可选槽。

五、校验与边界：固定目标、分类目标与子方案槽的 num 均为正整数；分类筛选后不得为空。随机模式候选数为 1 至 100，全量模式允许超过 100。

五、校验与边界：全量模式按全部可能产出核验背包空间、装备实例数量和直接入账灵石，不能沿用随机选中单个候选的产出上界；数量或金额超出可表示范围时拒绝方案。

五、校验与边界：不设置独立“保底槽”或 guaranteed 字段。需要必得时，在适用的概率方案里配置 100% 命中，或通过方案组合表达；不得偷偷占用权重方式的抽取次数。

五、校验与边界：不设计掉落概率衰减规则。

## 六、产出与其他系统的边界
六、产出与其他系统的边界：怪物境界、品质、来源和首领职能可以选择不同掉落方案；原生、魔化、造物只作为选择方案的条件，不自动绑定固定掉落。物品的“功能_随机产出”也可以引用掉落方案，由该物品配置调用次数；每次调用仍按所引用方案的规则结算。掉落目标自身的品质以其物品／装备配置为准，不在掉落时临时改写。

怪物死亡与掉落不直接增加修为。

同一次死亡不得重复发放掉落。地面掉落有所有者与保护期：保护期内只有所有者或允许的队伍成员可拾取，结束后转为公开拾取。普通物品手动点击拾取，自动拾取沿用已有开放范围，两者遵守同一背包规则；灵石自动进入钱包，不占背包格。背包容量、整笔失败、结果一致性与进度保留规则以背包系统需求为准。
