# P11 背包规则

> 定位：定义容量、分页、堆叠、拾取、使用、穿戴与事务边界。

## 一、容量

- V0 初始背包容量固定为12格。
- UI 每页显示6格，共2页；分页不改变真实容量。
- 后续扩容增加真实格数，UI按每页6格继续分页。
- 灵石显示在钱包区域，不占背包格。

## 二、格子模型

每个格子保存：

```text
slot_index, item_id, quantity, instance_id, bind_state
```

- 普通可堆叠物品使用 `item_id + bind_state` 判断是否同堆，并受 `pile_max` 限制；不同纯度或剩余杂质丹药不套用普通堆叠判定。
- 不可堆叠物品必须有唯一 `instance_id`。
- 装备、器具和法宝默认不可堆叠。

## 三、放入顺序

1. 优先填充相同物品且未满的堆叠。
2. 再按格子顺序占用空格。
3. 一笔收入必须全部可容纳才提交。
4. 空间不足时整笔失败，不允许部分放入。

灵石不执行以上流程，直接进入钱包事务。

## 四、拾取事务

拾取必须原子提交以下变化：

- 校验地面物仍存在且拾取者有权限。
- 预计算全部堆叠和空格。
- 写入背包或钱包。
- 删除地面物。
- 写入唯一事件日志。

任一步失败则全部回滚。同一拾取事件 ID 重复到达时只返回已有结果，不重复发放。

## 五、手动与自动拾取

- V0 普通物品点击拾取。
- V0 灵石自动进入钱包。
- V1 普通物品自动拾取启用后，仍调用同一拾取事务。

## 六、物品使用

使用前检查拥有数量、冷却、境界要求与当前状态，按 `function_type` 解释 `function_id`。执行实际效果成功后才扣数量；失败不消耗，数量归零时清格。

普通“丹药”按已配置丹效及服药前丹毒检查。没有有效丹效时禁止直接服食，不消耗、不增加杂质；配置错误不可跳过后部分执行。待定丹效保持未配置。

“突破丹”使用后打开突破准备面板，不立即消耗、不增加杂质、不自动投入。正式突破的材料消耗与额外单枚丹药由突破规则处理；背包不绕过突破条件，不将普通丹效是否为空用作突破丹准入依据。

## 七、穿戴

- V0 可只开放武器与法袍两个技术验证位。
- 完整装备六位为冠、法袍、武器、佩、印绶、鞋履。
- 穿戴只改变装备集合，属性系统随后从全部来源重算。
- 替换失败时原装备和背包必须保持不变。
- 法宝不进入固定出战槽，按神识预算和单件御使负荷结算。

## 八、整理与拆分

- 整理和拆分在 V3 后启用，不属于 V0。
- 整理必须保持物品实例、绑定状态和总数量不变。
- 拆分数量满足 `0 < split_quantity < original_quantity`，且必须有空格。

### 丹药实例信息

整理、拆分时保留每枚丹药的实际纯度和剩余杂质，不重新计算、不取平均、不丢失。同物品 ID 丹药能否合并仍属待定，当前保留原有实例信息，`pile_max` 不能单独决定合并。

### 炼丹材料身份

灵植入包、占格和扣数量使用物品 ID，物品功能关联的灵植 ID 只用于查询药力、药性、材位等属性；丹效 ID 与基础丹方 ID 也不能代替背包物品 ID。

## 九、校验

- 真实格数、分页格数和 UI 显示必须一致。
- 物品总数量在失败、重连和重复事件后不变。
- 灵石不得占格。
- 任何穿脱、替换和使用异常都不得造成物品复制或丢失。

> 修订：v2.0 统一12格容量与6格分页，补齐原子拾取、灵石钱包和六装备位边界。
