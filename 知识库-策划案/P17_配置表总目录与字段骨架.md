### 物品与业务配置关联

W物品表负责背包身份、功能入口、资源关联与统一基础售价。灵植表负责材料属性，丹方丹效表负责炼制条件及成品效果，打造材料的分类与境界读取物品 tags，品质读取 quality；辅助列不参与运行判断。

境界进阶 `materials` 为必需物品 ID 与数量；`materials_rate:array,BreakRateMaterial` 每项为 id、count、rate，单枚规则下 count=1。角色逐级属性增量由境界角色属性配置提供，与对象的大境界枚举分开。

### 图标资源配置

`Z图标配置表.xlsx` 的 `id:int` 是唯一主键，同时为资源命名编号。物品 `icon_id` 关联该主键，不再使用单独的 name 保存资源编号。

`path:string` 是资源目录，不含资源文件名；使用目录、id 与对应扩展名定位资源，不能把目录当成完整文件。类别、检查序号和检查用名称属于辅助列，不作为导出字段或主键。

## 二、权威与加载门禁

- 三区实际 xlsx 是字段、枚举和数值的唯一权威；本文不复制完整列清单。
- 文件名、表名、主键、字段类型和枚举由 Schema 固定，代码不得另建同义字段。
- 启动时加载并完成必填、类型、主键唯一性、外键存在性和枚举合法性校验。
- 任一 P0 配置校验失败时阻止进入游戏并报告具体表、主键与字段，不静默降级。
- V0 不提供运行中热更新；配置变更经重新导表和重新启动生效。
- 任何文档中的示例 ID 都只是示例，不得反向覆盖实际配置。

## 三、共享字段语义

### 统一大境界 MajorRealm

采用 `MajorRealm` 的境界字段统一按大境界枚举读取：

| 枚举值 | 境界 |
|---:|---|
| 1 | 炼气 |
| 2 | 筑基 |

| 枚举值 | 境界 |
|---:|---|
| 3 | 金丹 |
| 4 | 元婴 |

| 枚举值 | 境界 |
|---:|---|
| 5 | 化神 |
| 6 | 炼虚 |

| 枚举值 | 境界 |
|---:|---|
| 7 | 合体 |
| 8 | 大乘 |

0为保留值，含义由所属字段确定，不能统一解释为炼气、通用或无限制。

配表可以使用规定的中文枚举别名，原有合法数字也兼容；导出后使用同一套枚举值。相关字段说明不能继续标注为任意字符串，也不能自行维护另一套境界编号。

### 境界字段的独立职责

各字段仍按所属规则发挥作用：

- 丹药、灵植、法宝境界表示对应对象的大境界。
- 丹炉最高可炼境界限制炼制范围。
- 除渣力 `base_realm` 用于该来源的跨境计算。
- 丹毒池境界用于选择角色当前境界对应的容量与消退配置。
- 打造 `realm_req` 判断角色打造资格。
- 奇珍录境界用于对应条目的配置语义，不自动成为点亮门槛。

材料是否同境界、角色是否达到门槛、丹炉是否可以炼制、是否享受跨境加成，必须分别判断，不能因为都使用 `MajorRealm` 就合并成一个条件。

### 品质

- 品质统一为凡、灵、玄、仙、神、道六档。
- 颜色由品质映射派生，不把白绿蓝紫橙红作为第二套品质值。
- “品阶”和独立“稀有度”轴废弃。

### 器物身份

- 装备、器具、法宝是运行结构身份；品质与身份正交。
- 本命法宝是共生关系，有灵法宝表示器灵已成，道器是承载独一规则的特殊身份。
- 不使用凡器、法器、灵器、法宝、本命法宝、道器的线性六级梯。
- 法宝不使用固定出战位；单件登记神识御使负荷，角色按神识预算结算。

### 物品与奇珍

- 奇珍身份与装备、器具、法宝结构身份正交。
- 灵石进入钱包，不进入背包格、不参与堆叠。
- 物品不得使用职业限制；堂口也不是职业。

### 魔物来源

- 怪物来源至少区分原生、魔化、造物。
- “魔化”是来源状态，不代表所有魔化生物具有同一 AI 行为。
- 普通野兽不用修行境界名，使用野兽强度或推荐境界表达危险度。

## 四、跨表关系

| 来源 | 目标 | 约束 |

| 场景区域 | 刷新方案 | 区域引用的刷新方案必须存在 |
| 刷新方案 | 怪物 | 怪物 ID 必须存在；刷新与 AI 共用同一出生/返回边界 |

| 来源 | 目标 | 约束 |
|---|---|---|
| 怪物 | 掉落方案 | 掉落方案必须存在；击杀不直接增加修为 |
| 掉落方案 | 物品/装备 | 目标 ID、数量和权重合法；广播按统一品质门槛 |

| 来源 | 目标 | 约束 |
|---|---|---|
| 角色/怪物/装备 | 属性字典 | 属性字段键必须存在且类型一致 |
| 境界角色属性 | 属性字典 | 分别提供逐级属性增量与修炼基础量，按各自语义汇总；最终属性由属性系统重算 |

| 来源 | 目标 | 约束 |
|---|---|---|
| 神通/Buff | 属性字典 | 效果只引用现行属性键；蓝条消耗固定使用法力 `mp` |
| 灵根 | 属性字典 | 五行影响是修正，不构成绝对胜负或职业锁 |

| 来源 | 目标 | 约束 |
|---|---|---|
| 灵气源 | 系统参数 | 在线与离线共用同一生产、容量和分配参数 |

## 五、掉落骨架

- 当前掉落模型统一为32槽权重池，不再与“每槽独立概率”并存。
- 每个有效槽至少包含目标 ID、权重、最小数量、最大数量和是否保底。
- 先确定本次抽取次数，再在有效槽内按权重抽取；无放回或可重复必须由方案字段明确。
- 最少/最多掉落数用于约束抽取次数，不得与抽取结果二次冲突。
- 广播门槛由统一品质规则决定；单条覆盖只作为显式例外。

## 六、属性与装备骨架

- 属性表 V0 只启用生命值、法力、攻击、防御四项。
- 攻击、防御使用单值，不建立物理/法术上下限。
- 装备完整六位为冠、法袍、武器、佩、印绶、鞋履；别名只用于显示映射，不生成新枚举。
- 装备效果使用修饰项列表，支持固定值与万分比，不把最终属性直接写回装备或存档。
- 穿脱装备后由属性系统从来源集合重算。

## 七、修炼骨架

- 灵气源每个结算周期只生产一次，再按分配规则给玩家。
- 时段不直接乘入修炼倍率。
- 丹药服用准入与五味丹毒由炼丹规则拥有；突破投入走突破规则，不另建耐药组或每日次数限制。
- 修为使用足够精度持久化，显示时取整。

### 系统参数的职责

除渣跨境倍率、技能熟练度对除渣的增幅、行为触发熟练度增长的概率分别解释，不能互相代替。突破失败每次增加 5 个百分点是固定突破规则，不从熟练度或额外丹药加成字段读取。

## 八、变更规则

- 新增游戏配置表时，同时登记用途、主键、外键、权威区与启用版本。
- 删除或改名时先更新同步白名单和 Schema，再更新本文；不得留下两张同义表。
- 字段新增由实际 xlsx 与 Schema先落地，本文只登记语义，不在代码和文档中另存一套字段结构。
