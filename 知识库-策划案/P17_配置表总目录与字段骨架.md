## 物品与业务配置关联
W物品表负责背包身份、功能入口、资源关联与统一基础售价。灵植表负责材料属性，丹方丹效表负责炼制条件及成品效果，打造材料的分类与境界读取物品 tags，品质读取 quality；辅助列不参与运行判断。

境界进阶 `materials` 为必需物品 ID 与数量；`materials_rate:array,BreakRateMaterial` 每项为 id、count、rate，单枚规则下 count=1。角色逐级属性增量由境界角色属性配置提供，与对象的大境界枚举分开。

## 图标资源配置
`Z图标配置表.xlsx` 的 `id:int` 是唯一主键，同时为资源命名编号。物品 `icon_id` 关联该主键，不再使用单独的 name 保存资源编号。

`path:string` 是资源目录，不含资源文件名；使用目录、id 与对应扩展名定位资源，不能把目录当成完整文件。类别、检查序号和检查用名称属于辅助列，不作为导出字段或主键。

## Luban Schema 不计入游戏配置表
`__beans__.xlsx`、`__enums__.xlsx`、`__tables__.xlsx` 是 Luban Schema，不计入游戏配置表清单。

## 配置表权威与加载门禁
实际 xlsx 是字段、枚举和数值的唯一权威。文件名、表名、主键、字段类型和枚举由 Schema 固定，不得另建同义字段。启动时加载并完成必填、类型、主键唯一性、外键存在性和枚举合法性校验；任一配置校验失败时阻止进入游戏并报告具体表、主键与字段，不静默降级。任何文档中的示例 ID 都只是示例，不得反向覆盖实际配置。

## 统一大境界 MajorRealm
采用 `MajorRealm` 的境界字段统一按大境界枚举读取：
| 枚举值 | 境界 |
|---:|---|
| 1 | 炼气 |
| 2 | 筑基 |
| 3 | 金丹 |
| 4 | 元婴 |
| 5 | 化神 |
| 6 | 炼虚 |
| 7 | 合体 |
| 8 | 大乘 |
0为保留值，含义由所属字段确定，不能统一解释为炼气、通用或无限制。

配表可以使用规定的中文枚举别名，原有合法数字也兼容；导出后使用同一套枚举值。相关字段说明不能继续标注为任意字符串，也不能自行维护另一套境界编号。

## 境界字段的独立职责
各字段仍按所属规则发挥作用：
- 丹药、灵植、法宝境界表示对应对象的大境界。
- 丹炉最高可炼境界限制炼制范围。
- 除渣力 `base_realm` 用于该来源的跨境计算。
- 丹毒池境界用于选择角色当前境界对应的容量与消退配置。
- 打造 `realm_req` 判断角色打造资格。
- 奇珍录境界用于对应条目的配置语义，不自动成为点亮门槛。

材料是否同境界、角色是否达到门槛、丹炉是否可以炼制、是否享受跨境加成，必须分别判断，不能因为都使用 `MajorRealm` 就合并成一个条件。

## 共享字段语义·品质
品质统一为凡、灵、玄、仙、神、道六档，不把颜色作为第二套品质值。物品图标、光柱与边框读取显式资源配置，不仅凭品质推定资源。品质与器物身份分别表达，不使用独立的“品阶”或“稀有度”替代品质。

## 共享字段语义·器物身份
装备、器具、法宝是运行结构身份，品质与身份正交。本命法宝是共生关系，有灵法宝表示器灵已成，道器是承载独一规则的特殊身份。不使用凡器、法器、灵器、法宝、本命法宝、道器的线性六级梯。法宝不使用固定出战位；单件登记神识御使负荷，角色按神识预算结算。

## 共享字段语义·物品与奇珍
奇珍身份与装备、器具、法宝结构身份正交。灵石进入钱包，不进入背包格、不参与堆叠。物品不得使用职业限制；堂口也不是职业。

## 共享字段语义·魔物来源
怪物来源至少区分原生、魔化、造物。魔化是来源状态，不代表所有魔化生物具有同一 AI 行为。普通野兽不用修行境界名，使用野兽强度或推荐境界表达危险度。

## 场景、怪物与掉落配置的引用关系
| 来源 | 目标 | 约束 |
|---|---|---|
| 场景区域 | 刷新方案 | 区域引用的刷新方案必须存在 |
| 刷新方案 | 怪物 | 怪物 ID 必须存在；刷新与 AI 共用同一出生与返回边界 |
| 怪物 | 掉落方案 | 掉落方案必须存在；击杀不直接增加修为 |
| 掉落方案 | 物品或装备 | 目标 ID、数量和权重合法；广播按统一品质门槛 |

## 属性与修炼配置的引用关系
| 来源 | 目标 | 约束 |
|---|---|---|
| 角色、怪物、装备 | 属性字典 | 属性字段键必须存在且类型一致 |
| 境界角色属性 | 属性字典 | 分别提供逐级属性增量与修炼基础量，按各自语义汇总；最终属性由属性系统重算 |
| 神通与 Buff | 属性字典 | 效果只引用现行属性键；蓝条消耗固定使用法力 `mp` |
| 灵根 | 属性字典 | 五行影响是修正，不构成绝对胜负或职业锁 |
| 灵气源 | 系统参数 | 在线与离线共用同一生产、容量和分配参数 |

## 掉落骨架
掉落模型统一为 32 槽权重池，不与「每槽独立概率」并存。每个有效槽至少包含目标 ID、权重、最小数量、最大数量和是否保底。先确定本次抽取次数，再在有效槽内按权重抽取；无放回或可重复必须由方案字段明确。最少与最多掉落数用于约束抽取次数，不得与抽取结果二次冲突。广播门槛由统一品质规则决定，单条覆盖只作为显式例外。

## 属性与装备骨架
攻击、防御使用单值，不建立物理与法术的上下限。装备完整六位为冠、法袍、武器、佩、印绶、鞋履；别名只用于显示映射，不生成新枚举。装备效果使用修饰项列表，支持固定值与万分比，不把最终属性直接写回装备或存档。穿脱装备后由属性系统从来源集合重算。

## 修炼骨架
灵气源每个结算周期只生产一次，再按分配规则给玩家。时段不直接乘入修炼倍率。丹药服用准入与丹毒结算由炼丹规则拥有，本目录不另设服用限制。修为使用足够精度持久化，显示时取整。

## 新增与删除配置表的约束
新增游戏配置表时，同时登记用途、主键、外键与权威区。删除或改名时先更新同步白名单和 Schema，不得留下两张同义表。字段新增由实际 xlsx 与 Schema 先落地，不在代码和文档中另存一套字段结构。

## 物品与炼丹配置的关联边界
物品配置拥有背包身份与功能关联，灵植配置拥有材料属性，丹方丹效配置拥有炼制条件和成品效果；同名或近似编号不表示同一主键。配置总目录只登记关系，具体外键列、空值含义及品质分组由物品配置口径和炼丹规则分别定义。缺少类型、目标不存在或分组未明确的关联，不能凭行序、名称或编号运算补全。

## 系统参数的归属边界
X系统参数的查询身份是 `ParamID`，`ConfigID` 用于标识配置行。炼丹除渣与服药参数、神通熟练度获取概率、神通真意开格与分组参数各自有不同用途。熟练度获取概率不等于熟练度对除渣率的增幅；参数虽在同一张表，也不能互相替代。具体概率、触发条件和取值单位由对应系统规则拥有。
