# 任务系统完整设计规格
任务系统按已成立的业务事实推进步骤；尚未确认的任务流程、教学数值与补授方案不作为已定规则，具体数值与配置字段以正式配置为准。

## 当前任务表配置边界
`R任务表.xlsx` 的 `quest_config` 一行一项任务，`quest_step_config` 一行一个步骤，两表通过任务 ID 关联；首步骤由 `first_step` 指定，后续步骤只按 `next_step` 串联。`step_id` 是任务内稳定身份，不按大小决定流程顺序。两页均使用 `##var`、`##type`、`##group`、`##` 四行表头，枚举填中文别名。`##group` 留空的判定列同时导出给客户端与服务端，填 `c` 的文案、图标、表现列只导出给客户端。B 列“策划备注”不导出；数组槽位从第 1 个连续填写，已用槽位的每一格都要填，不适用的参数填 `0`，未使用的整槽留空，不得在已用槽位中留空导致后续列错位。

当前任务类型只有**主线、支线、悬赏**，同一时间只能进行一条主线。`quest_config` 提供前置任务 1～3、接取条件 1～3、自动接取、接取 NPC、首步骤、周期与任务奖励；`quest_step_config` 提供进入条件 1～3、目标 1～4、完成授予 1～3、末步交付及激活时的表现动作 1～4。正式任务奖励可配物品、修为、角色币和账号币；步骤完成可授予物品、背包或快捷栏扩容、功能解锁。步骤表现动作属于客户端展示，不承担授予或服务端判定。

自动接取只在登录、前置任务领奖、角色等级或大境界变化时检查；自动接取行的接取条件只能使用“任务已完成”“等级≥”“大境界≥”，`accept_npc` 必须为 0。需要持有物品、功能开放、与 NPC 交互等额外接取判定时，按主动接取设计。任务目标的“本步骤起算、接取起算、可回溯”按目标类别分别解释，

当前配置暂不开放每日／每周任务和采集目标；对话表及提示文本表未建，对话节点参数、交付对话节点和屏幕提示文本 ID 暂填 0。本文后续章节涉及世界／宗门任务、实例作用域、失败规则、邮件补发、功法路径熟练度等内容时，它们是后续设计目标或跨系统能力，不能仅凭本任务表直接配置投放。上述能力开放前须补齐配置入口和明确的规则与配置边界。

## 任务通用规则

### 1. 任务系统定位
任务根据战斗、物品、对话、修炼和突破中已成立的事实，推进任务及当前步骤，提供奖励、解锁与任务进度展示。任务目标与结算以权威业务结果为准，不能由界面自行宣告完成。

### 2. 设计前提
- **开局身份【已裁决】**：玩家开局已是宗门弟子，删除 1.1「加入宗门」，新手线从 1.2 开始。
- **身份口径统一【已裁决】**：玩家开局已经是青冥宗外门弟子，境界为炼气第一层；服饰是外门常服奖励，不承担预备弟子转正。所有对白删除“刚拜入山门”“穿上才是正式弟子”等身份升级含义。
- **节点组织**：新手任务以大任务节点组织，节点内用步骤（Step）逐步引导，不引入“子任务”三级结构。

### 任务与步骤层级
任务采用“任务＋步骤”两级结构，不引入独立子任务。大任务节点指任务，小任务或教学环节指步骤。任务整体完成时领取正式奖励，步骤完成可即时授予物品、扩容或功能解锁。一次独立接取、放弃和交付的委托属于一个任务。

### 4.2 StepDef 与 `quest_step_config` 字段对应
| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `step_id` / `next_step` | int | `step_id` 在任务内唯一且稳定，不是顺序号；`next_step` 指向本任务下一步骤，末步填 0。`quest_config.first_step` 指向首步骤 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `title` | string | 任务栏当前目标文案 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `objective_mode` | enum | 填“全部／任一／顺序”；留空等于“全部”。顺序模式按目标槽位推进，持有类与阈值类轮到时按当前状态判断 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `enter_cond` | 条件槽位 1～3 | 多项为“并且”；不满足则等待进入，全空表示上一步完成即进入。仅使用任务接取与步骤进入条件的已定义谓词 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `objectives` | 目标槽位 1～4 | 每槽填写稳定 `oid`、类型、`target`、`param`、`count`、击杀范围、计数起算；未用槽整槽留空。`oid` 不随槽位调整而重编号 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `actions` | 表现动作槽位 1～4 | 步骤激活时执行，仅客户端表现；每槽填写稳定动作 ID、类型、一次性、`target`、`param`，传送必须一次性 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `grants` | 授予槽位 1～3 | 步骤完成时授予物品、扩容或功能解锁；物品放不下时整次步骤完成失败。正式任务奖励仍在末步交付后的领奖流程中结算 |

| 字段 | 类型 | 取值 / 行为 |
|---|---|---|
| `deliver_npc` / `deliver_dialogue` / `must_interact` | 末步交付字段 | 只配在末步；需要 NPC 当面交付时 `deliver_npc` 非 0 且 `must_interact=TRUE`；节点表未建期间对话节点填 0 |

**末步交付**：`deliver_npc=0, must_interact=FALSE` 时目标达成后可在面板领奖；NPC 非 0 且 TRUE 时必须与该 NPC 交互；NPC 非 0 且 FALSE 时面板和 NPC 都可交付。NPC 为 0 却要求 TRUE 是配置错误。新手线明确写“回 X 处交任务”的末步配 NPC 和 TRUE，不能只靠导航或 UI 标记限制领奖。对话节点表未建期间 `deliver_dialogue=0`，只核对 NPC；待对话表接入后再开放精确节点校验。

**失败规则的边界**：旧案的 `failRule={kind,onFail}` 不在现行两张任务表的字段中。新手线默认不配置任务失败；1.8 心魔战“死亡后原地重试且不重复扣材料”仍是突破／副本流程需求，须由突破或副本规则独立确定，不能写成已经可由 `quest_step_config` 填出的失败规则。限时、护送失败同属后续扩展。

**步骤表现动作的恢复语义**：`actions` 在步骤激活时执行。一次性为 FALSE 的导航、高亮、提示、镜头动作可在重新进入或恢复任务时重放；一次性为 TRUE 的动作在同一次步骤激活中按稳定动作 ID 去重，传送必须填 TRUE。物品和功能解锁走 `grants`，不放在表现动作中：

| Action 类型 | 举例 | 重连行为 |
|---|---|---|
| `REPLAYABLE` 可重放 | 导航寻路、教学高亮、UI 提示、镜头指向 | 每次进入/重连都重放，无副作用 |

| Action 类型 | 举例 | 重连行为 |
|---|---|---|
| `ONCE` 一次性 | 传送；确需仅播一次的客户端演出 | 同一次步骤激活按动作 ID 去重；玩家已在传送目标地图时不再传送 |

| Action 类型 | 举例 | 重连行为 |
|---|---|---|
| 不放入 `actions` | 物品、扩容、功能解锁、正式任务奖励 | 前三项在步骤完成时由 `grants` 授予；正式任务奖励在领奖时由 `quest_config` 结算 |

**目标计数基线**：任务目标分别区分接取时刻与步骤首次激活时刻，重连恢复不得重置计数起点。`quest_step_config.objectives[].count_mode` 使用下列中文枚举：

- “本步骤起算”：步骤首次激活时记录基线，事件类只算此后事件；持有物品／货币的进度是当前持有量减去该基线。
- “接取起算”：任务接取时记录基线，步骤激活前的新增事件或持有量变化也计入。到达区域、对话节点、客户端动作仍须目标开放后才计数，配此值等同本步骤起算。
- “可回溯”：持有物品／货币按当前总量判定，接取前已有的也计入；事件类不得配此值。等级、已学技能、熟练度、穿戴装备、完成任务等阈值类始终只看当前状态，不受三种起算值影响。
- **重连恢复表现动作时不得重置步骤基线**。
- 新手教学的计数目标（杀 4 只、炼 3 颗）配“本步骤起算”；跨步骤累计的新事件配“接取起算”；提前持有的材料是否可用，由该条目标显式选择“可回溯”或起算基线，不用一条全局规则代替。

### 任务接取、推进与异常恢复
任务接取时检查条件及主线互斥，按 first_step 和 next_step 推进；末步目标达成后，核对 deliver_npc 与 must_interact，再领取正式奖励并完成任务。一次性已完成任务不能再次接取，重复交付不能重复发奖。

断线重连保留当前步骤、进度与目标计数起点；只恢复允许重放的表现，不再次授予奖励或执行已完成的一次性动作。死亡不清任务或步骤进度。副本死亡重试、退出及回退由副本或突破规则决定，任务表没有 failRule 字段。任务道具丢失的补领规则仍待确定。

### 5.2 现行任务表字段与目标白名单
**`quest_config`：**任务 ID 是稳定主键，不随剧情序号或上线顺序改动；主线、支线、悬赏分别建议从 100001、200001、300001 起编号。`prev_quests` 最多三个且全部完成才可接；`accept_cond` 最多三个且彼此为“并且”；`auto_accept=TRUE` 时仅可用“任务已完成、等级≥、大境界≥”作条件，接取 NPC 必须为 0。`first_step` 指向该任务的步骤 ID。同一时刻仅一条主线进行中。

接取与步骤进入条件共用的谓词只有：等级≥、大境界≥、任务已完成、任务进行中、持有物品≥、已学技能、功能已解锁。等级参数填角色等级，大境界参数填炼气至大乘的枚举值 1～8；“已学技能”填技能识别 ID，持有物品条件填物品 ID 与数量。任务自动接取还受上一段的三谓词限制。区域触发、持有货币和副本实例状态目前没有接取条件谓词，不得在配置栏填自造名称。

**`quest_step_config`：**每步 1～4 个目标，`objective_mode` 为“全部、任一、顺序”，留空按“全部”。每个目标的 `oid` 在步骤内稳定，从 1 编号；改变槽位顺序不改 `oid`。击杀范围填“同图”或“仅本人”；“同图”允许同地图在线队友击杀计入，非击杀目标也须填“同图”。目标类型及 `target`／`param`／`count` 口径如下：

| 类别 | 当前可配置的目标 | 配置与判定要点 |
|---|---|---|
| 战斗与获取 | 击杀怪物、拾取物品、获得物品 | 击杀填怪物 ID，可用 `param` 限定地图；拾取只计拾取成功，获得物品计一切进入角色所有权的路径；二者不能混写 |

| 类别 | 当前可配置的目标 | 配置与判定要点 |
|---|---|---|
| 持有与使用 | 持有物品、持有货币、使用物品、穿戴装备 | 持有物品读取综合背包与快捷栏；货币 `target` 填角色币 1 或账号币 2；使用物品计成功使用，包含服丹；穿戴装备只看当前装备位，`count=1` |

| 类别 | 当前可配置的目标 | 配置与判定要点 |
|---|---|---|
| 成长与修炼 | 学会技能、技能熟练度达到、等级达到、突破成功、打坐时长、获得修为、炼丹成功、完成任务 | 学会／熟练度目标填技能识别 ID；熟练度按本级值且技能须配“施放本神通”；等级目标填角色等级；打坐只计已结算秒数；炼丹成功按成品颗数 |

| 类别 | 当前可配置的目标 | 配置与判定要点 |
|---|---|---|
| 交互与引导 | 到达区域、对话节点、客户端动作 | 到达区域填地图 ID 与区域 ID；对话节点在对话表未建期间节点参数填 0、只核对 NPC；客户端动作只填当前白名单值 |

| 类别 | 当前可配置的目标 | 配置与判定要点 |
|---|---|---|
| 暂不开放 | 采集 | 采集事件来源未上线，不配置；将来按采集行为次数计，不能用持有物品量冒充 |

“可回溯”对持有类目标按当前总持有量计算；阈值类目标允许填写三种计数起算值，但始终只读当前状态，填“可回溯”也不改变结果；事件类目标不得填“可回溯”。到达区域、对话节点、客户端动作只在目标开放后计数；顺序模式下目标轮到时才开放。新手目标所需的先后顺序通过步骤链和目标模式保证，不按 `step_id` 大小推断。

**授予、表现与领奖：**步骤完成时 `grants` 最多三槽，类型为物品、扩容、功能解锁。配物品授予的步骤，其所有目标都必须属于“对话节点、到达区域、客户端动作”；授予物品放不下时整次步骤完成失败。扩容只支持综合背包（容器 1）和快捷物品栏（容器 6）。功能开放项目前只列任务面板 1、炼丹 2、悬赏委托 3、突破 4。表现动作最多四槽，在步骤激活时执行，当前支持导航 NPC／区域、传送、高亮界面、镜头看向 NPC、屏幕提示；传送必须一次性。高亮和“客户端动作”目标共用教学动作白名单：打开背包 1、打开任务栏 2、打开修炼面板 3、点击突破 4；超出白名单须先扩枚举。

任务领奖的 `reward_items` 最多四槽，另可发修为与最多两种货币奖励。正式任务奖励与步骤授予是不同入口；现行任务表没有直接发宗门贡献、称号、配方、功法的奖励列。周期列虽有一次性／每日／每周及北京时间重置规则，计划每日 05:00、每周一 05:00 重置，且未领奖的周期任务跨重置点作废；但当前每日、每周任务未开放，投放前只填“一次性”、`repeat_limit=0`。提示文本表未建时，表现动作“屏幕提示”的文本 ID 暂填 0。

### 6. 作用域、存档与领奖规则

#### 6.1 三种作用域
以下作用域是事件与存档方案，现行目标槽位只提供“同图／仅本人”两档击杀范围，没有副本实例作用域列。实例击杀需要战斗／副本事件提供归属与隔离，不能把“仅本人”误当作“仅本实例”。

| 作用域 | 适用内容 | 例子 |
|---|---|---|
| 个人存档 | 主线、突破材料、首次筑基、独有 BOSS、教学解锁 | 1.2—1.8 主进度 |

| 作用域 | 适用内容 | 例子 |
|---|---|---|
| 房间实例 | 普通怪击杀、普通掉落、可组队悬赏、临时副本 | 1.2/1.4 副本、部分 1.6 悬赏 |

| 作用域 | 适用内容 | 例子 |
|---|---|---|
| 全服表现 | 世界播报、活动状态、排行榜 | 1.8 筑基播报（非任务完成事实） |

#### 6.3 领奖原子顺序
步骤完成时先校验目标与授予容量；若物品授予放不下，本次步骤完成与授予一起失败，不产生部分发放。末步目标达成后按 `deliver_npc`、`must_interact` 校验交付，再对正式任务奖励执行幂等领奖；材料扣除属于相应玩法或另行明确的交付规则，不能从现行任务奖励列推导。正式领奖遇背包满是否采用邮件补发，当前任务表说明没有给出统一规则，须由奖励系统单独定稿，不能把步骤授予的失败口径改成邮件补发。
