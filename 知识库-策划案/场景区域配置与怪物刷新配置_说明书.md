# 场景区域配置与怪物刷新配置说明书
## 一 功能范围与配置分工
场景表示玩家当前所在的一片游戏空间；区域表示场景内的一块矩形，可以承担出生、传送、镜头边界或刷怪等用途。一个场景包含多个区域，`region_config` 汇总各场景的区域，通过 `scene_id` 区分归属。

| 工作簿与页签 | 负责内容 |
| --- | --- |
| `C场景区域配置.xlsx / ConfigScene` | 场景身份、名称、镜头、地图图片和背景音乐 |

| 工作簿与页签 | 负责内容 |
| --- | --- |
| `C场景区域配置.xlsx / region_config` | 区域身份、真实边界、用途标记、传送目标、传送进入条件和刷怪方案引用 |

| 工作簿与页签 | 负责内容 |
| --- | --- |
| `G怪物刷新配置.xlsx / spawn_config` | 每个刷怪方案包含的怪物、数量、刷新位置说明与日常活动引用 |

| 工作簿与页签 | 负责内容 |
| --- | --- |
| `G怪物表.xlsx / monster_config` | 怪物本体，包括属性、复活时间、掉落方案等；本案只解释与场景刷怪直接相关的配置 |

刷怪关系为：**场景 → 区域 → 刷怪方案 → 怪物配置**。区域表已经收纳“在哪个区域刷哪些方案”，方案本身仍独立维护。

编号用于稳定标识对应对象。连接、条件和怪物组成读取实际字段，不从编号大小、行号或名称推断。说明页、编号参考页、设计台账和旧样例页不能代替正式数据页。

## 二 场景配置：ConfigScene
一行登记一个场景。这里的 `scene_name` 是场景显示名，与区域表同名字段的“地编名”用途不同。

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `config_id` | int | 场景唯一正整数 ID，供区域的 `scene_id` 引用 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `scene_name` | string | 场景显示名称，用于场景标题等展示；改名不改变场景身份 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `camera_distance` | int | 场景镜头距离，表示视野远近，不是区域宽高或角色移动距离 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `camera_angle` | int | 场景镜头初始角度，不表示区域方向或传送朝向 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `minimap` | string | 小地图图片资源标识，对应图片须实际存在；留空表示不配置该场景的小地图图片 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `bigmap` | string | 大地图图片资源标识；留空表示不配置该场景的大地图图片 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `grade` | int | 场景等级配置，不作为角色准入门槛。传送最低角色等级使用目标区域的 `min_level` |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `bgm_sound_id` | int | 场景背景音乐 ID，正数引用有效声音配置；0/空表示不指定场景背景音乐 |

镜头、地图图片和音乐不产生地形或碰撞。登记场景也不等于地图已经完成制作和运行验收。

## 三 区域配置：region_config
### 3.1 身份与用途标记
| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `config_id` | int | 区域唯一正整数 ID；传送目标引用此 ID，不填场景 ID、行号或地编名 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `rect_name` | string | 区域中文名称，表头口径为“传送才外显”；用于识别区域，不参与身份匹配 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `scene_name` | string | 地编矩形名，须与实际地图矩形对应；不是场景中文显示名 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `scene_id` | int | 所属场景 ID，须存在于 `ConfigScene.config_id`；决定场景归属以及跨场景传送的目标场景 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `is_main_rect` | int | 1 为场景主区域，0/空为否；规定场景镜头边界，不表示角色无法走出该矩形 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `is_born_rect` | int | 1 为出生区域，0/空为否；规定角色出生区域。可进入场景须有有效出生区域；此标记不表示区域内禁止战斗 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `is_minimap_rect` | int | 1 为小地图镜头区域，0/空为否；提供小地图世界坐标与图片位置的对应范围，可以与主镜头区域不同 |

同场景的主区域和小地图区域应各有明确选定的一行，避免范围歧义。同一矩形兼任多种用途时，分别填写相应标记；只在备注中写用途不会启用功能。

### 3.2 传送进入条件
| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `min_level` | int | 通过传送进入本行区域所需的最低角色等级。正整数表示角色等级必须大于或等于该值；0/空不限制。不是场景等级、推荐境界或怪物等级 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `completed_quest_id` | int | 通过传送进入本行区域前必须已完成的任务 ID。正整数须引用有效任务，且角色已有完成记录；0/空不限制。已接取或正在进行不等于已完成 |

两项都填写时必须同时满足。负数、非法数值及不存在的任务引用属于配置错误，不能作为“不限制”。

**条件配在哪个区域，就限制通过传送进入哪个区域。传送检查目标区域，不检查来源区域的这两列。** 普通走路经过或进入区域不检查，不扩成整张场景的持续等级锁。出生、复活和存档恢复不因新增两列自动改变规则。

### 3.3 边界、传送目标和刷怪方案
| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `min_x` | float? | 区域左边界，WC3 世界坐标 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `max_x` | float? | 区域右边界，须大于 `min_x` |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `min_y` | float? | 区域下边界，WC3 世界坐标 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `max_y` | float? | 区域上边界，须大于 `min_y` |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `teleport_target` | int | 从本区域触发传送后到达的目标区域 ID；正数引用有效区域，0/空表示本区域不作为传送入口。它决定“从这里传到哪里”，不表示进入本区域的条件 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `refresh_monster_plans` | array,int | 本区域引用的刷怪方案 ID 列表，当前展开为“刷怪方案1～8”；每格填一个有效 `spawn_config.config_id`，未用格留空，全空表示不挂刷怪方案 |

边界须与实际地图一致，统一使用 WC3 世界坐标。源表坐标列留空不代表边界为 0；作为传送、出生、镜头范围的区域，验收时必须有完整有效的实际边界。不凭编号或文档猜坐标。

同一个方案挂到不同区域时分别展开怪物，不是无效果的备注。重复挂接可能增加投放数量，应逐项核对。

| 辅助列 | 用途 |

| --- | --- |

上述辅助列仅作填写说明，不凭文字触发功能。表头与中文说明行不是游戏数据行。

## 四 传送规则
### 4.1 连接与落点
四 传送规则：1. A 区域的 `teleport_target` 填 B 区域 ID，表示角色走进 A 的矩形范围后尝试传送到 B。

四 传送规则：2. 落点为 B 的矩形中心：X 取左右边界平均值，Y 取上下边界平均值。地编须保证中心可站立、可以走出入口。

四 传送规则：3. A、B 可以在同一场景或不同场景。跨场景时由 B 的 `scene_id` 确定目标场景，无需再填第二份目标场景。

四 传送规则：4. 连接为单向，A 指向 B 不自动生成 B 指向 A。B 自己没有填写传送目标，也可以作为落地区域。

四 传送规则：5. 两端区域和所属场景都须存在，矩形完整有效；坏引用、缺坐标或退化矩形不作为可用连接。

四 传送规则：6. 入口布局不得因重叠造成目的地歧义，不以表格行序作为玩法优先级。

四 传送规则：7. 落地后有防弹回保护，角色须走出全部有效传送入口后再进入，才触发下一次踩点传送。

### 4.2 条件检查与失败结果
传送前读取目标区域的两项条件，按当前角色真实等级和任务完成记录判断。同场景、跨场景传送进入的条件含义相同；不同入口指向同一目标时都须检查该目标。

传送须检查目标区域要求的角色实际等级与任务完成记录，不能凭自报“条件已满足”放行。未满足条件的区域传送不得更新角色所在场景。

不满足时保留原位置和原场景，说明等级或前置任务不足，不能先传入再踢回。存在路线不等于已经取得进入资格。

踩点传送被拒后，角色停留在入口内不重复尝试、不重复弹出提示；须先走出全部传送入口，再次进入入口才重新判断条件。条件在原地变为满足，也不自动发起传送。

以虚构区域 ID 1、2 为例：区域 1 的传送目标为 2，而区域 1 自身要求最低等级 20、已完成任务 Q。

| 操作 | 判断 |
| --- | --- |
| 从其他区域传入区域 1 | 检查等级至少 20，且已完成 Q |

| 操作 | 判断 |
| --- | --- |
| 从区域 1 传入区域 2 | 检查区域 2 的条件，不把区域 1 的条件当作离开限制 |

| 操作 | 判断 |
| --- | --- |
| 走路进入区域 1 | 不检查这两列 |

| 操作 | 判断 |
| --- | --- |
| 区域 2 两列均为 0/空 | 不设这两项门槛，基础连接有效性仍须满足 |

Q 代表实际有效任务 ID，配表不填写字母 Q。

## 五 怪物刷新配置：spawn_config
一行定义一个方案，最多 10 组怪物。一个区域最多挂 8 个方案；“8 个方案”与“每方案 10 组怪物”是两个不同层次。

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `config_id` | int | 方案唯一正整数 ID，供区域表的 `refresh_monster_plans` 引用 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `position` | string | 刷新位置方式。“区域随机”表示在所挂接区域内随机选择出生位置；出生位置须可站立，不落在阻挡、安全出生点或不可达位置。其他填写方式须另有明确规则 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `spawn_monsters` | array,SpawnMonster | 怪物组列表，表内展开为“怪物1配置ID/数量”至“怪物10配置ID/数量” |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `spawn_monsters.id` | int | 每组怪物配置 ID，引用有效 `monster_config.config_id`，不是模型 ID 或刷新方案 ID |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `spawn_monsters.count` | int | 每组在一次方案展开中的怪物数量，有效投放填写正整数；不是每小时产量或全场景存活上限 |

| 字段 | 类型 | 含义与填写规则 |
| --- | --- | --- |
| `activity` | int | 本方案生成怪物的日常活动引用，按表头对应 `activity_config.id`；0/空为驻留，正数引用有效活动，不代替战斗行为和技能配置 |

每组 ID 与数量成对填写，未使用组留空。只填 ID、只填数量，或有效组数量为 0、负数，均为配置错误，应指出具体方案和怪物组，修正后再作为有效投放。全空组表示不配置怪物，不属于上述错误。

辅助列“场景名称、怪物类型、怪物数量、说明”便于人工核对，不用辅助数量覆盖正式怪物组的数量。

### 5.1 数量与生成时机
角色进入场景后，该场景配置的怪物按区域及方案分布。无需角色逐一走进每个刷怪区域，才使该区域的初始怪物出现。

某区域引用方案甲（怪物 A 两只）和方案乙（怪物 B 三只），展开为五只。另一独立区域也引用方案甲时，另计两只。挂接关系决定区域投放量。

同一对局内，多人进入同图或离开后返回，不得额外增加一批初始怪物，也不得通过往返场景跳过既定重刷等待。

### 5.2 复活时间与掉落
| 怪物表字段 | 用途 |
| --- | --- |
| `refresh_time` | 怪物死亡后的重刷间隔，单位毫秒；30000 表示 30 秒。正数表示等待对应时长后重刷，0 表示不按间隔重刷；负数为配置错误 |

| 怪物表字段 | 用途 |
| --- | --- |
| `drop_methods` | 引用掉落方案；区域挂接不直接发放物品和奖励 |

重刷等待以怪物死亡为起点，尸体展示时长不改变配置中的重刷间隔。

每次重刷后的怪物可以再次被击杀并按规则结算；同一次击杀不得重复发奖。`refresh_time=0` 只规定不按间隔重刷，不表示跨对局永久消失。

## 配置范围
场景配置范围不包含五时段刷新选择、魔化环境倍率或额外的灰盒区域类型。这些扩展玩法不由名称、备注或 `grade` 隐式启用。

## 区域有效性与同场景传送
场景没有有效出生区域时不允许正常进入；地编名不匹配、坐标缺失或矩形退化时，相关区域不能作为有效传送端点、出生矩形或镜头范围。

任务传送的目标与角色在同一场景时，仍按目标区域判断条件，并按实际落地结果反馈，不能因场景相同提前报告完成。
