# 法宝系统策划案
面向：策划、后台程序。本文中的“后台”指游戏规则与结算逻辑，不特指存档服务器。

## 一、系统定位与范围
法宝是玩家获得、使用并通过祭炼培养的能力载体。系统提供获取、御使、收回、单次手动使用、祭炼与打造。

法宝有两种使用方式：持续御使的法宝占用神识，单次手动使用的法宝不占神识。玩家管理战斗和持续效果的组合时需要取舍，但不必为了每次炼丹、探查等单次操作反复更换战斗法宝。

法宝系统策划案定义规则、条件、计算、状态与配置含义；法宝系统交互案定义页面、操作与反馈。具体数值和效果引用由配置表提供，程序内部架构与实现方法由程序团队决定。

本次范围不包括升品、法宝境界成长、经验养成、图鉴收集加成、器灵、本命、临时或限时法宝、祭炼保底、打造概率、御使预设与一键切换。器灵、本命仅保留既定界面的未开放表现。面板数据展示优化暂缓，不在本案重做评分或展示方案。

## 二、对象与术语
### 2.1 法宝身份
一条法宝主表记录对应一种独立法宝，以法宝 ID 区分。同名但品质或境界不同、ID 不同的法宝，属于不同对象。

| 名称 | 含义 |
|---|---|
| 品质 quality | 获得的法宝所属品质；当前没有升品路径 |
| 法宝境界 realm_id | 法宝自身境界；对持续御使类同时作为主动御使门槛 |
| 祭炼层 refine_lv | 法宝当前养成进度，是当前唯一成长维度 |
| 用途分类 category | 战斗 Combat、生产 Produce、辅助 Support，用于内容归类及界面分组 |
| 神识 sense_cost | 配置正数表示持续御使的需求；留空表示单次手动使用 |
| 普攻技能 basic_skill_id | 战斗类的基础攻击技能，随法宝本身配置，不随祭炼层变化 |
| 主表技能 skill_id1～3 | 法宝本身携带的最多三个额外技能，所有祭炼层共有；可不配置 |
| 效果槽 effects | 祭炼层上随层变化的属性、技能、BUFF、词条配置；其中的调用技能与主表技能合称额外技能 |

角色境界、品质、属性名与炼器技能等级均沿用项目已有定义，不另建法宝专属等级。

主动御使读法宝的 realm_id；祭炼读目标层的 realm_req；打造读配方的 realm_req。三处门槛独立，不能相互推导。能打造出来不代表当前境界能够御使。

### 2.2 拥有、御使与生效
| 状态 | 含义与结果 |
|---|---|
| 未拥有 | 没有该法宝的拥有记录，不能御使、使用或祭炼 |
| 已拥有、未御使 | 法宝保留当前祭炼层，不自动提供持续效果 |
| 已御使、当前生效 | 保留御使选择，通过神识分配且运行正常，提供当前层效果 |
| 已御使、神识不足失效 | 保留御使选择与祭炼层，暂停运行和持续效果 |
| 已御使、角色死亡暂停 | 法宝自身不死亡；停止运行和持续效果，原有可见法宝停在原地，等待角色复活 |
| 已御使、配置或运行异常 | 保留玩家记录，但异常法宝不运行；可收回，不可继续祭炼 |
| 单次手动使用 | 已拥有的手动法宝执行本次用途，不进入御使队列 |

“已御使”是玩家的配置选择，“当前生效”是根据当前条件得到的结果，两者不能等同。没有场上模型或因显示名额不足而隐藏，也不等于失效。

## 三、使用方式与神识配置
### 3.1 持续御使
战斗法宝必须配置正数神识。持续提供生产、辅助效果或自动重复执行用途的法宝，也必须配置正数神识。

持续法宝只有在已御使、通过神识分配且角色在线存活时才运行。仅拥有、不御使，不提供持续效果。

法宝没有独立死亡状态。角色死亡时，法宝停止新施法、自动行为及持续贡献；原有可见法宝停在死亡时的位置，不再绕飞、追击或跟随，不因死亡销毁。原本没有显示的法宝不新增表现。角色复活后按当前神识重新判定，符合条件的法宝回到角色身边恢复运行，其余按失效或异常规则处理。

玩家手动点击后开始长期自动运作，仍属于持续御使，不因启动动作是“点击”而免除神识。

### 3.2 单次手动使用
神识字段留空的法宝用于一次明确的操作，不占神识，不允许御使，不参加自动战斗，也不因拥有而自动提供常驻增益。

一次使用可以是一次有结束点的炼制、探查或特殊操作，不要求瞬间完成；连续自动重复执行多次，则属于持续御使。

手动使用校验：已拥有、主表、唯一有效 0 层与当前祭炼层有效，以及该用途的目标、材料、冷却等既有条件。不因神识不足而拒绝，也不要求收回战斗法宝。法宝的御使境界门槛不自动变成手动用途门槛；具体用途自身的条件照常生效。

单次使用不等于消耗整件法宝。具体用途消耗什么、产生什么、何时结束，由所调用的技能、BUFF、词条和对应玩法规则决定。

### 3.3 配置边界
一件法宝由 sense_cost 确定一种使用方式，不额外建立使用方式分类表。同一件持续法宝可以同时配置战斗效果与世界用途，但不能把其中一次点击解释为整件法宝免神识。

| 配置情况 | 判定 |
|---|---|
| sense_cost 为正数 | 持续御使；sense_cost_min 为正数且不超过 sense_cost |
| sense_cost 留空 | 单次手动；sense_cost_min 留空，祭炼层不配置神识减免 |
| sense_cost 填 0 或负数 | 无效配置，不解释为免费御使 |

生产、辅助不天然免神识；是否持续运行才是判断依据。配置留空必须保留“单次手动”的业务含义，不能被导出默认值误变成免费御使。

## 四、神识检测与生效分配
### 4.1 容量与单件需求
角色属性“神识”提供可用容量，法宝系统只读取，不把神识作为蓝条逐次扣除。

持续法宝的实际神识需求取当前祭炼层：

实际神识需求 = min(配置神识, max(最低占用, 配置神识 − 当前层祭炼减免))

未配置减免按无减免处理。最低占用始终为正数，祭炼不能把持续法宝减成零占用。手动法宝不参与此计算。

御使队列总需求，是全部已御使持续法宝的实际需求之和，包含神识不足而暂时失效的法宝。实际生效占用，是本次通过分配的法宝需求之和。前者可能超过容量，后者不得超过容量。

### 4.2 检测时机
以下情况都重新检测，不依赖玩家打开面板或确认通知：

- 角色神识增加或减少。
- 玩家御使或收回法宝，改变御使队列。
- 祭炼成功或当前有效配置变化，改变法宝实际需求。
- 登录、复活、更换角色载体后恢复御使配置。

仅继承属性变化而神识及需求未变化时，更新法宝属性与展示，不无故重启技能和效果。

### 4.3 分配规则
1. 对已御使的持续法宝，按当前实际神识需求从高到低排序。
2. 同需求按法宝 ID 升序，保证每次计算顺序一致。
3. 从第一件开始逐件判断：该件需求不超过剩余神识则通过分配，并从剩余容量中扣除该需求。
4. 该件放不下则因神识不足失效，不占用容量；跳过它，继续检查更低需求的法宝，直到全部检查完。
5. 分配不自动调整玩家的御使选择；失效的法宝保留御使选择，条件满足时自动恢复。

三件法宝实际需求为 100、50、30 时：

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 180 | 100、50、30 | 无 |
| 150 | 100、50 | 30 |
| 140 | 100、30 | 50 |
| 100 | 100 | 50、30 |
| 90 | 50、30 | 100 |

神识 140 时，100 生效后剩余 40；50 放不下，跳过后 30 生效，最终剩余 10，无须先收回 50。神识 90 时 100 放不下被跳过，50 与 30 生效。

### 4.4 结果应用
由生效转为神识不足失效：立即停止自动行为，移除该法宝持续提供的效果，停止独立场上表现。保留拥有记录、祭炼层和御使选择。

由失效转为符合条件：自动按当前祭炼层恢复效果和运行，不要求玩家再次御使。恢复后是否有独立表现，仍受模型配置与显示名额约束。

同一层且生效结果不变时，不反复移除和重新触发效果。祭炼层发生变化时，即使仍然生效，也必须完整替换为新层效果，不保留旧层贡献。完整替换的范围是祭炼层上的效果槽与继承；普攻技能与主表技能不属于任何一层，换层时保持装载，不中断、不重启，其冷却按 8.2 连续。

每次重算有新增神识不足失效的法宝时，统一通知本次受影响的法宝。通知不阻塞结算；玩家不处理也已失效。同一失效状态不因重复刷新而反复通知。仅有法宝恢复生效时，更新实际状态及已有界面，不另发恢复通知；同次检测既有新增失效又有恢复时，只通知新增失效项。

收回、神识失效或角色死亡，停止的是法宝继续运行及其持续贡献；已经造成的伤害、已经产出的物品不撤回。已发出的飞弹、已经触发的一次性延迟效果继续按正常技能规则结算，不因法宝停止而取消或重复执行。尚未发出的技能停止，持续引导不再产生后续作用；独立临时效果按自身配置结束。

后续一次性结算保留原法宝、技能及所属玩家来源；属性取值沿用通用技能结算规则，不为收回、失效或换层另设追回、补偿或重算流程。神识变化仍正常检测，但死亡期间不恢复效果、不重新安排场上表现；死亡停驻优先，复活后再应用最新结果。

### 4.5 神识不足与境界回退分别处理
神识不足按本案重新分配并暂停效果，不再采用全部继续生效的处理。

角色境界被动下降，仍沿用既有规则：不因此取消已御使选择，也不单独因此停用；但这些法宝仍必须通过当前神识分配。新的御使操作继续按当前境界校验。

登录、复活不能跳过神识检测而恢复全部法宝，也不能把显示名额上限当作御使数量上限。

## 五、御使与收回
### 5.1 主动御使条件
主动御使必须同时满足：

- 角色存活、数据已就绪，且该玩家没有进行中或结果待确认的法宝管理操作。
- 玩家已拥有且尚未御使。
- 主表、0 层及当前祭炼层配置有效，且属于持续御使类。
- 角色当前境界达到法宝 realm_id；0 表示无御使境界门槛。
- 新增后的御使队列总需求不超过当前神识。

主动御使仍以整个队列总需求校验，不能只看目前生效的部分。存在因不足而失效的保留项时，玩家可先收回调整，再新增御使。

校验失败不改变已有选择，不扣资源。成功后提交御使选择并生效；若操作受理后角色死亡，只保留御使选择、等待复活，不将正常暂停算成启用失败。其他首次启用失败恢复为未御使，不留下部分效果。

### 5.2 收回
收回无代价、无冷却；御使本身也没有额外操作冷却。

角色存活且没有进行中或结果待确认的法宝管理操作时，已御使法宝均能收回，包括神识不足、配置异常或运行异常的法宝。

收回取消该件的御使选择，停止其持续效果和自动行为，并对剩余队列重新分配。只移除本件法宝的贡献，不影响其他来源的同名效果；重复请求不得重复扣属性。

### 5.3 管理操作的公共条件
御使、收回、祭炼、打造共用同一组公共条件：角色存活、数据就绪、该玩家没有另一笔进行中或结果待确认的法宝管理操作。各自门槛在公共条件通过后再校验。

同一玩家一次只处理一个法宝管理操作，不同时处理不同法宝的管理请求。确认弹层尚未提交时不占用这个处理资格；提交后切页、改选中项或关闭面板，都不取消已受理操作。此限制不暂停法宝正常自动战斗、神识检测和其他玩家的操作；单次手动用途仍由对应玩法定义。

角色死亡期间面板只读，不新发起这四类操作。死亡前已经受理的操作照常完成、只结算一次，不因死亡额外判失败、取消或退料；结果涉及生效或场上恢复的部分等角色复活后再判定。因已受理的收回而移除表现，属于收回结果，不属于法宝死亡。

## 六、获取、祭炼与打造
### 6.1 获取
同一玩家同一法宝 ID 只持有一份记录。首次获得为祭炼 0 层、未御使；0 层已有完整效果配置，但获得动作不自动执行效果。

所有法宝都必须在物品表中配置对应的法宝道具，持续法宝和手动法宝均不例外。掉落、宝箱、任务奖励可通过背包中的法宝道具授予法宝。使用该道具是“登记获得法宝”，与已拥有手动法宝的“执行一次用途”不同。

| 授予结果 | 处理 |
|---|---|
| 首次成功获得 | 创建 0 层未御使记录；通过法宝道具授予时消耗该道具 |
| 已拥有 | 不覆盖祭炼层或御使选择；不消耗法宝道具 |
| 配置无效 | 不创建残缺记录；不消耗法宝道具，提示异常 |

掉落、奖励和打造遵循同一授予规则，不能各自产生一份重复记录。

### 6.2 祭炼条件与结果
持续法宝和手动法宝都可祭炼。未御使、正常生效、神识不足失效均不是祭炼门槛；配置或运行异常时禁止继续祭炼，但可收回已御使法宝。

目标层为当前层加一。先校验有效配置、现有炼器技能等级、当前角色境界、全部背包材料和货币；任一不足，全部不扣。通过后一次性扣除，再按目标层成功率判定。

| 结果 | 层数与消耗 | 效果处理 |
|---|---|---|
| 成功 | 升一层，消耗本次材料和货币 | 当前层完整替换为目标层；持续类重新分配整个御使队列 |
| 概率失败 | 层数不变，材料和货币已消耗 | 保持原层效果；不掉层、不损坏、不补偿、无保底 |
| 校验未通过 | 层数、资源均不变 | 不执行祭炼 |
| 成功后的运行恢复异常 | 保留已经获得的新层，不恢复旧层或再次扣料 | 异常法宝暂不运行，不混用新旧效果；显示异常并允许收回 |

每层都是完整快照，不将历次层数的效果累计相加。神识需求降低也可能改变排序，因此祭炼成功不能只刷新选中法宝。

配置完整有效且当前层已达最高祭炼层时，为正常满层，不能继续祭炼；不要求再有下一层配置。尚未到最高层，但所需后续层缺失、停用或层序断裂时，属于祭炼配置异常，不能跳层，也不能当作正常满层。

### 6.3 打造
一件法宝可以没有打造配方；配置时最多一条配方行，以法宝 ID 关联目标。没有启用且有效配方的法宝不进入打造图录，不增加多配方切换规则。

打造前校验有效配方、启用的法宝主表、唯一有效 0 层、尚未拥有、炼器技能等级、角色境界、全部材料与货币。全部通过才扣除，不允许部分扣料后才发现不能授予。

打造必定成功，没有成功率、幸运或保底分支。成功获得 0 层未御使法宝，不自动启动持续效果，也不自动执行一次手动用途。

重复打造不扣资源。若扣料后因异常未完成授予，必须明确记录已扣内容与授予结果，不能静默吞料，也不能提示成功。

## 七、效果与属性
### 7.1 当前层效果
当前祭炼层最多配置八组效果，每组包含行为、参数或 ID、数值。

| 行为 | 参数 | 数值含义 |
|---|---|---|
| 加属性 | 已定义的属性名 | 必填，增加法宝自身属性 |
| 调用技能 | 有效技能 ID | 留空，具体数值读取技能配置 |
| 调用 BUFF | 有效 BUFF ID | 留空，具体数值读取 BUFF 配置 |
| 调用词条 | 有效词条 ID | 留空，具体数值读取词条配置 |

加属性只加给法宝自身，不直接加给角色。无场上模型的法宝也有自身属性。要改变角色、生产结果或世界玩法，应由被引用的技能、BUFF、词条定义目标及作用。

持续类通过神识分配后才提供持续效果；调用技能表示该技能在法宝生效期间可按自身触发条件运行，不表示每次恢复都立即施放一次。

法宝的额外技能有两个来源：主表技能 skill_id1～3 属于法宝本身，所有祭炼层共有，可不配置；效果槽的调用技能属于某一祭炼层，随层变化。两者语义相同：持续类在法宝生效期间按技能自身触发条件运行，并参加 8.1 的自动施法选择；手动类由对应玩法在使用时调用。主表技能不占用效果槽，不受八组上限约束，也不因祭炼换层而移除或重新装载。

手动类在本次用途被发起并校验通过后，使用当前层效果与主表技能完成本次操作；不因持有或打开面板而持续生效。效果持续时间由所引用的配置决定，不在法宝效果槽另加一份通用持续时间。

行为为空的槽不生效；非空槽必须是合法行为，参数有效。多个加属性槽可累加；同层相同的“调用行为＋ID”不得重复。技能不重复只约束同时生效的来源：普攻技能与主表技能 1～3 互不重复；每一祭炼层的效果槽调用技能不得与普攻、主表技能重复，同层内也不重复。不同祭炼层各自是完整快照，同一技能在多层的效果槽中重复填写属于正常配置，不算重复。

各槽按配置序号稳定装载，主表技能在法宝生效时与当前层效果一起装载；调用效果前法宝自身属性必须已确定。槽位顺序与主表技能的序号都不决定多个技能的施放优先级。任何启用或换层失败都不得留下半套效果，不得误删其他法宝或其他来源的同名效果。

### 7.2 属性继承
法宝自身属性[X] = 当前层全部“加属性 X”之和。

法宝有效属性[X] = 法宝自身属性[X] + 向下取整(角色属性[X] × 当前层继承比例[X] ÷ 10000)。

未配置继承比例的属性不继承；上下限属性分别计算。角色属性变化时，法宝继承值同步更新，不等待重新御使。法宝自身属性不能再回加给角色形成重复计算。

### 7.3 威能与说明文本
威能沿用当前展示评分：对配置了权重的有效属性，取非负值乘权重求和后向下取整；没有权重的属性不计入。评分包含继承部分，不由法宝主表直接填写，不参与伤害或其他实际结算。

战斗效果说明 combat_desc、世界用途说明 world_desc 只用于展示。文字本身不生成能力，不替代技能、BUFF、词条或其他有效配置。面板评分准确性与更详细的数值展示不在本轮调整。

## 八、自动战斗与场上表现
### 8.1 自动战斗
法宝释放技能时，施法主体是发起本次技能的具体法宝，所属玩家是归属者，玩家角色不是代替法宝施法的主体。这是技能执行与结算必须落实的规则，不只是场上表现或设定说明。

每次法宝施法必须明确所属玩家、具体法宝、技能 ID 及目标或目标位置；这些来源信息必须传递至技能执行，以及涉及本次施法的服务器校验与结算环节。后台依据权威状态校验归属、该法宝是否可用、技能是否属于其当前有效配置、冷却及目标条件，不能仅凭前台标签认定主体，也不能只传玩家角色而丢失法宝来源。具体调用接口、传递方式与 WC3 执行载体由程序团队决定。

技能表定义技能效果与释放条件，不将一个技能固定为只能由人物或法宝施放；调用方负责提供或解析本次正确的施法主体。同一技能由法宝调用时，“施法者自身”指这件法宝；效果若作用于所属角色，应由效果目标明确表达，不能靠把施法主体换成人物来实现。

战斗法宝通过神识分配后，按普攻技能与额外技能的配置自动行动。普攻技能单独配置；额外技能来自主表技能 skill_id1～3 与当前层效果槽的调用技能，按自身触发条件执行。同一技能在本次同时生效的来源中只能出现一次，不能因来源重复而多次触发；不同祭炼层可以各自保留同一技能。

角色被攻击、承受伤害或亲自造成伤害时进入或刷新战斗状态。法宝及其派生伤害不能被当作角色亲自出手而不断延长战斗。超过配置的脱战时间后，法宝退出攻击并回到跟随。

目标在角色附近搜索，限定为存活敌对目标，排除法宝的辅助表现或出伤对象，选择距角色最近的合法目标。

- 近战：接近目标至普攻技能允许的距离后攻击；超过配置的放弃距离则返回跟随。
- 远程：留在角色附近施放；选取和保留目标都必须满足技能实际射程，不停留在“选得到却打不到”的状态。
- 目标死亡、无效或超距时返回跟随；后续有效战斗信号再更新目标，不擅自无限接战。

每件法宝独立选择下一次自动施放的技能：

1. 先筛选当前满足全部释放条件的技能，包括冷却可用、目标合法、射程满足及技能自身条件。普攻与可主动施放的额外技能均参加选择，不区分额外技能来自主表还是效果槽。
2. 可用技能按技能表配置的完整冷却时长（CD）从长到短排序，优先释放 CD 长的；不是比较剩余冷却时间。CD 相同按技能 ID 升序。
3. 长 CD 技能仍在冷却或不满足其他条件时，不参加本次选择，不阻塞其他可用技能；没有可用技能时不施放。
4. 每次选择一个技能开始施放，能够发起下一次施放时重新筛选和排序。长 CD 技能变为可用，不因此打断已经开始的施法或引导。

被动、命中触发及派生技能仍按自身触发规则执行，不因 CD 较长就被改成主动轮流施放。上述优先级只决定自动施法的选择次序，不改变技能原有冷却、触发条件或效果。

法宝伤害读取自身有效属性，伤害类型、射程、冷却与命中效果读取实际技能配置。持续法宝自动施放不套用英雄职业、等级、蓝量和英雄施法动作的限制；其他技能条件照常。手动用途的具体条件仍由对应用途定义。

命中、词条触发、延迟与派生伤害均保留所属玩家、法宝和技能来源，不能中途改算成英雄伤害或另一件法宝的属性。“法宝命中”包含普攻与额外技能；需要排除普攻时使用“法宝技能命中”的含义。

### 8.2 冷却
冷却归属于具体法宝的对应技能，不借用或混用玩家角色、其他法宝的技能冷却。

法宝技能在同一局内的冷却连续保留。收回、重御使、神识失效与恢复、祭炼换层、死亡复活、更换角色载体，都不能刷新已有技能冷却。

技能本局首次启用时初始化为可用；已有冷却未结束时，再次启用不能提前使用。离线后的冷却保存不在本系统增加永久存档字段。手动用途原本有冷却的，不能通过反复使用或切换面板绕过。

### 8.3 表现资格
法宝当前层模型优先，留空时沿用主表模型；两处均无模型则没有独立场上表现，但合法效果仍可生效。

当前仅做绕飞跟随、近战追敌、远程随身施放和传送归位。表现参数读取全局配置，不增加单件覆盖。

每名玩家独立表现名额读取 MaxVisibleIndependent，当前配置为六件。只在当前正常生效且有模型的法宝中，按法宝 ID 升序取得显示资格。

上述资格分配用于角色存活时。死亡期间仅保留死亡时已有的可见法宝静止表现，不按“仅生效者显示”把它们销毁，也不因神识恢复而新增或移动表现；静止可见不代表效果生效。复活后重新计算资格。

超出显示名额的法宝仍占神识、仍生效；不得因此禁止御使。神识不足失效的法宝不参加显示资格分配，不能套用“只是隐藏”的处理。

新增、收回或资格变化只调整受影响的显示位置，其他法宝不集体跳位。传送后随角色归位，不改变拥有、御使和祭炼层。

场上表现不充当独立可选中、可受击、占人口或占治疗名额的战斗单位。距离、范围和弹道起点与法宝实际表现位置一致，不能因内部辅助对象的位置不同而改变结算。

## 九、数据保存与异常结果
### 9.1 保存内容
拥有记录以法宝 ID 标识，保存祭炼层 refineLv 与御使选择 equipped。记录存在即已拥有，不另存一份拥有状态。

神识需求、实际生效状态、属性、威能、效果与表现资格均由当前记录、角色数据和有效配置推导，不作为独立永久状态保存。手动法宝的御使选择固定为未御使（equipped=false）。

授予、御使、收回、祭炼完成后保存对应结果；祭炼失败也需保留资源消耗记录。玩家离线保存尚未完成的结果。单纯神识变化、死亡或显示资格变化，不改写御使选择。

### 9.2 生命周期
| 场景 | 处理 |
|---|---|
| 登录 | 读取拥有、祭炼层与御使选择；等角色数据就绪后，按当前神识重新分配，再恢复符合条件的效果 |
| 死亡 | 法宝自身不死亡；停止新施法、自动行为及持续贡献，原有可见法宝原地停驻；保留御使选择和祭炼层 |
| 复活、更换角色载体 | 使用当前角色属性重算，不重复残留旧效果；仍按高需求优先、放不下则跳过继续检查；符合条件的法宝归位恢复，其余按失效或异常处理 |
| 离线 | 停止运行并完成待保存结果 |
| 传送 | 更新随身位置，不重新获得法宝，不重置冷却 |
| 主表、0 层或当前层缺失、停用 | 原记录保留，不擅自降层、删除或覆盖；异常法宝不运行 |

恢复时神识不足并不是存档错误。配置或数据缺失不能拿零需求、默认层数来伪造合法结果；神识计算所需输入不完整时，不开放新增御使，待数据有效后重新判定。

### 9.3 一致性与容错
同一次操作的资源与结果只能结算一次。后台必须能识别操作所属玩家、操作类型、目标法宝及这一次操作；重复确认、重传或重复回执沿用原结果，不重新扣费、升层或抽取成功率。前台禁用按钮不能代替后台校验；多玩家环境下必须得到一致的层数、扣费、御使选择与神识分配结果。

前台预检用于即时反馈，正式结果以后台重新校验与结算为准。确认提交必须对应玩家确认的目标法宝、目标层或配方及消耗；这些内容发生变化时要求重新确认，不按未展示的新条件静默扣费。资源持有量等条件仍在实际受理时校验。

未收到回执、超时或断线不等于失败，不能推断未扣费。此时进入“结果待确认”，仍视为同一笔未完成核对的操作，暂停该玩家新的法宝管理提交；不得以重开面板或重新登录把它清成新的操作。

连接恢复、重新打开面板或重新登录后，由后台核对原操作并返回明确结果：已完成则同步实际结果；确认原操作已终止、不会再执行且没有未处理的资源消耗时，才允许重新发起；仍无法确认则继续显示待确认并保留保护。查不到记录本身不等于原操作已经终止。已扣费但未完成授予等异常也按真实进度核对，不伪装成未扣费失败。查询不重复执行操作，技术上的识别、重试和恢复方式由程序团队决定。

取得明确终态后结束处理中或待确认状态，刷新真实数据并解除公共操作限制；未核实时允许查看和关闭界面，不无条件承诺重登即可恢复。结果核对与存档写入重试分别处理。

存档写入失败时保留本局已生效结果，不重复扣费或重新抽取祭炼结果，并记录玩家、法宝、层数、资源消耗和错误，供恢复处理。重试次数、间隔及具体恢复机制由程序确定，不改变本节的结果保护要求。

读档解析失败不得以空列表、0 层或未御使覆盖旧记录。合法旧记录缺少可补齐字段与整份解析失败必须区分。

运行异常与神识不足分别提示。运行恢复失败保留记录、停止异常效果、允许收回；恢复或重新登录后重新校验，不能无条件承诺一定成功。

### 10.8 配置完整性与辅助信息

**法宝配置完整性：物品、层序与引用**
- 所有法宝必须配置对应物品，获取物品 ID（unlock_id）必填且引用 W物品表中的有效物品；缺失或引用无效属于配置异常。
- 每件法宝恰有一条有效 0 层，有效层从 0 连续；最高层必须与预期上限一致，不能把中间缺层当作已满级。
- 图标及属性、材料、货币、技能、BUFF、词条等引用必须真实有效。示例中的占位 ID、未登记属性名不能直接启用。

**法宝配置完整性：辅助信息、使用方式与技能**
- 法宝主表中的“预期最大祭炼层”仅用于核对配置完整性，不决定玩家实际层数。各页回显名称与配置备注只帮助填表，不生成效果、门槛或玩家存档。
- 持续类神识与最低占用为正，最低占用不超过配置神识；祭炼减免非负。手动类三项留空，不配置自动普攻或攻击方式；主表技能不受使用方式限制。
- 主表技能 skill_id1～3 各自可空，空值或 0 表示无技能；填写时须为有效技能 ID，三项互不重复，不与普攻技能重复，也不出现在任何一层的效果槽中。不重复只针对同时生效的来源；同一效果槽技能在多个祭炼层重复填写属于正常配置。

**法宝配置完整性：祭炼层、成对项与空值**
- 0 层保留完整效果、继承与可选模型，但升级门槛、材料、货币、成功率均空。1 层起成功率为 1～10000，炼器与境界要求有效。
- 材料、货币、继承的成对项与效果行为的必填项按本章校验；不将无效引用解释为“无效果”。
- 行停用标记、可空类型、枚举空值及组内空值须验证实际导出和读取结果。技术表示不能把手动判成免费御使、把无攻击方式判成近战，或把空效果组当作有效效果。

## 十一、系统协作与交付边界
### 11.1 手动用途的职责
法宝面板管理拥有记录、持续御使、祭炼与打造。单次手动用途由对应玩法的操作入口发起；本案只规定通用资格与神识含义，不规定某件法宝的具体用途。哪件法宝有什么效果、需要哪些参数，由内容配置确定；炼丹、探查等玩法中的法宝选择、调用时机、效果应用、消耗及反馈，在对应玩法策划案与交互案中约定。手动法宝的主表技能与当前层效果一样，只提供给对应玩法在使用时调用，不因持有而自动运行。本案不另建通用使用流程、分类体系、“使用”页或按钮，也不改变已定的整体界面。

本案与配套交互案使用同一套拥有、御使、生效、失效含义。后台负责结算，前台展示实际结果，不以“已御使”推断必然生效。

### 11.3 接入验收
配置表说明与“祭炼减免”中文表头已同步；字段类型、枚举、数组结构和示例启用状态未改。正式启用前须填齐必需参数与有效引用，并完成以下导出、读取与配置校验，不能以说明已更新代替验证：

| 核对项 | 必须得到的结果 |
|---|---|
| 空值与 0 值 | sense_cost 留空仍识别为手动，填 0 仍为无效；非战斗类攻击方式留空不变成近战；主表技能空或 0 不生成技能 |
| 停用行与 enable | 首列 ## 的示例行不进入导出数据；正常导出行的 enable=false 按对应配置的停用规则处理，不与“整行未导出”混淆 |
| 空材料、效果与继承组 | 未使用组不生成有效配置；效果行为为空整组不生效；调用技能、BUFF、词条的空数值不变成额外效果参数 |
| 技能来源与换层 | 二层获得、三层保留的同一效果槽技能允许重复填写；同层重复或与普攻、主表重复仍拒绝；换层不重启主表技能、不刷新已有冷却 |

技能选择还须验证：多个技能均可释放时选完整 CD 较长者；该技能不满足条件时选择其余可用技能，同 CD 按技能 ID 升序。

技能目标、完整 CD 与神识属性即使已有定义，仍须验证法宝调用和变化响应。临时神识不足、死亡暂停仍保留原御使选择。
