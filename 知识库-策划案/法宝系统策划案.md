# 法宝系统策划案
## 一、系统定位与范围
法宝是玩家获得、使用并通过祭炼培养的能力载体。系统提供获取、御使、收回、单次手动使用、祭炼与打造。

法宝有两种使用方式：持续御使的法宝占用神识，单次手动使用的法宝不占神识。玩家管理战斗和持续效果的组合时需要取舍，但不必为了每次炼丹、探查等单次操作反复更换战斗法宝。

法宝系统策划案定义规则、条件、计算、状态与配置含义；法宝系统交互案定义页面、操作与反馈。具体数值和效果引用由配置表提供，程序内部架构与实现方法由程序团队决定。

法宝打造与养炼同时提供法宝面板、炼器面板两处入口：法宝面板为“打造”“养炼”，炼器面板对应“法宝打造”“法宝养炼”。养炼中的祭炼使用同一功能与同一块操作面板，器灵、本命仍只保留未开放入口；入口不同不改变规则。

法宝打造与祭炼的详细规则、配置、条件和结算统一由本案维护，详细交互统一由《法宝系统交互案.md》维护。炼器系统文档负责四页签和入口说明，以及装备强化、装备炼化的详细需求。

两处法宝入口共用所有权、材料、货币和操作结果，并沿用同一组管理操作公共条件。已提交请求不因切换入口而取消或重复提交；请求重试与结束遵循项目公共网络机制，后台对同次请求保证一次结算。

本案包含法宝打造概率及祭炼升境界，不包含升品、经验养成、图鉴收集加成、器灵、本命、临时或限时法宝、祭炼保底、御使预设与一键切换。器灵、本命仅保留既定界面的未开放表现。面板数据展示优化暂缓，不在本案重做评分或展示方案。

## 二、对象与术语
### 2.1 法宝身份
一条法宝主表记录对应一种独立法宝，以法宝 ID 区分。同名但品质或境界不同、ID 不同的法宝，属于不同对象。同一玩家同一 ID 只拥有一份。

| 名称 | 含义 |
|---|---|
| 品质 quality | 法宝所属品质；当前法宝打造开放仙品、神品、道品，无升品路径；物品系统六档品质枚举保留 |

| 名称 | 含义 |
|---|---|
| 法宝境界 realm_id | 法宝自身境界；对持续御使类同时作为主动御使门槛；祭炼提升后转为目标境界的法宝 ID |

| 名称 | 含义 |
|---|---|
| 用途分类 category | 战斗 Combat、生产 Produce、辅助 Support，用于归类及界面分组 |

| 名称 | 含义 |
|---|---|
| 法宝类型 | 飞剑、宝伞、葫芦等，在同类别下聚合最终成品；与 category 分开配置 |

| 名称 | 含义 |
|---|---|
| 神识 sense_cost | 配置正数表示持续御使的需求；留空表示单次手动使用 |

| 名称 | 含义 |
|---|---|
| 普攻技能 basic_skill_id | 当前法宝 ID 的基础攻击技能 |

| 名称 | 含义 |
|---|---|
| 主表技能 skill_id1～3 | 当前法宝本身携带的最多三个额外技能，可不配置 |

| 名称 | 含义 |
|---|---|
| 效果槽 effects | 当前法宝 ID 的完整属性、技能、BUFF、词条配置；其中的调用技能与主表技能合称额外技能 |

| 名称 | 含义 |
|---|---|
| 祭炼 | 保持类型、品质和材料搭配，将原法宝直接提升为所选更高境界的目标法宝；不设置强化层数 |

角色境界、品质、属性名与炼器技能等级沿用项目已有定义，不另建法宝专属等级。法宝不再保存或读取祭炼层；获得、使用和重建均不依赖起始层配置。

主动御使读当前法宝主表的 realm_id；打造读目标打造行的 realm_req；祭炼复用所选目标法宝打造行的 realm_req，并要求原法宝境界低于目标、目标不超过玩家境界。主动御使与打造配方的门槛不能相互推导。

### 2.2 拥有、御使与生效
| 状态 | 含义与结果 |
|---|---|
| 未拥有 | 没有该法宝的拥有记录，不能御使、使用或祭炼 |

| 状态 | 含义与结果 |
|---|---|
| 已拥有、未御使 | 法宝保留当前身份与境界，不自动提供持续效果 |

| 状态 | 含义与结果 |
|---|---|
| 已御使、当前生效 | 保留御使选择，通过神识分配且运行正常，提供当前法宝完整效果 |

| 状态 | 含义与结果 |
|---|---|
| 已御使、神识不足失效 | 保留御使选择与当前法宝身份，暂停运行和持续效果 |

| 状态 | 含义与结果 |
|---|---|
| 已御使、角色死亡暂停 | 法宝自身不死亡；停止运行和持续效果，原有可见法宝停在原地，等待角色复活 |

| 状态 | 含义与结果 |
|---|---|
| 已御使、配置或运行异常 | 保留玩家记录，但异常法宝不运行；可收回，不可继续祭炼 |

| 状态 | 含义与结果 |
|---|---|
| 单次手动使用 | 已拥有的手动法宝执行本次用途，不进入御使队列 |

“已御使”是玩家的配置选择，“当前生效”是根据当前条件得到的结果，两者不能等同。没有场上模型或因显示名额不足而隐藏，也不等于失效。

## 三、使用方式与神识配置
### 3.1 持续御使
战斗法宝必须配置正数神识。持续提供生产、辅助效果或自动重复执行用途的法宝，也必须配置正数神识。

持续法宝只有在已御使、通过神识分配且角色在线存活时才运行。仅拥有、不御使，不提供持续效果。

法宝没有独立死亡状态。角色死亡时，法宝停止新施法、自动行为及持续贡献；原有可见法宝停在死亡时的位置，不再绕飞、追击或跟随，不因死亡销毁。原本没有显示的法宝不新增表现。角色复活后按当前神识重新判定，符合条件的法宝回到角色身边恢复运行，其余按失效或异常规则处理。

玩家手动点击后开始长期自动运作，仍属于持续御使，不因启动动作是“点击”而免除神识。

### 3.2 单次手动使用
神识字段留空的法宝用于一次明确的操作，不占神识，不允许御使，不参加自动战斗，也不因拥有而自动提供常驻增益。

一次使用可以是一次有结束点的炼制、探查或特殊操作，不要求瞬间完成；连续自动重复执行多次，则属于持续御使。

手动使用校验：已拥有、当前法宝主表及完整能力配置有效，以及该用途的目标、材料、冷却等既有条件。不因神识不足而拒绝，也不要求收回战斗法宝。法宝的御使境界门槛不自动变成手动用途门槛；具体用途自身的条件照常生效。

单次使用不等于消耗整件法宝。具体用途消耗什么、产生什么、何时结束，由所调用的技能、BUFF、词条和对应玩法规则决定。

### 3.3 配置边界
一件法宝由 sense_cost 确定一种使用方式，不额外建立使用方式分类表。同一件持续法宝可以同时配置战斗效果与世界用途，但不能把其中一次点击解释为整件法宝免神识。

| 配置情况 | 判定 |
|---|---|
| sense_cost 为正数 | 持续御使；sense_cost_min 为正数且不超过 sense_cost |

| 配置情况 | 判定 |
|---|---|
| sense_cost 留空 | 单次手动；sense_cost_min 与神识需求减免留空 |

| 配置情况 | 判定 |
|---|---|
| sense_cost 填 0 或负数 | 无效配置，不解释为免费御使 |

生产、辅助不天然免神识；是否持续运行才是判断依据。配置留空必须保留“单次手动”的业务含义，不能被导出默认值误变成免费御使。

## 四、神识检测与生效分配
### 4.1 容量与单件需求
角色属性“神识”提供可用容量，法宝系统只读取，不把神识作为蓝条逐次扣除。

持续法宝的实际神识需求取当前法宝 ID 的完整配置：

实际神识需求 = min(配置神识, max(最低占用, 配置神识 − 当前法宝减免))

未配置减免按无减免处理。最低占用始终为正数，祭炼不能把持续法宝减成零占用。手动法宝不参与此计算。

御使队列总需求，是全部已御使持续法宝的实际需求之和，包含神识不足而暂时失效的法宝。实际生效占用，是本次通过分配的法宝需求之和。前者可能超过容量，后者不得超过容量。

### 4.2 检测时机
以下情况都重新检测，不依赖玩家打开面板或确认通知：

- 角色神识增加或减少。
- 玩家御使或收回法宝，改变御使队列。
- 祭炼成功或当前有效配置变化，改变法宝实际需求。
- 登录、复活、更换角色载体后恢复御使配置。

仅继承属性变化而神识及需求未变化时，更新法宝属性与展示，不无故重启技能和效果。

### 4.3 分配规则
1. 对已御使的持续法宝，按当前实际神识需求从高到低排序。
2. 同需求按法宝 ID 升序，保证每次计算顺序一致。
3. 从第一件开始逐件判断：该件需求不超过剩余神识则通过分配，并从剩余容量中扣除该需求。
4. 该件放不下则因神识不足失效，不占用容量；跳过它，继续检查更低需求的法宝，直到全部检查完。
5. 分配不自动调整玩家的御使选择；失效的法宝保留御使选择，条件满足时自动恢复。

三件法宝实际需求为 100、50、30 时：

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 180 | 100、50、30 | 无 |

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 150 | 100、50 | 30 |

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 140 | 100、30 | 50 |

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 100 | 100 | 50、30 |

| 当前神识 | 生效法宝 | 神识不足失效法宝 |
|---:|---|---|
| 90 | 50、30 | 100 |

神识 140 时，100 生效后剩余 40；50 放不下，跳过后 30 生效，最终剩余 10，无须先收回 50。神识 90 时 100 放不下被跳过，50 与 30 生效。

### 4.4 结果应用
由生效转为神识不足失效：立即停止自动行为，移除该法宝持续提供的效果，停止独立场上表现。保留拥有记录、当前法宝 ID 和御使选择。

由失效转为符合条件：自动按当前法宝完整配置恢复效果和运行，不要求玩家再次御使。恢复后是否有独立表现，仍受模型配置与显示名额约束。

法宝身份与生效结果不变时，不反复移除和重新触发效果。祭炼成功后，原法宝被目标法宝替换，必须以目标 ID 重建完整属性、效果、技能、神识需求与表现，不能保留原法宝的独有贡献或重复叠加。目标仍保留的相同技能不因迁移刷新冷却，已有技能的剩余冷却连续保留。

每次重算有新增神识不足失效的法宝时，统一通知本次受影响的法宝。通知不阻塞结算；玩家不处理也已失效。同一失效状态不因重复刷新而反复通知。仅有法宝恢复生效时，更新实际状态及已有界面，不另发恢复通知；同次检测既有新增失效又有恢复时，只通知新增失效项。

收回、神识失效或角色死亡，停止的是法宝继续运行及其持续贡献；已经造成的伤害、已经产出的物品不撤回。已发出的飞弹、已经触发的一次性延迟效果继续按正常技能规则结算，不因法宝停止而取消或重复执行。尚未发出的技能停止，持续引导不再产生后续作用；独立临时效果按自身配置结束。

后续一次性结算保留发出时的法宝、技能及所属玩家来源；属性取值沿用通用技能结算规则，不为收回、失效或祭炼升境界另设追回、补偿或重算流程。神识变化仍正常检测，但死亡期间不恢复效果、不重新安排场上表现；死亡停驻优先，复活后再应用最新结果。

### 4.5 神识不足与境界回退分别处理
神识不足按本案重新分配并暂停效果，不再采用全部继续生效的处理。

角色境界被动下降，仍沿用既有规则：不因此取消已御使选择，也不单独因此停用；但这些法宝仍必须通过当前神识分配。新的御使操作继续按当前境界校验。

登录、复活不能跳过神识检测而恢复全部法宝，也不能把显示名额上限当作御使数量上限。

## 五、御使与收回
### 5.1 主动御使条件
主动御使必须同时满足：

- 角色存活、数据已就绪，且该玩家没有请求尚未返回的法宝管理操作。
- 玩家已拥有且尚未御使。
- 当前法宝主表及完整能力配置有效，且属于持续御使类。
- 角色当前境界达到法宝 realm_id；0 表示无御使境界门槛。
- 新增后的御使队列总需求不超过当前神识。

主动御使仍以整个队列总需求校验，不能只看目前生效的部分。存在因不足而失效的保留项时，玩家可先收回调整，再新增御使。

校验失败不改变已有选择，不扣资源。成功后提交御使选择并生效；若操作受理后角色死亡，只保留御使选择、等待复活，不将正常暂停算成启用失败。其他首次启用失败恢复为未御使，不留下部分效果。

### 5.2 收回
收回无代价、无冷却；御使本身也没有额外操作冷却。

角色存活且没有请求尚未返回的法宝管理操作时，已御使法宝均能收回，包括神识不足、配置异常或运行异常的法宝。

收回取消该件的御使选择，停止其持续效果和自动行为，并对剩余队列重新分配。只移除本件法宝的贡献，不影响其他来源的同名效果；重复请求不得重复扣属性。

### 5.3 管理操作的公共条件
御使、收回、祭炼、打造共用同一组公共条件：角色存活、数据就绪、该玩家没有另一笔请求尚未返回的法宝管理操作。各自门槛在公共条件通过后再校验。

同一玩家在一笔法宝管理请求尚未返回期间不同时提交另一笔法宝管理请求；请求由公共网络机制交回后解除本笔忙碌，不建立跨请求的业务串行队列。确认弹层尚未提交时不占用这个处理资格；提交后切页、改选中项或关闭面板，都不取消已受理操作。此限制不暂停法宝正常自动战斗、神识检测和其他玩家的操作；单次手动用途仍由对应玩法定义。

角色死亡期间面板只读，不新发起这四类操作。死亡前已经受理的操作照常完成、只结算一次，不因死亡额外判失败、取消或退料；结果涉及生效或场上恢复的部分等角色复活后再判定。因已受理的收回而移除表现，属于收回结果，不属于法宝死亡。

## 六、获取、祭炼与打造
### 6.1 获取
同一玩家同一法宝 ID 只持有一份记录。首次获得为未御使，完整属性与能力读取该 ID 的法宝配置；获得动作不自动执行效果，不创建强化层数。

所有法宝都必须在物品表中配置对应的法宝道具，持续法宝和手动法宝均不例外。掉落、宝箱、任务奖励可通过背包中的法宝道具授予法宝。使用该道具是“登记获得法宝”，与已拥有手动法宝的“执行一次用途”不同。

| 授予结果 | 处理 |
|---|---|
| 首次成功获得 | 创建目标法宝 ID 的未御使记录；通过法宝道具授予时消耗该道具 |

| 授予结果 | 处理 |
|---|---|
| 已拥有 | 不覆盖当前法宝或御使选择；不消耗法宝道具 |

| 授予结果 | 处理 |
|---|---|
| 配置无效 | 不创建残缺记录；不消耗法宝道具，提示异常 |

掉落、奖励和打造遵循同一授予规则，不能各自产生一份重复记录。打造成功的直接授予沿用奇珍收录及既有行为成长规则；不额外在背包创建一份成品道具。

### 6.2 祭炼升境界
持续法宝和手动法宝都可祭炼。未御使、正常生效、神识不足失效均不是祭炼门槛；配置或运行异常时禁止祭炼，但已御使法宝仍可按公共条件收回。

#### 6.2.1 目标境界与对应法宝
祭炼可直接跨境界，不逐境界重复打造。合法目标满足“原法宝境界 < 目标境界 ≤ 玩家当前境界”，默认目标为玩家当前境界。例如合体玩家可将筑基法宝直接升合体，也可选金丹、元婴、化神或炼虚。

玩家达到元婴及以上、且当前法宝至少有两个理论目标境界时，显示目标境界选择；只有一个则固定展示，没有则提示“当前境界无法祭炼”。理论目标不因个别配方映射缺失被隐藏。

类型、品质和三材搭配不变，投入该搭配在所选目标境界对应的材料；材料名称可以随境界变化，不开放自由重配。常规主材按正式材料系列及辅材、特性分类确定对应关系；稀有材料跨境界改换系列时，须补明确的法宝目标关联。不能凭名称、ID 邻近或表格顺序猜测。目标缺失或不唯一时禁止执行；缺少对应配方的玩家提示统一为“当前境界无法祭炼”。

#### 6.2.2 复用打造配置
祭炼直接读取所选目标法宝的打造行，复用三材及数量、币种及费用、realm_req、forge_skill_lv_req 和 success_rate；完全忽略该行宝种物品及数量，不要求持有宝种。不另建祭炼配方或成功率表。祭炼与直接打造同一目标法宝，使用同一打造行的 success_rate，成功率保持一致；不是读取原法宝或中间境界的成功率。

跨境界只结算目标行的一次三材、一次货币及一次概率，不补扣中间境界，不累计各境界成功率。类型和品质不因祭炼改变。

校验公共条件、原法宝归属及有效性、目标范围及唯一性、目标主表与打造行、目标尚未拥有、角色与炼器门槛、全部三材及货币和成功率。任一未通过，全部不消耗、不判概率。

#### 6.2.3 结果与运行恢复
| 结果 | 法宝与消耗 | 效果处理 |
|---|---|---|
| 成功 | 三材、货币消耗；原 ID 变为目标 ID，不另留原件；无宝种消耗 | 按目标完整配置替换；持续类保留原御使选择并重算整个御使队列 |

| 结果 | 法宝与消耗 | 效果处理 |
|---|---|---|
| 概率失败 | 三材、货币已消耗；保留原 ID、境界、品质和御使选择；无宝种消耗 | 保持原法宝效果，不损坏、不补偿、无保底 |

| 结果 | 法宝与消耗 | 效果处理 |
|---|---|---|
| 取消或校验未通过 | 法宝及全部资源不变 | 不执行祭炼 |

| 结果 | 法宝与消耗 | 效果处理 |
|---|---|---|
| 成功后的运行恢复异常 | 保留已经获得的目标法宝，不恢复原件、不再扣料 | 异常法宝暂不运行，不混用新旧效果；显示运行异常，已御使则可收回 |

成功迁移后，属性、技能、神识需求与显示资格均按目标配置重建。属性与效果不累计原件及历次境界；神识需求变化可能调整整个队列的生效分配，不只刷新当前选中项。死亡前已受理的操作照常完成，目标持续效果等复活后再恢复。

玩家已拥有目标 ID 时拒绝，不合并两件。法宝与玩家同境或高于玩家境界时，优先提示“当前境界无法祭炼”。

旧“祭炼”配置页签不再作为法宝能力与成长依据。界面的“养炼→祭炼”功能保留。

### 6.3 打造
#### 6.3.1 基本过程
玩家选择境界，在战斗、生产、辅助中选择想打造的法宝类型，再自由安排宝种、主材、辅材、特性材。材料组合确定唯一已有成品，概率只决定是否成功，不随机抽取成品或生成新法宝。

初次进入及关闭重开后，打造境界默认玩家当前境界；可浏览其他已配置境界，实际执行仍须通过目标配方门槛。左侧使用“选择法宝”，同一类型只列一次，不平铺几百件最终成品。每个境界不设品质筛选。

| 类别 | 当前法宝类型 |
|---|---|
| 战斗 | 飞剑、宝印、缚灵索、宝伞、养生珠 |

| 类别 | 当前法宝类型 |
|---|---|
| 生产 | 育植瓶、炼丹炉、炼器鼎、符笔 |

| 类别 | 当前法宝类型 |
|---|---|
| 辅助 | 葫芦、乾坤袋、回灵瓶、探灵镜、行舟、隐息幡 |

类型与共同特质须有正式配置依据，字段，不能按备注或命名猜测。无有效配方的类型不可作为打造入口；库存、角色境界或炼器等级不足不因此隐藏整个类型。

#### 6.3.2 宝种与三材
| 投入 | 配方职责与准入 |
|---|---|
| 无相宝种 | 成宝核心，玩家单选；境界通用，与三材及成品同品质；仅成功消耗 |

| 投入 | 配方职责与准入 |
|---|---|
| 主材 | 器身基础承载；从当前类型有效打造行的 main_item_id 聚合去重，最终符合对应行固定物品 |

| 投入 | 配方职责与准入 |
|---|---|
| 辅材 | 参与承载与效果差异；具体材料须符合允许分类、境界和品质 |

| 投入 | 配方职责与准入 |
|---|---|
| 特性材 | 参与性质及能力差异；具体材料须符合允许分类、境界和品质 |

宝种与三材可任意先后选择。第一项投入确定本次品质，之后四项同品质；先选神品宝种，只能选神品三材。普通三材还须与目标法宝同境界。不能混品、平均、随机升品或以高品等量替代低品。

选材只安排投入，不立即消耗。各已选项可单独移除，不清其他项；只要宝种或任一三材仍在，品质继续受约束，四项全清才恢复待定。切换境界、类别或类型清空本次宝种与三材。

“通用”境界仅对宝种开放例外；其他通用材料在全库中可浏览，不因此获得三材准入资格。同名不同品质为不同物品，不混扣库存。

#### 6.3.3 匹配与材料池
筛选以境界、类别、正式类型、已确定品质及所有已选项为条件。替换一个材位时，保留其他选择约束，检查拟选项能否对应至少一条有效完整方案。

不另设“A 主材天然只能配 A 辅材”的通用限制。当前同境界、品质、类型下，不同主材支持的辅材及特性组合集合一致，不强制先选主材；将来配置若有明确专属组合，再按有效行联动。

默认池包含当前类型、材位、境界涉及的各品质条目，不符合本次品质、搭配或库存的仍保留灰显；浏览资格不等于投入资格。

#### 6.3.4 唯一成品与名称
当前有效方案均要求三材。三材未齐时，即使只剩一个候选，也不显示完整成品名；只选两材不能打造。三材齐备且唯一时可预览最终名称与效果；宝种尚未选择时仍禁止提交。以后仅当配方明确不要求某一材位时才显示“无需”，玩家不能自行省略。

最终以唯一目标法宝 ID 为准。无匹配或匹配多个不同 ID 均禁止打造，配置歧义不能由前台任意挑一件。同名不同境界、品质和 ID 不合并拥有判定。

名称整体读取目标正式配置，不由前台拼前后缀。辅材也参与命名区分：筑基仙品飞剑、玄铁主材下，獠牙加金行凝华为“青冥剑·断金”，翎羽加金行凝华为“青冥剑·惊鸿”，獠牙加木行凝华为“青冥剑·折柳”。此例不构成独立命名公式。

类型特质只说明共同用途。未成组合的“法宝效果”显示“最终法宝效果由所选材料的搭配共同决定。”唯一成品确定后，关联物品 desc、desc1 分段显示，不拿配方备注替代。

#### 6.3.5 库存与执行资格
宝种区显示汇总“宝种总数 X 枚”、本次需求及“仅成功消耗”；宝种物品框显示所选品质和自身库存，不按境界建立独立库存。汇总足够但所需品质不足仍禁止，提示如“神品无相宝种不足：需要 1，当前 0”。

三材显示实际物品、需求和拥有量。同物品用于多个位置须合计需求，不能重复占用一份库存。币种和金额读 money_id、money_count，在确认按钮次行显示，不写死灵石。

确认须通过公共条件、主表及配方有效性、唯一组合、宝种与三材身份／分类／境界／品质／合计数量、角色与炼器门槛、目标未拥有、货币充足及成功率合法。没有祭炼层配置前置。前台预检不代替后台重新校验。

#### 6.3.6 成功率与结算
打造行 success_rate 为整数万分比 0～10000；10000 必成，0 必败。每条启用行必填，缺失或非法值不自动当作必成或显式 0。客户端显示除以 100 后的百分比，由后台判定一次；不新增幸运、连续失败加成或保底。

| 结果 | 宝种 | 三材及货币 | 法宝 |
|---|---|---|---|
| 取消或校验拒绝 | 不消耗 | 不消耗 | 不变 |

| 结果 | 宝种 | 三材及货币 | 法宝 |
|---|---|---|---|
| 已执行，概率失败 | 保留 | 按配方消耗 | 不获得 |

| 结果 | 宝种 | 三材及货币 | 法宝 |
|---|---|---|---|
| 已执行，成功 | 按配方消耗 | 按配方消耗 | 获得目标 ID，初始未御使，不自动执行用途 |

一件法宝可无打造配方；有配方时每个目标 ID 最多一条有效行。已拥有目标禁止重复打造，但可继续换材和查看同类型其他成品。扣料、扣钱、成败、授予及回执整体结算，不允许部分扣费后才发现无法授予。

成功与概率失败都只结算一次。公共网络机制对同次请求的重传不另开抽取、不重扣资源；业务请求失败不等于概率失败，也不能推断为未扣费。失败、取消和已结算结果分别处理，不自行重抽或重复扣费。

## 七、效果与属性
### 7.1 当前法宝完整效果
每个法宝 ID 配置自身完整结果，不按强化层数叠加。最多八组效果，每组包含行为、参数或 ID、数值，随主表承载或由主表正式关联；不再从旧祭炼页读取。

| 行为 | 参数 | 数值含义 |
|---|---|---|
| 加属性 | 已定义的属性名 | 必填，增加法宝自身属性 |

| 行为 | 参数 | 数值含义 |
|---|---|---|
| 调用技能 | 有效技能 ID | 留空，具体数值读取技能配置 |

| 行为 | 参数 | 数值含义 |
|---|---|---|
| 调用 BUFF | 有效 BUFF ID | 留空，具体数值读取 BUFF 配置 |

| 行为 | 参数 | 数值含义 |
|---|---|---|
| 调用词条 | 有效词条 ID | 留空，具体数值读取词条配置 |

加属性只加给法宝自身，不直接加给角色。无场上模型的法宝也有自身属性。要改变角色、生产结果或世界玩法，由被引用的技能、BUFF、词条定义目标及作用。

持续类通过神识分配后才提供持续效果；调用技能表示技能在法宝生效期间按自身触发条件运行，不表示每次恢复都立即施放一次。

额外技能仍分主表技能 skill_id1～3 与效果槽调用技能两个来源，语义相同：持续类在法宝生效期间参加 8.1 的自动施法选择及自身触发，手动类由对应玩法在使用时调用。主表技能不占八组效果槽。祭炼变为另一个法宝 ID 时，两类来源均读取目标配置，不继续加载原 ID 的独有技能。

手动类在本次用途被发起并通过校验后，使用当前法宝完整效果及主表技能完成操作；不因持有或打开面板而持续生效。持续时间由被引用配置决定，不另加通用持续时间。

行为为空的槽不生效；非空槽必须为合法行为且参数有效。多个加属性槽可累加。同一法宝相同“调用行为＋ID”不得重复；普攻技能、主表技能互不重复，效果槽调用技能不能与它们重复。不同法宝 ID 可以分别配置同一技能，不因此重复触发同一件法宝的效果。

各槽按配置序号稳定装载，主表技能与完整效果一起准备；调用效果前法宝有效属性必须已确定。槽序和主表技能序号不决定施放优先级。任何启用或祭炼后重建失败均不能留下半套效果，不能误删其他法宝或其他来源的同名效果。

### 7.2 属性继承
法宝自身属性[X] = 当前法宝全部“加属性 X”之和。

法宝有效属性[X] = 法宝自身属性[X] + 向下取整(角色属性[X] × 当前法宝继承比例[X] ÷ 10000)。

未配置继承比例的属性不继承；上下限属性分别计算。角色属性变化时，法宝继承值同步更新，不等待重新御使。法宝自身属性不能再回加给角色形成重复计算。

### 7.3 威能与说明文本
威能沿用当前展示评分：对配置了权重的有效属性，取非负值乘权重求和后向下取整；没有权重的属性不计入。评分包含继承部分，不由法宝主表直接填写，不参与伤害或其他实际结算。

战斗效果说明 combat_desc、世界用途说明 world_desc 只用于展示。文字本身不生成能力，不替代技能、BUFF、词条或其他有效配置。打造及祭炼目标预览另读取关联物品 desc、desc1 分段展示。

## 八、自动战斗与场上表现
### 8.1 自动战斗
法宝释放技能时，施法主体是发起本次技能的具体法宝，所属玩家是归属者，玩家角色不是代替法宝施法的主体。这是技能执行与结算必须落实的规则，不只是场上表现或设定说明。

每次法宝施法必须明确所属玩家、具体法宝、技能 ID 及目标或目标位置；这些来源信息必须传递至技能执行，以及涉及本次施法的服务器校验与结算环节。后台依据权威状态校验归属、该法宝是否可用、技能是否属于其当前有效配置、冷却及目标条件，不能仅凭前台标签认定主体，也不能只传玩家角色而丢失法宝来源。具体调用接口、传递方式与 WC3 执行载体由程序团队决定。

技能表定义技能效果与释放条件，不将一个技能固定为只能由人物或法宝施放；调用方负责提供或解析本次正确的施法主体。同一技能由法宝调用时，“施法者自身”指这件法宝；效果若作用于所属角色，应由效果目标明确表达，不能靠把施法主体换成人物来实现。

战斗法宝通过神识分配后，按普攻技能与额外技能的配置自动行动。普攻技能单独配置；额外技能来自当前法宝主表技能 skill_id1～3 与效果槽调用技能，按自身触发条件执行。同一技能在本件同时生效的来源中只能出现一次，不能因来源重复而多次触发；不同法宝 ID 可分别配置同一技能。

角色被攻击、承受伤害或亲自造成伤害时进入或刷新战斗状态。法宝及其派生伤害不能被当作角色亲自出手而不断延长战斗。超过配置的脱战时间后，法宝退出攻击并回到跟随。

目标在角色附近搜索，限定为存活敌对目标，排除法宝的辅助表现或出伤对象，选择距角色最近的合法目标。

- 近战：接近目标至普攻技能允许的距离后攻击；超过配置的放弃距离则返回跟随。
- 远程：留在角色附近施放；选取和保留目标都必须满足技能实际射程，不停留在“选得到却打不到”的状态。
- 目标死亡、无效或超距时返回跟随；后续有效战斗信号再更新目标，不擅自无限接战。

每件法宝独立选择下一次自动施放的技能：

1. 先筛选当前满足全部释放条件的技能，包括冷却可用、目标合法、射程满足及技能自身条件。普攻与可主动施放的额外技能均参加选择，不区分额外技能来自主表还是效果槽。
2. 可用技能按技能表配置的完整冷却时长（CD）从长到短排序，优先释放 CD 长的；不是比较剩余冷却时间。CD 相同按技能 ID 升序。
3. 长 CD 技能仍在冷却或不满足其他条件时，不参加本次选择，不阻塞其他可用技能；没有可用技能时不施放。
4. 每次选择一个技能开始施放，能够发起下一次施放时重新筛选和排序。长 CD 技能变为可用，不因此打断已经开始的施法或引导。

被动、命中触发及派生技能仍按自身触发规则执行，不因 CD 较长就被改成主动轮流施放。上述优先级只决定自动施法的选择次序，不改变技能原有冷却、触发条件或效果。

法宝伤害读取自身有效属性，伤害类型、射程、冷却与命中效果读取实际技能配置。持续法宝自动施放不套用英雄职业、等级、蓝量和英雄施法动作的限制；其他技能条件照常。手动用途的具体条件仍由对应用途定义。

命中、词条触发、延迟与派生伤害均保留所属玩家、法宝和技能来源，不能中途改算成英雄伤害或另一件法宝的属性。“法宝命中”包含普攻与额外技能；需要排除普攻时使用“法宝技能命中”的含义。

### 8.2 冷却
冷却归属于具体法宝的对应技能，不借用或混用玩家角色、其他法宝的技能冷却。

法宝技能在同一局内的冷却连续保留。收回、重御使、神识失效与恢复、祭炼升境界、死亡复活、更换角色载体，都不能刷新已有技能冷却。

祭炼更换法宝 ID 时，原法宝与目标法宝共有技能的剩余冷却随结果连续保留；不能借身份替换刷新。技能本局首次启用时初始化为可用；已有冷却未结束时，再次启用不能提前使用。离线后的冷却保持规则不由本案另行扩展。手动用途原本有冷却的，不能通过反复使用或切换面板绕过。

### 8.3 表现资格
法宝模型读取当前法宝 ID 的主表完整配置；未配置则没有独立场上表现，但合法效果仍可生效。

当前仅做绕飞跟随、近战追敌、远程随身施放和传送归位。全体法宝共用全局页选定的行为引用，绕飞、脱战等细节读取其关联行为表；配置来源及接入状态，不增加单件覆盖。

每名玩家独立表现名额的正式规格为六件。只在当前正常生效且有模型的法宝中，按法宝 ID 升序取得显示资格。MaxVisibleIndependent 源表行为注释行，不能将该行数值解释成已生效的配置。

上述资格分配用于角色存活时。死亡期间仅保留死亡时已有的可见法宝静止表现，不按“仅生效者显示”把它们销毁，也不因神识恢复而新增或移动表现；静止可见不代表效果生效。复活后重新计算资格。

超出显示名额的法宝仍占神识、仍生效；不得因此禁止御使。神识不足失效的法宝不参加显示资格分配，不能套用“只是隐藏”的处理。

新增、收回或资格变化只调整受影响的显示位置，其他法宝不集体跳位。传送后随角色归位，不改变当前法宝身份、拥有和御使选择。

场上表现不充当独立可选中、可受击、占人口或占治疗名额的战斗单位。距离、范围和弹道起点与法宝实际表现位置一致，不能因内部辅助对象的位置不同而改变结算。

## 九、数据保存与异常结果
### 9.1 法宝身份与结果保持
玩家已拥有的法宝身份与御使选择在离线、重连后保留，不保留祭炼层数。手动法宝不进入御使队列。神识、生效、属性、威能与表现资格按当前角色和法宝有效配置重新判定。

授予、御使、收回、祭炼与打造的既成结果必须保留；概率失败也保留实际消耗和结果。单纯神识变化、死亡或显示名额变化不改变御使选择。祭炼成功替换原身份，迁移御使选择，不同时留下原件或丢失目标；重复执行不能再次替换或扣费。

### 9.2 生命周期
| 场景 | 处理 |
|---|---|
| 登录 | 读取当前拥有 ID 与御使选择；等角色数据就绪后，按当前神识重新分配，再恢复符合条件的效果 |

| 场景 | 处理 |
|---|---|
| 死亡 | 法宝自身不死亡；停止新施法、自动行为及持续贡献，原有可见法宝原地停驻；保留御使选择和当前法宝身份 |

| 场景 | 处理 |
|---|---|
| 复活、更换角色载体 | 使用当前角色属性重算，不重复残留旧效果；仍按高需求优先、放不下则跳过继续检查；符合条件的法宝归位恢复，其余按失效或异常处理 |

| 场景 | 处理 |
|---|---|
| 离线 | 停止运行并完成待保存结果 |

| 场景 | 处理 |
|---|---|

| 场景 | 处理 |

恢复时神识不足并不是存档错误。配置或数据缺失不能拿零需求、默认法宝或境界来伪造合法结果；神识计算所需输入不完整时，不开放新增御使，待数据有效后重新判定。

### 9.3 一致性与容错
同一次操作的资源与结果只能结算一次。后台必须能识别操作所属玩家、操作类型、目标法宝及这一次操作；重复确认、重传或重复回执沿用原结果，不重新扣费、替换法宝或抽取成功率。前台禁用按钮不能代替后台校验；多玩家环境下必须得到一致的法宝身份、扣费、御使选择与神识分配结果。

前台预检用于即时反馈，正式结果以后台重新校验与结算为准。确认提交必须对应玩家确认的原／目标法宝、所选目标境界、配方及选材和消耗；这些内容发生变化时要求重新确认，不按未展示的新条件静默扣费。资源持有量等条件仍在实际受理时校验。

请求等待、超时与断线使用项目公共反馈。法宝不另设“确认上次操作”入口或持续管理锁；请求交回后结束忙碌。请求失败不等于概率失败，也不能据此推断未扣费、退料或重抽。

法宝界面的本笔“处理中”只对应尚未返回的请求。公共网络机制将成功或失败交回后结束本笔忙碌并按当前条件重判按钮；不能因查不到业务记录而无限禁用所有法宝管理。请求尚在公共重试中时不重复提交，但列表、翻页、切页和关闭可继续使用。

请求失败、超时、断线都不能由界面推断“未扣费”或“概率失败”，不能据此自行退料、扣费、授予或替换法宝。收到可采纳的权威状态后刷新实际结果；法宝不为正常成功额外发起恢复查询，不借重新打开或登录自建“核对原操作”流程。登录、重连和状态恢复沿用公共模块契约。

同一请求在公共传输层重传时，服务器识别为同次操作并重放安全，不重新判概率、不重复扣费或改变法宝。请求失败交回后玩家再次操作是新一次尝试，使用新的操作请求；界面不把新尝试串接成自己的旧操作恢复链。上述网络行为不改变成功、概率失败、校验拒绝的不同消耗规则。

已结算结果因保存异常不得再次扣费或重抽，恢复时保留已经生效的结果。

读档解析失败不得以空列表、默认法宝或未御使覆盖旧记录。合法旧记录缺少可补齐字段与整份解析失败必须区分。旧层数存档的兼容须保留有效法宝身份与御使选择，不从旧层数猜测境界、复制成多件或覆盖原记录。

运行异常与神识不足分别提示。运行恢复失败保留记录、停止异常效果、允许收回；恢复或重新登录后重新校验，不能无条件承诺一定成功。

#### 10.4.1 分类选材和目标定位
main_item_id 是当前目标的固定主材物品，不是“任意同类主材”；选择法宝类型后，将该类型在所选境界的有效打造行按主材去重，形成主材候选池。aux_categories、trait_categories 是允许选择的材料分类集合，和物品表 tags 对应；集合内多个分类表示任选允许分类，不是每类都要各放一件。当前每个普通材位投入一种物品，数量分别读取 main_item_count、aux_count、trait_count。

匹配时同时校验所选类型、目标境界、普通三材的境界与品质、固定主材 ID、辅材和特性分类；宝种只约束品质、境界通用。主材物品本身的境界与品质由物品表读取，不能仅凭 tags 命中就放行。三材组合指向唯一有效 fabao_id 后才显示完整成品名，确认还须选中匹配宝种并满足全部门槛与库存。相同物品占用多个材位时合计数量，不按材位分别判断“各自够用”。

#### 10.4.2 打造与祭炼怎样读取同一行
例如当前源表 fabao_id=34000（金丹仙品“青虹剑·断金”）的 success_rate=8000：直接打造该目标显示 80%；具备合法跨境界对应关系的原法宝祭炼到这个相同目标时也显示 80%。这里只说明“同一目标读同一行”，不开放不符合原搭配的祭炼路径。

打造读取宝种及三材、货币、门槛和成功率；祭炼读取所选目标行的三材、货币、门槛和同一 success_rate，完全忽略 core_item_id、core_item_count。祭炼替换原法宝，不额外保留原件；跨境界跳转只结算所选目标行一次。两者的原件归属、重复拥有与成功后资产处理不同，不能只把祭炼转发给现有打造入口。

成功率使用整数万分比，8000=80%，10000=100%，0=0%。缺少必填值不能被导表默认 0 掩盖；配表及程序须能区分漏配与明确填 0。具体判定与失败消耗仍 执行，不新增祭炼概率配置。

- 图标、属性、材料、货币、技能、BUFF、词条引用必须有效，不直接启用占位 ID 或未登记属性。

#### 神识与完整效果
- 持续类神识与最低占用为正，最低占用不超过神识，减免非负；手动类神识、最低占用、减免留空，不配置自动普攻和攻击方式，主表技能仍可用于对应玩法。
- 同一法宝的普攻、主表技能与效果槽调用技能不得重复；跨境界同技能迁移不能刷新冷却。
- 效果与继承组遵守数量、成对项、引用及空值含义；不把无效引用解释成“无效果”。

#### 打造材料与目标约束
- 宝种与三材同品，三材与目标同境；不凭分类命中跳过品质、境界或合计数量校验。
- 打造行 success_rate 必填且为 0～10000 的整数；缺失不自动解释为 0 或必成。
- 所有选材组合只能唯一对应目标；跨境界对应关系也须唯一，稀有改换材料系列时落实正式目标关联。
- 配方停用的影响包含祭炼到该目标，不关闭原法宝当前的合法效果。
- 行停用、可空类型、枚举空值和组内空值须验证导出及读取结果，不能把手动判成免费御使、把空攻击方式判成近战或把空效果组当有效效果。
