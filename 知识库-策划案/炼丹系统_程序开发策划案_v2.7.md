# 炼丹系统
炼丹规则负责材料构成、丹方定位、成丹与升品、丹效和丹毒结算，并定义炼丹配置字段。物品身份与背包行为分别由物品配置和背包规则拥有；未确定的数值、熟练度触发和丹效边界集中列为待定项。

## 一炉的构成
每炉固定投入：**一份君材、一个丹头**，以及**至少一份臣材、至少一份使材、零至多份佐材**。
| 材位 | 数量 | 职责 |
|---|---|---|
| 君材 | 每炉固定 1 份 | 决定本炉境界、基础品质和药力门槛；其药性构成开炉初值 |
| 丹头 | 每炉固定 1 个 | 给出臣佐使最大承药份数；可作为特殊丹方凭证 |
| 臣材 | ≥1 份 | 决定丹药作用（五行） |
| 使材 | ≥1 份 | 决定丹药作用部位（五味），并决定服药入哪个丹毒池 |
| 佐材 | 0..N 份 | 补药力、调药性 |
丹头不参与药力、药性和绝对杂质求和，但每炉消耗一个，并计入材料需求。

## 炼丹境界
炼丹相关大境界字段采用 `MajorRealm`，炼气至大乘依次为 1—8；中文别名与合法数字兼容，0 为保留值，不当作炼气。炼丹只开放筑基至大乘，除渣境界差按统一枚举计算；丹毒池覆盖炼气并使用角色当前境界。

## 炼丹品质与除渣列
炼丹品质 `ItemQuality` 从低到高为凡品、灵品、玄品、仙品、神品、道品，分别对应除渣力 `filter1..filter6`。每个丹方坐标的实际开放品质读取配置，不从行数、丹名或品质文字推定其他品质存在。

## 炼丹五行、五味与性值
炼丹五行为金、木、水、火、土。五味与丹毒池固定对应：酸为血肉、苦为心神、甘为丹田、辛为气脉、咸为骨底。自由炼制按 `realm、jun_quality、element、taste、nval` 定位候选，再按实际丹头消歧。

## 炼丹比例量纲
炼丹概率与比例采用万分比整数，10000 表示完整比例；倍率可大于 10000。系统参数中以小数填写的低境界倍率须先换算为万分比整数。参与判定和结算的值不以浮点小数累加。

## 炼丹预览与正式结算
炼丹先配置材料并预览，确认后按当前角色、技能、库存和丹炉重新检查全部条件，随后一次性扣除本次全部材料，逐枚判定成丹与升品，生成成品。预览与正式结算使用同一套规则；预览数值不能替代正式检查。配置阶段失败不扣料，单枚成丹失败不退该枚材料。

## 炼丹配置的物品与公共参数
炼丹通过 W物品表取得背包物品身份及显示信息。X系统参数按 `ParamID` 提供除渣、熟练度和服药相关参数；属性配置提供神识、五味绝对杂质与丹毒，以及丹效可引用的属性。
丹炉过滤率保存在除渣力配置中，不放入丹炉本体配置。各表的编号、计算、说明等辅助页不决定炼丹规则。

## 炼丹表头与字段声明
炼丹配置字段由 `##var` 命名，`##type` 声明类型，`##group` 声明导出范围，`##` 为中文说明；数据从说明行之后开始。无独立字段声明的辅助列不作为配置输入，`seq` 只用于配表排序。
实体关联使用整数 ID，名称仅作说明。字段须满足所属表的类型与分组声明，不能因出现了一个字段名就认定其已具备完整导出配置。

## 炼丹空值与零值
炼丹配置中，显式 0 的含义由具体字段定义，例如 `head_id=0` 表示不指定丹头、`ast_id=0` 表示不投佐材。空单元格表示未配置，不能静默当作 0，也不能从相邻行继承。参与当前操作的必需配置缺失时，不能作为有效配方使用。系统默认模板使用同组最低启用品质行；其他品质未配置默认投料不禁止其合法自由炼制。

| id | int | 材料或丹头的唯一配置 ID，不等于背包物品 ID |
| name | string | 检查用名称，正式显示名取物品系统 |
| realm | MajorRealm | 材料所属境界 |
| role | string | 君、臣、佐、使或丹头 |
| quality | string | 六品质之一 |

## 灵植五行、五味与承药字段
灵植五行、五味与承药份数按材位分别生效。
| 灵植字段 | 类型 | 配置语义 |
|---|---|---|
| element | string | 仅臣材必填，金木水火土之一 |
| taste | string | 仅使材必填，酸苦甘辛咸之一 |
| max_material_count | int | 仅丹头必填，正整数，限制臣佐使合计份数 |

## 灵植药性、药力、杂质与价格字段
灵植的药性、药力、杂质与价格分别配置，不用辅助描述列代替数值。
| 灵植字段 | 类型 | 配置语义 |
|---|---|---|
| nval | int | 君材开炉药性或单份药性增量，范围 −4..+4 |
| power | int | 君臣佐使单份药力，非负整数 |
| dross | int | 君臣佐使单份绝对杂质，非负整数 |
| target_power | int | 仅君材必填，正整数；本炉目标药力 U |
| 对应物品 sell_price | long | 以灵植物品 ID 从物品表读取基础售价，不另读灵植 price |
灵植表的“药势”“ID编号用”“编号ID”等无独立字段声明的列用于配表整理，不作为药力或药性输入。

## 丹方表品质分组
丹方表每行以 `id` 标识具体品质结果；同一基础丹方的开放品质行共用 `recipe_id`。丹方列表、玩家配方与发现记录按 recipe_id 归组，每组一个条目、一套玩家配方。不同指定丹头的基础丹方仍分别归组，不按同名、相邻行或编号运算生成关系。

丹方坐标字段约束实际材料形成的五行、五味、性值和丹头。
| 丹方字段 | 类型 | 配置语义 |
|---|---|---|
| element | string | 全部臣材须符合的五行 |
| taste | string | 全部使材须符合的五味，并决定服药入池 |
| nval | int | 最终累计药性必须精确命中的 −2..+2 整数 |

## 丹方纯度与杂质门槛字段
丹方成丹门槛及基础成丹率以本品质行配置为准。
| 丹方字段 | 类型 | 配置语义 |
|---|---|---|
| min_purity | int | 最低纯度 Qmin，万分比 |
| rate_cap_purity | int | 成丹率封顶纯度 Qcap，万分比 |
| min_impurity | int | 剩余杂质下限 L，正整数 |
| base_rate | int | 纯度为 Qmin 时的成丹率 B，万分比 |

## 丹方成丹率上限与并炼神识字段
| 技术字段 | 类型 | 中文表头 | 程序含义与范围 |
|---|---|---|---|
| `max_rate` | `int` | 成丹率上限 | 纯度达到 `Qcap` 时的成丹率 `C`，万分比 |
| `spirit_requirement` | `int` | 神识要求 | 单枚并炼所需神识，正整数；用于批次上限 |

丹方的 `rate_cap_purity` 表示同境满熟练条件下，考虑全部合法同境材料、丹头、丹炉和安全投药顺序后的最高可达纯度。参与标定的丹炉须通过本行基础品质准入，除渣包含命中五行的额外值和各来源适用加成。玩家条件超过标定条件时，成丹率仍不超过 `max_rate`。

## 默认投料
系统默认投料用灵植配置 ID 指定材料，每个材位同时填写数量。
| 默认投料字段 | 类型 | 配置语义 |
|---|---|---|
| jun_id | int | 君材 ID |
| jun_num | int | 君材数量，必须为 1 |
| min_id | int | 臣材 ID |
| min_num | int | 臣材数量，正整数 |
| ast_id | int | 佐材 ID；0 表示不投佐材 |
| ast_num | int | ast_id=0 时为 0；ast_id>0 时为正整数 |
| env_id | int | 使材 ID |
| env_num | int | 使材数量，正整数 |

## 系统默认配方的适用边界
系统默认配方只配置各材位材料及数量，不预设投药顺序，每个材位只支持一种默认材料。默认配方用于教学和快捷投料，不限制自由炼制使用其他合法材料。系统默认配方取同组最低启用品质行的有效默认投料；其他品质行默认投料为空表示未配置，不继承其他行效果或条件，不禁止合法自由炼制。

## 丹效与价格
丹方品质行用 `pill_effects` 保存按配表顺序生效的丹效，类型为 `array,PillEffect`。`effect_desc` 是白话说明，不参与效果结算。
| 字段 | 类型 | 含义 |
|---|---|---|
| duration | int | 持续秒数；0 按具体行为解释为瞬时或永久 |
| pill_effects | array,PillEffect | 有效丹效条目及其顺序 |
| wupin_id2 | int | 成品物品关联；基础售价读物品 sell_price |

## 丹效条目的类型与参数
丹效 `PillEffect` 是抽象配表类型，不能直接填为一条效果；实际条目使用下列具体类型。
| 效果类型 | 中文行为 | 必填参数 |
|---|---|---|
| PillAttrEffect | 加属性 | attr：属性键；value：基础整数数值 |
| PillSkillEffect | 调用技能 | skill_id：技能 ID |
| PillBuffEffect | 调用BUFF | buff_id：BUFF ID |
| PillAffixEffect | 调用词条 | affix_id：词条 ID |

## 丹效条目的空值与校验
丹效只按 `pill_effects` 中的有效条目顺序结算；工作表中的连续单元格用于填写数组，不是独立的 action、param、value 编号字段。每条效果的属性或目标配置必须存在；调用技能、BUFF、词条不读取通用 value。未配置丹效不能由白话作用说明补造效果，普通丹药无有效丹效时禁止直接服用，不扣药、不加杂质；数组容量按配置结构，不固定三槽。已填写但错误的效果必须阻断，不能跳过后执行其他效果。

## 丹炉身份与境界字段
丹炉基础身份与可炼范围由 furnace_config 表达。
| 丹炉字段 | 类型 | 配置语义 |
|---|---|---|
| seq | int | 配表排序序号 |
| id | int | 丹炉唯一配置 ID，供除渣力关联 |
| name | string | 名称 |
| max_realm | MajorRealm | 最高可炼丹方境界 |
| quality | ItemQuality | 丹炉品质，也是可直接炼制的基础丹方最高品质 |
| enabled | bool | 是否允许选择 |

## 丹炉境界与品质准入
丹炉必须同时满足 `max_realm ≥ 基础丹方.realm`、`quality ≥ 基础丹方.quality` 及神识门槛。品质按凡、灵、玄、仙、神、道比较；凡品炉不能直接炼制灵品及以上基础丹方。跨境、五行与技能加成都不能抵消品质不足；预览与正式炼制均须检查，不通过时说明“丹炉品质不足”且不扣材料。准入比较成丹前的基础品质，成丹后的既有升品另按升品规则执行。

## 丹炉炉膛、神识与价格字段
丹炉的可承药性由闭区间表达，不另设“炉性”。
| 丹炉字段 | 类型 | 配置语义 |
|---|---|---|
| cold_min | int | 承寒下限 |
| heat_max | int | 承热上限，不小于 cold_min |
| spirit_requirement | int | 驱动丹炉所需神识，正整数 |
| price | int | 非负整数价格 |
丹炉过滤率另由除渣力配置按丹炉 ID 提供，不存本表。

## 除渣力配置字段
除渣力配置按 `source_type、source_id` 唯一识别来源。
| 除渣力字段 | 类型 | 配置语义 |
|---|---|---|
| seq | int | 配表排序序号 |
| source_id | int | 技能等级或丹炉配置 ID |
| name | string | 检查用名称 |
| base_realm | MajorRealm | 基础除渣率对应境界 |
| source_type | string | 技能或丹炉 |
| filter1..filter6 | int | 六品质同境基础除渣率，万分比 |

## 丹炉五行额外除渣字段
丹炉五行额外值取除渣力中 `source_type=丹炉` 的对应行，字段类型均为 int，单位为万分比，范围 0..10000。`200` 表示增加 2 个百分点，与基础除渣率相加；`0` 表示该五行无额外加成，空值表示未配置，不能替代 0。
| 基础丹方 element | 额外除渣字段 |
|---|---|
| 金 | filterjin |
| 木 | filtermu |
| 水 | filtershui |
| 火 | filterhuo |
| 土 | filtertu |
每炉只取实际丹方五行对应的一列，不把五列求和，不按臣材份数重复叠加；对应列为 0 时仍保留基础除渣率。

## 除渣力来源与品质选择
除渣力 `filter1..filter6` 依次对应凡、灵、玄、仙、神、道，按本炉基础丹方 `quality` 选择。炼丹术与灵植术分别使用自身技能等级对应行，乘入各自熟练度除渣参数；丹炉使用自身对应行，没有熟练度加成。`source_type=技能` 只区分技能与丹炉，不单独区分炼丹术和灵植术。

## 丹炉向下炼制的品质取值
丹炉先通过基础丹方品质准入，再按目标基础丹方 `quality` 取 `filter1..filter6`。高品质炉炼低品质丹的基础优势由这六列配置表达，不另生成品质差倍率。五行额外值直接取对应五行列，与基础值合计后共同享受跨境倍率；两项技能仍按各自技能公式计算。

## 丹毒池境界与容量字段

| 丹毒池字段 | 类型 | 配置语义 |
|---|---|---|
| seq | int | 配表排序序号 |
| base_realm | MajorRealm | 角色当前境界 |
| blood_capacity | int | 酸味血肉池容量 |
| mind_capacity | int | 苦味心神池容量 |
| dantian_capacity | int | 甘味丹田池容量 |
| meridian_capacity | int | 辛味气脉池容量 |
| bone_capacity | int | 咸味骨底池容量 |

## 丹毒池每日消退字段
丹毒池的消退字段均为 int，单位为“每游戏日按对应池容量消退的万分比”，范围 0..10000。
| 丹毒池消退字段 | 对应池 |
|---|---|
| blood_daily_decay | 酸味血肉池 |
| mind_daily_decay | 苦味心神池 |
| dantian_daily_decay | 甘味丹田池 |
| meridian_daily_decay | 辛味气脉池 |
| bone_daily_decay | 咸味骨底池 |
五味池分别按自己的容量和消退比例计算，彼此独立。

## 五味丹毒的属性对应

## 成丹率描述表 `成丹率描述`
成丹率描述由 `id、min_rate、max_rate、text` 表达，前三个字段为 int，text 为 string。以 `min_rate ≤ R ≤ max_rate` 命中唯一文字，其中 R 为本次成丹率，min_rate 与 max_rate 均为万分比整数。各闭区间无重叠、无空隙，完整覆盖 1..10000；成丹率至少为 1，保证有效成丹率均有提示。

## 炼丹杂质售价区间
炼丹杂质售价配置使用 `id、name、min_g、max_g、price_factor`。各档闭区间连续、无重叠，并完整覆盖实际杂质占比 0..10000。`price_factor` 为万分比且随杂质占比升高严格递减；成色名称和系数读取配置，不根据丹药名称猜售价。

## 系统参数 `ConfigSystemVar`
炼丹使用 X系统参数的 `ConfigSystemVar`：`ConfigID` 为 int 配置行标识，`ParamID` 为 string 查询键，`ParamValue` 为 string 参数值，按参数各自的单位解释。配置行重排或改编号不改变参数含义，不能以行序代替 `ParamID`。

## 炼丹低境界倍率参数
`参数_低境界炼丹` 表示三种除渣来源炼制低于自身基准境界的丹方时，每相差一境乘入的倍率。配置值不小于 1，换算为 `K_bp = round(配置值 × 10000)`，要求 `K_bp ≥ 10000`。逐境倍率的取整顺序由炼丹境界倍率公式定义。

## 炼丹熟练度除渣参数
`参数_炼丹术熟练` 与 `参数_灵植术熟练` 的单位均为“万分比／每 1% 熟练度”，分别控制炼丹术、灵植术的熟练度对基础除渣率的增幅。两个参数不表示获得熟练度的概率，不能用于判定一次行为是否增长熟练度。

## 炼丹服药参数
`参数_效果减半丹毒` 为 0..10000 的万分比整数，表示服药前对应丹毒达到多少时药效减半。丹毒禁服线固定为 10000，不另设系统参数。除渣和服药结算所需的四个参数必须存在；丹炉可炼境界、炉膛与过滤率分别来自丹炉及除渣力配置。

## 炼丹配置与关联有效性
炼丹配置的主键和外键必须有效、类型完整，字段值满足所属配置约束。可选引用的 0 与未配置空值分开处理，不从相邻行补值。相关配置错误时不能开放受影响内容；无法确定有效全局配置时，炼丹入口不可用。

## 丹方坐标与品质约束
启用丹方的 `realm` 必须为可炼境界；`quality` 与 `jun_quality` 相等。同一 `realm、jun_quality、element、taste、nval、head_id` 只能存在一条启用品质行。每个自由主坐标最多一条 `head_id=0` 普通行，可存在不同指定丹头的专用行。

## 炼丹成丹数值约束
成丹配置须满足 `0 ≤ jump_tier_prob ≤ 10000`、`1 ≤ base_rate ≤ max_rate ≤ 10000`、`0 ≤ min_purity < rate_cap_purity ≤ 9999`。`min_impurity`、丹方及丹炉 `spirit_requirement`、丹头 `max_material_count` 和丹毒池容量均为正整数。

## 炼丹材料与除渣数值约束
材料 `nval` 在 −4..+4，丹方 `nval` 在 −2..+2；材料 `power`、`dross` 非负，君材 `target_power` 为正整数。丹炉 `cold_min ≤ heat_max`。同一除渣来源的 `filter1..filter6` 均在 0..10000，按品质升高单调不增；每日消退比例在 0..10000。

## 丹炉五行额外值的有效条件
丹炉的五行额外列分别为 0..10000 的整数，未加成的五行显式填 0，空值不能用于实际计算。五行之间不要求单调，不将五列合计校验为 10000 以内；每炉只取对应一列。基础值与命中五行值相加并应用境界倍率后，按丹炉实际除渣率封顶。高于丹炉品质的丹方即使其基础除渣列有值，也不允许炼制。

## 系统默认投料的有效条件
提供系统默认配方时，`jun_num=1`，`min_num`、`env_num` 为正整数；`ast_id=0` 时 `ast_num=0`，否则佐材数量为正整数。材料的材位、境界、品质、五行、五味必须合法，君材品质等于 `jun_quality`，同境臣佐使允许混用品质。默认投料为空的品质行不据此自动补料或继承。

## 默认丹头与升品目标的有效条件
指定丹头必须同境、同品质且容量足够；不指定丹头时，须存在至少一个启用且符合相同条件的丹头。`jump_tier_prob>0` 的品质行须能明确找到同一基础丹方的相邻更高启用品质，最高启用品质的升品概率为 0。升品目标取同一 recipe_id 下相邻更高的启用品质，不按编号运算推定。

## 炼丹公共配置的有效条件
每个启用丹炉须有唯一对应除渣力行，且基准境界等于丹炉最高可炼境界。成丹率描述须完整覆盖 1..10000，杂质售价须完整覆盖 0..10000，区间均不能重叠或留空隙。除渣与服药参数须存在并满足各自单位；每个非空丹效条目须属于具体类型且目标引用合法。

## 条件计算顺序·前段
炼丹预览按顺序检查条件；依赖不足的项目标为不能计算，不填造数值。
1. 君材、丹头、至少一份臣材和使材齐备。
2. 丹炉与各材料配置有效、启用。
3. 所有材料和丹头同境；君材与丹头品质符合 `jun_quality`。
4. 丹炉最高境界不低于目标境界、丹炉品质不低于目标基础品质，当前神识满足丹炉门槛；基础品质由君材确定，并与定位后的丹方复核。
5. 逐份投药全程不越出炉膛范围。
6. 臣材五行唯一，使材五味唯一。
7. 汇总份数、药力、杂质与最终药性，并取得丹方候选。

## 条件计算顺序·后段
炼丹预览取得候选后继续检查：
8. 按实际丹头定位或复核唯一品质行。
9. 最终药性等于丹方 `nval`。
10. 臣佐使份数不超过丹头承药上限。
11. 药力达到君材 `target_power` 且大于 0。
12. 除渣后纯度达到 `min_purity`。
13. 计算成丹率、提示文字与实际售价。
14. 检查库存和批量上限。
炼丹预览保留所有可确定结果，按顺序给出首个失败原因。投药越界时保留配料及顺序，直到玩家调整后重新检查。

## 自由炼制定位
自由炼制的候选由君材 `realm`、君材品质、臣材唯一五行、使材唯一五味和最终药性确定，再按丹头消歧。
1. 有匹配实际丹头的专用行时优先选专用行。
2. 否则选择唯一 `head_id=0` 普通行。
3. 候选存在但两者均不匹配时，判定丹头不符。
4. 没有候选时，判定无法成丹。
臣材混五行、使材混五味均不合法。普通丹方与专用丹头丹方各自独立发现、各自保留玩家配方，不能只按五行、五味和药性合并。

## 手动参考丹理与实际配方
手动炼丹选择的丹理只供阅读，不限制实际成丹结果；最终丹方由真实材料定位。系统默认配方和玩家配方也须按实际材料、品质与丹头复核，不能因已选中丹方就跳过条件检查。

## 材料聚合
炼丹汇总中，N 为臣佐使总份数，P 为总药力，Z 为原始绝对杂质，count 为某材料份数。君材固定 1 份，丹头不进入求和。
```text
N = Σ(臣、佐、使 count)
P = Σ(君、臣、佐、使 count × power)
Z = Σ(君、臣、佐、使 count × dross)
finalNval = 君材.nval + Σ(每份臣、佐、使 nval)
```
炼丹必须满足 `N ≤ max_material_count`、`P ≥ target_power` 且 `P>0`；承药上限取丹头配置，目标药力取君材配置。

## 投药路径与炉膛
炼丹开炉的累计药性等于君材 `nval`；之后按实际入炉顺序，每加入一份臣佐使材料，累计药性增加该材料 `nval`。开炉及每次投料后都必须满足 `cold_min ≤ 累计药性 ≤ heat_max`；边界取所用丹炉。任一步越界，整条路径不通过，并指出步骤、材料与偏寒或偏热。
投药结束的累计药性必须等于丹方 `nval`。同一组材料换序只影响路径是否安全，不改变最终药力、杂质、纯度、成丹率与丹效。

## 炼丹数值精度与取整符号
炼丹数值判定与结算保留整数精度，比例采用万分比。向上取整记为 ceil，向下取整记为 floor；`clamp(下限, 值, 上限)` 表示将值限制在闭区间内。乘法中间结果不得丢失整数精度，也不能通过改变取整位置来简化公式。

## 境界倍率（整数定点）
炼丹术、灵植术和丹炉分别计算来源境界倍率。Δ 为来源 `base_realm` 序数减丹方 `realm` 序数；`K_bp` 为低境界倍率换算后的万分比整数。
```text
Δ < 0：来源实际除渣率为 0
Δ = 0：M_bp = 10000
Δ > 0：从 M_bp = 10000 起，逐境计算
M_bp = floor(M_bp × K_bp ÷ 10000)
```
每跨一境都向下取整，共计算 Δ 次；不能改成先连乘全部境界再统一取整。丹炉境界不足时整炉不通过；技能境界不足时仅该技能除渣率为 0。丹炉基础值与命中五行额外值共同乘入丹炉的境界倍率。

## 炼丹术与灵植术除渣率
炼丹术和灵植术分别计算技能除渣率。filter 取对应来源行中基础丹方 `quality` 的除渣列；p 为该技能当前整数百分数熟练度 0..100；S 为该技能熟练度除渣参数；M_bp 为该来源的境界倍率。
```text
技能除渣率 = clamp(0, floor(filter × (10000 + p × S) × M_bp ÷ 100000000), 10000)
```
每种技能分别代入自身的 filter、p、S、M_bp，所有倍率相乘后只在末尾向下取整一次。

## 丹炉基础与五行除渣的合计
丹炉须先通过境界、品质和神识准入。filter 按基础丹方品质取列，element_bonus 按基础丹方五行取丹炉额外列，M_bp 为丹炉境界倍率；丹炉没有熟练度加成。
```text
丹炉除渣率 = clamp(0, floor((filter + element_bonus) × M_bp ÷ 10000), 10000)
```
丹炉先加基础与命中五行值，再乘逐境取整后的倍率，仅在该来源公式末尾向下取整一次并封顶 10000。不得只给基础值跨境加成，也不得把两部分分别取整后相加。

## 三种来源的总除渣率
炼丹术与灵植术各自按自身品质列、熟练度及境界倍率计算，丹炉按基础与命中五行合计计算；将三种来源实际除渣率相加。
```text
Rt = min(10000, 炼丹术除渣率 + 灵植术除渣率 + 丹炉除渣率)
```
总除渣率 Rt 封顶 10000。升品发生在成丹之后，不改变本炉所取的基础品质除渣列、五行额外列或已经结算的除渣结果。

## 丹炉五行叠加与跨境示例
示例不代表档位定值：若基础除渣列为 300、命中五行额外列为 200，同境丹炉提供 500，即 5%；若高一境且境界倍率 M_bp=10300，则 floor((300+200)×10300÷10000)=515，即 5.15%。目标五行对应列为 0 时，同境为 3%、高一境为 3.09%。目标基础丹方品质高于丹炉品质时不能开炉，任何除渣加成都不能抵消品质门槛。

## 丹炉除渣取整边界
丹炉基础值与五行额外值必须先相加。示例：基础 150、命中五行 150、M_bp=10300，丹炉实际除渣率为 floor(300×10300÷10000)=309。将两部分分别向下取整再相加会得到 154+154=308，不符合规则；三源总和与剩余杂质继续使用各自既定的封顶及取整公式。

## 丹炉同境同品标定口径
丹炉分系统基础丹炉、普通主材法宝丹炉、特殊主材法宝丹炉三大档。同档、同辅材倾向及同五行特性的丹炉，在各自同境、同品炼制时保持相同除渣标准。提高丹炉境界与品质用于开放对应炼制范围，向下炼制时按境界倍率与目标品质列获得优势，不额外抬高同档同境同品基准。

## 除渣与丹方门槛的标定顺序
灵植药力、杂质、药性等既有数值保持不变。先定丹炉基础与五行额外除渣、两项技能的除渣范围，再固定这一组数值，逐丹方品质行校准 min_purity、min_impurity 并复算 rate_cap_purity。标定记录同时列出未命中与命中五行时的丹炉贡献，每次只调整一组变量。

## 剩余杂质
炼丹剩余杂质 D 由原始绝对杂质 Z、总除渣率 Rt 和基础品质行 `min_impurity` 共同确定。
```text
D = max(min_impurity, ceil(Z × (10000 − Rt) ÷ 10000))
```
剩余杂质先按比例向上取整，再与最低杂质取大。`min_impurity` 为正整数，因此成品剩余杂质不为 0。

## 杂质占比与纯度
炼丹实际杂质占比 G 和纯度 Q 均为万分比，D 为剩余杂质，P 为总药力且必须大于 0。
```text
G = clamp(0, ceil(D × 10000 ÷ P), 10000)
Q = 10000 − G
```
D 至少为 1，因此纯度最高为 9999，不能达到 10000。纯度必须达到基础品质行 `min_purity`，否则不能成丹；升品不回改本炉 Rt、D、G、Q。

## 成丹率
炼丹只有纯度 Q 达到 `min_purity` 时才计算成丹率 R。Qmin、Qcap、B、C 分别取基础品质行的 `min_purity`、`rate_cap_purity`、`base_rate`、`max_rate`。
```text
Qc = clamp(Qmin, Q, Qcap)
R = min(C, B + floor((C − B) × (Qc − Qmin) ÷ (Qcap − Qmin)))
```
Q 等于 Qmin 时成丹率为 B；达到或超过 Qcap 时为 C。要求 Qcap>Qmin、B≥1，因此分母为正且 R≥1。增加量向下取整，再按成丹率区间取得唯一提示文字。

## 丹药售价输入
炼丹提供本枚实际杂质占比与最终品质行 wupin_id2。对应物品 sell_price 为唯一基础售价，实际价格按物品售价规则与杂质售价系数计算；不读取 reference_price，不把丹方物品价格作为成品价格，计算与显示保持 long 精度。

## 批次上限
炼丹并炼上限同时受神识与库存约束。神识上限为 `floor(当前神识 ÷ 丹方.spirit_requirement)`；库存上限为各材料“拥有数量÷单炉所需数量”向下取整后的最小值，包含君材、丹头和全部臣佐使。库存数量按关联物品核对。
实际批量上限取两者较小值。丹方炼丹数量为 1 至上限的整数，手动炼丹固定 1 枚；预览、保存前复核及正式炼制均检查数量约束。神识只作门槛与上限，不消耗。

## 系统默认配方的丹头选择
炼丹系统默认配方提供完整材料及数量后，先确定实际丹头。`head_id>0` 时使用指定丹头；`head_id=0` 时选择启用、同境、同品质且容量足够的丹头。候选优先按拥有数量降序，同数量按灵植配置 ID 升序。
候选库存均为 0 时仍选择 ID 最小的候选展示完整配方，并报告材料不足。没有符合条件的丹头时，默认配方不合法。

## 系统默认配方的安全投药顺序
系统默认配方须从君材开炉药性开始，找到每次投入都在炉膛范围内、结束时药性精确命中丹方的顺序。多条安全顺序以材料配置 ID 升序、同材料按展开次序稳定选择。不存在安全顺序时报告原因，不能开始炼丹，也不扣料。
丹炉、品质行、材料、数量或普通丹头候选库存变化后重新检查。正式炼制使用确认的原顺序，不在确认后换成另一套；玩家配方保留实际丹头与投药顺序，不重新选材或换序。

## 炼丹重复确认与异常恢复
炼丹确认后，按当前条件复核配法与库存；条件不符则不扣料。全部通过后一次性扣除批量所需材料。同一次炼制重复确认只产生一份结果，处理中不能再次扣料；已完成时重复操作也不能再次发放。产物处理失败时，扣料和产物一同恢复，不能出现扣料成功但没有产物的结果。

## 扣料范围
炼丹单炉消耗君材 1 份、丹头 1 个和按顺序加入的全部臣佐使材料。批量炼制按单炉材料乘以数量一次性扣除，丹头同样计入总消耗和库存可炼套数。配置阶段不扣料，成丹随机失败不退该枚已经投入的材料。

## 逐枚判定
炼丹每枚独立在 1..10000 内判定成丹，随机值不大于成丹率 R 时成功，否则不产丹且不退该枚材料。成功枚再独立判定升品，随机值不大于 `jump_tier_prob` 时升至同一基础丹方的相邻更高启用品质，否则保留基础品质。相邻品质关系必须明确，不能按 `recipe_id` 差值或相邻行推定。

## 丹药实例
炼丹成品保留最终丹效品质行的身份，以及本炉实际纯度 Q 和剩余杂质 D。最终品质行决定 `quality、duration、pill_effects、wupin_id2`，对应物品决定背包物品身份及显示信息，丹方配置中的 `pill_name` 与成品物品名称需保持一致。
升品后不使用高品质行的 `min_purity、rate_cap_purity、base_rate、max_rate、min_impurity、spirit_requirement` 重新复核本炉，它们属于炼制输入。升品也不重算纯度与剩余杂质。

## 丹方炼丹列表的获得来源
丹方炼丹列表按 recipe_id 汇总玩家经默认授予、使用丹方道具、手动保存有效配方三种来源获得的丹方。默认投料不等于初始拥有全部丹方。手动预览通过不自动保存，只有主动保存成功才通过该来源进入列表；正式成丹的发现记录不代替手动保存，也不自动增加第四种列表准入来源。

## 玩家配方与丹方发现
玩家可在手动炼丹中保存已定位基础丹方且全部成丹条件满足的配方；保存不要求先炼制成功，不扣材料。配方保留实际君材、丹头、臣佐使投入顺序和君材品质。每名角色的每个基础丹方只保留一套玩家配方，再次保存时覆盖原配方，不增加命名或多方案选择。

## 玩家配方载入与恢复
丹方炼丹优先载入玩家配方，没有玩家配方时使用该基础丹方最低启用品质的有效系统默认配方。玩家配方失效时仍保留并原样载入，显示具体失败原因，不能静默替换为系统配方。只有玩家执行“恢复系统配方”才删除原玩家配方并使用默认配方。

## 丹方发现与品质分组
正式炼制至少成功一枚后，实际基础丹方记为已发现；失败不改变发现状态。普通丹方与专用丹头丹方分别发现。发现状态和玩家配方都按基础丹方区分，不依据每个品质行的编号单独扩成一套记录，分组键为 recipe_id。

## 丹毒的派生关系
炼丹五味池分别记录绝对杂质 I，Cpool 为角色当前境界对应五味池的容量，丹毒 T 为万分比。
```text
T = clamp(0, floor(I × 10000 ÷ Cpool), 10000)
```
境界或池容量变化时保留绝对杂质 I，并按新容量重新计算丹毒 T，不沿用旧容量下的丹毒占比。

## 丹药功能分流与效果校验
功能类型为 `Pill / 功能_丹药` 的物品尝试直接服用；`BreakthroughPill / 功能_突破丹` 只提供突破入口，必需材料与额外成功率加成按突破规则处理，不触发普通丹效，且不以普通丹效数组为空判定不可投入。

普通丹药 `pill_effects` 为空或没有有效丹效时，禁止直接服食，不消耗、不增加杂质、不产生药效。待定效果保持未配置，不从丹名、`effect_desc` 或历史概念推导效果。全部已配置丹效须先完成类型、目标引用和参数校验；配置错误不能跳过后继续结算。

## 服用准入
丹药服用前按最终品质行的 `taste` 确定五味池。T_before 为本枚服用前丹毒，H 为 `参数_效果减半丹毒`，效果倍率采用万分比。
| 服用前条件 | 准入与效果倍率 |
|---|---|
| T_before < H | 允许，10000 |
| H ≤ T_before < 10000 | 允许，5000 |
| T_before ≥ 10000 | 禁止服用 |
正式服用按最新角色状态与本枚丹药重新判定，不能只凭先前预览直接消耗。

## 服用顺序
丹药通过准入后，按 `pill_effects` 的有效条目顺序执行。全部丹效成功后，将本枚剩余杂质 D 加入对应五味池，再消耗该枚丹药。
```text
I_after = min(Cpool, I + D)
T_after = clamp(0, floor(I_after × 10000 ÷ Cpool), 10000)
```
任一丹效失败，属性、丹药与毒池都恢复原状。新增杂质在全部丹效成功后才入池，因此只从下一枚丹药开始影响效果倍率。

## 丹效执行与倍率取整
丹效 `PillAttrEffect` 按 `attr` 定位属性，用基础数值 value 与本枚效果倍率 effectMultiplier 计算实际变化。
```text
实际变化 = floor(value × effectMultiplier ÷ 10000)
```
负数同样向下取整。`PillSkillEffect、PillBuffEffect、PillAffixEffect` 分别以 `skill_id、buff_id、affix_id` 定位效果；可缩放数值按相同倍率向下取整，开关型效果不缩放，不读取通用 value。

## 每日消退
炼丹五味丹毒每游戏日各自消退一次，一游戏日等于一现实小时。Cpool 为当前境界对应池容量，daily_decay 为对应池每日消退万分比，I_before 为消退前绝对杂质。
```text
dailyDecay = floor(Cpool × daily_decay ÷ 10000)
I_after = max(0, I_before − dailyDecay)
T_after = clamp(0, floor(I_after × 10000 ÷ Cpool), 10000)
```
消退向下取整，绝对杂质不低于 0；五味池相互独立。

## 除渣档位与关联丹方门槛待定项
三类丹炉的基础与五行额外除渣百分比、两项技能满熟练合计，以及重标定后的各丹方纯度和最低杂质门槛尚待验算定值。讨论中的 3%、6%、7%—8% 等是示例，不作为正式数值；固定除渣范围后再校准丹方门槛，灵植参数保持原值。

## 熟练度触发规则待定项
灵植与炼丹相关概率参数的触发条件和计数单位尚未确定，包含“新灵植”的定义、炼丹失败是否计数、批量按炉还是按枚。当前仅记录参数的概率单位与关联主题，不据表备注生成经验奖励规则；定案会影响灵植获取、炼制结算和神通熟练度增长。

## 未定丹效边界
只有概念而未确定具体规则的丹效保持 pill_effects 未配置，不从丹名、说明或历史讨论生成效果。普通丹药没有有效丹效就禁止直接服食，不消耗、不加杂质；突破丹按突破节点规则投入，不以普通丹效数组是否为空作为准入依据。
