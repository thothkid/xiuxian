# 物品表

> 定位：定义 W物品表的表结构、字段语义、功能参数、导表方式和配置规则。
> 边界：本文不收录有效物品清单，不复制具体物品的现行数值和资源编号。字段类型与枚举以权威配置表为准；尚未确定的玩法口径集中列在文末，不从配置示例推定。

## 一、工作表结构

`W物品表.xlsx` 中的配置与说明分工如下：

| 工作表 | 作用 | 配置关系 |
|---|---|---|
| `item_config` | 物品主表 | 每行定义一种物品，`id` 为唯一主键 |
| `item_effect_config` | 物品效果组 | 每行定义一个效果，同一 `group_id` 的多行组成一个效果组 |

| 工作表 | 作用 | 配置关系 |
|---|---|---|
| 编号表 | 物品编号辅助 | 提供编号大类、品质、境界与各自编号值的对应关系 |
| 字段说明 | 效果组字段填写说明 | 解释 `item_effect_config` 的字段和列间约束，不是物品主表的完整字段说明 |

| 工作表 | 作用 | 配置关系 |
|---|---|---|
| 效果算子对照 | 功能参数填写说明 | 解释 `function_type`、`op` 及其对应参数 |
| 枚举与注册、更新说明、物品效果更新说明 | 配置接入与变更记录 | 不作为物品数据；枚举及表注册以元表为准 |

`item_config` 与 `item_effect_config` 都由四行表头和若干数据行组成：

| 表头标记 | 作用 | 处理规则 |
|---|---|---|
| `##var` | 声明导出字段名 | 建立字段索引；空单元格不是独立字段 |
| `##type` | 声明字段类型 | 按类型解析并校验 |

| 表头标记 | 作用 | 处理规则 |
|---|---|---|
| `##group` | 声明导出分组 | 由导表器按目标分组筛选，不作为物品数据 |
| `##` | 中文说明行 | 只供配置定位，不导出 |

数据行从中文说明行之后开始。首列是控制列，不属于物品对象；导表器必须先判断控制标记，再解析其余字段。未在 `##var` 中声明名称的列属于配置辅助列，不应直接生成运行时字段。

## 二、正式导出字段

`item_config` 的正式字段按权威配置表逐项登记：

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `id` | `int` | 物品唯一主键 | 必填、全表唯一；已有物品不得随意改 ID |
| `name` | `string` | 物品显示名称 | 必填；不得代替 ID 参与物品定位 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `quality` | `ItemQuality` | 物品品质 | 填写枚举中存在的值；不由品质反推图标、边框或光柱编号 |
| `dur_t` | `int` | 物品存在时间 | 表头批注明确单位为秒；非负整数；计时范围、起点、到期行为及空值、0 的含义待明确 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `main_class` | `string` | 运行结构大类 | 用于物品一级结构分类；与编号辅助列“大类”、界面显示分类分别填写 |
| `sub_class` | `string` | 运行结构子类 | 与 `main_class` 配套；合法大类、子类组合及各组合用途待明确 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `drop_level` | `int` | 物品档次 | 与 `required_level` 分别配置；档次如何参与投放或筛选待明确，不直接解释为使用等级或品质 |
| `display_type` | `ItemDisplayType` | 界面显示分类 | 填写对应枚举，用于显示归类，不承担运行结构判断 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `attrLimit` | `int` | 属性限制 | 限制对象、整数编码及比较方式尚未明确；不得自行解释为属性 ID、属性值或限制组 ID |
| `keep_dur_t` | `int` | 物品有效时间 | 与 `dur_t` 分别填写；单位、适用范围、计时起点及空值、0 的含义待明确 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `is_drop` | `bool` | 是否可丢弃 | TRUE 表示允许丢弃，FALSE 表示不允许；不表示怪物是否掉落该物品 |
| `is_quick_slot` | `bool` | 是否可进快捷物品栏 | TRUE 表示允许进入，FALSE 表示不允许；不代替功能类型或自动使用开关；空值含义待明确 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `is_auto_use` | `bool` | 是否可以自动使用 | 区分未配置、TRUE、FALSE；自动使用的触发时机、条件及空值含义待明确 |
| `required_level` | `int` | 使用级别下限 | 只表达使用门槛；整数与角色等级、境界的对应关系待明确，不用 `drop_level` 代填 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `cultivation_tag` | `string` | 修炼路线标签 | 标签集合、匹配方式及是否限制使用待明确；不自行解释为职业限制 |
| `pile_max` | `int` | 单格堆叠上限 | 必须大于等于 1；填 1 表示同一格最多一个，不另建不可堆叠字段 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `function_type` | `ItemFunctionType` | 物品功能类型 | 使用枚举规定的名称、别名或数值；不是自由字符串；各功能的参数含义分别登记 |
| `function_id` | `int` | 功能目标编号 | 可能是技能 ID、币种、物品 ID、掉落方案 ID 或效果组 ID，按 `function_type` 解释 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `function_value` | `int` | 功能数值 | 可能是数量、修为量、抽取次数或具体效果参数，按 `function_type` 解释；不需要时按功能说明填 0 |
| `use_panel_id` | `int` | 使用道具时打开的面板编号 | 0 表示不额外打开面板；有业务配置关联的道具保留原 `function_id`，面板编号填在此列 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `desc` | `string` | 功能说明 | 功能、用途等事实性说明；可保留颜色控制码 |
| `desc1` | `string` | 氛围说明 | 引文、传闻等补充文本，不参与功能结算 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `spec_desc` | `string` | 获得说明 | 说明投放或获得方式，不参与功能执行 |
| `icon_id` | `int` | 背包图标资源编号 | 填资源编号，不填文件路径或资源名称 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `mdx_id` | `string` | 地表模型资源标识 | 保留字符串标识，不因相邻资源字段是整数而改成整数编号 |
| `light_eff_id` | `int` | 掉落光柱资源编号 | 填资源编号；无光柱时保留空值，不由品质补出资源 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `border1` | `int` | 静态边框资源编号 | 填资源编号，直接读取配置，不由品质猜测 |
| `border2` | `int` | 动态边框资源编号 | 填资源编号，直接读取配置，不与静态边框共用一个字段 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `sell_price` | `long` | 单件基础售价 | 按实际物品 ID 读取，不从其他业务表重复取得基础价格 |
| `tags` | `array,string` | 检索与筛选标签数组 | 标签1至标签4共同组成数组；读取完整数组，标签参与具体规则匹配时需另有明确口径 |


## 三、配置辅助列

| 所属表 | 辅助列 | 作用 | 导出规则 |
|---|---|---|---|
| `item_config` | ID 编号 | 同一编号大类内的本地序号 | 参与新物品 ID 公式，不生成同名运行时字段 |
| `item_config` | 大类 | 在编号表中查找编号大类 | 只用于生成 ID；不要与 `main_class` 混用 |

| 所属表 | 辅助列 | 作用 | 导出规则 |
|---|---|---|---|
| `item_config` | 标签2—标签4 | `tags` 数组的后续元素 | 合并进 `tags`，不生成四个独立标签字段 |
| `item_effect_config` | 组名称 | 便于定位效果组 | 不导出，只需在每组第一行填写 |

| 所属表 | 辅助列 | 作用 | 导出规则 |
|---|---|---|---|
| `item_effect_config` | 策划备注 | 解释单行效果和特殊参数 | 不导出；备注不能替代正式参数 |

辅助列可以参与导表计算，但运行时物品对象只保留正式导出字段。

## 四、物品 ID

新物品 ID 由编号大类、品质、境界的编号值和本类序号共同生成：

`id = 10000000 + 编号大类值 × 100000 + 品质编号 × 10000 + 境界编号 × 1000 + 本类序号`

编号大类值取编号表 A—B 列映射，品质编号取 E—F 列映射，境界编号取 C—D 列映射；名称必须精确匹配。当前物品主表公式分别读取 G 列的大类、D 列的品质、AF 列填写的境界名称和 E 列的本类序号。AF 列当前表头为“标签3”，此处仅说明现行 ID 公式的取值位置。

配置步骤：

1. 在辅助列“大类”中选择编号表已有的大类。
2. 填写物品品质和用于编号的境界名称，分别匹配编号表中的品质、境界映射。
3. 在“ID 编号”中填写该大类内未占用的本地序号。
4. 使用表内公式生成 `id`，不得为新物品手填另一套编号。
5. 导表前校验大类、品质、境界映射存在，本地序号有效，最终 ID 全表唯一。
6. 已有旧物品可能使用固化 ID；读取最终 `id`，不在运行时重新计算，也不批量重排旧 ID。

示意一，仅说明公式，不是有效物品配置：编号大类值为 4、品质编号为 1、境界编号为 1、本类序号为 36 时，生成 ID 为 `10411036`。

## 五、分类字段

三个分类字段用途不同：

| 字段 | 面向对象 | 能否参与功能判断 |
|---|---|:---:|
| `main_class` | 运行时一级结构 | 是 |
| `sub_class` | 运行时二级结构 | 是 |

| 字段 | 面向对象 | 能否参与功能判断 |
|---|---|:---:|
| `display_type` | 界面展示与筛选 | 否 |

不得用 `display_type` 代替 `main_class` 或 `sub_class`。调整界面分组时，只改显示分类；调整运行结构时，必须同步检查对应功能规则。大类与子类目前没有完整的合法组合说明，不能仅凭已有数据归纳出封闭的分类清单。

`quality` 是独立枚举字段。资源边框、光柱和图标已经有独立字段，应读取显式资源配置，不从品质反推资源编号。

`drop_level` 表示物品档次，`required_level` 表示使用门槛，`cultivation_tag` 表示修炼路线标签，三者分别配置。档次不直接换算成使用门槛，修炼标签不直接换算成职业限制；具体匹配规则列入待明确口径。

## 六、功能字段与效果组

### 6.1 单功能参数

`function_type`、`function_id`、`function_value` 构成一组功能参数：

- `function_type` 决定物品的功能语义，类型为 `ItemFunctionType`。
- `function_id` 指向该功能需要的目标配置或目标类别。
- `function_value` 提供该功能需要的数量或数值。
- 参数列不是通用的“目标物品 ID”和“效果强度”，不能跨功能套用含义。
- 参数不需要时，按对应功能的明确约定填 0；未定义的参数不能自行用 0 补齐。
- 枚举成员及数值以 `__enums__.xlsx` 为准；物品名称、说明文本和标签不代替功能类型。

### 6.2 功能类型与参数含义

功能参数口径依据 `W物品表.xlsx` 的“字段说明”和“效果算子对照”整理。下表登记配置含义，不据表内的实现状态文字判定功能是否已经可用。

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `功能_无` | 物品不能通过使用操作触发效果 | 填 0 | 填 0 |
| `功能_客户端效果` | 触发具体效果，如恢复、增益或表现效果 | 由具体效果定义；现有说明未给出统一编号规则 | 由具体效果定义；不能统一解释为恢复量或百分比 |

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `功能_技能书` | 学习指定技能 | 技能配置行 ID | 填 0 |
| `功能_加货币` | 增加指定类别的货币 | 表内口径：1 为角色级货币，2 为账号共享货币 | 数量，正整数 |

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `功能_加修为` | 增加修为 | 填 0 | 修为量，单位为 1/100 点；填 2000 表示 20 点修为 |
| `功能_加物品` | 固定发放指定物品 | 物品 ID | 数量，正整数 |

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `功能_随机产出` | 按掉落方案产生奖励 | `D掉落方案.xlsx` 中的方案 ID | 抽取次数；表内口径规定 0 或 1 均表示抽取 1 次 |
| `功能_多效果组` | 引用一个效果组 | `item_effect_config.group_id` | 填 0 |

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `Pill / 功能_丹药` | 尝试直接服用 | 丹方表 `id`，定位丹效品质行 | 不作为突破加成来源 |
| `BreakthroughPill / 功能_突破丹` | 使用时打开突破准备面板，不直接服用 | 同样关联丹方表 `id`，不是面板编号 | 不作为突破加成来源 |

| `function_type` | 用途 | `function_id` | `function_value` |
|---|---|---|---|
| `OpenPanel / 功能_打开面板` | 使用时只打开业务面板，不直接结算或消耗 | 面板编号 | 填 0 |

`功能_无` 与 `功能_多效果组` 只用于物品主表，不能作为效果组中的单行算子。`功能_随机产出` 的概率和重复抽取规则属于掉落方案，物品表只填写方案和抽取次数，不再配置一套独立概率。

### 6.2.1 炼丹物品关联与使用入口

灵植物品 `function_id` 关联灵植表 `id`，用于查炼丹属性；丹药与突破丹 `function_id` 关联丹方表 `id`；丹方物品 `function_id` 关联基础丹方 `recipe_id`。背包操作使用物品主键，不混用业务 ID。

丹药和突破丹仍属于丹药物品分类，功能类型只决定使用入口。普通丹药无有效 `pill_effects` 时禁止直接服食，不扣药、不加杂质；效果暂定时保持未配置。突破丹打开面板不等于投入或消耗，其正式使用按突破节点规则判定，不以普通丹效数组为空限制使用。

### 6.2.2 使用道具打开业务面板

道具的“使用”是统一动作，可由背包右键、左键菜单的“使用”选项、快捷栏等入口触发。凡声明打开业务面板的道具，各入口都应先打开同一面板；不能让不同入口分别决定是否直接消耗。打开、切换或关闭面板均不消耗道具，玩家在面板里确认业务操作后，才按该业务规则校验并结算。

仅用于打开面板、没有其他业务配置关联的道具，填写 `function_type=功能_打开面板`、`function_id=面板编号`、`function_value=0`、`use_panel_id=0`。`功能_打开面板` 不可配置为 `item_effect_config.op`，也不通过普通物品使用请求扣除。

既需打开面板，又需用 `function_id` 关联技能、丹方等业务配置的道具，保留原功能类型及 `function_id` 含义，在 `use_panel_id` 填面板编号。突破丹按此规则配置：`function_type=功能_突破丹`，`function_id` 继续指向丹方品质行，`use_panel_id=1` 表示使用时打开突破准备面板。面板编号 1 固定代表突破准备面板；其他面板编号须登记后才能填表。

使用入口应把玩家实际操作的容器、槽位、物品 ID，以及丹药载荷等实例信息交给目标面板，供面板预选和重新核对。面板不得只凭物品 ID 自行改选另一堆。道具已被移走或实例信息变化时，确认操作须重新校验并拒绝错位消耗；关闭或取消不产生结算。

### 6.3 效果组字段

`item_effect_config` 一行一个效果，同一 `group_id` 的多行组成一组。物品填写 `function_type=功能_多效果组`，再以 `function_id` 指向该组。

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `group_id` | `int` | 效果组标识 | 必填；同组多行共用同一个值；物品主表的 `function_id` 引用该值 |
| `seq` | `int` | 组内效果顺序 | 必填；从 1 开始，同组内唯一且连续；0 不表示第一项 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `op` | `ItemFunctionType` | 单行效果的功能类型 | 与主表 `function_type` 共用枚举；不能填 `功能_无` 或 `功能_多效果组` |
| `target_id` | `int` | 单行效果目标 | 按 `op` 解释，对应单功能中的 `function_id`；不需要时填 0 |

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `amount` | `int` | 单行数量或数值 | 按 `op` 解释，对应单功能中的 `function_value`；不需要时填 0 |
| `duration` | `int` | 单行效果持续时间 | 单位为秒；0 表示瞬时；具体持续效果需有对应定义 |

### 6.4 效果组配置约束

- 一个物品包含多个效果，或某个效果需要单独填写持续时间时，使用效果组；主表的三列功能参数没有持续时间字段。
- 效果组以 `group_id` 归组，以 `seq` 排定顺序；不能把同组重复的 `group_id` 当作重复物品主键。
- 不允许效果组再引用另一个效果组。
- 表内说明仅为 `功能_客户端效果` 定义了 `duration` 的使用入口，其余算子填 0；具体效果如何解释持续时间仍需有独立口径。
- 效果组没有逐行概率列。需要随机结果时，用 `功能_随机产出` 引用掉落方案；这不表示掉落方案中的每个奖励都会产出。
- 表内说明限制：含账号共享货币效果的组，不得再包含其他行。本文保留该配置限制，不据此推定相关功能的实现进度。

## 七、时间、丢弃、快捷栏与堆叠

### 7.1 时间字段

| 字段 | 已明确的含义 | 尚需明确的边界 |
|---|---|---|
| `dur_t` | 物品存在时间，表头批注明确单位为秒 | 适用场景、计时起点、离线是否计时、到期处理、空值与 0 的含义 |
| `keep_dur_t` | 物品有效时间，与存在时间分别配置 | 时间单位、适用场景、计时起点、是否重置、到期处理、空值与 0 的含义 |

| 字段 | 已明确的含义 | 尚需明确的边界 |
|---|---|---|
| 效果组 `duration` | 效果持续秒数，0 表示瞬时 | `功能_客户端效果` 下各具体效果的持续规则 |

三个时间字段不能合并或互相补值。效果持续时间不代替物品有效时间；不能因现有数据大量填 0，就把 0 一律解释成永久有效。

### 7.2 丢弃、快捷栏与自动使用

- `is_drop` 控制玩家是否可以丢弃物品，不控制怪物投放、活动投放或系统赠送。
- `is_quick_slot` 控制物品是否可以进入快捷物品栏，不代表物品一定可使用，也不等同于自动使用。
- `is_auto_use` 表达是否可以自动使用，不代替使用门槛与功能参数；触发条件仍待明确。
- 三个布尔字段分别保留 TRUE、FALSE、空值。空值的具体业务含义尚未确定，不统一按 FALSE 或 TRUE 补写。

### 7.3 堆叠上限

`pile_max` 只定义单格数量上限，必须大于等于 1。填 1 表示单格不能叠加数量；填更大数值表示单格最多容纳该数量。同类物品能否合并、实例状态是否相同，属于背包堆叠规则，不能仅凭上限字段决定。

## 八、文本、资源与标签

- `desc` 为功能与用途说明，`desc1` 为引文、传闻等氛围说明，`spec_desc` 为获取途径；按对应区域展示，不解析文字生成属性、药效、成功率或价格。
- `icon_id`、`light_eff_id`、`border1`、`border2` 为整数资源编号；`mdx_id` 为字符串资源标识，不能统一改成同一种类型。
- 图标、地表模型、光柱、静态边框、动态边框分别读取各自资源字段；空资源不自动套用相邻物品配置。
- 资源校验在导表阶段检查格式，在资源构建阶段检查资源是否真实存在。
- `tags` 是字符串数组。导表器按连续标签单元格收集非空值，保持顺序并去除纯空白项。
- 标签用于检索、筛选和规则匹配，不替代主键、分类或功能类型。`tags` 与 `cultivation_tag` 是不同字段，不直接互相复制；标签参与何种规则需有明确约定。

## 十、导表校验

## 10.1 身份与分类校验

- `id` 必填、为整数、全表唯一。
- `name` 必填；名称重复是否允许由项目另定，但物品定位始终使用 `id`。
- `quality`、`display_type`、`function_type`、`op` 必须属于对应枚举，不按任意文本接受。
- 结构大类与子类组合必须符合确定后的分类规则，不能以当前数据出现过为唯一合法依据。
## 10.2 数值参数与引用校验

- `pile_max >= 1`；时间和级别字段不得为非法负数。
- 按每种功能分别校验 `function_id`、`function_value`；不能把不需要参数时的 0 判为漏填，也不能把需要正整数的数量填成 0。
- `功能_打开面板` 的 `function_id` 和非零 `use_panel_id` 必须指向已登记的面板编号；未登记的编号不得静默放行。
- `功能_多效果组` 引用的 `group_id` 必须存在；同组 `seq` 从 1 开始且连续、唯一。
- 按 `op` 分别校验 `target_id`、`amount`、`duration`，并校验不可嵌套及账号共享货币的组内限制。
- TRUE、FALSE、空值分别处理；未明确空值业务含义时，不在填表说明中擅自增加默认行为。
- `tags` 输出为数组；辅助标签列不得泄漏成独立运行时字段。
- 资源字段格式错误时终止导表；资源缺失由资源构建校验报告。
- 文档只在表结构、字段语义、编号算法或配置接入方式变化时更新；普通物品增删改不更新本文。

## 十一、基础售价与资源关联

### 11.1 单件基础售价

`item_config.sell_price:long` 是对应物品 ID 的单件基础售价。灵植表 `price`、丹方表 `reference_price` 不再作为独立基础售价来源。灵植用关联物品 ID；成品丹药用实际最终品质行 `wupin_id2`；丹方物品用自身 ID，三者不能混用。

读取、计算和展示不得将 long 收窄为 int。空值不自动视为 0，也不据此推定允许或禁止出售。

### 11.2 丹药实际售价

丹药售价按本枚实际杂质占比 G 匹配“杂质售价”闭区间，取得万分比系数 `price_factor`：

`丹药单件实际售价 = floor(实际成品物品.sell_price × price_factor ÷ 10000)`。

向下取整，保持整数精度。同一物品 ID 的实例杂质不同，实际售价可以不同，不可只按物品 ID 缓存最终价格。标注“实际售价”必须与出售结算一致；“基础售价”才直接展示 sell_price。

### 11.3 图标关联与说明字段

物品 `icon_id` 关联图标配置 `id`；图标主键同时作为资源命名编号，`path` 为资源目录，资源定位结合目录、ID 与对应扩展名。字段完整定义由配置表目录的图标条目拥有。

正式字段按 `##var` 声明，不因旧快照缺列而删除权威字段。说明文本不决定效果；功能、资源、售价按对应字段和实例结果解释。
