# 神通系统策划案
配置工作簿为 `J技能BUFF表.xlsx`。`skill_config` 一行配置一门神通的一个等级；`buff_config` 一行配置一条状态的一个等级。本案中的字段名、枚举值和无效配置处理以当前《技能表配置说明》《状态表配置说明》为准；词条的作用对象与系别转换以《词条表配置说明》为准。

## 一、共同填写口径
一、共同填写口径：两张表均使用多行表头：`##var` 三行依次表示字段名、效果序号、块内子字段名，随后是 `##type`、`##group`，以及以 `##` 开头的中文列名行。按中文别名填写枚举。先选选择器或效果类型，再填【公共】列与该类型的专属列段；其余类型列留空。

不使用固定 Excel 列号或通用参数槽位定位字段。

一、共同填写口径：时间字段统一填**毫秒**，不按固定帧数换算配置值；有效时长精度以当前逻辑帧为单位并四舍五入，少于半帧的普通时长视为瞬时。比例统一为万分比，`10000` 表示 100%；距离、半径、长度用地图距离单位，速度用地图距离每秒。

空格按类型默认导出：整数 `0`、文本空串、布尔“否”、普通枚举的 0 值（多数为“无”）。可空ClassType字段例外：留空继承根，显式0是无元素，不得互换。

## 二、技能表 `skill_config`
### 2.1 身份、展示、分类与成长
| 字段 | 填写与规则 |
|---|---|
| `id` | 技能等级行 ID，格式为六位族号加两位等级；与状态 ID、词条 ID 不重复。 |

| 字段 | 填写与规则 |
|---|---|
| `identify_id`、`skill_level` | 同门神通各等级共用识别 ID；`skill_level` 为本行等级。已学、技能栏、升级及按神通识别 ID 的词条均按识别 ID 关联。相同识别 ID、相同等级重复时后一行覆盖前一行且无提示，配置时须自行排重。 |

| 字段 | 填写与规则 |
|---|---|
| `required_skill_id`、`next_level_id` | 前者为学习或升级本行所需掌握的技能等级行 ID，`0` 为无；后者指向同识别 ID 的下一等级行，末级填 `0`。 |

| 字段 | 填写与规则 |
|---|---|
| `name`、`internal_name`、`description`、`icon_id` | 分别为显示名、内部名、面板描述、`icon_config.id`。图标查不到时显示占位图；描述须与实际效果一致。 |

| 字段 | 填写与规则 |
|---|---|
| `color`、`base_realm` | 颜色标签为凡品、灵品、玄品、仙品、神品、道品；基准境界为大境界枚举，炼气至大乘为 1～8，`0` 为无，仅记录、不参与技能结算。 |

| 字段 | 填写与规则 |
|---|---|
| `skill_type` | 分类为人道、地道、天道，分别进“人道·神通”“地道·百艺”“天道·功法”页签；面板只列 1 级行。“英雄技能”为历史兼容值，“无”和“英雄技能”不进面板。地道神通配炼丹、灵植、炼器、灵材系别时视为默认拥有，仅供展示。 |

| 字段 | 填写与规则 |
|---|---|
| `skill_class` | 每门神通只配一个默认系别：无、神通、修炼、破境、神识、剑道、术法、炼体、金行、木行、水行、火行、土行、五行、灵植、灵材、炼丹、炼器、符箓、阵法、御兽、毒。无所属及普攻填“无”；“无”不被按系别加成或词条命中。 |

| 字段 | 填写与规则 |
|---|---|
| `required_level`、`required_wupin` | 分别为学习本行所需角色等级、本级升下一级消耗的道具 ID。后者每次消耗 1 个，`0` 为不消耗，末级填 `0`。 |

| 字段 | 填写与规则 |
|---|---|
| `exp_to_next`、`exp_trigger` | 前者为本级熟练度上限，`0` 表示不积累，末级填 `0`，面板显示“-”；后者填增加本神通熟练度的行为。多个值在同一格用竖线 `|` 分隔，例如 `获得灵植|炼丹`。 |

二、技能表 `skill_config`：`exp_trigger` 可填：无、施放本神通、修炼时辰、使用本系别人道神通、使用任意人道神通、使用本命神通、炼丹、炼器、制符、获得灵植、获得灵材。任务目标“技能熟练度达到”要求该神通配“施放本神通”。

当前行有 `next_level_id` 时，`exp_to_next` 和 `required_wupin` 分别决定熟练度与道具门槛：两者都非零则都满足；只一项非零则只满足该项；两者均为零则本级不可按这两项升级。升级目标仍需满足目标行的前置技能与角色等级。

二、技能表 `skill_config`：熟练度只在已学且本级 `exp_to_next>0` 时积累。原案的人道战斗神通规则为每次施放本神通判一次，判中加 1～3 点，引导整次只计一次；

二、技能表 `skill_config`：行为成长每次命中配置的 `exp_trigger` 行为后，按该门神通识别 ID 对应的系统参数概率独立判定，判中加 1 点，缺少该概率参数则不结算该门的行为成长。一项行为可以让多门神通分别判定，同门配置多项行为时仍使用同一门的概率参数。

数值概率参数沿用 `X系统参数.xlsx` 的 `ConfigSystemVar` 中 `参数_识别ID<技能识别ID>`。例如灵植术的触发格填写 `获得灵植|炼丹`；不要用逗号、顿号或待程序决定的列表格式。

二、技能表 `skill_config`：技能默认系别与生效系别分开：词条可按《词条表配置说明》设定生效系别。含转换的词条按默认系别定位，其余按转换后的最终系别匹配；五行加成覆盖五行及金、木、水、火、土行，单行加成只匹配该行。转换不改变 `skill_type` 面板归属。

词条作用对象只能在作用系别、作用神通识别 ID、作用状态识别 ID 三者中选择一个；每次计算先按来源适用范围筛选有效来源；同一词条 ID 在本次范围内由多个来源提供时只按一条生效。

| 字段 | 填写与规则 |

| 字段 | 填写与规则 |
|---|---|
| `lingli_cost` | 灵力消耗；`0` 或负数表示不消耗。灵力不足不能施法，起手时一次扣完，被打断不返还。 |

|---|---|
| `cast_time`、`recovery_time`、`hit_stun` | 前摇、后摇、受击硬直均为毫秒；**本项目当前都填 `0`**。列保留供扩展，不以正值设计前摇、后摇或受击硬直玩法。 |

| 字段 | 填写与规则 |
|---|---|
| `stop_move` | TRUE 时起手停止当前移动。 |

| 字段 | 填写与规则 |
|---|---|
| `channel_time`、`channel_interval`、`channel_move_cancel` | 引导时长与结算间隔均为毫秒。引导开始即结算首跳，之后每隔一个间隔结算；换算后的引导间隔不足 1 帧时整行不生效。只有间隔、没有时长时警告；间隔大于时长时警告且只跳一次。移动中断只针对引导期间新下达的移动指令，被动位移不算。 |

2.2 施法、冷却、引导与被动：字段：`cast_action`、`cast_effect`、`cast_point_effect`、`hurt_effect`、`cast_sound_id`、`hit_sound_id`；

填写与规则：分别是施法动作名、起手特效 `effect_config.id`、命中帧施法点特效路径、每次伤害的受击特效路径、起手音效 `sound_config.id`、命中音效路径。表现不参与结算；施法点特效优先放目标单位、其次落点、最后施法者脚下，持续 2 秒。

| 字段 | 填写与规则 |
|---|---|
| `damage_type`、`base_power` | 前者是展示文本，实际伤害类型由伤害效果的 `dmg_type` 决定。基础威力为万分比；伤害威力为本行基础威力加角色“法术威力”，治疗只用本行基础威力。基础威力小于等于 0 时警告并按 `10000`。 |

2.2 施法、冷却、引导与被动：`aim_kind` 为无、单位、目标点、目标方向。无瞄准时施法点在脚下；单位瞄准未点到合法单位时按 `acquire_range` 智能施法查询半径寻找最近的合法单位，仍找不到则以落点瞄准。智能查询仅用于单位瞄准，`0` 或负数不自动找；候选阵营取主选择器，未配主选择器按敌对找；

友方或自己阵营找不到时落到施法者自己。`cast_distance` 只限制单位与目标点瞄准，`0` 或负数不检查，超出时角色自动走近。

2.2 施法、冷却、引导与被动：`is_basic_attack` 为 TRUE 的行必须配单位瞄准、`is_invoked=FALSE`、`is_passive_skill=FALSE`、`passive_trigger=无`、`cooldown>0`，否则整行不生效。普攻受“禁止普攻”影响，不受沉默影响，可被主动技能打断；未禁止冷却缩减会警告。

2.2 施法、冷却、引导与被动：是否为被动以 `passive_trigger` 为准：无为主动；`is_passive_skill` 只影响面板显示和自动施法候选，单独勾选不会触发被动。常驻在被动生效时对自己执行一次；造成伤害、暴击、击杀作用于受害者；受到伤害作用于攻击者，缺失则对自己；施法起手、命中帧作用于本次瞄准单位；

自身死亡作用于击杀者，缺失则对自己；低血量作用于自己。周期被动配常驻并调用带 `interval` 的状态。被动无需主动施放，不扣灵力、不进冷却、不播放施法特效、施法点特效与命中音效；受击特效仍播放。

2.2 施法、冷却、引导与被动：`passive_skill_id` 填条件神通的**识别 ID**，`0` 表示不限；该识别 ID 无可用技能行时整行不生效，填在自身死亡或低血量上也整行不生效，填在常驻上仅警告。

2.2 施法、冷却、引导与被动：事件来源按玩家实际施放的神通算，包含它调用的子技能、弹道、延迟伤害、所挂状态的周期伤害和光环，以及召唤物挂载状态的光环；装备、丹药或环境伤害没有来源神通。再次施加状态后来源跟最后一次施加者与神通走。`passive_icd` 填毫秒，按“单位＋该条被动”计时，常驻配置时警告且不生效。

低血量被动必须将 `passive_hp_threshold` 填为 `1～10000`；其余被动填阈值仅警告。

`is_invoked=TRUE` 的行不进入自动施法候选。被调用行不扣灵力、不进冷却、不触发命中帧事件、不计熟练度；使用自己的选择器、基础威力和效果，继承外层施法者及当前目标。弹道命中调用时以命中目标或落点为原点。调用技能与弹道命中共用最多 8 层调用深度，跨帧延迟和飞行仍计层数。

### 2.2.1 常驻被动的承受者与法宝持有来源
技能字段`passive_recipient`表示常驻被动的承受者，使用可空枚举`PassiveRecipient`：`Caster=0`为施法者自身，`OwnerRole=1`为所属角色。留空与Caster都按施法者自身处理，不推断所属角色；未知枚举无效。该字段只配置在技能表，不配置在状态表；已有技能不自动改变承受者。

OwnerRole用于《法宝系统策划案》7.6规定的免御使法宝角色持有属性。完整关联为“法宝引用有效技能→技能常驻且明确OwnerRole→技能效果调用状态→状态属性修正”。仅给法宝配置状态或直接加属性不能代替技能关联；角色永久已学神通不因法宝持有而增加。

OwnerRole技能须`is_passive_skill=TRUE`、`passive_trigger=常驻`，且`passive_skill_id`、`passive_icd`、`passive_hp_threshold`均为0。技能效果仅允许有效调用状态，每条`rate=0或10000`、`delay=0`、`require_target_hp_below=0`、`effect_range=全部`。

OwnerRole所调用状态须`duration=0`、`interval=0`，且只含有效属性键、必定概率的属性修正。主动、事件触发、概率、限时、周期或混入其他效果的组合不能作为持有属性；异常时完整能力无效，不能只保留其中一部分加成。这些严格条件只适用于OwnerRole，不改变其他技能或状态原有警告、降级及无族并存规则。

OwnerRole所调用状态的`identify_id`须为1至2147483647的规范十进制整数文本，`level`须为正整数。空值、0、负数、前导零、加号、空白、小数、指数或溢出文本均使该关联无效，不能借无族状态绕过去重。

OwnerRole所引用状态在整张状态表中须满足“同识别ID、同等级只有一条状态行”。同一行被多个来源引用不算冲突；出现不同状态行时，该OwnerRole关联及引用它的法宝完整能力均无效。此限制不改变其他状态的同级先挂规则，也不改变已有冲突内容；永久并存状态仍按3.4无效，不能因持有来源例外生效。

OwnerRole选择所属角色承受效果，效果阵营仍相对于提供被动的法宝判断，仅`target_faction=全部/友方`合法。“自己”仍指法宝施法者自身；OwnerRole与自己、敌方、无的组合无效。持有属性不需要主动施法，不产生施法消耗和冷却，不按区域选择器选人；法宝的其他技能仍以各自原定施法者为准，能力归属须明确到具体法宝、技能与状态来源。

OwnerRole涉及的法宝拥有关系、`sense_cost`资格、获得、祭炼、配置变化、重复恢复、死亡复活及同族等级压制，按法宝7.6、11.4判断。角色学会同一技能、穿戴器法或打开面板不自动获得法宝来源；角色词条不覆盖该法宝来源。

角色已学功法与合法法宝持有来源共同参加状态等级裁决。全部合法法宝普通被动均参与，不按法宝境界、品质只保留一件；同族等级压制仍按状态规则。撤除一项只撤除该来源，剩余合法来源继续生效。

法宝授予、祭炼等来源变化影响修炼时，变化前后分别按对应有效属性结算，过去时间不按新属性补算。装备器法、套装及穿脱装备仍按各自规则；属性与修炼公式保持原规则，不因持有属性额外获得熟练度、资源或永久已学资格。

### 2.3 主选择器、子选择器
`skill_selector` 实际选单位；`sub_selector` 只将主选择器已选单位分成子范围内和外。两块均先填形状，再填五个【公共】列和形状专属列；类型留空表示未配。主选择器留空按单体结算，但不触发“显式单体须单位瞄准”的校验。

| 形状 | 专属列 | 合法值 |
|---|---|---|
| 单体 | 无 | 主选择器显式配单体时 `aim_kind` 必须为“单位”。 |

| 形状 | 专属列 | 合法值 |
|---|---|---|
| 圆形 | `circle_radius` | 半径大于 0。 |

| 形状 | 专属列 | 合法值 |
|---|---|---|
| 扇形 | `sector_radius`、`angle` | 半径大于 0，总张角大于 0 且不超过 180 度。 |

| 形状 | 专属列 | 合法值 |
|---|---|---|
| 线形 | `length`、`width` | 长度、全宽均大于 0；按半宽向两侧判定。 |

| 形状 | 专属列 | 合法值 |
|---|---|---|
| 环形 | `inner_radius`、`outer_radius` | 内圈半径大于等于 0，外圈半径大于内圈半径。 |

2.3 主选择器、子选择器：主选择器的【公共】`target_faction` 为全部、自己、友方、敌对；“无”选不中单位。“自己”必须同时将 `include_caster` 填 TRUE。

2.3 主选择器、子选择器：`max_target_ally`、`max_target_enemy` 分别限制友方（含施法者）和敌对目标数量，`0` 为不限。`priority` 为最近（距施法点）、血量最低、血量最高（按血量百分比）、随机；两类数量上限均为 0 时不排序。

候选超过 64 个时先按单位编号截取前 64 个再排序。子选择器的五个【公共】列不参与目标、数量或优先级判断。

2.3 主选择器、子选择器：主、子范围共用原点和方向：目标点瞄准以落点为原点，方向为施法者指向落点，线形从落点延伸；目标方向以施法者为原点；有目标单位（含子技能或弹道命中）以目标为原点，抛物线落地调用以落点为原点；都没有则以施法者为原点、取当前朝向。不可被选中的单位不能被圈入。

瞄准类型不是单位且未配区域主选择器时，命中帧没有目标，需目标的效果都会跳过；给自己加状态应配包含施法者的区域主选择器。

2.3 主选择器、子选择器：`effect_range` 选“仅子范围内”或“子范围外”时，主、子选择器都必须是区域形状，否则整行不生效。子选择器配单体时警告并视作未配；主选择器不圈人却配子选择器也警告。示例：主圆形 `circle_radius=300`、敌对，子圆形 `circle_radius=100`，核心伤害效果选“仅子范围内”，外围效果选“子范围外”。

### 2.4 技能效果公共列与执行顺序
2.4 技能效果公共列与执行顺序：`skill_effects` 有效果1～效果3，按顺序处理。每块选类型，再填【公共】列及同名【伤害】【治疗】【调用状态】【召唤】【位移】【弹道】【调用技能】列段。

现有类型只有：技能效果_伤害、技能效果_调用状态、技能效果_治疗、技能效果_召唤单位、技能效果_位移、技能效果_弹道、技能效果_调用技能。

2.4 技能效果公共列与执行顺序：每个效果先按目标阵营、作用范围和触发概率确定是否作用于该目标；符合时按配置延迟生效，血量阈值取实际生效时的目标状态。效果【公共】`target_faction` 为全部、自己、友方、敌对；“无”在**效果层**表示不过滤，与选择器层不同；没有目标时也不过滤。

2.4 技能效果公共列与执行顺序：`rate` 为万分比，`0`、负数和不小于 `10000` 都必定触发，超过 `10000` 警告。`delay` 为毫秒，换算为 0 帧立即执行，负数警告后按立即处理；同时等待延迟生效的效果最多256条。`effect_range` 为全部、仅子范围内、子范围外。

`require_target_hp_below` 为万分比，目标在实际生效时血量百分比须**严格低于**阈值；`0` 或负数无条件，正阈值却没有目标时不生效，负数或大于 `10000` 会警告。

### 2.5 伤害、治疗与调用状态
2.5 伤害、治疗与调用状态：技能效果_伤害填【伤害】`dmg_type`、`dmg_coefficient`、`dmg_flat`、`dmg_can_crit`、`dmg_crit`、`falloff_edge_ratio`。`dmg_type` 取**物理、魔法、物理真伤、法术真伤**；“无”按物理。前两者分别走物理／法术通道与防御，后两者保留对应通道但无视防御。未配置合法关联分量时，伤害系数与固定伤害同时为0整行不生效；有关联分量时按下述替换规则校验。

2.5 伤害、治疗与调用状态：伤害统一按P03《战斗公式与战斗规则》执行：命中与区间攻防取值、穿透、技能威力和效果系数、通用增减伤及固定附伤、境界修正、暴击、追加固定伤害、BOSS来源减伤、最终系别增减净差乘区、保底、护盾与扣血。每步按P03取整；本案不再维护另一份简版总公式。

`dmg_flat`不乘威力和系数，但在暴击前加入，能被暴击放大。最终暴击率为施法者暴击率加`dmg_crit`减目标免暴击率，限制在0～100%；`dmg_can_crit=FALSE`时不判暴击。暴击率加成为负数，或不允许暴击却填非零加成，均警告。

2.5 伤害、治疗与调用状态：普通未覆盖伤害按根神通经词条转换后的最终`skill_class`匹配；混伤分量及状态持续伤害有显式有效系别时优先使用自身ClassType，空值才继承根：金木水火土各用对应行增幅和减免，毒用毒伤增幅/减免，神识系造成的伤害归灵魂、用灵魂伤害增幅/减免；非伤害效果不受这些伤害属性放大。

2.5 伤害、治疗与调用状态：物理/法术攻防通道仍由效果`dmg_type`决定，转换系别不自动改变通道。子技能、弹道、延迟的空系别分量沿根归属；状态持续伤害按施加时有效状态系别冻结，空值才沿根。技能调用不重复叠乘同一次系别增幅。仅配“五行”不自动叠加五个单行属性。

同系增幅减去减免，原值不预截断，净差限制在±10000，再对完整伤害乘一次；净差允许为负，负属性值直接参与差值。七系对应关系、边界与投放待定项归P03、属性定义归P02及属性源表；

2.5 伤害、治疗与调用状态：`falloff_edge_ratio` 以圈人原点到范围边缘线性衰减系数部分与固定伤害：`10000` 不衰减，`5000` 边缘剩一半，接近无伤可填 `1`。`0` 或负数警告后按不衰减，大于 `10000` 警告；单体配置警告且不起作用。

范围尺度取主选择器半径、线形长度或环形外圈半径。

2.5 伤害、治疗与调用状态：技能效果_治疗填【治疗】`heal_type`、`heal_coefficient`、`heal_flat`、`heal_can_crit=FALSE`、`heal_crit=0`。治疗类型为物理（施法者物理攻击）、魔法（施法者法力）、目标血量上限、施法者血量上限、无（基数为 0）。

2.5 伤害、治疗与调用状态：攻击型治疗的基数按伤害取值规则在上下限间取值。治疗量＝`floor(floor(治疗基数 × base_power / 10000) × heal_coefficient / 10000)＋heal_flat`，**不加施法者法术威力**；结果不大于 0 或目标已死亡时不治疗。

系数与固定值同时为 0 时整行不生效；治疗暴击列填了其他值只警告，仍不暴击。例如治疗基数 101、基础威力 15000、系数 5000、固定值 5，结果为 `floor(floor(101×1.5)×0.5)+5=80`。

技能效果_调用状态只填【调用状态】`buff_id`，指向 `buff_config` 的有效状态 ID；没有目标时跳过，时长和叠层读状态自身。ID 小于等于 0、不存在或状态无效时，**引用它的技能整行不生效**。

### 2.5.1 同一伤害效果的独立分量
2.5.1 同一伤害效果的独立分量：技能配置的伤害分量列表`damage_components`，全技能9槽以内；

2.5.1 同一伤害效果的独立分量：每槽按`effect_index`（从1起，指向本行伤害效果）、`skill_class:ClassType?`、`damage_type:DamageType`、`coefficient:int`（万分比）、`flat:int`填写。空系别继承最终根，0显式无元素；

伤害类型0继承父`dmg_type`。金8、木9、水10、火11、土12、毒21、神识4沿既有ClassType，不新增分类枚举或AffixParam。

有关联分量即用分量系数／固定值替换父`dmg_coefficient/dmg_flat`；至少一条合法分量才豁免父0/0。每分量数值须整数且不同为0，允许范围沿父效果；非法序号、非伤害目标、超9槽、非法枚举或数值拒绝整行。无分量保留旧行为。

2.5.1 同一伤害效果的独立分量：同目标同伤害效果共享一次命中结果及暴击随机样本，不同效果独立。公共固定项只首分量，BOSS固定减免只扣整包一次、按各分量追加后原伤比例floor分摊，剩余减免按配置顺序补扣；之后各分量分别乘BOSS比例减免并floor、各自系别净差并floor，合计后只保底一次，统一吸盾、扣血及判断触发与死亡。完整细节归P03第十二节。

2.5.1 同一伤害效果的独立分量：词条修改效果后，伤害分量仍跟随原先所属效果：删除前序效果不改变分量所属，删除本效果同时取消其分量，替换／追加时采用模板对应效果的分量；无分量模板替换会清除原分量。根系别转换只影响空系别继承槽，显式0或其他系别保留。已绑定分量的效果不允许旧词条直接增减／设定父系数或父固定值，应诊断并使整条词条不生效；

未绑定分量的旧效果保持原规则。单独修改分量数值及父数值向各分量分摊的词条规则尚未定义。公共基础威力、暴击许可／加成、概率／延迟／衰减等仍走原词条规则。

本次施法的分量配置在起手时确定；弹道与延迟效果沿用起手时确定的攻方数值，目标防御和减免取实际结算时的值。不附加“伤害命中后才附状态”的条件联动；状态施加仍走原效果顺序与判定。

### 2.6 召唤与位移
2.6 召唤与位移：技能效果_召唤单位只从【召唤】`summon_id` 引用 `owned_entity_config.config_id`。不直接填怪物表 ID 或状态表 ID；从属实体自身可以承载怪物、图腾、地板及其状态。`summon_id≤0` 整行不生效；正值但实体不存在时本次召唤放弃并报错。

2.6 召唤与位移：【召唤】`position` 为目标点、施法者、目标身上；“无”警告且不召唤。目标点无落点时用目标位置；目标身上无目标时在施法者身边生成。`duration` 为**毫秒**，`0` 不限时，正数不足一帧按一帧计；`summon_count` 必须大于 0；

2.6 召唤与位移：`max_count≤0` 不限，同类上限已满先销毁最早的一只，单次数量超过上限会警告。上限按 `summon_id` 统计。`init_lv` 是初始等级，`max_lv>0` 时取两者较小值，否则沿用初始等级；

生成时查同 `kind_id` 的相应等级行，缺行报错并回退到 `summon_id` 所指行。

2.6 召唤与位移：地板玩法配置示例：玩家技能用“目标点”瞄准，效果填“技能效果_召唤单位”，【召唤】`summon_id` 填**地板从属实体行 ID**、`position=目标点`、`duration=10000`、`summon_count=1`。地板从属实体的状态来源及挂载关系在从属实体配置中确定；

状态行配 `interval=1000` 毫秒与【光环】`sub_skill_id`；光环子技能配区域主选择器、阵营和伤害／治疗。召唤物的存续取召唤效果，状态和光环运行取各自配置。不得把状态 ID 当作 `summon_id`。对应地板从属实体行须存在且有效，此示例才能产生所述效果。

2.6 召唤与位移：技能效果_位移填【位移】`subject`（施法者／命中者）、`mode`（直线／闪现）、`direction`（技能瞄准处／远离施法者／拉向施法者／施法者朝向／施法者朝向反方向／远离技能瞄准处）、`distance`、`move_speed`、`pass_through`。

2.6 召唤与位移：主体、模式、方向任一为“无”时警告且本效果不执行；方向无法计算时跳过并警告。距离必须大于 0，否则整行不生效。直线按地图距离每秒的速度移动，速度不大于 0 时警告并按 900；闪现一次到位，不读速度。`pass_through=TRUE` 时无视地形，FALSE 时按地形修正落点。

新位移覆盖该单位正在进行的旧位移。击退示例：`subject=命中者`、`mode=直线`、`direction=远离施法者`、`distance=300`、`move_speed=600`、`pass_through=FALSE`。

### 2.7 弹道与调用技能
2.7 弹道与调用技能：技能效果_弹道本身不造成伤害，命中时调用【弹道】`proj_sub_skill_id` 指向的技能等级行；ID 为 0、不存在或结构校验失败时整行不生效。

2.7 弹道与调用技能：`proj_speed`（地图距离每秒）、`proj_count`、`range`（地图距离）、`hit_radius`（地图距离）必须大于 0；命中半径小于当前帧飞行距离时警告。`portion≤0` 按每波 1 枚；`interval≤0` 表示每帧发一波，字段单位仍为**毫秒**。

2.7 弹道与调用技能：要一波发完，将 `portion` 填到不小于 `proj_count`。`spread_angle<360` 按扇形均分且正中指向目标，`≥360` 按整圈均分、第一发指向目标；散布的多发不锁定。`height` 仅控制表现，抛物线以它为峰值；

`effect` 和 `sound` 分别填弹体模型与每波释放音效路径。

2.7 弹道与调用技能：【弹道】`path` 为直线、抛物线、回旋、弹射、追踪；“无”警告且不发射。`pierce` 在直线是一路能穿过几个单位，在回旋是**每一程**可打几个单位，在弹射是能跳几次（填 0 警告），在追踪是命中后还能追几个新目标；抛物线途中不撞人，不读穿透。

`range` 在直线是全程距离，在抛物线是到落点距离，在回旋是外程距离，在弹射是每跳距离兼下一跳搜索半径，在追踪是含外飞与转弯的总飞行距离。效果【公共】`target_faction` 决定碰撞对象；填“无”且未锁定时撞不到单位。

有施法目标且单发或多发不散布的普通弹道锁定目标；锁定弹道只撞锁定目标并随目标转弯，目标死亡或消失后沿当前方向碰撞。抛物线、回旋、追踪轨迹不使用这种锁定；不锁定的点地、方向或散布弹道沿出膛方向碰撞。抛物线落地调用子技能时以落点为原点。

2.7 弹道与调用技能：追踪轨迹另填【弹道】`seek_distance`（外飞距离，地图距离）、`seek_radius`（索敌半径，地图距离）、`turn_rate`（最大转向速度，度／秒）、`seek_mode`（最近／分散／集火，留空为最近）。

2.7 弹道与调用技能：`seek_radius` 必须大于 0，`seek_distance` 和 `turn_rate` 不能为负，否则整行不生效；外飞距离不小于射程时警告，因为永远无法开始追踪。`seek_distance=0` 表示出膛就索敌；外飞段不拐弯但仍撞人。

转向速度 `0` 表示每次直接对准目标，正数按约每 60 毫秒一次校正、每次至多转 `turn_rate×0.06` 度。追上目标后追到命中；目标死亡或已被本弹体穿过时另找未命中过的目标，找不到则直飞并继续找，飞满射程消失。不可被选中的单位不能被撞到或追踪。

“最近”让每枚各追最近目标；“分散”优先没人追的目标，再比被追数量及距离；“集火”整组追同一目标，有施法目标时优先追它且不受索敌半径限制，否则追第一枚找到的目标，目标死亡时整组换目标。

2.7 弹道与调用技能：技能效果_调用技能填【调用技能】`call_skill_id`，指向被调用技能的**具体等级行 ID**。被调用行提供自己的选择器、基础威力和效果，承接当前施法者、目标与瞄准信息；消耗、冷却与施法时序由外层承担。ID 小于等于 0、不存在或结构校验失败时整行不生效；指向自己时警告。技能和弹道调用链合计最多 8 层，超过时终止链条。

### 2.8 功法、词条与熟练度玩法
2.8 功法、词条与熟练度玩法：常驻加属性功法可配：技能行 `passive_trigger=常驻`，使用“技能效果_调用状态”与【调用状态】`buff_id` 指向永久状态；

2.8 功法、词条与熟练度玩法：状态行 `duration=0`、`category=增益`，效果配【属性修正】`attr_key`、`attr_value`，多属性占多个连续效果块。当前项目的 `cast_time`、`recovery_time`、`hit_stun`、`consumable_id` 均填 `0`。

常驻状态随携带者死亡清除，复活后重新执行常驻被动。

2.8 功法、词条与熟练度玩法：上述施法者自身功法示例还须在技能行配置区域主选择器，例如 `aim_kind=无`、`skill_selector=圆形`、【圆形】`circle_radius=1`、【公共】`target_faction=自己`、`include_caster=TRUE`，让施法者进入目标集；

只填 `passive_trigger` 和 `buff_id` 不能保证“调用状态”取得目标。OwnerRole持有属性另按2.2.1直接选择所属角色，以全部或友方筛选，不套用“自己＋包含施法者”或区域主、子选择器条件。

2.8 功法、词条与熟练度玩法：**词条与技能对象的关系。** 词条是技能系统、状态系统之外的独立修正规则。技能表中的对象按 `skill_type` 分类为人道·神通、地道·百艺、天道·功法等；这些技能对象、神通效果和状态（Buff）都只能作为词条的修正对象，不提供词条来源或词条 ID。

2.8 功法、词条与熟练度玩法：词条只修改已有技能或状态的参数与效果，不授予角色新的神通，也不替换角色已拥有的神通。功法需要常驻属性加成时，按本节常驻被动与状态配置生效；技能卸下或升级换行时撤销旧来源；其他来源仍提供同一状态时按剩余来源保留。具体哪些外部系统提供词条、当前接入了哪些来源，待核对后再确定；

按《词条表配置说明》处理有效来源提供的词条。

### 2.9 无效技能配置与降级规则
技能行的字段与跨表引用均须合法；错误使该等级不可用并明确提示原因。状态行无效或被调用技能结构校验失败时，引用方整行不生效。警告不使整行失效，按各字段的降级规则运行。

| 处理 | 触发情况 | 不可用结果 |
|---|---|---|
| 整行不生效 | 显式单体主选择器却不是单位瞄准；圆／扇／线／环尺寸不合法；子范围效果缺区域主、子选择器；无合法关联分量的伤害效果或治疗效果系数与固定值同为0；召唤数量、位移距离不大于 0；弹道速度、射程、命中半径、总数不大于 0，追踪索敌半径不大于 0 或外飞距离／转向速度为负 | 该技能等级不可用；不以跳过坏效果代替整行错误。 |

2.9 无效技能配置与降级规则：处理：整行不生效；触发情况：`buff_id≤0` 或状态不存在／无效；`summon_id≤0`；弹道子技能 ID 为 0／不存在／结构失败；调用技能 ID 不大于 0／不存在／结构失败；引导间隔换算不足 1 帧；普攻约束失败；低血量阈值非法；

自身死亡／低血量被动配条件技能 ID；条件识别 ID 无可用技能行；不可用结果：引用方也不可用；状态被整条拒绝时引用它的技能随之失败。

| 处理 | 触发情况 | 不可用结果 |
|---|---|---|
| 效果不执行或本次跳过，行仍有效并警告 | 召唤位置“无”、位移主体／模式／方向“无”、弹道轨迹“无”；位移方向实际无法计算；正值从属实体 ID 查不到时本次召唤放弃并报错 | 其他有效效果照常执行；从属实体缺失时本次召唤报错，不把怪物或状态 ID 当作替代。 |

| 处理 | 触发情况 | 不可用结果 |
|---|---|---|
| 仅警告或按值降级 | 基础威力不大于 0、无效果、概率超过 10000、负延迟、血量阈值越界、伤害衰减非法或单体衰减、暴击列无效、治疗暴击列非默认、子选择器单体／主选择器不圈人、召唤数超上限、直线位移速度不大于 0、弹道半径小于帧移动距离、弹射穿透 0、追踪外飞距离不小于射程、调用技能自指 | 行仍有效；分别按前述字段规则降级或忽略。 |

| 处理 | 触发情况 | 不可用结果 |
|---|---|---|

## 三、状态表 `buff_config`
### 3.1 身份、同族压制与并存
状态表每行最多 3 个效果，效果1开始连续填写，空效果块表示没有该效果。`id` 是六位族号加两位等级；同一状态的不同等级族号相同，与技能、词条 ID 不重复。奇珍按前六位归族并取末两位最大行。

三、状态表 `buff_config`：`name`、`icon_name`、`icon_id`、`display_position`、`show_time`、`description` 分别管展示名、图标资源名、图标配置 ID、图标位置、剩余时间显示和描述；`icon_id=0` 不影响效果。

`target_type` 为无、角色状态、怪物状态，只记录所属对象类别，不限制实际施加对象。

三、状态表 `buff_config`：`identify_id` 为**字符串形式的数字**；留空表示不参与同族压制，非数字或 `0` 按留空并警告。相同有效识别 ID 的不同状态行属一族；同单位上以 `level` 最高的状态行生效，同级先挂者生效。

被压制状态只继续自己的到期计时，不加属性、不挂控制、不跳周期效果，生效行消失后从剩余行中重新选择最高级。`level` 仅在有效识别 ID 下比较；状态识别 ID 同时是词条“作用状态识别 ID”的匹配依据。族号归族与 `identify_id` 同族压制分别用于不同用途，不混为一列。

三、状态表 `buff_config`：`pile_type` 为无、有限叠加、无限叠加、并存。无时恒 1 层；有限叠加每次加 1 到 `pile_max`，上限不大于 0 按 1；无限叠加上限固定 999，忽略 `pile_max`。属性修正、持续伤害、持续治疗按层数放大；控制和光环不按层数放大。

非并存状态再次施加后，归属及后续攻方数值按最后一次施加者与该次施加时的有效属性确定。

三、状态表 `buff_config`：**并存**每次施加新建一个独立实例，各次施加分别确定当时的有效属性，各自到期、判效果概率和周期结算；属性修正按实例相加。`pile_max` 是实例数上限，`0` 或负数按 999，达到上限时顶掉最早实例；填 1 警告。`duration` 必须大于 0 毫秒，永久并存状态整条无效。`time_override` 对并存无效，填“无”以外警告。同一行的多个并存实例互不压制；同族更高等级状态出现时整批被压制，消失后整批接替。免疫期间并存减益的每次施加都是新实例，都会被拒绝。

### 3.1.1 独立状态伤害系别
3.1.1 独立状态伤害系别：状态配置可空系别字段`skill_class`（ClassType）。留空继承发起根神通最终系别；Poison=21令持续伤害独立成为毒，DivineSense=4为灵魂，None=0显式无元素。火技能的直伤可仍为火，其所挂状态单独配毒；状态名字叫毒不会自动改变归属。

该字段不改变状态的物理／法术伤害通道，也不放大治疗、控制或其他非伤害效果。

状态的有效系别与攻方属性在施加时确定，目标防御和对应系别减免取每跳生效时的值；再次施加按原有实例与叠层规则更新。施加者实体消失后，持续伤害仍按施加时的攻方属性结算，归属按原规则。每跳按天运与区间规则分别取值，不能把一次随机结果用于全部跳动。物理与物理真伤取攻击上下限，魔法与法术真伤取法力上下限；系别不改变通道，神识不成为第三套攻击基数。

词条沿用既有`set_skill_class`选项，作用状态时只允许位置=自身设置该状态的有效系别；直接状态词条与沿神通引用进入状态均走已有优先级、同级冲突和整条失效。瞄准类型／目标优先级／目标阵营等原神通专属选项仍不允许作用状态，不因此增加其他可修改项目。

### 3.2 时长、周期、来源与驱散
3.2 时长、周期、来源与驱散：`duration` 为毫秒，`0` 或负数表示永久，直到显式移除或随携带者死亡清除；到期时整条状态连同全部层数移除。持续型丹效与奇珍挂上的状态由来源决定存续，不读本表 `duration`；丹方持续秒数为 0 时按本表时长。

`time_override` 在同一状态再次施加时为无（保留原到期时间）、覆盖（刷新满时长）、叠加（剩余时长再加满时长，无总上限）。再次施加导致时长刷新时不重启原周期节奏、不额外首跳。

3.2 时长、周期、来源与驱散：`interval` 为毫秒，持续伤害、持续治疗、光环共用。施加后的下一逻辑帧结算首跳，此后每满一个间隔再跳；到期那一刻不跳。例如 `duration=12000`、`interval=3000`，在施加时及第 3、6、9 秒跳，共 4 次。

被同族压制后重新接替生效，或重新判概率后周期效果从全部未命中变为命中时，从该时刻重新起跳并立即首跳。有周期效果而间隔不大于 0 时**丢弃全部周期效果并警告**；没有周期效果却填正间隔时警告并按 0 处理。

状态效果【公共】`rate` 为万分比，`0`、负数及不小于 `10000` 均必定生效。每次施加时各效果独立判一次，结果随实例保存，各跳不重判。再次施加时，若有限／无限叠加，或时间覆盖为覆盖／叠加，各效果重新判；未判中的效果保留已有结果，已判中的不会因此消失。并存实例各自独立判。

`effect_path` 是携带者身上的持续特效路径；`binding_position` 只有“原点”才实际挂载，“无”不挂。再次施加保留原特效，状态移除、被同族压制、携带者死亡或销毁时清理；并存时每实例各挂一份。

3.2 时长、周期、来源与驱散：`category` 为无、增益、减益、中性。只有**减益**是负面状态，会被“免疫”控制拒绝新的施加；已有同一条减益的非并存再次施加仍可刷新。`dispel_level` 参与实际驱散：`0` 不可驱散，`1` 可被普通驱散，`2` 需强驱散；驱散强度须不小于状态级别。

驱散对象按分类另判：净化驱自己身上的减益，驱魔驱敌方身上的增益，不能只看驱散级别或效果名称。

3.2 时长、周期、来源与驱散：携带者死亡时清除全部状态，停止周期并撤除属性、控制和特效；携带者实体消失后同样不保留这些效果。施加者死亡但实体仍在时，持续伤害继续并归属施加者；施加者实体销毁后，施加时确定的攻方属性仍用于逐跳取值结算，击杀无人归属，光环停止释放。

持续伤害每跳必定命中，防御和减伤按每跳目标实时属性，施加者增伤与系别增幅取施加时确定的值，守方对应系别减免按每跳实时属性；不计施加者穿透、法术威力和法术附带伤害。由神通施加的状态，其持续伤害和光环每跳按该发起神通匹配被动条件；再次施加后改随最后一次施加的神通。

### 3.3 状态效果的类型专属列段
`effects` 为效果1～效果3；每块先选类型，再填【公共】`rate` 和对应类型列段。类型只有状态效果_控制、状态效果_持续伤害、状态效果_持续治疗、状态效果_属性修正、状态效果_光环。

| 类型及专属列 | 填写与执行 |
|---|---|
| 【控制】`tag` | 控制类型填中文别名；“无”时跳过本效果并警告。眩晕／石化／冰冻／击飞禁移动、普攻、施法；禁锢／击退只禁移动；沉默只禁施法；缴械只禁普攻；嘲讽强制攻击施加者；恐惧禁普攻与施法并随机游走；隐身不可被选中；无敌不受伤害；免疫拒绝新减益；净化／光环是纯标记。击退控制本身不产生位移，位移由技能效果配置。 |

3.3 状态效果的类型专属列段：类型及专属列：【持续伤害】`damage_type`、`dot_coefficient`、`dot_flat`、`dot_can_crit`、`dot_crit`；填写与执行：类型取物理、魔法、物理真伤、法术真伤，“无”按物理；

3.3 持续伤害配置：伤害类型决定攻击／法力及物防／法防通道；物理和物理真伤取攻击，魔法和法术真伤取法力。每跳按施加时确定的攻方属性，分别依天运及上下限规则取值，守方防御与天佑逐跳实时取值；不固定取攻击下限，也不冻结一次随机结果供全部跳动复用。系数为万分比；每跳攻击基数＝`(floor(A×dot_coefficient/10000)+dot_flat)×层数`，其中A是本跳按天运与区间规则取得的攻方数值。完整结算归P03持续伤害规则。

3.3 持续伤害配置：系数与固定值同时为0时不结算且不进行攻击取值；负基数不结算，零基数且两项均非正时也不结算。零基数有正系数或正固定值时继续按原伤害顺序结算，最终系别对抗后保底1，再吸收护盾，不提前将基数抬到1；无敌、伤害取消及全护盾仍可使实际扣血为0。每跳不暴击，后两列填 FALSE、`0`；其他值警告且不生效。

例：本跳取值100、系数2200、固定2、1层，基础值为24；本跳取值3、系数500、固定0时基数为0，仍进入最终保底。

3.3 状态效果的类型专属列段：类型及专属列：【持续治疗】`heal_type`、`hot_coefficient`、`hot_flat`、`hot_can_crit`、`hot_crit`；填写与执行：类型与技能治疗相同，“无”只取固定值。物理、魔法、施法者血量上限按施加时的数值确定治疗基数；

目标血量上限每跳读当前值。每跳治疗量＝`(floor(治疗基数×hot_coefficient/10000)+hot_flat)×层数`。每跳不暴击，后两列填 FALSE、`0`；其他值警告且不生效。

3.3 状态效果的类型专属列段：类型及专属列：【属性修正】`attr_key`、`attr_value`；填写与执行：属性名填属性字典中文别名，数值可正可负，按层数相乘，移除时撤销。基础属性按自身单位增减；

攻击、法力、物防、法防上下限增幅及生命、灵力增幅等修饰属性直接按万分比加在修饰属性上，再按字典父子关系作用。`attr_key` 为“无”或查不到时只跳过本效果并警告。多属性用多个连续效果块。

3.3 状态效果的类型专属列段：类型及专属列：【光环】`sub_skill_id`；填写与执行：指向 `skill_config` 的**等级行 ID**。每跳以携带者当前位置为原点、施加者身份释放该子技能；范围、阵营与效果取子技能。ID 不大于 0 时跳过本效果并警告；

指向不存在的技能仅警告。施加者实体消失后停止释放。单实例光环自挂回携带者按再次施加处理；并存光环自挂会持续新增实例直至上限，配置校验时警告。

## 常驻状态、熟练度与周期结算
常驻功法卸下、升级或覆盖变化时撤销旧来源；其他来源仍提供同一状态时继续保留。携带者死亡清除状态，复活且功法仍有效时恢复常驻状态。

施放本神通的成长要求到达命中帧后才计一次，引导整次至多一次，命中帧前打断不计；判中增加1至3点。升级扣除本级exp_to_next并将余量带入新等级，例如110点跨100点门槛后余10点；道具、前置技能和目标等级门槛仍须满足。

同一状态的一跳先按槽位顺序结算持续伤害和治疗，再按光环槽位顺序结算光环。周期数值取施加时确定的攻方属性，光环每跳读取实时施法者；施加者销毁后已保存周期数值可继续，光环停止。

## 七系属性与词条匹配边界
七系伤害属性与词条的“作用系别”分别匹配：属性83至96按分量或状态最终分类生效；词条作用系别仍匹配整门神通的最终`skill_class`，不逐个选中内部显式分量。“角色所有火伤增幅”使用属性86；分量数值的独立词条修改规则尚未定义。
