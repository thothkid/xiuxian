# P02 修仙属性体系

> 版本：v3.0｜2026-08-05
> 定位：S属性配置表的属性字段、有效属性、修改器关系与显示标记说明。
> 权威边界：属性名称、编号、role、修改器关系和显示标记以 S属性配置表为准。本文不自行改名、不补表外属性、不替表格决定计算顺序。

## 一、有效范围
〔出处：P02_修仙属性体系.md · §一、有效范围 ｜ 定位：代码依据——写代码用〕

- 现行有效属性为 `config_id 1—70`，共 70 条；编号连续且不重复。
- role 只有 `BASE` 与 `MODIFIER`：BASE 56 条，MODIFIER 14 条。
- 数值口径只有“整数”与“万分比”：整数 42 条，万分比 28 条。
- 表尾以 `##` 开头的 6 条为禁用行，不属于现行属性。
- 表内没有 V0/V1 等启用版本字段，没有初始值字段，也没有完整属性计算公式；本文不再保留旧 P02 的版本分期、默认值和推导公式。

## 二、配置字段
〔出处：P02_修仙属性体系.md · §二、配置字段 ｜ 定位：代码依据——写代码用〕

| 配置字段 | 类型 | 说明 |
|---|---|---|
| `config_id` | `int` | 配置主编号；现行值为1—70 |
| `name` | `AttrKey` | 属性Key；表内当前使用中文名称 |
| `role` | `AttrRole` | `BASE` 或 `MODIFIER` |
| `parent_attr_modifier` | `array,AttrModifier` | MODIFIER 对父级属性的 ADD/MUL 关系，可登记一组或两组 |
| `tab` | `string` | 表内“标记”列，用于归组或显示标签 |
| `desc` | `string` | 属性说明 |
| `is_show` | `bool` | 是否显示在装备栏；空值不等于 TRUE |
| `is_show_tip` | `bool` | 是否显示在属性 Tips；空值不等于 TRUE |

表内“整数/万分比”、两组父级属性与影响方式、“属性id”和“备注”是配置表中的辅助列。其中“属性id”没有出现在 `##var` 声明中，不能代替 `config_id` 作为唯一键。

## 四、修改器关系
〔出处：P02_修仙属性体系.md · §四、修改器关系 ｜ 定位：代码依据——写代码用〕

- `MUL` 与 `ADD` 按表内字面保留；S属性配置表没有定义全局结算顺序，本文不补写先乘后加或先加后乘。
- 20—27分别对攻击、法力、物防、法防的上下限执行 `MUL`。
- 29对生命值执行 `MUL`，30对灵力值执行 `MUL`。
- 47“攻法上限”同时对攻击上限与法力上限执行 `ADD`；48“攻法下限”同时对攻击下限与法力下限执行 `ADD`。
- 49对攻法上限执行 `MUL`，50对攻法下限执行 `MUL`。
- 其余 BASE 属性没有 `parent_attr_modifier`。

## 六、表内异常与实现边界
〔出处：P02_修仙属性体系.md · §六、表内异常与实现边界 ｜ 定位：代码依据——写代码用〕

- “属性id”缺失：39“击中回灵”、40“受击回灵”、57“攻击范围”、58“警戒范围”。
- “属性id”重复：`jcxy`＝11“天运”、59“天佑”；`mfbfb`＝26“法防下限增幅”、30“灵力值增幅”；`jnsh`＝42“法术威力”、43“法术附带伤害”。
- 因此程序唯一定位只能使用 `config_id`；“属性id”只能作为旧标识或人工对照信息。
- 表内名称按原文使用：2“灵力值”、5—6“法力下限/法力上限”、28“经验值增幅”、59“天佑”以及60—63的 BOSS 属性均为现行有效行。本文不得用旧 P02 的概念裁定将其改名或删除。
- S属性配置表没有声明英文 `hp/mp/atk/def` 键、五行亲和、境界编号、神识、法宝御使、耐药、丹毒等属性；这些内容不得写入本属性清单，除非先进入属性配置表。
- `name` 的类型虽然声明为 `AttrKey`，当前单元格实际使用中文名称；实现层应按当前导表结果读取，不在文档中臆造另一套键。
