# P03 战斗公式与战斗规则

> 版本：v2.0｜2026-08-05｜现行战斗计算定义
> 定位：定义 V0 最小战斗闭环、后续双伤害通道、境界压制、结算顺序与验收值。具体系数以配置表为准。

---

## 一、伤害通道

战斗只保留两条伤害通道：

| 通道 | 攻方属性 | 守方属性 | 用途 |
|---|---|---|---|
| 物理 | `atk` | `def` | 普攻、肉身攻击、明确标为物理的神通 |
| 术法 | `matk` | `resist` | 明确标为术法的神通与法宝效果 |

“法力”不是伤害通道。法力字段 `mp` 是施展神通消耗的蓝条资源。

攻击、防御均为单值。现行公式不读取攻击上下限、法术攻击上下限、物防上下限或法防上下限。

## 二、V0 最小公式

V0 没有神通、暴击、闪避、抗性、境界压制和百分比修饰，仅验证单位、属性、攻击、受伤、死亡与复活链路。

```text
raw_damage = attacker.atk - defender.def
final_damage = max(raw_damage, 1)
defender.hp = max(defender.hp - final_damage, 0)
```

规则：

- 每次有效普攻至少造成1点伤害。
- 死亡单位不再接受攻击、移动或交互指令。
- 单次攻击只结算一次；动画事件重复回调不得重复扣血。
- V0 不从击杀行为直接发放修为。

## 三、V1+ 结算顺序

后续版本严格按以下顺序结算：

1. 校验攻方、目标、距离、存活状态、冷却和法力。
2. 支付本次神通法力消耗；支付失败则不生成攻击事件。
3. 执行命中判定。
4. 按伤害通道读取攻防单值。
5. 计算神通倍率与固定伤害。
6. 计算通用增伤、减伤和护盾。
7. 计算境界压制或破压制。
8. 计算暴击。
9. 钳制并取整，扣除生命。
10. 生成唯一战斗日志、飘字和死亡事件。

百分比统一按万分比整数解释：

```text
pct_value = stored_value / 10000
```

不得让同一修饰项在属性系统和伤害公式中重复计算。

## 四、V1+ 通用公式骨架

物理基础伤害：

```text
base_damage = max(attacker.atk - defender.def, 1)
```

术法基础伤害：

```text
base_damage = max(attacker.matk - defender.resist, 1)
```

神通倍率与固定值：

```text
ability_damage = base_damage × ability_coefficient + ability_fixed
```

通用增减伤：

```text
modified_damage = ability_damage × max(0, 1 + damage_bonus - damage_reduction)
```

境界修正：

```text
realm_delta = attacker.realm_id - defender.realm_id
realm_modifier = clamp(1 + realm_delta × configured_step + anti_suppression, configured_min, configured_max)
suppressed_damage = modified_damage × realm_modifier
```

暴击与最终值：

```text
critical_damage = suppressed_damage × critical_multiplier   // 仅暴击时
final_damage = max(round(critical_damage), 1)
```

边界：

- `configured_step/min/max` 必须来自系统参数，不在代码写死。
- PvE 与 PvP 使用不同的境界修正参数；PvP 系数默认更弱。
- 破压制只能修正境界系数，不得直接抹除全部境界差。
- 减伤可实际降低基础伤害，但最终有效命中仍至少造成1点伤害；免疫是独立判定。
- 护盾在生命值之前吸收伤害。

## 五、命中与暴击

V0 默认命中且不暴击。启用后：

```text
hit_chance = clamp(base_hit + attacker.hit - defender.dodge, hit_min, hit_max)
crit_chance = clamp(attacker.crit - defender.crit_resist, 0, crit_max)
```

- 命中、闪避、暴击和免暴均使用万分比。
- 必中、不可暴击、免疫等是显式标签，不通过极端百分比暗示。
- 命中失败不造成伤害；是否返还法力由神通自身配置明确。

## 六、攻击事件与幂等

每次攻击生成唯一 `combat_event_id`。服务端或主机只接受该 ID 一次：

- 动画事件、弹道到达和范围命中都必须携带同一事件 ID。
- 重复到达只记录重复事件，不重复结算。
- 多段神通使用 `combat_event_id + hit_index` 标识每一段。
- 持续伤害使用 `combat_event_id + tick_index` 标识每一跳。

## 七、死亡与复活

```text
hp <= 0
→ 进入死亡状态
→ 清理当前攻击与受控状态
→ 等待配置时长
→ 在当前场景指定安全复活点复活
```

复活恢复比例、保护时间和是否保留 Buff 由系统参数配置。没有指定安全复活点时，场景不得通过加载校验。

## 八、验收用例

### V0

| 攻击 | 防御 | 期望伤害 |
|---:|---:|---:|
| 10 | 5 | 5 |
| 5 | 5 | 1 |
| 3 | 10 | 1 |

### 百分比与境界

| 场景 | 输入 | 期望 |
|---|---|---|
| 无修饰 | 基础伤害100 | 100 |
| 增伤20% | 基础伤害100，增伤2000 | 120 |
| 增伤20%、减伤30% | 基础伤害100 | 90 |
| 高一大境界 | 基础伤害100，境界步长10% | 110 |
| 低一大境界 | 基础伤害100，境界步长10% | 90 |
| 重复事件 | 同一事件 ID 到达两次 | 只扣一次生命 |

正式测试应从配置读取系数并计算期望值，不把表中示例系数写入代码。

## 九、废弃口径

- 天运取攻击上限、天佑取防御上限。
- 物理/法术上下限随机取值。
- “法术威力”作为所有伤害的无基准乘数。
- 角色死亡后在未配置的位置原地或随机复活。
- 把技能、法术和法力混作同一概念。

> 修订：v2.0 改为单值攻防、物理/术法双通道、法力资源、统一境界压制、幂等事件与可执行验收值。
