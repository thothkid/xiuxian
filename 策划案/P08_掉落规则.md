# P08 掉落规则

> 版本：v2.0｜2026-08-05｜现行掉落算法
> 定位：定义32槽权重池、掉落归属、拾取与背包事务。具体方案和数值以配置表为准。

## 一、抽取模型

- 每个掉落方案最多32个有效槽。
- 当前模型是权重池，不是每槽独立概率。
- 先根据方案确定抽取次数，再在有效槽内按权重抽取。
- 是否允许重复抽中由方案字段明确；未配置时默认可重复。
- 保底槽先结算，剩余次数再进入权重池。

每个槽至少包含：

```text
target_id, target_type, weight, count_min, count_max, guaranteed
```

权重只决定同池相对概率，不解释为万分比命中率。

## 二、抽取步骤

1. 校验方案、抽取次数和全部目标 ID。
2. 结算保底槽并占用相应抽取次数。
3. 对剩余次数按有效权重抽取。
4. 为每个结果生成数量。
5. 合并允许堆叠的同类结果。
6. 生成地面掉落或钱包收入事件。
7. 记录唯一掉落事件 ID，重复回调不重复发放。

最少和最多掉落数只约束本次抽取次数，不在抽取完成后再次截断结果。

## 三、来源与品质

- 怪物境界、品质、来源和首领职能可以选择不同掉落方案。
- 怪物品质提高时通过方案或权重提高掉落品质，不在代码中临时改物品品质。
- 原生、魔化、造物只作为方案条件，不自动绑定固定掉落。
- 击杀与掉落不直接增加修为；修炼资源先进入对应资源系统。

## 四、归属

- 掉落事件记录所有者、保护开始时间和保护结束时间。
- 保护期内只有所有者或其允许的队伍成员可拾取。
- 保护期结束后转为公开拾取。
- 灵石进入钱包，不生成背包堆叠。

## 五、V0 与后续版本

- V0 普通物品必须点击拾取。
- V0 灵石例外自动进入钱包，不占背包格。
- V1 才允许普通物品按范围自动拾取。
- 自动拾取与手动拾取调用同一服务端事务，不各写一套发放逻辑。

## 六、背包原子事务

拾取普通物品前先计算：

1. 现有未满堆叠可容纳量。
2. 新增格子所需数量。
3. 当前空格数量。

只有整笔数量全部可容纳时才提交。空间不足则整笔保留在地面，不允许先塞一部分再留下不确定余量。

事务提交必须同时完成地面物删除、背包变更和日志记录；任一步失败则全部回滚。

## 七、品质播报

- 播报门槛由统一品质规则决定。
- 单槽播报覆盖只能作为显式例外。
- 同一掉落事件中相同物品合并播报。

## 八、校验

- 有效槽权重总和必须大于0。
- 数量范围满足 `0 < count_min <= count_max`。
- 目标 ID 和类型必须存在且匹配。
- 抽取次数不得超过配置上限。
- 重复掉落事件 ID 不得重复发放。

> 修订：v2.0 统一为32槽权重池，补齐保底、归属、原子拾取、灵石钱包和幂等边界。
