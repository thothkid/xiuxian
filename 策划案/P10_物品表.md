# P10 物品表

> 版本：v3.1｜2026-08-06
> 定位：定义 W物品表的表结构、字段语义、导表方式、运行时接入和配置规则。
> 边界：本文不收录有效物品清单，不复制任何现行配置值。具体物品、枚举成员、数值和资源编号始终以配置表为准。

## 一、工作表结构

`item_config` 由四行表头和若干数据行组成：

| 表头标记 | 作用 | 代码处理 |
|---|---|---|
| `##var` | 声明导出字段名 | 建立字段索引；空单元格不是独立字段 |
| `##type` | 声明字段类型 | 按类型解析并校验 |
| `##group` | 声明客户端等导出分组 | 由导表器按目标分组筛选，不作为物品数据 |
| `##` | 中文说明行 | 只供配置定位，不导出 |

数据行从中文说明行之后开始。首列是控制列，不属于物品对象；导表器必须先判断控制标记，再解析其余字段。未在 `##var` 中声明名称的列属于配置辅助列，不应直接生成运行时字段。

## 二、正式导出字段

| 字段 | 类型 | 用途 | 配置要求 |
|---|---|---|---|
| `id` | `int` | 物品唯一主键 | 必填、全表唯一；已有物品不得随意改 ID |
| `name` | `string` | 物品显示名称 | 必填；不得代替 ID 参与代码定位 |
| `quality` | `ItemQuality` | 物品品质 | 只能填写枚举中存在的值 |
| `dur_t` | `int` | 物品存在时间 | 按运行时约定的单位填写非负整数 |
| `main_class` | `string` | 运行结构大类 | 用于代码一级分类，不等于显示分类 |
| `sub_class` | `string` | 运行结构子类 | 必须属于对应大类允许的子类 |
| `drop_level` | `int` | 物品档次 | 与使用级别下限是两个独立字段 |
| `display_type` | `ItemDisplayType` | 界面显示分类 | 只控制显示归类，不承担运行结构判断 |
| `attrLimit` | `int` | 属性限制 | 无值时保留空值，不擅自补零 |
| `keep_dur_t` | `int` | 有效时间 | 无时效要求时按表的空值规则处理 |
| `is_drop` | `bool` | 是否可丢弃 | 只表示玩家能否丢弃，不表示怪物是否掉落 |
| `is_auto_use` | `bool` | 是否自动使用 | 空值、TRUE、FALSE 必须区分 |
| `required_level` | `int` | 使用级别下限 | 只控制使用门槛，不替代物品档次 |
| `cultivation_tag` | `string` | 修炼路线标签 | 无限制时使用配置表规定的空值或无标签值 |
| `pile_max` | `int` | 单格堆叠上限 | 必须大于等于1 |
| `function_type` | `string` | 功能处理器标识 | 由代码按该值路由到对应处理器 |
| `function_id` | `int` | 功能目标编号 | 含义由 `function_type` 决定；不需要时留空 |
| `function_value` | `int` | 功能数值 | 含义由 `function_type` 决定；不需要时留空 |
| `desc` | `string` | 物品说明 | 玩家可见文本；允许保留项目使用的颜色控制码 |
| `spec_desc` | `string` | 获得说明 | 说明投放或获得方式，不参与功能执行 |
| `icon_id` | `string` | 背包图标资源 ID | 由资源加载层解析 |
| `mdx_id` | `string` | 地表模型资源 ID | 由地面物品显示层解析 |
| `light_eff_id` | `string` | 掉落光柱资源 ID | 无光柱时按空值处理 |
| `border1` | `string` | 静态边框资源 ID | 直接读取配置，不由代码根据品质猜测 |
| `border2` | `string` | 动态边框资源 ID | 直接读取配置，不由代码根据品质猜测 |
| `tags` | `array,string` | 检索与筛选标签数组 | 读取完整数组，不得只取第一个标签单元格 |

## 三、配置辅助列

| 辅助列 | 作用 | 导出规则 |
|---|---|---|
| ID 编号 | 同一编号大类内的本地序号 | 参与新物品 ID 公式，不生成同名运行时字段 |
| 大类 | 在编号表中查找编号大类 | 只用于生成 ID；不要与 `main_class` 混用 |
| 标签2—标签4 | `tags` 数组的后续元素 | 合并进 `tags`，不生成四个独立标签字段 |

辅助列可以参与导表计算，但运行时物品对象只保留正式导出字段。

## 四、物品 ID

新物品 ID 由编号表和本地序号生成：

`id = 30000000 + 编号大类值 × 10000 + 本类序号`

配置步骤：

1. 在辅助列“大类”中选择编号表已有的大类。
2. 在“ID 编号”中填写该大类内未占用的本地序号。
3. 使用表内公式生成 `id`，不得为新物品手填另一套编号。
4. 导表前校验大类存在、本地序号有效、最终 ID 全表唯一。
5. 已有旧物品可能使用固化 ID；代码读取最终 `id`，不在运行时重新计算，也不批量重排旧 ID。

示意一，仅说明公式，不是有效物品配置：编号大类值为4、本类序号为36时，生成 ID 为 `30040036`。

## 五、分类字段

三个分类字段用途不同：

| 字段 | 面向对象 | 能否参与功能判断 |
|---|---|:---:|
| `main_class` | 运行时一级结构 | 是 |
| `sub_class` | 运行时二级结构 | 是 |
| `display_type` | 界面展示与筛选 | 否 |

代码不得用 `display_type` 代替 `main_class` 或 `sub_class`。调整界面分组时，只改显示分类；调整运行结构时，必须同步检查对应代码处理器。

`quality` 是独立枚举字段。资源边框、光柱和图标已经有独立字段，运行时优先读取显式资源配置，不从品质反推资源 ID。

## 六、功能字段

`function_type`、`function_id`、`function_value` 构成一组功能参数：

- `function_type` 决定调用哪个功能处理器。
- `function_id` 指向该处理器需要的目标配置。
- `function_value` 提供该处理器需要的数值。
- 某个处理器不需要 ID 或数值时，对应字段留空；不得用0代替空值，除非该处理器明确把0定义为有效参数。
- 导表校验器按 `function_type` 检查其必填参数；运行时不根据物品名称猜功能。

示意二，仅说明字段配合，不是有效物品配置：某恢复类处理器可读取 `function_type=恢复处理器`、`function_id=空`、`function_value=100`，由处理器解释100的具体含义。

## 七、时间、丢弃与堆叠

- `dur_t` 与 `keep_dur_t` 是两个字段，代码分别存储，不合并、不互相补值。
- 时间单位由物品运行时统一规定，配置文档不自行换算。
- `is_drop` 只控制能否丢弃。怪物投放、活动投放和系统赠送不由该字段决定。
- `is_auto_use` 必须保留三态：未配置、TRUE、FALSE。
- `pile_max` 小于1时导表失败；不可堆叠物品也通过该字段表达，不另建同义字段。

## 八、文本、资源与标签

- `desc` 与 `spec_desc` 都是文本：前者说明物品，后者说明获得方式。
- 图标、地表模型、光柱、静态边框、动态边框分别读取各自资源字段；空资源不自动套用相邻物品配置。
- 资源校验在导表阶段检查格式，在资源构建阶段检查资源是否真实存在。
- `tags` 是字符串数组。导表器按连续标签单元格收集非空值，保持顺序并去除纯空白项。
- 标签用于检索、筛选和规则匹配，不替代主键、分类或功能处理器。

## 九、导表与运行时实现

导表流程：

1. 读取 `##var`、`##type`、`##group`，建立字段和类型定义。
2. 跳过控制行、中文说明行和明确停用的数据行。
3. 先解析辅助列和公式，取得最终 `id` 与完整 `tags`。
4. 按 `##type` 转换正式字段；空值保持为空，不统一补0或FALSE。
5. 执行主键、枚举、范围、功能参数和资源格式校验。
6. 生成以 `id` 为键的物品配置映射；重复 ID 直接终止导表。
7. 输出目标分组需要的字段；辅助列不进入运行时对象。

运行时建议保持一个只读物品定义对象：

- 背包实例只保存物品 ID、数量和实例态数据，不复制整份静态配置。
- 显示层通过物品 ID 读取名称、说明、显示分类和资源字段。
- 使用物品时通过 `function_type` 路由处理器，并把 `function_id`、`function_value` 作为参数传入。
- 丢弃、堆叠、级别限制分别读取 `is_drop`、`pile_max`、`required_level`，不从名称或标签推断。
- 配置热更新后替换静态映射；物品文档不需要随每条配置增删而改动。

## 十、导表校验

- `id` 必填、为整数、全表唯一。
- `name` 必填；名称重复是否允许由项目另定，但代码定位始终使用 `id`。
- 枚举字段必须属于对应枚举；结构大类与子类组合必须合法。
- `pile_max >= 1`；时间和级别字段不得为非法负数。
- `function_type` 存在时，按处理器规则检查 `function_id` 与 `function_value`。
- TRUE、FALSE、空值分别处理，禁止把空布尔统一转成 FALSE。
- `tags` 输出为数组；辅助标签列不得泄漏成独立运行时字段。
- 资源字段格式错误时终止导表；资源缺失由资源构建校验报告。
- 文档只在表结构、字段语义、编号算法或代码接入方式变化时更新；普通物品增删改不更新本文。
