# P11 背包规则

> 版本：v2.0｜2026-08-05｜现行背包行为定义
> 定位：定义容量、分页、堆叠、拾取、使用、穿戴与事务边界。

## 一、容量

- V0 初始背包容量固定为12格。
- UI 每页显示6格，共2页；分页不改变真实容量。
- 后续扩容增加真实格数，UI按每页6格继续分页。
- 灵石显示在钱包区域，不占背包格。

## 二、格子模型

每个格子保存：

```text
slot_index, item_id, quantity, instance_id, bind_state
```

- 可堆叠物品使用 `item_id + bind_state` 判断是否同堆。
- 不可堆叠物品必须有唯一 `instance_id`。
- 装备、器具和法宝默认不可堆叠。

## 三、放入顺序

1. 优先填充相同物品且未满的堆叠。
2. 再按格子顺序占用空格。
3. 一笔收入必须全部可容纳才提交。
4. 空间不足时整笔失败，不允许部分放入。

灵石不执行以上流程，直接进入钱包事务。

## 四、拾取事务

拾取必须原子提交以下变化：

- 校验地面物仍存在且拾取者有权限。
- 预计算全部堆叠和空格。
- 写入背包或钱包。
- 删除地面物。
- 写入唯一事件日志。

任一步失败则全部回滚。同一拾取事件 ID 重复到达时只返回已有结果，不重复发放。

## 五、手动与自动拾取

- V0 普通物品点击拾取。
- V0 灵石自动进入钱包。
- V1 普通物品自动拾取启用后，仍调用同一拾取事务。

## 六、物品使用

- 使用前校验物品、数量、冷却、境界要求和当前状态。
- 效果成功后才扣除数量；效果失败不消耗。
- 数量归零时清空格子。
- 丹药连续服用受耐药值和丹毒约束，不设每日次数上限。

## 七、穿戴

- V0 可只开放武器与法袍两个技术验证位。
- 完整装备六位为冠、法袍、武器、佩、印绶、鞋履。
- 穿戴只改变装备集合，属性系统随后从全部来源重算。
- 替换失败时原装备和背包必须保持不变。
- 法宝不进入固定出战槽，按神识预算和单件御使负荷结算。

## 八、整理与拆分

- 整理和拆分在 V3 后启用，不属于 V0。
- 整理必须保持物品实例、绑定状态和总数量不变。
- 拆分数量满足 `0 < split_quantity < original_quantity`，且必须有空格。

## 九、校验

- 真实格数、分页格数和 UI 显示必须一致。
- 物品总数量在失败、重连和重复事件后不变。
- 灵石不得占格。
- 任何穿脱、替换和使用异常都不得造成物品复制或丢失。

> 修订：v2.0 统一12格容量与6格分页，补齐原子拾取、灵石钱包和六装备位边界。
