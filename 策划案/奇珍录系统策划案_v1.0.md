## 一、系统定位

奇珍录是一套图鉴系统，三层职能各自独立。

| 层 | 记什么 | 有无奖励 | 数据性质 |
|---|---|:---:|---|
| **收录** | 曾经拥有过哪些奇珍 | 无 | 只增不减的历史记录 |
| **携带** | 当前生效的是哪几件 | 有（奇效） | 当前状态，可增可减 |
| **奇缘图谱** | 凑齐了哪几组成套的奇珍 | 有（羁绊奖励） | 由收录状态推导 |

口径：

- 奇珍是评价与收录身份。一件东西可以同时是装备、器具、法宝、材料、灵植、功法载体和奇珍，各种身份互不排斥。
- 活着的妖兽与精怪归灵兽系统；死后材料归灵材，有灵法宝以器物之身归炼器。
- **奇珍录是纯图鉴。** 收录记录「曾经拥有过」；携带不再检查背包或仓库中的实体，但仍须同时满足 `can_carry`、条目启用、条目携带境界和对应携带位已解锁等条件（§5.2）。每条奇珍的效果由配置表写死，恒定。

## 二、奇珍八类

顺序固定。

| # | 类 | 所属学问 | 收录范围 | 携带位 |
|---|---|---|---|---|
| 1 | 灵植 | 地道·灵植 | 奇花异草与特殊灵植 | 灵植位 |
| 2 | 灵材 | 地道·灵材 | 灵矿、灵木、妖丹、精血、兽骨、鳞甲等 | 灵材位 |
| 3 | 炼丹 | 地道·炼丹 | 奇丹、古丹及承载特殊丹方的古物 | 炼丹位 |
| 4 | 炼器 | 地道·炼器 | 特殊装备、器具、法宝、古修器物与有灵法宝 | 炼器位 |
| 5 | 符箓 | 地道·符箓 | 特殊灵符及其载体 | 符箓位 |
| 6 | 阵法 | 地道·阵法 | 阵图、阵心、阵印与特殊阵势拓印 | 阵法位 |
| 7 | 功法 | 天道 | 功法玉简、古碑、残页及其他功法载体 | 功法位 |
| 8 | 道痕 | 天道为主 | 被收取、封存或拓印到载体上的特殊规则痕迹 | 道痕位 |

**实体载体**：奇珍以可随身的实体载体存在。功法依托玉简、碑片、残页；道痕以收取、封存或拓印的形式存在；阵势以阵图、阵心、阵印等小型载体存在。

## 三、三条独立配置

收录、携带、图谱组合三项由配置各自决定，**三者之间无推导关系**。

| 项 | 由什么决定 |
|---|---|
| 收录 | 登记在「收录」页的条目都参与收录与进度统计 |
| 携带 | `can_carry` 字段独立配置 |
| 图谱组合 | `codex_id` 字段独立配置 |

任意组合都合法：

| 组合 | can_carry | codex_id |
|---|:---:|:---:|
| 只收录 | ✗ | 空 |
| 收录 ＋ 可携带 | ✓ | 空 |
| 收录 ＋ 图谱成员 | ✗ | 有 |
| 收录 ＋ 可携带 ＋ 图谱成员 | ✓ | 有 |

## 四、收录规则

### 4.1 触发与判定

- **首次获得即入录。**
- 「获得」＝该奇珍对应的物品或装备实例进入玩家所有权。掉落、任务发放、宝箱、商店购买、合成产出、邮件领取等一切路径均计。程序取统一的所有权变更入口接入。
- **判定方式**：实例进入所有权时，用该实例的配置 ID 在「收录」页的 `unlock_id` 索引中查表，命中则点亮对应 `qz_id`。
- 收录状态是布尔量：`0 = 未收录`、`1 = 已收录`。
- 收录**永久保留**。实体后续被丢弃、出售、消耗、分解、夺取，收录状态保持。
- 同一条目重复获得时，收录状态、进度与奖励保持不变。奇珍录只记录有没有。
- 首次点亮 `qz_id` 后，若该条目的 `codex_id` 非空，立即重算该图谱的已收录成员数。若本次计数跨过一档或多档已配置的 `need_count`，对应羁绊档位立即生效，并触发属性系统全量重算。一个 `qz_id` 最多归属一个图谱，运行时只检查该 `codex_id`，不遍历全部图谱。

### 4.2 收录无奖励

收录本身不直接产出属性、道具、货币、称号或修为。若本次收录使奇缘图谱达到新的羁绊档位，由图谱规则产生的属性变化按 §6.3、§5.5 立即结算。

### 4.3 进度统计

| 项 | 分子 | 分母 |
|---|---|---|
| 本类收录 | 当前类已收录且 `enable = TRUE` 的条目数 | 当前类 `enable = TRUE` 的条目数 |
| 全录进度 | 八类已收录且 `enable = TRUE` 的条目合计 | 八类 `enable = TRUE` 的条目合计 |
| 图谱收集 | `enable = TRUE` 且已全部集齐的图谱数 | `enable = TRUE` 的图谱数 |
| 奇缘进度 | `enable = TRUE` 图谱内已收录成员合计 | `enable = TRUE` 图谱的成员合计 |

分母动态取。本节四项总览进度只作展示，不另外配置或发放进度奖励；其中图谱成员计数仍是 §6.3 羁绊档位的结算输入。

### 4.4 存档

按角色独立保存，数据由服务器权威维护。

| 数据 | 结构 | 说明 |
|---|---|---|
| 收录集合 | `collected: Set<qz_id>` | 只增不减 |
| 携带位 | `carry_slots: Map<QizhenCategory, qz_id>` | 最多 8 条 |
| 图谱进度 | 由 `collected` 实时推导 | 不存档 |
| 羁绊生效档 | 由图谱进度实时推导 | 不存档 |

**收录集合与携带位由各自独立的接口读写**，在存储层与接口层都不耦合，为后续账号维度共享留出改造空间。

### 4.5 启用状态

`enable = FALSE` 的奇珍：

- 前台不显示；
- 不参与任何进度分子分母；
- 不可携带；已在携带位上的条目自动卸下并重算属性。

`enable = FALSE` 的图谱：

- 前台不显示；
- 不参与任何进度分子分母；
- 该图谱的全部羁绊档位停止生效，并由属性系统重算。

已保存的收录记录继续保留。重新启用后，奇珍收录状态、图谱进度与羁绊档位均按 `collected` 恢复。

图谱成员不能在仍被启用图谱引用时单独停用。若要停用某个成员，先将该 `qz_id` 从图谱 `members` 移除并清空「收录」页对应行的 `codex_id`，再把成员 `enable` 改为 `FALSE`；若整组内容同时下线，则直接停用整个图谱。

## 五、携带规则

### 5.1 位数

- **八类各一个携带位，共 8 位。** 每个位对应一类，同一类的奇珍在该位上一次生效一件。
- 八个位在角色面板展示。

**两处入口都能完成携带、卸下、替换**，读取同一份 `carry_slots`，操作后同步刷新：

| 界面 | 入口 |
|---|---|
| 奇珍录 · 收录页 | 右栏按钮。未携带时执行携带，已携带时执行卸下，同类位已有其他奇珍时执行替换确认 |
| 角色面板 · 奇珍区 | 八个携带位。点任意可用位打开该类携带选择，选择新条目时执行携带或替换，选择「卸下」时取下当前条目 |

### 5.2 携带条件

五条同时满足：

1. 该条目 `can_carry = TRUE`；
2. 该条目已收录；
3. 该条目 `enable = TRUE`；
4. 角色境界达到 `required_realm`（为 0 时无门槛）。
5. 该条目所属类的携带位已按 `unlock_realm` 解锁（§5.7）。

收录记录代表玩家不再需要保留对应实体；实际携带仍须同时满足上列五条。携带与背包、仓库里的实体状况各自独立。

角色境界下降时，服务器立即重新校验八个携带位。当前境界低于条目 `required_realm`，或低于所在携带位 `unlock_realm` 时，自动卸下该位奇珍，并触发属性系统全量重算。

### 5.3 效果配置结构

每条可携带的奇珍配 **4 组效果**。填几组生效几组。

一组 5 项：

| # | 项 | 类型 | 说明 |
|:--:|---|---|---|
| 1 | 属性名 | AttrKey | 与「引用ID」二选一 |
| 2 | 引用ID | int | 技能 / BUFF / 词条 的 8 位 ID，与「属性名」二选一 |
| 3 | 整数/万分比 | InfluenceOp | 属性修正方式 |
| 4 | 属性值 | int | 修正数值 |
| 5 | 展示文字 | string | 玩家可见的一行效果描述 |

规则：

- 一组内**属性名与引用ID二选一**。
- **属性组**填：属性名、整数/万分比、属性值、展示文字，四项全填。
- **引用组**填：引用ID、展示文字，两项全填；整数/万分比与属性值该组不参与结算。
- 引用ID 的结构见 §5.4。
- 属性名与引用ID 都为空的组不生效、不展示。
- 4 组之间无顺序要求，可以第 1 组配引用ID、第 2 组配属性。

### 5.4 引用ID 结构

引用ID 是 8 位数：

| 位 | 含义 |
|---|---|
| 第 1 位 | 指向哪张表 |
| 第 2—6 位 | 条目编号 |
| 第 7—8 位 | 等级 |

首位分配：

| 首位 | 指向 | 表 |
|:--:|---|---|
| 4 | 技能 | `J技能BUFF表 / skill_config` |
| 6 | BUFF | `J技能BUFF表 / buff_config` |
| 8 | 词条 | `Z装备 / ConfigCitiao` |

**前 6 位相同即为同一条目的不同等级**，结算时只取末 2 位最大的那条（§5.5）。

### 5.5 结算公式

```text
最终值 =（基础值 ＋ Σ固定值加成）×（1 ＋ Σ万分比加成）
```

- 全部万分比修正之间加算聚合，再整体作用一次。
- 放入与取下改变携带位集合，由属性系统从全部来源重算全部派生属性。
- 携带位的属性来源与装备六位、功法、丹药、图谱羁绊并列，进同一次重算。
- **同一技能、BUFF 或词条的多个等级只生效最高等级**，低等级被覆盖，效果不叠加。跨来源生效——携带的奇珍与图谱羁绊各挂了同一条目的两个等级时，同样只留最高的那条。
- 卸下奇珍或失去图谱档位时按来源重算；其他仍在生效的来源保持原效果。

### 5.6 与装备位的关系

奇珍携带位与装备六位（冠、法袍、武器、佩、印绶、鞋履）是两套并行的位，各自独立结算。装备位枚举保持六位（P12 §七）。

### 5.7 携带位解锁

八个位各配一个解锁境界 `unlock_realm`（realm_id 0—8），登记在「携带位」页。

- 角色境界达到 `unlock_realm` 后，该位可用。
- `unlock_realm` 为 0 时该位开局可用。
- 奇珍录与角色面板发起携带时都由服务器校验携带位是否已解锁；未解锁时不得写入 `carry_slots`。
- 携带位是否解锁由当前境界实时判定，不存永久解锁状态。境界回落到 `unlock_realm` 以下时，该位重新锁定；位上已有奇珍则按 §5.2 自动卸下并重算属性。

## 六、奇缘图谱

### 6.1 组队方式

**图谱跨八类，按来源或主题组队。** 一个图谱可以同时收灵植、灵材、炼器等不同类的奇珍。

成员按任意顺序集齐即达成。

UI 稿给出三个图谱的名称与件数：古战残响 5 件、雾岭旧藏 7 件、丹炉遗韵 5 件。

### 6.2 集齐判据

**图谱成员按「已收录」计数。**

- 成员的实体后续被卖掉、用掉、丢掉，图谱计数保持，羁绊奖励保持。
- 羁绊奖励达成后**永久生效**。
- 图谱进度完全由 `collected` 集合推导。

### 6.3 羁绊奖励配置结构

每个图谱配 **4 组奖励**。填几组生效几组。

一组 6 项：

| # | 项 | 类型 | 说明 |
|:--:|---|---|---|
| 1 | 需求件数 | int | 已收录成员达到此数时该组生效 |
| 2 | 属性名 | AttrKey | 与「引用ID」二选一 |
| 3 | 引用ID | int | 技能 / BUFF / 词条 的 8 位 ID，与「属性名」二选一 |
| 4 | 整数/万分比 | InfluenceOp | 属性修正方式 |
| 5 | 属性值 | int | 修正数值 |
| 6 | 展示文字 | string | 玩家可见的一行奖励描述，如「2 件：气血 +80」 |

规则：

- 每组必填需求件数。需求件数为空的组不生效、不展示。
- 一组内**属性名与引用ID二选一**，两类组的必填项同 §5.3。
- 已填写的组，需求件数严格递增，且不超过成员总数。
- 已生效的组在达到更高档后继续保留，效果累加。
- 多个图谱同时达标，各自的奖励全部生效并累加。
- 属性修正与等级覆盖走 §5.4、§5.5 的同一套规则。

### 6.4 与装备套装的关系

奇缘图谱与 `ConfigTaozhuang` 装备套装是两套独立系统，各自结算，可同时达成，奖励累加。

## 七、收录钥匙

### 7.1 `unlock_id`

「收录」页的 `unlock_id` 是点亮该条奇珍的钥匙，指向玩家实际能拿到的那个实例的配置 ID。

| 首位 | 指向 | 表 |
|:--:|---|---|
| 1 | 物品 | `W物品表 / item_config` |
| 5 | 装备 | `Z装备 / equip_config` |

- 玩家获得实例时，用该实例的配置 ID 查 `unlock_id` 索引，命中则点亮该 `qz_id`（§4.1）。
- `unlock_id` 只服务于收录判定，不参与携带校验；实际携带条件见 §5.2，携带位解锁见 §5.7。
- 首位路由与效果组「引用ID」（§5.4）是同一套写法。

> 全项目 ID 首位分配规则见《配置表ID首位分配总览》，本章不重复。

## 八、配置表结构：`Q奇珍录.xlsx`

沿用 Luban 四行表头规范（`##var` / `##type` / `##group` / `##`），首列为控制列。页签：**收录 / 奇缘图谱 / 可携带 / 携带位 / 编号表 / 说明**。

**列序要求**：辅助列与数组续列的 `##var` 都为空，导表器以「下一个已声明字段」断边界。因此数组字段排在表尾；辅助列夹在两个已声明字段之间，或在没有数组字段的页签排在表尾。

### 8.1 页签「收录」

| 字段 | 类型 | 中文 | 说明 |
|---|---|---|---|
| `qz_id` | int | 奇珍ID | 主键，全表唯一。第1位固定 7、第2位类编号 1—8、第3—8位本类序号，即 `70000000 + 类编号×1000000 + 本类序号` |
| `name` | string | 名称 | 与 item / equip 两边同名（导表校验） |
| `category` | QizhenCategory | 所属类 | 八类枚举，决定归属页签与携带位 |
| `quality` | ItemQuality | 品质 | 六档：凡品 1 / 灵品 2 / 玄品 3 / 仙品 4 / 神品 5 / 道品 6 |
| `realm_id` | int | 境界阶 | 0—8，对应 P17 §三 |
| `art_id` | string | 主图资源 | 方形主图一张。详情区用大尺寸展示，收录格缩到 42×42 |
| `effect_desc` | string | 奇效说明 | 玩家可见文本 |
| `source_desc` | string | 来源说明 | 如「古战场·残垣」。人间传说口径 |
| `can_carry` | bool | 是否可携带 | 独立配置（§三） |
| `codex_id` | int | 所属奇缘图谱 | 独立配置，可空；非空时存在于「奇缘图谱」页 |
| `unlock_id` | int | 收录钥匙ID | 点亮该条奇珍的实例配置 ID。首位 1 ＝ 物品表，5 ＝ 装备表（§7.1） |
| `sort_order` | int | 类内排序 | |
| `enable` | bool | 是否启用 | 进度分母只统计 TRUE 的条目 |
| ——辅助列—— | | 类编号 / 本类序号 / 配置备注 | `##var` 留空，不导出；参与 `qz_id` 公式计算 |

**导表校验：**

- `qz_id` 必填、唯一。
- `name`、`category`、`quality`、`realm_id`、`effect_desc`、`source_desc`、`can_carry`、`enable` 必填。
- `art_id` 必填。
- `realm_id` 取 0—8。
- `unlock_id` 必填，首位取 1 或 5，且在对应表中存在。
- 每个 `unlock_id` 对应一条奇珍。
- 与 `unlock_id` 指向的那一行，`name`、`quality` 两项一致。不一致时终止导表并报出两个 ID。
- `codex_id` 非空时存在于「奇缘图谱」页，且该 `qz_id` 出现在该图谱的 `members` 中。
- `can_carry = TRUE` 的条目在「可携带」页有对应行，反之亦然。

> 一致性校验只校 `name` / `quality`。奇珍主图 `art_id` 是方形主图，与物品表、装备表的背包图标是两套资源，各自配置。境界字段三表异名异义（物品表 `required_level`、装备表 `show_level(EquipRank)`、奇珍表 `realm_id`），也各自独立配置。

新建 bean `QizhenTier`（一组羁绊奖励，6 字段，对应 §6.3）：

| 字段 | 类型 | 中文 |
|---|---|---|
| `need_count` | int | 需求件数 |

**导表校验：**

- `codex_id` 必填、唯一；`name`、`icon_id`、`codex_quality`、`member_count`、`flavor_desc`、`enable` 必填。
- `members` 内 `qz_id` 存在且 `enable = TRUE`。
- 停用仍在 `members` 内的单个成员前，必须先从 `members` 移除并清空该成员的 `codex_id`；也可直接停用整个图谱。
- `members` 长度 == `member_count`。
- `member_count` 取 1—7；同一图谱的 `members` 内不得重复。
- `members` 中每个 `qz_id` 在「收录」页的 `codex_id` 指向当前图谱。
- 每个 `qz_id` 最多归属一个图谱。
- 每组内 `attr_key` 与 `ref_id` 二选一，同时填写时终止导表并报出 `codex_id` 与组序号。
- 属性组四项齐全（属性名 / 整数万分比 / 属性值 / 展示文字）；引用组两项齐全（引用ID / 展示文字）。
- 已填写的组中 `need_count` 严格递增，且不超过 `member_count`。

### 8.3 页签「可携带」

| 字段 | 类型 | 中文 | 说明 |

新建 bean `QizhenEffect`（一组奇效，5 字段，对应 §5.3）：

| 字段 | 类型 | 中文 |
|---|---|---|

**「可携带」页只配携带位、境界门槛与 4 组奇效。** 收录钥匙登记在「收录」页，本页以辅助回显列引用，理由：

1. 全部奇珍（含 `can_carry = FALSE` 的条目）都以 `unlock_id` 判定收录，映射需覆盖全表；
2. 单一登记处保证配置不漂移。

辅助回显列用 VLOOKUP 从「收录」页取值，`##var` 留空不导出，符合《物品表》§三 对辅助列的规定。

**导表校验：**

- `qz_id` 必填、唯一，在「收录」页存在且对应行 `can_carry = TRUE`。
- `carry_part` 等于「收录」页同 `qz_id` 的 `category`。
- `required_realm` 取 0—8。
- 每组内 `attr_key` 与 `ref_id` 二选一，同时填写时终止导表并报出 `qz_id` 与组序号。
- 属性组四项齐全（属性名 / 整数万分比 / 属性值 / 展示文字）；引用组两项齐全（引用ID / 展示文字）。
- `attr_key` 存在于 `S属性配置表` 属性字典。
- `op` 取整数或万分比。
- `ref_id` 的首位取 4 / 6 / 8 之一，且该 8 位 ID 在对应表中存在。

## 十一、验收要点

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 首次获得点亮 | 拿到任一奇珍的 `unlock_id` 对应实例（物品或装备），对应条目转已收录 |
| 2 | 获得途径全覆盖 | 掉落、任务、宝箱、商店购买、合成、邮件领取各走一遍，均点亮 |
| 3 | 收录永久 | 实体丢弃 / 出售 / 消耗后重开面板，收录状态保持 |
| 4 | 收录无直接奖励 | 未跨越图谱羁绊档位时，点亮前后角色属性、背包、货币保持不变；跨档时只结算图谱羁绊 |
| 5 | 重复获得 | 再拿一件，进度分子保持不变 |
| 6 | 进度分母动态 | 配置增删条目后重新导表，分母跟着变 |
| 7 | 三项解耦 | 配一条 `can_carry = FALSE` ＋ `codex_id` 有值的奇珍：收录正常、携带按钮隐藏、图谱计数正常 |
| 8 | 携带脱离实体 | 收录后把实体全部卖光，仍可正常携带并生效 |
| 9 | 效果组按填写数生效 | 只填 2 组时生效 2 组，第 3、4 组留空不产生任何效果 |
| 10 | 属性组结算 | 放入后属性变化符合 §5.5 公式；取下后精确还原，反复穿脱结果一致 |
| 11 | 引用组挂载 | 填引用ID 的组按首位正确路由到技能 / BUFF / 词条，取下后正确移除 |
| 12 | 二选一校验 | 配一组同时填了属性名与引用ID，导表失败并报出组序号 |
| 13 | 属性重算路径 | 断点确认走属性系统全量重算 |
| 14 | 图谱计数 | 收录第 N 件时图谱进度同步 +1，跨类成员均计 |
| 14b | 收录触发羁绊 | 首次点亮使图谱跨过一档或多档 `need_count` 时，对应档位同次生效并触发属性全量重算；无 `codex_id` 时不检查图谱 |
| 15 | 图谱无序 | 乱序集齐同样达成羁绊 |
| 16 | 羁绊阶梯 | 达第二组需求件数时，第一、二组同时生效 |
| 17 | 羁绊永久 | 成员实体全部卖光后重登，羁绊保持生效 |
| 18 | 羁绊与套装并行 | 同时达成图谱羁绊与装备套装，两份加成累加 |
| 19 | 图谱不存档 | 清掉图谱进度存档段后重登，进度由 `collected` 正确重建 |
| 20 | 导表校验 | 配一条 `unlock_id` 为空的奇珍，导表失败并报出 `qz_id` |
| 21 | 导表校验 | 让两条奇珍引用同一个 `unlock_id`，导表失败 |
| 22 | 图谱双向一致 | 改一处 `codex_id` 或 `members` 使两边对不上，导表失败 |
| 23 | 停用行为 | 把已携带条目改 `enable = FALSE` 重新导表，该位自动清空、属性重算、收录记录保持 |
| 24 | 重新启用 | 该条目改回 `enable = TRUE`，收录状态与图谱进度按 `collected` 恢复 |
| 25 | 等级覆盖 | 携带的奇珍与图谱羁绊各挂同一条目的两个等级（前 6 位相同、末 2 位不同），只生效末 2 位最大的那条 |
| 25b | 等级覆盖回落 | 同一条目高等级与低等级来自不同来源；移除高等级来源后，仍存在的低等级来源恢复生效，不得随高等级一起消失 |
| 26 | 存档解耦 | 单独清空 `carry_slots` 后重登，`collected` 不受影响；反之亦然 |
| 27 | 携带位解锁 | 给某位配 `unlock_realm = 3`，角色未到金丹时该位不可用，达到后可用 |
| 28 | 图谱停用 | 把已达成图谱改 `enable = FALSE` 重新导表，图谱不显示、不计进度、羁绊停止生效；重新启用后按 `collected` 恢复 |
| 29 | 携带位未解锁 | 条目自身满足携带境界，但所属携带位尚未达到 `unlock_realm` 时，奇珍录与角色面板均不可携带；解锁后可正常写入 |
| 30 | 境界回落 | 角色境界降到条目 `required_realm` 或携带位 `unlock_realm` 以下时，对应奇珍自动卸下、携带位按当前境界重新锁定，属性全量重算；境界恢复后可再次携带 |
