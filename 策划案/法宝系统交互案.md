# 法宝系统交互案 · v3


面向：策划、美术、前台程序。目标平台：PC，设计分辨率 1344×756。
交付状态：本文件为正式策划案目录中的现行发布源稿，按项目索引同步二区；二区入库副本经知识库修订与发布检查后上传。

## 一、界面基准与职责

法宝界面的风格、材质、器物展示和三栏骨架沿用已定定妆图；页签、翻页、选择、确认与操作流程沿用 v1.4 交互原型。图中尚未覆盖的打造页等已有交互，以原型确定的方案为准，不重新设计。

本案整合已定交互，并明确神识不足失效、自动恢复、死亡暂停、单次手动使用边界及管理操作反馈。原型中的旧神识行为、全局忙碌时误显示其他操作名称等差异，以本文规则为准；演示数字、模拟按钮、固定成功失败节奏和程序缺陷不是正式规则。

系统策划案负责计算和结算，本案负责玩家看见什么、可以操作什么、发生什么反馈。前台可以即时预检，不能自行产生与后台不同的御使、生效、扣费或祭炼结果。

面板数值布局、威能评分与详细属性展示优化暂缓。仅修改新状态所必需的提示，不扩展指标卡、不增加页面。

## 二、整体页面与视觉

### 2.1 页面结构

顶部标题“法宝”，一级页签为“御使／养炼／打造”。

| 区域 | 御使 | 养炼 | 打造 |
|---|---|---|---|
| 左栏 | 已拥有法宝列表 | 已拥有法宝列表 | 有效打造配方的法宝图录 |
| 中栏 | 当前选中法宝详情 | 当前选中法宝详情 | 未拥有目标的 0 层预览，或已拥有目标的当前层详情 |
| 右栏 | 神识、御使状态、生效与表现状态、御使或收回 | 祭炼／器灵／本命；目标层条件、消耗、概率、结果预览与祭炼 | 条件、配方消耗、拥有状态与打造 |
| 左栏底部 | 统一翻页条 | 与御使共用翻页条状态 | 独立翻页状态 |

跨页切换只走顶部页签。御使页主操作为御使或收回，祭炼页为祭炼，打造页为打造；不恢复旧定妆图中重复的跨页“祭炼”按钮。

### 2.2 视觉与美术边界

保留玄青深底、旧铜描金、灰青玉和低对比祥云暗纹，以及原有标题玉牌、页签、器物展示区与主按钮比例。

选中和正常可操作状态沿用青玉色，品质与标题沿用旧金色，不足与异常沿用暗朱红，未开放与禁用沿用灰色。不能只靠颜色表达失效，必须带文字。

新增提示使用现有列表状态行、右栏说明和通知样式，不另开信息面板。没有新增完整定妆页的要求，不制作玩法图鉴或独立手动使用页。

### 2.3 打开、关闭与记忆

- 从主界面的“法宝”功能入口打开；已打开时只激活现有面板，不创建第二份。本案不新增专用快捷键，公共按键入口调用同一面板。
- 本次登录首次打开默认进入御使页，持有列表第 1 页选中排序后的第一件；首次进入打造页同样取第 1 页第一件。没有数据时按空列表处理；数据未就绪时显示“数据同步中”，不误报没有法宝。
- 本次登录期间记忆主页面、两套列表页码与选中项；关闭重开恢复原位置，重新登录回到初始选择。仅缓存界面状态，不新增永久存档字段；未确认的操作不能随界面记忆一起丢弃。
- 有确认或结果弹层时，Esc 只关闭最上层弹层；没有弹层时 Esc 关闭法宝面板。公共面板关闭操作与 Esc 一致，不在三栏中新增关闭按钮。弹层返回、关闭或点击其遮罩只关闭弹层；点击面板外空白不关闭主面板。
- 确认前关闭表示不提交、不扣费；提交后切页或关闭只改变显示，不取消结算。角色死亡不强制关面板，仍可查看。

## 三、列表、选中与翻页

### 3.1 数据源

御使与养炼只显示已拥有法宝，手动法宝也在持有列表中，不因不能御使而消失。

打造显示启用且有效的配方目标，可同时包含未拥有和已拥有法宝。无效配方、停用主表、缺有效 0 层等目标不得作为可打造项出现。

已拥有记录发生配置异常时仍保留可识别条目与异常提示，不让玩家误以为法宝丢失；不展示伪造的正常数值。

### 3.2 分组与排序

分组固定为战斗、生产、辅助。组内按 sort_order 升序，再按法宝 ID 升序。分组数量显示当前数据源中该分类总数，不是本页数量。

完成整个列表的排序后再统一分页，不对每个分类分别分页。神识检测的“需求从高到低”只用于后台分配，不改变列表既有排列。

### 3.3 选中与翻页

御使与养炼共用选中项和页码，打造单独记忆。切换页签回到对应列表的上次位置。

翻页条仍为“上一页／第 X／Y 页／下一页”。正式每页六件法宝，御使、养炼、打造一致；分类标题不占条数，只显示本页包含的分类。保持定妆图六件列表的行高与三栏骨架，使用既有底部翻页条；原型四条仅是演示数量，不作为正式分页值。

每页六件是独立的界面规格，本次不新增分页配置项，也不读取场上显示名额 MaxVisibleIndependent 作为每页条数。

- 首页禁用上一页，末页禁用下一页；只有一页时两个按钮均禁用，仍显示页码。
- 翻页后选中该页第一件，中栏、右栏与高亮条目保持一致。
- 数据刷新后选中法宝仍在列表中时保留它，并定位到它所在页，不能详情有选中项而当前页无高亮。选中项已移出列表时，原页越界则回到新的末页，再选该页第一件。
- 无已拥有法宝时显示“暂无已拥有法宝”；无有效配方时显示“暂无可打造法宝”。清空过期详情与主操作，不留下上一件的可点击按钮。

空列表显示第 1／1 页、两侧翻页禁用。新增法宝不强行抢走已有选中项；原列表为空时才选新增后的第一件。

### 3.4 列表操作

| 操作 | 结果 |
|---|---|
| 单击法宝 | 更新选中项，中栏与右栏联动 |
| 御使页双击未御使的持续法宝 | 等同御使；失败仅提示，不改变状态 |
| 双击手动法宝 | 不御使，不自动执行一次用途 |
| 养炼或打造页双击 | 只选择，不祭炼、不打造，避免误消耗 |
| 御使页双击已御使法宝 | 不额外定义双击收回；收回使用现有主按钮 |

## 四、中栏详情与使用方式

### 4.1 公共详情

中栏保留名称、品质、法宝境界、祭炼层、器物形象、核心四格与两栏效果说明。

核心四格仍为威能、神识、祭炼减免、实际占用；不在本轮改造数据展示结构。持续法宝的“实际占用”表示当前祭炼层的单件神识需求，不等于该法宝此刻必然生效。

详情模型取当前层模型，未配置则沿用主表；场上没有模型不妨碍面板展示已配置的图标或器物资源。中栏查看本身不启动场上效果。

战斗效果读取 combat_desc，世界用途读取 world_desc，留空显示“无”。说明文字不生成技能，也不因展示了一条用途就视为正在生效。

名称“神识”保持统一，不继续使用基础负荷、御使负荷等旧名称。sense_reduce 统一显示为“祭炼减免”，不再以“神识减免”另列一个指标。

### 4.2 手动法宝

| 配置含义 | 列表／详情 | 御使页主操作 |
|---|---|---|
| 神识为正数：持续御使 | 显示御使、生效及表现状态 | 按条件提供御使或收回 |
| 神识留空：单次手动 | 显示“手动使用，无需御使” | 不提供御使、收回，不替换成未经确认的“使用”按钮 |

手动法宝神识相关不适用项显示“—”，用“单次使用不占神识”说明含义，不包装成零神识的可御使法宝。无需重新设计核心四格。

手动法宝仍可查看、祭炼和打造。不能因为神识字段留空而显示配置异常，也不显示无意义的御使境界不足提示；具体玩法的使用条件由对应玩法展示。

## 五、御使页与神识变动

### 5.1 右栏内容

右栏保留神识总览、选中法宝需求、门槛、效果与表现状态，以及御使或收回按钮。

神识总览沿用现有数值区域，显示整个御使配置的总需求与角色神识。神识不足时，不能只显示仍然生效部分的需求来伪装成配置已足够。

例如总需求 180、神识 140，继续展示这组配置所需的 180／140，并提示部分法宝暂时失效；后台实际生效的占用为 130（100 与 30 生效，50 失效），两者不是同一个含义。数值区域布局及评分优化仍然暂缓。

选中持续法宝显示其神识、当前层减免、实际需求、最低占用与御使境界要求。境界不足时同时给出所需境界和当前境界，门槛取该件法宝的御使要求。

### 5.2 主动御使

未拥有、神识留空、配置无效、角色死亡、数据未就绪，或该玩家有进行中、结果待确认的法宝管理操作，不能发起御使。

持续法宝须满足当前境界和新增后的整个御使队列总需求。因神识不足而暂停的法宝仍属于队列，不能在新增时忽略它们。

点击御使后立即显示“御使中…”，禁止重复提交。后台成功后刷新御使选择、神识结果、列表与场上表现；明确失败后显示原因并重新判断可操作状态，不提前显示效果已生效。操作受理后角色死亡的，显示已御使但死亡暂停，不误报启用失败；未收到明确结果按“结果待确认”处理。

首次启用失败时恢复未御使，提示“法宝未能正常启用，请稍后重试”。不能留下半套效果或显示御使成功。

### 5.3 神识变化后的反馈

角色神识增加、减少或法宝需求、队列变化后，后台重新计算，面板是否打开不影响检测。

分配按当前实际需求从高到低逐件判断（同需求按法宝 ID 升序）：放得下则占用剩余容量，放不下则失效、不占容量，并继续检查后面的法宝。前台展示后台结果，不按左栏顺序自行分配。

- 新增失效时，使用通知提示“神识不足，{法宝名列表}暂时失效；可收回法宝调整，神识恢复后自动重新判定”。
- 同次检测涉及多件法宝时合并通知；同一失效状态不因刷新而重复通知。
- 通知不阻塞操作，不自动跳页，不要求玩家确认后才暂停效果。
- 玩家不操作，失效结果也立即生效；拥有、祭炼层与御使选择不丢失。
- 神识恢复后，符合条件的法宝自动恢复，刷新列表与右栏，无须重新点击御使；不另发恢复通知，不弹确认、不自动打开面板。
- 同次检测既有新增失效又有恢复时，只通知新增失效项；其余变化通过实际状态刷新体现。
- 不继续展示“神识过载，全部法宝仍生效”的旧提示。

神识 140，需求 100、50、30：100 与 30 生效，50 暂时失效，无须收回 50。神识 90 时跳过 100，50 与 30 生效。玩家不收回任何一件，之后神识恢复到 180，三件都恢复生效。

### 5.4 收回

角色存活、数据就绪且没有进行中或结果待确认的法宝管理操作时，已御使法宝均可收回，包括神识不足失效、配置异常、运行异常的法宝。收回不扣资源、无操作冷却；提交后对应按钮显示“收回中…”。

成功后取消该件御使选择，移除其持续效果，并刷新其他法宝的神识分配。未曾生效的暂停法宝收回后，也要重新计算队列，不能只减少一项显示数字。

收回不承诺所有其他法宝必然恢复，前台显示后台实际结果。

### 5.5 被动境界回退

境界回退不会单独取消或停用原有御使法宝，但原有法宝仍须通过当前神识分配。未御使且境界不足的法宝不能新增御使。

界面必须区分“不能新增御使”和“当前因神识不足失效”，不把境界、神识两种原因合并成同一处理。

## 六、状态显示与可操作性

### 6.1 持有列表状态

状态以实际原因为准；配置异常、运行异常优先显示，其次区分死亡暂停、神识不足与正常生效。数据未就绪时显示同步中，不推断生效状态。下表的操作资格按角色存活、数据就绪且无管理操作占用时列出；其他情况先应用公共操作限制。

| 实际情况 | 玩家看到的状态 | 御使页操作 | 祭炼 |
|---|---|---|---|
| 配置异常 | 配置异常 | 已御使则可收回，否则无御使操作 | 禁用 |
| 运行异常 | 运行异常，效果未生效 | 已御使则可收回 | 禁用 |
| 已御使、角色死亡 | 御使中 · 角色死亡，效果暂停 | 禁用 | 禁用 |
| 有效手动法宝 | 手动使用，无需御使 | 不提供御使或收回 | 按祭炼条件判断 |
| 已御使、神识不足 | 御使中 · 神识不足，暂时失效 | 收回 | 按祭炼条件判断 |
| 已御使、正常生效、有模型且取得名额 | 御使中 · 场上显示 | 收回 | 按祭炼条件判断 |
| 已御使、正常生效、有模型但无显示名额 | 御使中 · 表现隐藏，效果生效 | 收回 | 按祭炼条件判断 |
| 已御使、正常生效、无模型 | 御使中 · 无独立表现，效果生效 | 收回 | 按祭炼条件判断 |
| 持续法宝未御使、境界不足 | 境界不足 | 禁用御使并提示要求 | 按独立祭炼门槛判断 |
| 持续法宝未御使、境界满足 | 未御使 | 再按神识等条件判断 | 按祭炼条件判断 |

角色死亡期间面板只读，可查看、翻页和切换主页面，但不能新发起御使、收回、祭炼、打造，按钮说明“角色死亡，复活后可操作”。已受理的管理操作继续结算，结果归属原法宝；新效果不在死亡期间启用。复活后刷新实际神识、生效与可操作状态，不要求重新御使。

### 6.2 表现与生效

每名玩家同时最多显示当前配置允许的独立法宝表现，当前为六件。显示资格只从正常生效且有模型的法宝中按 ID 升序取得。

死亡是单独的暂停表现：死亡时已经显示的法宝停在原地，不绕飞、不追击、不跟随，不因死亡销毁；原本未显示的法宝不新增表现。此时右栏标明“原地停驻，效果暂停”，不能因模型仍在场就标成生效。复活后重新计算资格，符合条件的法宝归位恢复，其余按失效或异常结果显示。

“表现隐藏”仍然提供效果；“神识不足失效”不提供持续效果。三处必须一致：列表状态、右栏效果说明、场上表现。不能仅用 equipped=true 就显示“效果已应用”。

暂停后恢复的法宝仍需判断显示资格，因此可以从神识不足恢复为“效果生效、表现隐藏”，不保证一定重新出现在场上。

### 6.3 管理操作锁定

御使、收回、祭炼、打造按玩家共用一个管理操作资格：从提交到取得明确终态，一次只处理一笔，不能同时提交另一件法宝的管理操作。列表单击、翻页、切页与关闭仍可用；双击御使与按钮提交受同样限制。此锁定不暂停自动战斗、神识检测或其他玩家操作。

只有“当前选中法宝＋当前操作类型”对应的按钮显示“御使中…／收回中…／祭炼中…／打造中…”；其他主按钮保留原名称、禁用，并说明“正在{操作}{法宝名}，请稍候”。不能因照骨镜正在祭炼，就把星罗盘的按钮显示成“打造中…”。

存在待确认操作时，对应操作显示“结果待确认”，其他主按钮保持原名称并禁用；角色死亡时不新提交。已有操作先显示其真实进度，角色死亡作为并列提示，不隐藏正在核对的结果。空闲后再按各操作门槛判断按钮是否可用，不一律恢复为可点击。

### 6.4 配置异常与停用反馈

| 情况 | 界面与操作结果 |
|---|---|
| 主表、有效 0 层或当前层缺失、停用 | 已拥有条目仍保留并显示配置异常，不伪造正常数值；按 6.1 限制操作 |
| 尚未到最高层，所需后续祭炼层缺失、停用或层序断裂 | 右栏显示“祭炼配置异常，暂时无法祭炼”，禁用祭炼；有效当前层的御使和效果不因此停用。配置完整且已到最高层则按 7.1 显示正常满层，不要求再有下一层 |
| 仅打造配方停用 | 从打造图录移除，选中项按列表刷新规则处理；持有列表、已有御使和独立祭炼资格不变 |
| 仅威能权重停用 | 只刷新威能，不改御使、技能效果或管理操作资格 |

已经提交的操作仍按原操作核对实际结果，不因条目移出打造图录就显示“未扣费失败”。

## 七、养炼页：祭炼

### 7.1 页面内容

二级页签为祭炼、器灵、本命。器灵、本命只显示未开放，点击提示“暂未开放”，不发出功能请求。

祭炼右栏沿用当前层至目标层、进度、成功率、门槛、消耗、结果预览和单一主按钮。

- 显示目标层所需炼器技能等级、角色境界，并同时显示玩家当前值。
- 最多三种背包材料，另加一种货币；显示名称、图标、需要数和拥有数，不足项标红。
- 成功率读取目标层配置，万分比转百分比。
- 结果预览保留威能、祭炼减免、实际占用的当前与目标结果；手动法宝不适用的神识项显示“—”。
- 配置完整有效且当前层已达最高祭炼层时，隐藏升级消耗，禁用祭炼，显示“已达当前最高祭炼层”；不要求再有下一层配置。
- 尚未到最高层，但所需后续层缺失、停用或层序断裂时，按 6.4 提示祭炼配置异常，不能当作正常满层，也不因此停止有效当前层的效果。

### 7.2 确认与提交

点击祭炼先预检，条件满足后沿用原型的“确认祭炼”弹层。内容包括法宝、目标层、炼器与境界要求、成功率和全部消耗，并明确“失败仍消耗材料和货币；层数不变，不掉层、不损坏、无保底”。

取消或返回不扣费；确认后发出请求。确认绑定打开弹层时的目标法宝、目标层与消耗；这些内容变化时关闭旧确认并提示“操作条件已变化，请重新确认”，不悄悄改为另一件法宝或另一套消耗。弹层显示不是扣费或成功承诺，后台仍按提交时的当前条件重新校验。

处理中只有对应祭炼按钮显示“祭炼中…”，本玩家其他法宝管理提交同时禁用。明确成功、失败或终止后解除这笔操作的占用；超时或未收到回执转为结果待确认，不伪装成祭炼失败。

### 7.3 结果反馈

| 结果 | 反馈 |
|---|---|
| 成功 | 显示新层数，刷新资源、详情、下一层预览；持续类同时刷新整个御使队列的分配结果 |
| 概率失败 | 明确材料和货币已消耗、层数不变；保持原层效果 |
| 条件不足 | 显示具体不足原因，资源不减少 |
| 升层成功但效果恢复异常 | 仍显示已经获得的新层，同时显示运行异常；不显示降回旧层、再次扣费或效果正常 |
| 最高层 | 保留满层状态，不继续发祭炼请求 |

神识不足失效不等于运行异常，不单独禁止祭炼。祭炼降低需求可能改变优先顺序，使队列中的法宝恢复或失效；必须按后台实际结果刷新整个队列，不能只刷新选中项。

## 八、打造页

### 8.1 图录与预览

只显示启用且有效的配方目标。未拥有目标按 0 层完整结果预览，显示“打造后祭炼零层”；已拥有目标显示当前真实层数及“已拥有”。

打造页保留独立页码与选中项。查看未拥有法宝不生成拥有记录，不占神识，不执行用途。

### 8.2 右栏与按钮

右栏依次展示打造必成、炼器等级、境界、获得状态、禁止重复打造、材料与货币、首个不足原因、打造按钮。

| 条件 | 按钮与提示 |
|---|---|
| 已拥有 | 禁用；已经拥有此法宝，不重复扣料 |
| 配置异常、数据未就绪、操作中 | 禁用并显示对应原因 |
| 炼器等级不足 | 禁用；显示需要与当前等级 |
| 境界不足 | 禁用；显示所需与当前境界 |
| 材料或货币不足 | 禁用；显示名称、需要数与拥有数 |
| 条件全部满足 | 打造可用 |

所有不足项都可以高亮，但主提示只显示一个明确的优先原因。打造门槛读取配方，不读取御使或祭炼门槛。

### 8.3 确认与结果

沿用“确认打造”弹层，展示法宝、必成获得 0 层、门槛与全部消耗。

持续法宝补充“获得后未御使，不立即占神识或生效”；手动法宝补充“获得后可在对应玩法中手动使用，本次打造不自动执行用途”。

取消不扣费；确认绑定所展示的法宝、配方与全部消耗，发生变化则重新确认，提交时仍重新校验。处理中只有对应打造按钮显示“打造中…”，本玩家其他法宝管理提交同时禁用。打造不存在随机失败；超时或未收到回执属于结果待确认，不等于打造失败。

成功后当前条目变为已拥有，持有列表增加 0 层法宝。玩家仍停留在本次打造页与原选中项时，保留位置并显示结果弹层；已经切页、改选或关闭面板时保持玩家当前界面，只通知原法宝的结果。不强行跳回打造页，也不自动跳到御使页、不自动御使、不自动使用。

## 九、单次手动用途的交互边界

法宝面板负责查看、祭炼、打造与持续御使；一次炼制、探查等手动用途由对应玩法的操作入口发起。

手动使用必须满足：

- 不要求先打开法宝面板御使，也不要求收回战斗中的法宝。
- 不占神识，不改变当前战斗法宝的御使选择和神识分配。
- 根据用途自身的目标、材料、冷却与过程要求，提供处理中、成功或失败反馈。
- 一次用途有结束点；点击后连续自动工作的能力不能按手动类免神识。
- 持有法宝不自动执行用途，不自动提供永久常驻效果。

现有 v1.4 原型没有单次手动使用入口，本次不在法宝面板增设。哪件法宝有什么用途、增加什么参数，由内容配置确定；在炼丹、探查等场景中如何选择法宝、发起使用并展示结果，由对应玩法的策划案和交互案约定，不在本总案展开单件法宝设计。

所有法宝都有对应的法宝道具，持续法宝和手动法宝均不例外。背包中使用“法宝道具”是获得法宝，不是这里的单次用途。掉落、拾取、背包授予继续由物品系统承接：首次授予消耗道具，已拥有或配置异常不消耗。

### 10.1 超时、恢复与迟到结果

达到项目通用请求超时或连接中断时，若没有明确结算结果，将“处理中”改为“结果待确认”；保留当前已确认的数据，不自行退料、升层，也不显示“失败未消耗”。使用既有通知和右栏说明，不新增重试扣费按钮。

连接恢复、重新打开面板或重新登录后核对原操作：已完成则刷新真实结果；后台确认原操作已终止、不会再执行且没有未处理的资源消耗，才允许重新发起；仍未核实则保持待确认与管理提交限制。查不到记录不直接解锁。核对不能重新执行原操作；显示同一结果也不能再次播放获得、扣料或升层反馈。

结果始终对应原操作、原法宝，不对应回执到达时当前选中项。祭炼、打造结果弹层仅在仍停留于发起页、选中原法宝且没有其他弹层占用时显示；否则只通知并更新数据，不重开面板、不抢选中项、不覆盖现有弹层。御使、收回沿用通知反馈。实际结果确认后清理该笔操作的忙碌或待确认状态。

## 十一、前后台交接与验收要求

前台至少需要获知每件法宝的拥有状态、使用方式、祭炼层、御使选择、当前生效结果、失效原因、表现资格，以及角色是否存活、数据是否就绪。操作信息须能区分本次操作、操作类型、目标法宝、已确认的层或配方与消耗、处理中／待确认／明确终态及实际资源结果。具体字段与传输形式由程序团队确定。

资源、法宝状态变化后同步刷新列表、详情和右栏；切换页签或关闭面板、弹层不能取消已经提交的结算。结果待确认不能被清空成未操作，明确终态也不能留下过期的“处理中”。
