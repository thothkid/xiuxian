# 法宝系统
法宝的身份三轴与数据模型、神识与御使规则、祭炼流程、战力计算与效果槽、战斗行为、获取途径、世界用途，以及 `F法宝.xlsx` 的页签结构。具体条目与数值以配置表为准。
法宝是**在神识预算约束下自由配置的随身法器**。

## 三条线
法宝分三条线。御使线属于配置：神识有限，玩家决定带哪几件——战斗、生产还是辅助，随时可换、无代价。祭炼线属于养成：校验炼器技能等级与境界，消耗材料，按成功率提升祭炼层；每一层配一份完整快照，含效果槽、继承比例与神识减免。效果线同时覆盖战斗与世界：只有加属性、调用技能、调用 BUFF、调用词条四种行为，战斗效果与世界用途共用同一套效果槽，不分表不分列，御使即应用、收回即移除。

## 设计约束
> 下面六条是**不能顺手改掉**的地方。列在这里是因为它们看起来像可以简化，实际改了会连带出问题。除此之外全文不再解释设计意图。
| 约束 | 改掉会怎样 |
|---|---|
| 神识占用有下限夹取（`sense_cost_min`） | 祭炼减免堆高后占用归零，神识预算这个核心约束自己失效 |
| 威能只能由公式算出，不能配置表直填 | 会出现「威能高但实际输出低」，玩家据此做的取舍全是错的 |
| 效果统一走效果槽，战斗与世界不分表 | 一旦分开，每加一种世界用途都要改法宝核心代码 |
| 每层是完整快照，不是增量 | 增量式会让「跳层」「回滚」「读档重算」三处逻辑全部变复杂且容易错 |
| 存档只存 `refineLv` + `equipped` | 多存一个派生字段，就多一处会和配置表不同步的脏数据源 |
| 表现与出伤解耦 | 合一后每件法宝每 tick 都要移动单位，多人多件时是数千次 native 调用 |

## 身份三轴
| 名词 | 字段 | 说明 |
|---|---|---|
| **境界** | `realm_id` | 法宝自身的境界。**同时是御使门槛**：角色当前境界 ≥ 本值才能御使，见 「御使（装备）」。`0` ＝ 无境界门槛 |
| **品质** | `quality` | 灵品 / 玄品 / 仙品 / …。**获得时确定，本期无升品** |
| **祭炼层** | `refine_lv` | 本期**唯一的成长维度** |

> ⚠️ **三处 `realm` 不要混淆**：
> - `法宝.realm_id` ＝ 法宝自身境界，**御使门槛**
> - `祭炼.realm_req` ＝ 升到该层的**祭炼门槛**
> - `打造.realm_req` ＝ 打造这件法宝的**打造门槛**
>
> 三者独立配置，互不推导。都读角色当前大境界ID比较。

> ⚠️ 未实现升品功能不等于禁止升品：不加任何禁止性逻辑，也不加「永久锁定」的注释，只是当前没有这条路径。

> **一行 = 一件法宝。** 不存在"同名法宝多品质共享一条成长链"的结构。照骨镜·仙品 和 照骨镜·玄品 是配置表里两条独立记录、两件独立的法宝。

## 分类
| 分类 | 字段值 | 说明 |
|---|---|---|
| 战斗 | `Combat` | 出战自动攻击 |
| 生产 | `Produce` | 作用于炼丹 / 种植 / 采集等生产系统 |
| 辅助 | `Support` | 移动 / 背包 / 其他功能性 |

分类**只影响两件事**：UI 分组、默认表现等级。**不影响神识规则**——三类法宝一视同仁地消耗同一个神识池。

## 神识
**神识是一个属性名，角色和法宝两侧都用它。**
| 侧 | 字段 | 含义 | 来源 |
|---|---|---|---|
| 角色 | 属性「神识」 | **容量**（池子上限） | **角色属性体系里的一个 AttrField**，跟境界 / 装备 / 功法走 |
| 法宝 | `sense_cost`「神识」 | **消耗量** | 法宝主表的一个字段 |

>**两侧统一叫「神识」**，配置表、策划案、交互案、UI 文案一律用这两个字。**禁止出现「基础负荷」「御使负荷」「神识负荷」等别名。** 角色侧是池、法宝侧是消耗，由上下文区分。
```
实际占用 = clamp( 神识 − 祭炼减免 , 最低占用 , 神识 )
已占用   = Σ 所有御使中法宝的实际占用
剩余     = 角色神识 − 已占用
```

>**`最低占用` 必须存在，且必须夹取。** 不夹的话祭炼减免堆高后实际占用归零，神识池这个核心约束会自己失效。`最低占用` 是法宝主表的一个字段，填多少由策划定。

>**法宝系统对角色神识只读不写。** 神识上限由属性系统给出，法宝系统不得直接修改。

## 威能
**威能是一个纯展示的聚合评分，不参与任何实际计算。** 本期先使用简单线性公式，后续只改评分权重，不改战斗逻辑。
```
威能 = floor( Σ ( max(0, 法宝有效属性[X]) × 威能权重[X] ) )
```
- `法宝有效属性` = 效果槽「加属性」部分 + 继承部分（见 「法宝自身属性与有效战斗属性」），**含继承**
- `威能权重` 配在 `FabaoPowerWeight` 表里（属性名 → 临时权重）；未配置的属性不计入威能
- 负数按 0 处理；攻击间隔、技能 CD 等“数值越小越强”的字段暂不纳入，避免反向计分
- 战斗计算**只用底层那组真实属性**，从不读威能

> ⚠️ **威能不得由配置表直接填写**，只能由本公式从有效属性算出。
> ⚠️ **威能含继承，所以角色属性变更时必须触发重算**，见 「重算时机」。

## 御使（装备）·其一
玩家点击「御使」发出同步操作后，按下列顺序处理。同步输入未就绪返回 `data_not_ready`；操作锁已占用返回 `operation_busy`；否则立即取得该法宝操作锁并同步禁用相关按钮，随后进入受保护流程：
1. 后台重新校验拥有、未御使、主表与当前层配置有效——未拥有返回 `not_owned`，已御使返回 `already_equipped`，配置无效返回 `invalid_config`。
2. 角色当前境界低于法宝 `realm_id` 时返回 `realm_not_enough`。
3. 计算本次实际占用；已占用加本次实际占用超过角色神识时返回 `sense_not_enough`。
4. 分阶段创建临时运行时，未全部完成前不得公开运行时上下文：先建法宝自身逻辑属性容器并算有效属性，再按当前层注册技能、BUFF、词条并保存效果句柄，`model_id` 非空时建表现实体，需要出伤时建出伤代理并进入状态机。

## 御使（装备）·其二
5. 全部成功后一次性发布运行时上下文，置 `equipped = true` 并存档。
6. 任一步失败时按创建逆序清理临时运行时，保持 `equipped = false`、不存档，返回 `runtime_create_failed` 并记 error 日志。
无论成功、失败或异常，最后都必须释放操作锁并恢复界面。

> `equipped` 是持久化业务状态，**不是操作锁**。防重复点击与并发重入只能依靠 「操作同步与串行」 的运行时操作锁；`equipped=true` 只允许在运行时完整创建成功后提交。

## 收回（卸下）
收回无代价、无冷却，随时可收回。不设御使方案预设，玩家手动逐件切换。
玩家发出收回同步操作后，操作锁已占用返回 `operation_busy`；否则立即取得该法宝操作锁并同步禁用相关按钮，随后后台重新校验已御使，未御使返回 `not_equipped`；校验通过后置 `equipped = false`，移除当前祭炼层的全部效果槽，销毁运行时（先停所有 timer，最后才销毁实体），最后存档。无论成功、失败或异常，最后都必须释放操作锁并恢复界面。

收回清理必须**幂等**：同一个效果句柄、timer、事件订阅、表现或代理重复清理时直接跳过，不得重复扣属性或抛异常。即使某一项清理失败，也要继续清理其余项目并记录 error；记录层的 `equipped=false` 不得被清理异常反向改回。

## 超载与门槛回退
**主动操作一律拦截，被动变化一律不回收。** 两条门槛（神识、境界）规则完全一致：
| 时机 | 处理 |
|---|---|
| **主动御使**会超神识上限 | ⛔ **禁止**。按钮置灰 + 提示 `sense_not_enough` |
| **主动御使**时角色境界 < 法宝 `realm_id` | ⛔ **禁止**。按钮置灰 + 提示 `realm_not_enough` |
| **被动**神识上限下降导致已占用 > 上限 | ✅ **允许超载存在，不自动收回** |
| **被动**角色境界下降到低于已御使法宝的 `realm_id` | ✅ **继续生效，不自动收回** |

> ⚠️ **被动变化下所有已御使法宝必须仍然正常工作**：不能因为超载或境界回退让任何法宝失效，也不能报错或崩溃。这只是一个 UI 警示状态——神识条标红 + 提示，由玩家自己决定收哪件。
>
> ⚠️ 但**新的御使操作仍按当前值拦截**：超载期间不能再御使（因为 `已占用 + 任意值 > 上限` 必然成立），境界回退后不能再御使境界不足的法宝。

## 角色神识 / 境界变化的响应
订阅"角色属性变更"与"角色境界变更"事件 → 刷新 UI 显示 + 重算超载与境界回退状态。**不做任何自动收回。**

## 操作同步与串行
御使、收回、祭炼、打造等会改变游戏状态的操作，统一走同步消息；所有客户端按同一顺序执行同一套校验和状态变更。**只有 HTTP 存档与本地 UI 刷新使用 `GetLocalPlayer()` 守卫。**

同步操作依赖的全部输入也必须已经同步：至少包括背包物品、货币、角色属性、当前境界、现有「炼器」技能等级、当前法宝记录与配置版本。任一输入尚未就绪时统一返回 `data_not_ready`，不得让各客户端拿本地未同步数据各算各的。

每个玩家的每件法宝设置一个仅运行时存在的操作锁：操作开始后立即锁定，逻辑层拒绝同一法宝的重入请求，UI 同步禁用相关按钮。**取得锁后的主体必须使用 `try/finally`：成功、全部失败返回和异常抛出都在 `finally` 释放锁并恢复 UI。** 存档异步重试不长期占用操作锁，因为本地真相已经立即生效。

## 祭炼流程·其一
玩家点击「祭炼」后，未拥有返回 `not_owned`；操作锁已占用返回 `operation_busy`；否则立即取得该法宝操作锁，随后进入受保护流程：
1. 目标层等于当前祭炼层加一；查祭炼表目标层行，无配置即已达最高层，返回 `already_max_refine`。
2. 读取现有「炼器」技能等级，低于目标层行的 `forge_skill_lv_req` 时返回 `forge_skill_lv_not_enough`。
3. 读取角色当前境界，低于目标层行的 `realm_req` 时返回 `realm_not_enough`。
4. 整体校验材料，任一不足则全部不扣，返回 `material_not_enough` 并带上缺口物品与数量。
5. 扣除材料并生成材料消耗快照。
6. 成功率判定取 1 到 10000 的同步随机整数，小于等于目标层行的成功率（万分比）即成功。随机数必须使用同步随机源。

## 祭炼流程·其二
7. 成功时把祭炼层置为目标层，直接读取目标层的完整配置快照，重算有效战斗属性、实际占用与威能；若正在御使，先整体移除旧层效果槽再按新层重新应用，并刷新模型与运行时；最后存档。
8. 失败时材料已扣、层数不变，无补偿、不掉层、不损坏，提示失败并记录材料审计快照以便事后追查。
无论成功、失败或异常，最后都必须释放操作锁并恢复界面。

>从“立即取得操作锁”开始，后续所有 `return` 都只能发生在 `try` 内；锁释放和 UI 恢复只能写在唯一的 `finally`，禁止散落在各分支。
>
>**御使中换层的原子性**：祭炼成功后 `refineLv = targetLv` 是新的记录层真相，不因运行时异常回滚。运行时必须先完整移除旧层，再尝试应用新层；新层应用中途失败时逆序清理全部新句柄，禁止恢复旧层效果，也禁止留下新旧混合。此时保留 `equipped=true`，但 `ctx=null`、该法宝暂不运行，记录 `runtime_rebuild_failed` error，等待自动重试或重新登录重建。

## 规则
| 项 | 规则 |
|---|---|
| 炼器技能等级门槛 | **逐层配置**。直接读取玩家现有「炼器」技能当前等级，不创建任何新等级或造诣字段 |
| 境界门槛 | **逐层配置**。读取角色当前大境界ID |
| 消耗 | 材料道具，可多种，**数量与种类逐层配置** |
| 成功率 | **逐层配置**（万分比） |
| 失败处理 | **扣材料、层数不变、无保底、不掉层、不损坏** |
| 保底机制 | 未实现。若要实现，需要多存一个「连败次数」真相字段，存档结构会变 |
| 层数上限 | **祭炼表里配到多少层就是多少层**，每件法宝可以不同 |
| 0 层 |每件法宝必须配置 0 层行；获得时直接处于 0 层并立即拥有完整效果槽与继承 |
| 每层配置语义 |**完整快照，不是增量。** 当前层的效果槽、继承比例、神识减免、模型均只读当前层行 |
| 层数连续性 | 必须从 0 开始连续配置，不允许缺层；最高连续层就是运行时上限 |

> ⚠️ 祭炼成功率的判定结果必须在全部客户端一致。所有客户端跑同一份逻辑，一旦各端算出不同的成功或失败结果，游戏状态会分叉，且不会立刻报错，而是在后续某个不相关的地方以诡异形式暴露。

## 材料消耗与存档的一致性
祭炼是**先扣材料后存档**，存档失败就是纯数据损失。处理方式：
- 网络写失败 → **自动重试 2 次，间隔 3 秒**
- 重试耗尽 → `log.error` 并标注「需GM介入」，日志里带上**玩家、法宝ID、层数、材料消耗快照**
- **不回滚本地状态**（回滚会带来更麻烦的竞态）

> ⚠️ **不要做"服务端确认后再扣材料"。** 本项目的服务端只是存档柜，不做背包验算，所谓"服务端确认"没有任何反作弊意义，却会引入一个窗口期：确认返回之前玩家可以再点一次。
> 正确顺序是：**验炼器技能等级与境界 → 验材料 → 立即扣 → 立即置位 → 异步存档**。门槛失败时不扣任何材料或货币。

## 效果槽法宝的**全部效果**——加属性、放技能、挂 BUFF、带词条——都用同一种结构表达，配在「祭炼」页，每层一组完整快照。
**一组效果槽 3 列，共 8 组：**
| 行为 | 参数/ID 填什么 | 数值列 |
|---|---|---|
| `加属性` | 属性名，须存在于 `S属性配置表.attr_config.name` | **必填**，写入法宝自身逻辑属性容器的基础值 |
| `调用技能` | 技能ID | **不读取，必须留空** |
| `调用BUFF` | BUFF ID | **不读取，必须留空** |
| `调用词条` | 词条ID | **不读取，必须留空** |
**属性归属唯一规则**：

-`加属性` **永远只加给法宝自身**，写入 `FabaoContext.ownAttr`；不得直接修改所属角色、表现实体或出伤代理的属性。
- 法宝没有模型、没有出伤代理时，`ownAttr` 仍然存在。它是纯逻辑数据容器，不依赖 WC3 单位实体。
- `调用技能 / 调用BUFF / 调用词条` 的目标、触发与作用对象由各自配置表决定；法宝只提供所属玩家、法宝ID、逻辑坐标、代理施法者等来源上下文，不在效果槽里再配一份目标。
- 需要改变角色或生产系统结果的世界用途，必须通过带法宝来源的 BUFF / 词条 / 技能接入对应系统；不得把 `ownAttr` 偷加到角色属性，也不得让其他系统反向遍历法宝属性。

**规则**：
- 行为为空 → 跳过整组，不读该组的参数与数值
- 行为非空 → 必须命中效果槽支持的四种行为之一，参数必填且能解析到对应配置
- 八组严格按 1 → 8 顺序执行
-**属性是整数还是万分比，由 `S属性配置表` 里那个属性自己的「属性类型」列决定**，效果槽不重复配这一列

**后台应用 / 移除契约**：
- 当前层快照加载时，先汇总全部 `加属性` 槽生成 `ownAttr`，再计算 `combatAttr`；随后才按 1 → 8 注册技能 / BUFF / 词条，避免技能注册瞬间读取到未初始化属性。
- 每个非空槽都生成可精确移除的 `EffectHandle`；`加属性`句柄指向本法宝逻辑属性贡献，其余行为调用 `applyEffect(sourceKey, slot)`。`sourceKey` 至少包含「玩家 + 法宝ID + 效果修订号 + 槽位序号」
- `调用技能` 的语义是**注册一个御使期间存在的技能运行时**，不是御使瞬间直接释放一次；触发条件、目标、CD 与持续时间仍由技能表决定
- `调用BUFF` 必须挂载带法宝来源的 BUFF 实例；`调用词条` 必须注册带法宝来源的监听实例。收回与换层时只能移除自己持有的实例，禁止按公共 ID 粗暴删除

**后台应用 / 移除契约**：
- 应用固定按 1 → 8；移除固定按 **8 → 1**。每次移除只使用保存的 `EffectHandle`，且 `removeEffect(handle)` 必须幂等
- 同层多个 `加属性` 指向同一属性时允许累加；同层重复的「调用技能 / 调用BUFF / 调用词条」行为 + ID 禁止配置。效果槽技能ID也不得与 `basic_skill_id` 重复，除非以后专门新增“允许双实例”的明确规则
- 应用中途失败时，立即按逆序移除本次已经成功创建的全部句柄，不得留下半套效果

**生效时机**：
效果槽的生效时机有四种：御使时应用当前祭炼层的全部效果槽；收回时全部移除；祭炼成功时先整体移除旧层效果、再按新层重新应用，不在旧层上叠加；角色死亡时随运行时一起移除，复活重建时重新应用。

>**法宝系统不判断一个效果属于战斗还是世界，只按行为分发。**
> 因此**不要建世界能力表，也不要做能力查询接口**。

> ⚠️ **与丹药效果槽的唯一差异**：丹药是服下后持续 N 秒，所以丹方表有 `duration` 列；法宝是**御使期间常驻**，所以本表没有 `duration`。被调用的 BUFF / 技能 / 词条自身的持续时间，由那三张表各自的配置决定，法宝这边不重复配。

## 法宝自身属性与有效战斗属性
```
法宝自身属性[X]
  = 当前祭炼层效果槽中「加属性」给出的 X 之和

法宝有效战斗属性[X]
  = 法宝自身属性[X]
  + floor( 角色属性[X] × 继承比例[X] / 10000 )
```
- `法宝自身属性` 存在于逻辑容器 `FabaoContext.ownAttr`，不要求法宝具有 WC3 单位实体。
- `加属性`只写入 `ownAttr`，**不会增加所属英雄的同名属性**，也不会写到 dummy 或表现壳单位。
- **继承部分**读取角色属性快照与当前层「继承组」，万分比，按属性分别配。
- 继承比例留空 = 该属性不继承，只用法宝自身属性部分。
- **上下限都算**：角色攻击 100–150、继承比例 1000（10%）→ 法宝额外获得攻击下限 10 / 上限 15。
- 出伤与威能只读取最终 `combatAttr`；角色系统不得反向读取或汇总 `ownAttr`。

## 技能化出伤
战斗类法宝在「法宝」页配置一个 `basic_skill_id`（普攻技能ID）；它和效果槽里 `调用技能` 的技能一样，读技能表并走同一套技能执行、命中事件与伤害管线。法宝本身可以没有 WC3 单位实体；需要合法施法者或伤害来源时使用出伤代理，但属性始终读取法宝自己的 `combatAttr`。
- `atk_type` 只决定表现与移动方式：近战进入 `Engage` 追近目标，远程进入 `Cast` 在角色附近执行技能。
- 普攻技能的伤害类型、伤害公式、作用范围、施放距离、冷却与命中效果全部读取技能表。
- 每次技能出伤都读取法宝自己的有效属性。
- 法宝作为施法者时，不检查英雄职业、英雄等级、英雄蓝量和英雄施法动作；其它技能配置照常读取。

> ⚠️ **伤害类型必须由技能配置显式传进伤害管线，不允许出伤调用点自行推断。**
> 反例：出伤时固定传 `isAttack = true`，伤害管线就会恒判为物理，配了道术/魔法继承比例的法宝**永远打不出这两类伤害**，而且不报错——属性算对了、注入了，就是不生效。

> **普攻与效果槽技能的区别**：普攻由状态机按技能 CD 循环执行，是持续的战斗行为；效果槽的 `调用技能` 是御使时注册一个常驻技能运行时（不是立即施放），技能自身的触发条件与 CD 由技能表定义。两者执行时机不同，所以普攻单独一个字段，不塞进效果槽。
>
>**CD 防重置默认规则**：玩家运行时维护轻量的 `Map<fabaoId, Map<skillId, nextReadyAt>>` 会话级冷却账本，它独立于 `FabaoContext`。收回、重新御使、祭炼换层、角色死亡 / 复活和更换角色载体都不得清空；技能重新注册时继续读取原 `nextReadyAt`。某技能在本局首次注册时才初始化为可用。冷却不写永久存档，玩家离线后可清理——本规则只堵住同一局内反复收回 / 御使刷新 CD 的漏洞，不扩大存档结构。

## 重算时机以下**任一**发生时，重建该法宝的 `ownAttr`、重算有效战斗属性与实际占用（效果槽里的技能 / BUFF / 词条不受影响，只在御使、收回、换层时增删）：
| # | 时机 | 说明 |
|---|---|---|
| 1 | 祭炼成功 | |
| 2 | 御使时 | 创建运行时 |
| 3 | **角色属性变更** |最容易漏的一条，见下 |
| 4 | 读档恢复 | |

>**第 3 条最容易漏。** 继承是乘法关系，角色换一身装备、吃 buff、加属性点之后，如果不重算，法宝用的还是旧数值——而且不会报错，只是一直算错，直到下一次祭炼或重新御使才碰巧对上。
>
> 实现：订阅"角色属性变更"事件 → 重算**所有御使中法宝**的属性 + 威能。
> ⚠️ **注意频率**：属性变更事件可能很频繁（每个 buff 刷新都触发）。要做**合并触发**——标脏 + 下一帧统一重算一次，不要每次事件都全量算。

## 威能计算
```
威能 = floor( Σ ( max(0, 法宝有效属性[X]) × 威能权重[X] ) )
```

本期权重配在「威能权重」页，简单线性；没有权重行的属性不计入。威能纯展示，不参与任何战斗计算，重算时机同 「重算时机」。以后优化评分公式时只改本节与权重表，不改底层真实属性和战斗结果。

> 📌 **威能权重后续整体迁入 `X系统参数`**，届时「威能权重」页删除。本期先放在 `F法宝.xlsx` 里，方便和法宝一起调。

## 状态机
**四个状态**：
| 状态 | 干什么 |
|---|---|
| `Hidden` | 不可见。表现物隐藏 |
| `Orbit` | 绕角色公转（本期只使用半径 / 周期 / 固定高度），默认态 |
| `Engage` | **近战**：飞向目标，进入攻击范围后出手 |
| `Cast` | **远程**：贴在角色身边不动；只保留处于当前普攻技能有效射程内的目标 |

另有一个 `TeleportReset` 过渡态：角色传送后瞬移归位防拖尾，立即转回 `Orbit`。
法宝表现实体的状态流转是：创建后进入 Hidden，再进入 Orbit（环绕）。近战法宝从 Orbit 进入 Engage，远程法宝从 Orbit 进入 Cast。目标死亡、句柄失效或目标超距时，无条件回到 Orbit，不链切下一个目标。

**转移规则**：
- 进战 + 有目标 → 按 `攻击方式` 字段进 `Engage` 或 `Cast`
- 已在 `Engage` 或 `Cast` 时再次收到进战事件 → 只更换目标，不重新起手，不重置攻击节奏
- 进入 `Engage`/`Cast` 时目标为空 → 降级回 `Orbit`
- 目标丢失 → **无条件回 `Orbit`，不链切**。因为角色打新目标时会重新触发进战，等效于链切且更符合"跟随角色"的意图
- `Cast` 中目标离开当前普攻技能有效射程 → 立即清空目标并回 `Orbit`；重新选目标时同样只枚举技能射程内目标，禁止停在“能选中但打不到”的距离区间

> `Cast` 的语义是**远程站桩执行技能**：普攻技能和额外主动技能都在该状态内执行。这个状态名不代表"只能平A"。

## 是否新增施法状态
**本期不新增。** 普攻技能与额外技能都在 `Engage` / `Cast` 内按各自技能配置独立判定；法宝状态机只负责位置、目标与退出条件，不另造一套技能调度规则。

> ⚠️ 四个状态里已经存在一处需要小心的递归：进入 `Engage`/`Cast` 时目标为空会立刻降级回 `Orbit`。实现时必须保证这个降级不会反过来再触发一次进入，否则会状态抖动。

**什么时候才需要加 `Casting` 状态**：技能有**前摇**、有**引导**、或需要法宝**位移到特定位置**（飞到目标头顶再砸下）。到那时再加，进入时停当前 timer、结束后回到进来之前的状态。

## 进战检测
监听**三类信号**，任一触发即刷新战斗时间戳并重新选目标：
| # | 信号 |
|---|---|
| 1 | 角色**被攻击** |
| 2 | 角色**承受伤害** |
| 3 | 角色**造成伤害****必须过滤代理标记** |

脱战：距最后一次战斗信号超过 `FabaoGlobal.CombatExitDelaySec` → 回 `Orbit`。

>**信号 3 的过滤是硬性的，两端缺一不可**：
> - **出伤端**：法宝打出的伤害必须打上 `NonHeroProxy` 标记
> - **检测端**：收到带该标记的伤害直接 return
>
> 不做的话，法宝每隔攻击间隔打一次 → 每次都刷新战斗时间戳 → **角色永远脱不了战**。
>
> **规则推广**：任何"以玩家名义出手的非玩家单位"都必须打代理标记，所有"角色是否在战斗 / 是否有输出"的判定都要过滤它。

## 目标选择
先确定本次允许搜索的最大半径：
```
近战 Engage：SearchRadius = FabaoGlobal.TargetSearchRadius
远程 Cast  ：SearchRadius = min(FabaoGlobal.TargetSearchRadius, 当前普攻技能有效射程)
```

再在角色周围 `SearchRadius` 内枚举单位：
```
筛选：存活 + 敌对 + 不是法宝出伤代理
取：距【角色】最近的一个   ← 不是距法宝最近
```
- `Engage`：目标距角色超过 `FabaoGlobal.TargetAbandonDistance` 时放弃；不配置独立停止距离，停止接近距离直接读取当前普攻技能有效射程。
- `Cast`：目标距 `FabaoContext.logicPos` 超过当前普攻技能有效射程，或距角色超过 `TargetAbandonDistance`，任一满足即放弃并回 `Orbit`。远程法宝不追目标，所以搜索阶段就必须限制在技能射程内。
- 转表阶段继续强校验 `TargetSearchRadius >= TargetAbandonDistance`；普攻技能射程由技能表校验为正数，不要求与两个全局距离写死相等。
- 所有射程判断使用 `FabaoContext.logicPos`，不得读取静止出伤 dummy 的单位坐标。

> ⚠️ 反例：技能射程 900、搜索半径 1200、目标在 1000。若远程搜索不按技能射程截断，法宝会选中目标但既不移动也打不到，并且目标未超过放弃距离，最终永久悬停。该场景搜索与退出规则就是为消除这个区间。

## 普攻执行
- **不使用 WC3 原生普攻。** 物编里写死的攻击数值与配置表完全无关，永远对不上。
- 战斗类法宝从「法宝」页读取 `basic_skill_id`，进入合法战斗状态且目标满足技能条件时，由技能系统执行。规格见 「技能化出伤」。
- 技能施法者使用法宝出伤代理单位，读取法宝自己的有效属性；所有伤害统一带 `NonHeroProxy` 与法宝来源上下文。
- 出伤代理只承担合法攻击者与归属身份。技能射程、弹道起点、范围中心及近战接近判定使用法宝的 `logicPos`；技能系统必须支持显式传入来源逻辑坐标，禁止偷偷回读静止 dummy 坐标。
- 普攻技能在本局首次注册时初始化为可用；同一局内重建运行时继续读取 「技能化出伤」 的会话级冷却账本，不得借收回、重御使、死亡或祭炼刷新冷却。后续冷却完全遵循技能表。
- 法宝系统**不自行换算一个独立的「攻击间隔」**，冷却读技能表。

## 效果槽里的技能与词条
效果槽的 `调用技能` / `调用BUFF` / `调用词条` 三种行为，结构与生效时机见 「效果槽」，这里只补战斗侧的实现约束。
- 不使用 `UnitAddAbility + IssueOrder` 的 WC3 原生数值；统一调用项目技能执行器并走正规伤害管线。
- 技能与词条效果一律读取**法宝自己的有效属性**（加属性 + 继承），不得 fallback 到所属玩家英雄属性。
- 多个技能同一时刻满足条件时，调度顺序必须是确定的、可复现的，默认按 `SkillID` 升序；不得依赖随机或不稳定的遍历顺序。
- 法宝系统向事件总线提供统一来源上下文，至少包含：所属玩家、法宝ID、施法者代理、技能ID、是否普攻技能、目标与伤害结果。词条系统据此复用现有触发器；`IsSkill` 等条件直接匹配实际执行的法宝技能ID。

至少开放两类语义事件：
- **法宝命中**：普攻技能与效果槽技能命中都触发
- **法宝技能命中**：仅效果槽技能命中触发，供需要排除普攻的词条使用

> ⚠️ **所有词条触发、派生伤害与二次伤害都必须透传 `NonHeroProxy + FabaoID + SkillID`**，否则法宝的连锁伤害会被重新计为英雄主动出手（角色脱不了战），或者丢失来源归属。

## 统一入口
**逻辑上只有一个入口：`授予法宝(玩家, 法宝ID)`。** 掉落、打造、任务奖励全部调它。
授予法宝入口接收玩家、法宝 ID 与来源上下文三个参数，按下列顺序处理：配置不存在或缺 0 层配置时返回 `invalid_config` 并记 error 日志；记录已存在时返回 `already_owned`，绝不覆盖已有数据；否则创建法宝记录，祭炼层为 0、`equipped` 为 false，建立完整的 0 层配置记录，此时效果尚未应用；首次御使后才应用 0 层属性、普攻、技能、BUFF、词条与世界用途；最后存档，材料与来源审计信息由来源上下文一并传入，返回 `newly_granted`。

>接口必须区分 `newly_granted` 与 `already_owned`。两者都不会改坏旧数据，但调用方是否消耗道具完全不同：只有 `newly_granted` 才能消耗法宝道具；`already_owned` 必须保留道具并提示“已拥有”。

## 掉落
**法宝在物品表里有对应条目。**
怪物掉落、宝箱与任务奖励都产出一个「法宝道具」进背包，走通用物品管线。玩家使用该道具时调用授予法宝入口：返回 `newly_granted` 则消耗道具；返回 `already_owned` 则不消耗并提示已拥有；返回 `invalid_config` 则不消耗并记 error 日志。

## 打造·其一
**独立的打造表**（配方）。
打造同步操作按下列顺序处理。同步输入未就绪返回 `data_not_ready`；操作锁已占用返回 `operation_busy`；否则取得该法宝操作锁，随后进入受保护流程：
1. 校验配方存在且 `enable` 为 true。
2. 校验法宝主表存在且 `enable` 为 true。
3. 校验该法宝有且只有一条有效 0 层配置。以上任一失败返回 `invalid_config`，不扣材料、不扣货币。
4. 再次检查是否已拥有，已拥有返回 `already_owned`，不扣材料、不扣货币。
5. 读取现有「炼器」技能等级，低于配方 `forge_skill_lv_req` 时返回 `forge_skill_lv_not_enough`。
6. 读取角色当前境界，低于配方 `realm_req` 时返回 `realm_not_enough`。
7. 整体校验材料与货币，任一不足则全部不扣。
8. 整体扣除材料与货币并生成消耗快照。

## 打造·其二
9. 调用授予法宝入口并传入打造快照，由授予入口完成唯一一次记录创建与存档。
无论成功、失败或异常，最后都必须释放操作锁并恢复界面。

>**主表与 0 层检查必须发生在扣料前。** `授予法宝()`里的 `invalid_config` 是最后一道不变量防线，不能把它当成打造流程的首次配置校验，否则会出现扣料后发不出法宝。

> 打造检查与记录创建处在同一个同步操作锁内。正常情况下扣料后不可能再得到 `already_owned` 或 `invalid_config`；如果发生，属于不变量破坏，必须打 error 日志并记录完整消耗快照，不能静默吞材料。

## 世界用途
炼丹、种植、采集、移动、背包等世界用途仍写在「祭炼」页效果槽，但必须遵守 「效果槽」 的属性归属：**`加属性`只增加法宝自身属性，不直接修改角色。**
| 项 | 规则 |
|---|---|
| 配置位置 | 「祭炼」页效果槽，与战斗效果同列同表 |
| 生效条件 | **御使才生效，持有不生效。** 御使时注册，收回时移除 |
| 法宝自身数值 | 使用 `加属性`，进入 `FabaoContext.ownAttr`，供法宝技能、词条与威能读取 |
| 影响角色或生产系统 | 使用 `调用BUFF` / `调用词条` / `调用技能`；目标、触发与数值由被引用配置定义，并携带法宝来源 |
| 新增一种世界用途 | 在对应系统新增可复用的 BUFF / 词条 / 技能，再把其 ID 填进法宝效果槽。法宝系统核心代码不改 |
| 不要做的 | ❌ 把法宝 `ownAttr`直接累加到英雄属性　❌ 世界能力专用表　❌ 让世界系统反向遍历法宝 |

「法宝」页的 `combat_desc` / `world_desc` 对应界面上「战斗效果」「世界用途」两栏。

> ⚠️ **描述文本不是执行配置。** 程序不得把 `combat_desc` / `world_desc` 当作任何运行参数解析。实际生效的永远只有效果槽。

> 例：吞火葫芦要提高炼丹表现，应调用一个由炼丹/BUFF/词条系统定义的效果；不能把“炼丹成功率”塞进英雄通用属性，也不能要求炼丹系统遍历玩家当前御使的全部法宝。

## 配置表结构
配置文件 `F法宝.xlsx`，五个导出页签：**法宝 / 祭炼 / 打造 / 威能权重 / 全局参数**，外加一个不导出的「说明」页。

**效果槽结构与 `D丹方丹效表.xlsx`「丹方表」完全同构**，用同一套 `行为 / 参数ID / 数值` 写法。

## 表头规范
沿用项目 Luban 四行表头。**首列是控制列**：
| 行 | 控制列 | 内容 |
|---|---|---|
| 1 | `##var` | 导出字段名。数组字段只在首列声明一次，续列留空；辅助列同样留空，不生成运行时字段 |
| 2 | `##type` | 字段类型 |
| 3 | `##group` | 导出分组，`c` ＝ 客户端 |
| 4 | `##` | 中文说明行，不导出 |
| 5+ | `#` / 空 | 数据行。首列 `#` ＝ 该行停用不导出 |

> ⚠️ **导表器以「下一个已声明字段」断数组边界。** 数组字段后面必须紧跟一个已声明字段，辅助列一律排在表尾。排错了不会报错，只会把后面的列吞进前一个数组。
>
> ⚠️ `#`表示整行不导出；已导出的配置中 `enable=false`表示不进入运行时有效索引。主表或当前层被停用时，已有存档保留但标记配置异常；新获取、御使、祭炼与打造都不得使用停用配置。

| `##var` | `##type` | 中文 | 说明 |
|---|---|---|---|
| `fabao_id` | int | 法宝ID | 主键。**只需本页内唯一**，跨表跨系统可重复 |
| `name` | string | 名称 | |
| `category` | FabaoCategory | 所属类 | 战斗 / 生产 / 辅助。只影响 UI 分组，不影响任何规则 |
| `quality` | ItemQuality | 品质 | 复用现有六档枚举，不新建 |
| `realm_id` | int | 境界 |法宝自身境界，**同时是御使门槛**：角色当前境界 ≥ 本值才能御使。`0` ＝ 无门槛。复用现有境界口径，不新建 |
| `icon_id` | string | 图标资源 | ⚠️ **必填**。留空时 UI 图标是透明的，且不报错 |
| `model_id` | string | 模型资源 |**留空 ＝ 不创建表现实体** |

## 页签「祭炼」一行 = 「某件法宝的某一祭炼层」。**法宝的全部效果都在这里。每件法宝必须有 0 层，层数从 0 连续。当前层行是该层的最终完整快照，不是相对上一层的增量。**（一）
| `##var` | `##type` | 中文 | 说明 |
|---|---|---|---|
| `refine_id` | int | 祭炼ID | 主键。建议按 `法宝ID × 100 + 祭炼层` 生成，便于人工对照，不强制 |
| `fabao_id` | int | 法宝ID | 外键 |
| `refine_lv` | int | 祭炼层 | 0 层必填；同一法宝必须 0、1、2… 连续 |
| `forge_skill_lv_req` | int | 炼器技能等级要求 |升到本层所需的现有「炼器」技能等级；1层起必填正整数，0层留空 |
| `realm_req` | int | 祭炼境界要求 |**祭炼门槛**，与 `法宝.realm_id`（御使门槛）互相独立。升到本层所需大境界ID；1层起必填，0层留空 |

## 页签「祭炼」一行 = 「某件法宝的某一祭炼层」。**法宝的全部效果都在这里。每件法宝必须有 0 层，层数从 0 连续。当前层行是该层的最终完整快照，不是相对上一层的增量。**（二）
| `##var` | `##type` | 中文 | 说明 |
|---|---|---|---|
| `materials` | array,FabaoMaterial | 材料1~3·物品ID / 数量 | 升到本层所需的**背包物品**。两项成对；0 层留空 |
| `money_id` / `money_count` | int | 消耗货币ID / 数量 |与背包物品分开，理由见下；0 层留空 |
| `success_rate` | int | 成功率 |**1 层起必填**，万分比 1~10000；**0 层必须留空** |
| `effects` | array,FabaoEffect | 效果1~8·行为 / 参数ID / 数值 |**法宝全部效果**。结构见 「效果槽」 |

## 页签「祭炼」一行 = 「某件法宝的某一祭炼层」。**法宝的全部效果都在这里。每件法宝必须有 0 层，层数从 0 连续。当前层行是该层的最终完整快照，不是相对上一层的增量。**（三）
| `##var` | `##type` | 中文 | 说明 |
|---|---|---|---|
| `inherits` | array,FabaoInherit | 继承1~4·属性名 / 比例 | 当前层最终继承比例快照，万分比。留空 ＝ 该属性不继承 |
| `sense_reduce` | int | 神识减免 | 当前层最终减免值 |
| `model_id` | string | 模型资源 | 允许逐层换模型；留空则用「法宝」页的 |
| `enable` | bool | 是否启用 | `false`不计入连续层与有效0层；当前存档命中停用层时保留记录并标记配置异常 |
| —（辅助） | — | 【辅助·回显】法宝名、【辅助】配置备注 | 不导出 |

**`FabaoEffect` bean = `{action, param, value}`**，合法 `action` 与填写规则见 「效果槽」。

> ⚠️ **属性名（效果槽的 `加属性`、继承组、威能权重页）必须存在于 `S属性配置表.attr_config.name`。**
> 填一个不存在的属性名，配置会被正常解析，但战斗系统读不到它——**完全无效且不报错**。必须在转表阶段做白名单校验并报错。

>**货币和背包物品必须分成两组列。** 材料校验查背包、货币校验查资源账户，是两条不同的查询路径。混在同一组列里代码无法判断该查哪个仓，典型症状是 **UI 显示"材料够"、点下去报 `material_not_enough`**。

>**转表强校验**：每个 `fabao_id` 有且只有一条 0 层；层数从 0 连续无缺层；【辅助】预期最大祭炼层 等于最高连续层；`basic_skill_id` 与效果槽内各 ID 在对应表中存在；`加属性` 必填数值、其余三种行为数值列必须留空；同层重复的「调用技能 / 调用BUFF / 调用词条」行为 + ID 禁止，效果槽技能ID不得与 `basic_skill_id` 重复；0 层 `success_rate / forge_skill_lv_req / realm_req` 全部为空；1 层起 `success_rate` 为 1~10000，`forge_skill_lv_req / realm_req` 为正整数；`sense_cost_min ≤ sense_cost`；`法宝.realm_id` 必填且 ≥ 0。任一不满足直接阻止生成配置。

## 页签「全局参数」
一行 = 一个全系统参数。**本期只支持全局值**，不做单件覆盖。
| `##var` | `##type` | 中文 | 说明 |
|---|---|---|---|
| `param_key` | string | 参数名 | 主键，取值见下表 |
| `value` | float | 参数值 | 类型与范围由各 `param_key` 自行约束 |
| `unit` | string | 单位 | 仅供策划看表，代码不读 |
| `desc` | string | 说明 | 仅供策划看表，代码不读 |

必须配置的 `param_key`：
| `param_key` | 用途 |
|---|---|
| `CombatExitDelaySec` | 脱战冷却（「进战检测」） |
| `TargetSearchRadius` | 目标搜索半径（「目标选择」） |
| `TargetAbandonDistance` | 放弃追击距离（「目标选择」） |
| `OrbitRadius` / `OrbitPeriodSec` | 绕飞半径 / 周期 |
| `OrbitHeight` | 飞行高度 |
| `EngageMoveSpeed` | 近战追击时法宝逻辑坐标的移动速度 |
| `VisualTickSec` | 表现 tick |
| `MaxVisibleIndependent` | 每玩家同屏表现实体上限 |

> ⚠️ **程序不得为这些参数准备表外兜底默认值。** 表里缺一个就应该在转表阶段报错，而不是运行时悄悄用一个魔法数字——那样改表不生效，排查时会怀疑到完全无关的地方。

>**转表强校验**：必需 `param_key` 齐全且唯一；`value` 类型与范围合法；`TargetSearchRadius >= TargetAbandonDistance`（不满足时怪物游走到两值之间的区间，法宝会既不追击也不重新索敌，表现为彻底罢工）；`VisualTickSec > 0`；`MaxVisibleIndependent >= 1`。
> 📌 **后续整体迁入 `X系统参数`**，届时本页删除。

## 待定项
**当前无程序侧待定项。** 炼器门槛直接复用现有「炼器」技能等级查询接口，不新增法宝专属等级；三处境界门槛（御使 / 祭炼 / 打造）都读角色当前大境界ID，不新增境界字段。

已收口：效果统一走效果槽（加属性 / 调用技能 / 调用BUFF / 调用词条），战斗与世界用途不分表；每名玩家同屏表现实体上限读 `MaxVisibleIndependent`，超出部分逻辑继续生效只隐藏表现；本期无祭炼保底；属性名与各类 ID 在转表阶段强校验；本期表现只做绕飞跟随 + 追敌攻击。

**内容侧**：具体哪些法宝进本期的掉落、打造与奖励，由策划按内容排期决定（「获取」），不构成程序侧的实现约束。
