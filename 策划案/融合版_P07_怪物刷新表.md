# P07 怪物刷新表

> 版本：v2.0｜2026-08-05｜现行刷新方案定义
> 定位：定义区域何时激活刷新、生成哪些怪物、数量上限与重刷时机。实际列名和主键以配置表为准。

## 一、逻辑结构

每行表示一个刷新方案，一个方案最多包含10组怪物：

```text
spawn_plan_id
region_id
trigger_mode
initial_delay
respawn_interval
monster_groups[1..10] { monster_id, initial_count, max_alive }
```

配置表可将10组怪物展开为固定列，但运行时必须解析成统一数组。

## 二、激活时机

| 枚举 | 行为 |
|---|---|
| `ON_ROOM_START` | 房间初始化后按延迟激活 |
| `ON_FIRST_ENTER` | 第一名玩家进入区域时激活一次 |
| `ON_EACH_ENTER` | 每次进入触发；V0禁止使用，避免重复生成 |

V0灰盒区域默认使用 `ON_FIRST_ENTER`。激活标记按房间和方案保存，同一方案只激活一次。

## 三、生成位置

- 刷新方案引用一个有效区域。
- 生成点必须位于区域边界内且不在阻挡、出生安全区或不可达位置。
- 多只怪物保持最小间距；超过重试上限时记录失败，不在非法坐标强行生成。
- 区域同时提供AI返回边界；具体实例仍记录本次出生点。

## 四、重刷

1. 怪物死亡事件只登记一次。
2. 尸体销毁后减少对应方案和怪物组的存活数。
3. 从尸体销毁时开始计算重刷间隔。
4. 计时结束后再次校验方案已激活、区域有效、当前存活数低于上限。
5. 创建成功后增加存活数；创建失败不增加。

## 五、字段边界

- `spawn_plan_id`、`region_id` 和 `monster_id` 的实际类型服从配置表，不在文档中另造ID格式。
- 时间单位在Schema中统一；运行时不得同时混用秒和毫秒。
- 刷新间隔只在刷新表维护，怪物静态表不重复保存第二个重刷真值。
- 一个怪物可被多个刷新方案引用。

## 六、校验

- 方案主键唯一，区域和怪物引用存在。
- 每组 `initial_count <= max_alive`，数量不为负。
- 重刷间隔和初始延迟不为负。
- 每行有效怪物组不超过10。
- V0禁止 `ON_EACH_ENTER`。
- 激活、死亡和重刷事件必须幂等。

> 修订：v2.0 统一为“一方案最多10组怪物”，明确首次进入激活、区域边界和唯一重刷时机。
