## 1. 时间体系

以下换算固定，不进配置表，不允许由其他系统修改。

| 中文 | 英文 | 换算 |
|---|---|---|
| 刻 | `quarter` | 现实 37.5 秒 |
| 时辰 | `game_hour` | 8 刻 = 现实 5 分钟 |
| 游戏日 | `game_day` | 12 时辰 = 现实 60 分钟 |

十二时辰顺序固定为 子→丑→寅→卯→辰→巳→午→未→申→酉→戌→亥，循环推进，**不产生任何时段修炼倍率**。

**单位约定**

- 速率类字段（每时辰产出、每时辰吸收、每时辰基础修为）以**游戏时辰**为单位。
- 时长类字段（虚弱时间、丹药持续时间）以**现实秒**为单位。
- 比率类字段用**万分比**整数，填 5000 表示 50%。

**时长的界面显示格式**

统一为 **「X时辰X刻」**，最小单位为刻，**不使用「天」**。

| 规则 | 说明 |
|---|---|
| 不用「天」 | 1 游戏日 = 现实 1 小时。显示「3天」玩家会误读成现实 3 天，误导性最大。时辰与刻是纯游戏词，不会引起这种联想。 |
| 写「时辰」不写「时」 | 「时」易被读作小时。 |
| 时辰为 0 时省略 | 只显示「X刻」。 |
| 不足 1 刻向上取整 | 避免出现「0刻」但状态尚未结束。 |

示例：96 刻 →「12时辰」；100 刻 →「12时辰4刻」；5 刻 →「5刻」；剩 0.3 刻 →「1刻」。

在线结算周期为 1 刻（现实 37.5 秒），另有事件触发点即时补算；离线不逐刻执行，上线时按总时长一次性算完。详见 §4.0、§8。

## 2. 境界体系

### 2.1 大境界枚举

| `realm_id` | 大境界 | 等级区间 | 层数 |
|---:|---|---|---:|
| 1 | 炼气 | Lv1–10 | 10 |
| 2 | 筑基 | Lv11–20 | 10 |
| 3 | 金丹 | Lv21–30 | 10 |
| 4 | 元婴 | Lv31–40 | 10 |
| 5 | 化神 | Lv41–50 | 10 |
| 6 | 炼虚 | Lv51–60 | 10 |
| 7 | 合体 | Lv61–70 | 10 |
| 8 | 大乘 | Lv71–80 | 10 |

共 8 个大境界 × 10 层 = 80 级。第一境统一写作「**炼气**」，旧写法已于 2026-08-01 全项目替换完毕。Lv80 为当前版本的等级终点。

> **`realm_id = 0`（凡）保留给物品与生物，不可玩。** 物品、野兽、材料需要标定"不为修士设计"这一档（凡铁、凡草、后山的普通野兽），因此 `realm_id` 的完整值域是 **0–8 共九档**；角色境界只用 1–8。本表不变，只是明确 0 号档位已被占用，不得他用。见 `世界观_中间层-物质法则.md` §二 双轴总表。
>
> **渡劫不是大境界**，是大乘圆满之后的特殊阶段，不占 `realm_id`（本文 §2.3.1 已如此处理，此处重申）。

### 2.2 小境界与阶段

每个大境界固定十层：1–3 层前期、4–6 层中期、7–9 层后期、10 层圆满。

### 2.3 突破边界

**每一级升级都必须由玩家主动点击确认，没有任何自动升级。** 修为达到 `exp_level_up` 后停在当前等级，界面出现突破按钮，等待玩家操作；期间继续累计溢出修为。

### 2.3.1 `boundary_type`：界面叫法

| 填法 | 玩家可见叫法 | 位置 | 数量 |
|---|---|---|---:|
| 小 | **突破** | 每个大境界的 1–9 层 | 72 |
| 大 | **破境** | 每个大境界的第 10 层 | 8 |

本字段只决定界面用词与表现分量，不决定成功后会发生什么。Lv80 填「大」，其成功后的去向另行定义。大乘之后的**渡劫**是独立于本字段的特殊事件，本期不做。

### 2.3.2 两类突破

所有突破都要点，区别在于要不要材料、会不会失败：

| | 直接突破 | 材料突破 |
|---|---|---|
| 位置 | 每个大境界的 1、2、4、5、7、8 层 | 3、6、9 层 + 第 10 层 |
| 数量 | 48 | 32 |
| 玩家操作 | 点一下 | 点一下 |
| `materials` | 不配置 | 必须配置，不足无法发起 |
| `base_success_rate` | 10000 | 配置决定 |
| 突破丹 | 无意义，界面不提供 | 可当场投入，提高本次成功率 |
| 结果 | 必定成功 | 按概率判定，可能失败 |
| `fail_weakness` | 不配置 | 必须配置，失败后按此进虚弱 |

**直接突破**：点一下立即完成，不消耗任何东西，不会失败。它存在的意义是给玩家一个可感知的推进动作和反馈时刻。

**材料突破**：需要材料才能发起，可另外投入突破丹提高成功率，然后判定。失败进入虚弱状态。

程序对两类走同一条流程、不做特判：读 `materials` 检查并扣除，读 `base_success_rate` 判定，失败读 `fail_weakness` 进虚弱。配置为 10000 且无材料的行，自然走成一路成功、无消耗。

策划想把某一级从直接突破改成材料突破，给它配上材料并把成功率调到 10000 以下即可，不需要改程序。

## 3. 修为与状态

1. 修为是累计进度，不是可消耗资源。
2. 修为达到 `exp_level_up` 后停在当前等级，出现突破按钮，等待玩家点击。**没有自动升级。**
3. 突破成功、失败均不清空累计修为；突破线之后继续累计的修为记为**溢出修为**。
4. 溢出修为不可跨越任一突破节点。
5. 对玩家文案、UI 和对外字段一律不用「经验」「经验条」。

### 3.1 状态优先级

| 优先级 | 状态 | 结算规则 |
|---:|---|---|
| 1 | 虚弱 | 禁止突破；不能吸收灵气；灵气源继续产出但不被消耗；基础修为按虚弱倍率 |
| 2 | 瓶颈 | 已达突破线未突破；溢出修为继续累计 |
| 3 | 正常 | 按完整修炼规则结算 |

离线是结算方式，不是角色状态。

## 4. 修为结算

### 4.0 运行时流程

#### 打坐可以在任何地方进行

**底层规则：角色在任何位置都可以打坐修炼。有没有灵气源、灵气源好不好，决定收益差多少，而不是决定能不能修炼。**

| 打坐位置 | 收益 |
|---|---|
| 洞府 | 基础修为 + 灵气修为，洞府可另有加成 |
| 野外临时灵气源（见 §5.6） | 基础修为 + 灵气修为 |
| 宗门修炼室等共享源 | 基础修为 + 灵气修为 |
| 无灵气源的任意地点 | **只有基础修为** |
| 有灵气源但名额已满 | **只有基础修为** |

#### 默认状态：进游戏就在洞府打坐

**角色每次进入游戏，默认状态就是「在自己的洞府中打坐」，修炼面板默认打开。** 玩家不需要先去找按钮、不需要任何前置操作，进来就已经在修炼。

上线顺序：登录 → 弹出闭关结算窗（见 §13.6）→ 关闭结算窗 → 界面停留在洞府打坐面板，角色已处于打坐状态。

**角色下线时自动进入闭关修炼**，无需玩家操作，见 §8。

#### 进入与退出

| 操作 | 效果 |
|---|---|
| 点「**打坐修炼**」 | **一键传送回洞府并直接开始打坐**，一步到位，不需要再做任何额外操作。用于玩家在外面时快速回来 |
| 就地打坐 | 在当前位置直接进入打坐状态，不移动 |
| 点「**出关**」 | 停止打坐，释放名额；若此前是被传送进洞府的，传送回原处 |

无论哪种方式，进入打坐即置 `is_meditating = true`。**只有 `is_meditating = true` 时才结算修为**，未打坐不产生任何修为，基础修为也不产生。

#### 灵气源名额

角色开始打坐时，若当前位置有灵气源且未满员，自动占用 1 个名额。**名额先到先得**——`max_absorbers` 为 3 时，前 3 个进入打坐状态的角色享受灵气，第 4 个照样能打坐，但只拿基础修为。

名额与 `is_meditating` **严格绑定、同生同灭**，以下情况立即释放：

1. 点「出关」
2. 离线或掉线
3. 因任何原因离开该灵气源所在场景
4. 该灵气源本身消失（临时源到期或被销毁）

不设重连宽限，不设保留位。判断某角色是否占位一律读 `is_meditating` 与 `cultivation_location`，不另设标记。名额已满时不排队，玩家可以选择留在原地只拿基础修为，或另寻他处。

#### 结算周期

**在线：每 1 刻（现实 37.5 秒）由服务端结算一次。**

配置中的速率一律以「每时辰」为单位，每次结算取 **1/8**（1 时辰 = 8 刻）。

另有下列**事件触发点**，发生时立即补算一次，不等下一刻：

- 玩家打开修炼界面
- 玩家点击突破
- 进入或离开灵气源
- 服用丹药
- 下线

选 1 刻而非更高频的理由：修为是时间的线性函数，任何时刻都能由「上次结算时间 → 当前」一次算出，高频结算不产生任何额外精度。1 刻与游戏时间体系和界面显示单位对齐；一个 24 人房间的服务端负载约 0.64 次/秒，可忽略。

**界面上的数字增长由客户端自行插值**，不依赖服务端推送，玩家看到的仍是平滑变化。

**离线**：不逐刻模拟，上线时按离线总时长一次性算完，见 §8。

#### 单次结算的执行顺序

固定按下列顺序，不得调整：

1. **灵气源产出**：`当前储量 = min(当前储量 + spirit_rate ÷ 8, spirit_cap)`。若 `spirit_total > 0`，同步累加「已累计产出」，达到 `spirit_total` 后该源停止产出。
2. **计算可分配灵气**，按 §5.4 分给所有占用名额的角色。
3. **扣减灵气源储量**。
4. **结算修为**：按 §4.2、§4.3 计算，累加到 `cultivation_total`。
5. **耐药值自然恢复**。
6. **虚弱倒计时**，到时解除虚弱。
7. **限时效果倒计时**，到期移除。
8. **检查突破条件**：`cultivation_total` 达到 `exp_level_up` 则标记为可突破，界面出现突破按钮。**不自动升级**，等待玩家点击。

先产出后吸收，保证本刻产出的灵气本刻即可被吸收。

#### 数值精度

服务端为 TypeScript，数值为双精度浮点，**直接按公式计算即可，不需要定点数或放大整数**。全程最坏累积误差远小于 1 点修为。

存档序列化时对 `cultivation_total` 取整。

### 4.1 结算原则

修为结算**只读取角色当前的属性值**，不追溯这个值由哪个系统加的。

```text
角色当前属性值 = 境界表提供的基础值 + 当前所有生效来源的加成
```

来源可以是所在的灵气源或场景、丹药、功法、装备、BUFF 等任意系统，修炼系统不区分。

### 4.2 基础修为

无论有没有灵气源，只要在打坐就产生基础修为。

```text
基础修为 = [ 每时辰基础修为 × (1 + 基础修为增幅 ÷ 10000) + 额外基础修为 ]
           × 虚弱倍率 × 经过时辰数
```

**万分比增幅只放大 `每时辰基础修为`，不放大 `额外基础修为`。**

### 4.3 灵气修为

只有占用到灵气源名额并分配到灵气时才产生。

```text
实际吸收灵气 = min( 每时辰灵气吸收 , 灵气源本次可分配给本角色的份额 ) × 经过时辰数

灵气修为 = 实际吸收灵气 × [ 基础转化值 × (1 + 转化值增幅 ÷ 10000) + 额外转化值 ]
```

**万分比增幅只放大 `基础转化值`，不放大 `额外转化值`。**

### 4.4 合计

```text
本次修为 = 基础修为 + 灵气修为
```

两段结构完全对称，都是「基数 × (1 + 万分比增幅) + 额外加值」：

| | 基数 | 万分比增幅 | 额外加值 |
|---|---|---|---|
| 基础修为 | 每时辰基础修为 | 基础修为增幅 | 额外基础修为 |
| 灵气转化 | 基础转化值 | 转化值增幅 | 额外转化值 |

式中所有量**全部取角色当前属性值**（境界表基础值 + 一切来源的加成），见 §4.1、§11。

## 5. 灵气源系统

### 5.1 分类

| `source_type` | 说明 | 储量存放位置 |
|---|---|---|
| 个人 | 每名角色各有一份独立储量 | 角色存档 |
| 共享 | 全场一份储量，在场角色共用 | 场景运行时状态 |

洞府、秘境、宗门修炼室、福地等只需在 `L灵气源配置表` 增加一行，不新增修炼公式。

### 5.2 引用方式

洞府等级表、场景表、宗门设施表各自持有一个 `spirit_source_id` 字段指向本表，**单向引用**，本表不反向记录来源。

`source_id` 取值规划：1xxx 洞府、2xxx 秘境、3xxx 宗门设施。

### 5.3 产出与储量

- `spirit_rate`：每游戏时辰自然生成的灵气量。
- `spirit_cap`：最多能积攒多少灵气，到上限停止积累。
- `spirit_total`：该灵气源**实例在其整个生命周期内**累计最多能产出多少灵气，产满后枯竭、不再产出。

**统计范围**：从该源实例被创建/开启起算，到它被关闭、注销或销毁为止，一共产这么多，与游戏局数无关。秘境这类每局随机生成的源，每个新实例都是一个新的额度，从 0 重新累计；实例销毁时累计值一并消失。

**运行时**：每个源实例需要维护一个「已累计产出」计数器，存放位置与当前储量同一套规则——个人源存角色存档，共享源存场景运行时状态。

**填法**：

| 填什么 | 含义 |
|---|---|
| 0 或留空 | 无限产出，不做总产量检查 |
| 正数 | 累计产满该值后枯竭 |

程序判断 `spirit_total <= 0` 时跳过总产量检查。

**为什么 0 可以用来表示无限**：「总产量为 0」这个状态在业务上不存在——一个一共只产 0 点灵气的源，等价于根本不产灵气，而那件事的正确表达是 `spirit_rate = 0`（每时辰产 0 点）。所以 0 在本字段上是空闲值，用来表示无限不会挡住任何合法配置，也就不需要 `-1` 这类魔法值或可空类型。

**要让某个源不产灵气，填 `spirit_rate = 0`，不要用 `spirit_total = 0` 表达。**

### 5.4 名额与分配（固定规则，不进配置表）

1. **名额先到先得。** 占用人数达到 `max_absorbers` 后，后来的角色**仍然可以在原地打坐**，但不占名额、不吸灵气，只获得基础修为。不排队。
2. 每位占用名额的角色先按自己的 `每时辰灵气吸收` 提出需求。
3. 灵气足够时，每人获得全部需求量。
4. 灵气不足时，按需求比例分配剩余灵气，单人不得超过自身吸收上限。
5. 本次分配不到灵气的角色，本次结算只获得基础修为。
6. 个人源 `max_absorbers` 固定为 1。

### 5.5 充盈与干涸

| 状态 | 判定 | 效果 |
|---|---|---|
| 充盈 | 本次结算能分配到灵气 | 结算灵气修为 |
| 干涸 | 本次结算分配不到灵气 | 不结算灵气修为，只获得基础修为 |

不设中间档。充盈/干涸只用于界面反馈，不替代存量、产出、吸收和分配规则。

### 5.6 野外临时灵气源

野外会不定期开启灵气充裕的地点，玩家可以走过去就地打坐修炼，机制与洞府完全相同，只是配置数值不同。

| 项 | 规则 |
|---|---|
| 开启方式 | 由场景/玩法系统在野外随机生成，形式类似「蓝门」——出现一个可进入的地点或区域 |
| 配置 | 与其他灵气源一样，在 `L灵气源配置表` 占一行，`source_type = 共享` |
| 修炼规则 | 与洞府同一套公式，无任何特殊逻辑 |
| 名额 | 按 `max_absorbers` 先到先得。配 3 就是前 3 个进入打坐状态的角色享受灵气，第 4 个只拿基础修为 |
| 前台提示 | **必须给足提醒**，见 §13.5 |
| 生命周期 | 属于临时实例。场景关闭、临时源到期或被销毁时，该源连同其储量与「已累计产出」一并消失 |
| 离线 | 角色离线即失去该源，离线闭关一律回洞府结算，见 §8 |

**与洞府的区别只在配置**：洞府是个人源、随洞府等级成长、可被家具阵法加成；野外临时源是共享源、参数由玩法系统决定、有时限。修炼系统对两者一视同仁。

## 6. 突破与破境

术语：**突破**（层内与阶段边界）＜ **破境**（跨大境界）＜ **渡劫**（大乘之后，本期不做）。下文「突破」在泛指时同时涵盖突破与破境。

### 6.1 突破与破境

前置条件：修为达到 `exp_level_up`、角色未虚弱、材料充足、**玩家主动点击**。

**执行顺序固定为「先扣后判」：**

1. 检查前置条件
2. **扣除材料与本次投入的突破丹**
3. 判定
4. 成功则升级；失败进虚弱

直接突破（无材料、成功率 10000）走同一条流程，只是第 2 步无可扣、第 3 步必过。

这个顺序是反作弊要求：先扣后判，最坏情况（断线、崩服）是扣了没判，玩家亏材料；反过来则是判成功了没扣，玩家可以卡断线白嫖突破。**失败不退还材料与丹药。**

```text
最终成功率 = realm_config.base_success_rate + 本次使用的突破丹加成
```

突破丹在突破界面**当场选择使用**，不是提前服用挂 buff。

突破成功率**不是角色属性**，不常驻在角色身上，只在突破发生时现场计算。

`materials` 配置本次突破必须消耗的材料，最多 3 组，每组为「材料ID + 数量」。**材料不足时无法发起突破。** 直接突破的行不配置。

`challenge_condition_group` 用于配置渡劫、心魔、指定击杀等附加挑战条件，条件内容由对应玩法系统定义，修炼系统只读取「是否满足」与「挑战结果」。**当前版本不配置，整列留空。**

### 6.2 结果

1. 成功：进入下一等级，累计修为与溢出修为保留。
2. 失败：不扣修为、不掉等级、不退大境界；进入虚弱状态。

### 6.3 虚弱（固定规则）

突破失败后角色进入**虚弱状态**，这是一个挂在角色身上的 debuff，有明确图标、剩余时间和效果说明。

| 项 | 规则 |
|---|---|
| 能否吸收灵气 | 否，占用的名额同时释放 |
| 基础修为效率 | 10% |
| 能否突破 | 否，突破按钮置灰 |
| 灵气源 | 继续按自身规则积攒，角色不消耗 |
| 时长 | 读 `realm_config.fail_weakness`，单位现实秒；界面按「X时辰X刻」显示 |
| 解除 | 时间到自然解除；**可服用丹药缩短剩余时长** |

丹药缩短虚弱的具体形式（直接扣减固定秒数，还是按比例缩短）在丹药系统设计时确定。

## 7. 丹药与耐药

1. 丹药挂**双轴**：`realm_id`（0-8，决定这颗丹给哪个境界服用）× `pill_quality`（1-6 六档品质：凡/灵/玄/仙/神/道品，决定效果强度与丹毒）。每颗丹药不按固定类别写死，而是配置一个或多个效果，效果目标取自属性表。
2. **不设置每日服药次数，也不设置大境界突破刷新次数。** 日常服药的唯一节流机制是耐药负荷与自然恢复。
3. 耐药性按耐药组累计，由丹药配置指定所属组。
4. 服药时先按当前耐药值结算药效，再增加对应耐药负荷。
5. 耐药值随游戏时间自然恢复，在线离线均恢复。
6. 药效衰减公式、耐药上限、最低药效、恢复速度由耐药配置表决定。

## 8. 离线闭关

1. 角色下线时**自动进入洞府闭关修炼，无需玩家任何操作**，也**无论下线时身在何处、是否正在打坐**。单次上限读 `X系统参数.xlsx` 的 `参数_闭关时长`，默认 9（现实 9 小时 = 游戏内 9 天）。超出上限的时长不产生收益。
2. **灵气源固定为角色自己的洞府**，读存档 `cave_source_id`。不使用下线时所在的灵气源，秘境、宗门修炼室等共享源一律不参与离线结算。
   - 与 §4.0「离线立即释放灵气源名额」配套：名额已让给在线角色，收益自然也不再来自该源。
   - 由此规避：共享源分配依赖他人实时行为无法重演、秘境实例已销毁、挂机占源刷收益。
3. **离线时长的起点**：正常点「出关」或退出时即时记录；异常掉线时取**最后一次心跳的时间**，不取心跳超时判定的时刻。客户端心跳超时阈值为 7 分钟，取超时时刻等于白送这段时间。
4. 除灵气源固定为洞府外，离线闭关使用与在线**完全相同**的基础修为、灵气吸收、虚弱、耐药和加成规则。
5. **离线期间不发生任何突破**，只累加修为，等级不动。上线后修为若已达标，界面出现突破按钮，由玩家逐级点击。
6. **结算方式：上线时按离线总时长一次性算完，不逐秒模拟。** 洞府为个人源（`max_absorbers = 1`），无他人竞争分配，整段收支闭式可解。

### 8.1 结算步骤

设离线经过的游戏时辰数为 **T**（已按闭关上限封顶）。

**第一步：分段。** 只有下列事件会改变结算参数，各自算出发生时刻，把 T 切开。正常情况 1 段，最多 3 段：

| 事件 | 发生时刻 |
|---|---|
| 虚弱结束 | 存档中的剩余虚弱时长 |
| 灵气源总产量耗尽 | `(spirit_total − 已累计产出) ÷ spirit_rate`，`spirit_total <= 0` 时不发生 |

**第二步：逐段套闭式公式。** 每段时辰数记为 t：

```text
本段产出 = spirit_rate × t
可吸总量 = 段初储量 + 本段产出
需求总量 = 每时辰灵气吸收 × t          （虚弱段填 0）
实际吸收 = min(可吸总量, 需求总量)
段末储量 = min(可吸总量 − 实际吸收, spirit_cap)

基础修为 = 每时辰基础修为 × 虚弱倍率 × t
灵气修为 = 实际吸收 × [ 基础转化值 × (1 + 转化值增幅 ÷ 10000) + 额外转化值 ]
```

虚弱段与正常段共用同一套公式，区别只在需求总量填 0、虚弱倍率取 10%。

**第三步：写回。**

1. 各段修为累加进 `cultivation_total`
2. 段末储量与「已累计产出」写回存档
3. 耐药值按总时长线性恢复
4. 限时效果按总时长扣减，到期移除

## 11. 属性登记

修炼系统用到的可变量登记在 `__enums__.xlsx` 的 `AttrKey` 枚举和 `S属性配置表.xlsx` 的 `attr_config` 中，其他系统通过 `Attr{key, value}` 指向它们。

```text
角色当前属性值 = 境界表提供的基础值 + 当前所有生效来源的加成
```

| `AttrKey` | 属性名 | `config_id` | 数值形态 | 基础值来自 | 说明 |
|---|---|---:|---|---|---|
| `Attr064` | 每时辰基础修为 | 64 | 整数 | `realm_config.base_cult_rate` | 打坐时每游戏时辰的基础修为产出，有无灵气都产生 |
| `Attr069` | 基础修为增幅 | 69 | 万分比 | 无，默认 0 | 对每时辰基础修为的万分比放大，**不放大额外基础修为** |
| `Attr070` | 额外基础修为 | 70 | 整数 | 无，默认 0 | 每时辰额外增加的固定基础修为，**不被基础修为增幅放大** |
| `Attr065` | 每时辰灵气吸收 | 65 | 整数 | `realm_config.spirit_absorb` | 每游戏时辰最多能从灵气源吸走的灵气量 |
| `Attr066` | 基础转化值 | 66 | 整数 | `realm_config.conversion_base` | 1 点灵气可转化为多少修为的基数 |
| `Attr068` | 转化值增幅 | 68 | 万分比 | 无，默认 0 | 对基础转化值的万分比放大，**不放大额外转化值** |
| `Attr067` | 额外转化值 | 67 | 整数 | 无，默认 0 | 每点灵气额外增加的固定修为，**不被转化值增幅放大** |

七个属性构成两组对称的「基数 / 增幅 / 额外值」三件套，见 §4.4。基数由境界表给出，增幅与额外值默认 0、完全靠外部来源提供。

灵气源自身的 `spirit_cap`、`spirit_rate`、`max_absorbers` 描述的是场景对象，不是角色属性，不登记进 `AttrKey`。

## 12. 角色修炼存档

| 字段 | 含义 |
|---|---|
| `level` | 当前等级 Lv1–80。**必须存档，不可由累计修为推导**——存在「修为已够、玩家尚未确认升级」的状态，推导会多算一级。升级成功时写入。 |
| `cultivation_total` | 全局累计修为，升级不清零。溢出修为 = 本值减去升到当前等级所需的累计量。 |
| `spirit_source_state` | 个人灵气源当前储量与已累计产出；共享源的对应状态由场景运行时保存 |
| `drug_tolerance_state` | 各耐药组的当前耐药值 |
| `weakness_end_time` | 虚弱结束时间，0 表示无虚弱 |
| `is_meditating` | 当前是否处于打坐。灵气源名额占用与本字段严格绑定，见 §4.0。 |
| `cultivation_location` | 当前所在灵气源的 `source_id`，用于在线结算与界面展示。为空表示不在任何灵气源。**不参与离线结算。** |
| `cave_source_id` | 角色自己的洞府对应的灵气源 `source_id`，由洞府系统维护，修炼系统只读。离线结算固定取此源，见 §8。 |
| `active_cultivation_effects` | 当前生效的丹药、功法等限时效果 |
| `last_settle_time` | 上次结算时间，防止重复结算 |
| `offline_start_time` | 离线开始时间。正常退出时即时记录；异常掉线取最后一次心跳时间，见 §8。 |

无「每日已服药次数」字段。

## 13. 前台表现与交互

本章供 UI 与美术做交互设计使用。**只定义「哪些时候要有什么信息、什么反馈」，不规定布局、配色和具体美术资源。**

### 13.1 修炼 HUD：打坐时的常驻信息

打坐状态下界面必须能看到以下六组信息。分组是逻辑分组，不是布局要求。

| 组 | 展示项 | 数据来源 |
|---|---|---|
| **境界** | 当前境界名（如「筑基三层」）、所处阶段（前/中/后期、圆满）、大境界标识 | `display_name`、`phase`、`realm_id` |
| **修为** | 当前累计修为、下一突破线、溢出修为、进度视觉 | `cultivation_total`、`exp_level_up` |
| **效率** | 基础修为/时辰、灵气修为/时辰、合计/时辰 | §4.2、§4.3 实时计算 |
| **灵气源** | 源名称、当前储量／上限、产出速度、本角色吸收速度、充盈或干涸、**名额占用 X/Y** | `L灵气源配置表` + 运行时 |
| **状态** | 虚弱剩余时间、耐药值与当前药效、生效中的丹药／功法效果及剩余时间 | `weakness_end_time`、`drug_tolerance_state`、`active_cultivation_effects` |
| **操作** | 突破按钮、出关按钮 | — |

三条硬约束：

1. 进度视觉可以叫「修为凝练度」之类，**但不得命名或等同为经验条**，文案与字段一律不出现「经验」。
2. 所有时长按 **「X时辰X刻」** 显示，见 §1。
3. 界面数字的增长由**客户端插值**，服务端每刻才结算一次，两者不同步是正常的，以服务端为准做校正。

### 13.2 角色状态的表现

| 状态 | 角色本体表现 | HUD 表现 |
|---|---|---|
| 未打坐 | 正常站立 | 修炼面板仍可查看，效率显示为 0 |
| 打坐中 · 有灵气 | 盘坐；灵气环绕特效，**强度随实际吸收量变化** | 灵气源组高亮，储量条持续变化 |
| 打坐中 · 无灵气源 | 盘坐；无灵气特效或极淡 | 灵气源组灰显，标「此处无灵气」，效率只显示基础修为 |
| 打坐中 · 名额已满 | 盘坐；无灵气特效 | 灵气源组标「名额已满 Y/Y」，提示「仅获得基础修为」 |
| 打坐中 · 灵气干涸 | 灵气特效消失 | 灵气源组标「干涸」，储量显示 0 |
| 修为已满可突破 | 角色身上出现待突破光效 | 突破按钮亮起并带呼吸动效，一次提示音 |
| 虚弱 | 角色形象变灰／低头等受创表现 | 状态组出现虚弱 debuff 图标 + 倒计时，突破按钮**置灰**并说明原因 |

### 13.3 突破交互

**直接突破**（48 级，无材料、必成功）

点按钮 → 立即完成 → 轻量特效 + 新境界名飘字 → 面板刷新。**不弹二次确认**，这一档的设计目的就是一下到位的爽快感。

**材料突破**（32 级，需材料、有失败率）

点按钮 → 弹出突破面板 → 玩家确认 → 判定 → 结果表现。

突破面板必须包含：

| 展示项 | 说明 |
|---|---|
| 目标 | 「筑基三层 → 筑基四层」，第 10 层显示为破境 |
| 基础成功率 | 由 `base_success_rate` 换算成百分比显示 |
| 材料需求 | 每种材料的图标、需求数、持有数；**不足的标红**，此时确认按钮置灰 |
| 可投入突破丹 | 列出可用的突破丹，选中后**实时更新最终成功率** |
| 最终成功率 | 大字突出，随投入实时变化 |
| 失败后果 | 明写「失败将进入虚弱 X时辰X刻」与「**材料与丹药不退还**」 |
| 确认 / 取消 | — |

失败后果必须写在确认之前，因为材料失败不退，这是玩家最容易产生纠纷的点。

### 13.4 关键时刻的反馈强度

同一件事按分量给不同强度，让玩家一眼分辨这次是不是大事。

| 时刻 | 反馈强度 | 内容 |
|---|---|---|
| 修为达到突破线 | 轻 | 角色光效 + 按钮亮起 + 提示音。**不打断当前操作**，不弹窗 |
| 直接突破成功 | 轻 | 短特效 + 境界名飘字 |
| 材料突破成功 | 中 | 特效 + 境界名飘字 + 专属音效 |
| **破境成功**（第 10 层跨大境界） | 重 | 全屏光效 + 角色变身式表现 + 音效。**不做广播**，表现只对本人 |
| 突破失败 | 中 | 反噬特效 + 角色踉跄 + 虚弱图标出现 + 明确文案说明失去了什么 |
| 虚弱解除 | 轻 | 图标消失 + 一次轻提示 |
| 服药生效 | 轻 | 角色短特效 + 对应属性数值跳动 |
| 耐药已高 | 轻 | 服药时提示当前药效已衰减到 X% |

### 13.5 野外临时灵气源的提醒

这是玩家最容易错过的内容，**必须多通道给足提醒**，见 §5.6。

| 阶段 | 提醒方式 |
|---|---|
| 出现 | 屏幕飘字「XX 方向灵气涌动」+ 音效 |
| 定位 | 小地图与大地图标记，标记上带**剩余时间** |
| 远处 | 地面光柱或天空异象，远距离可见 |
| 靠近 | 屏幕边缘方向指示 |
| 进入范围 | 提示「此处灵气充裕，可就地打坐」，同时显示**名额 X/Y** |
| 名额已满 | 标记变灰，提示「名额已满」，玩家仍可打坐但只有基础修为 |
| 即将消失 | 倒计时提示，给玩家收尾时间 |
| 已消失 | 移除标记；若玩家正在此处打坐，提示「灵气已散」并转为只有基础修为 |

### 13.6 上线闭关结算

**每次上线必须弹一次结算窗**，把离线收益集中展示。即使离线时间很短、收益为 0，也要给一个明确交代，不能什么都不显示。

| 展示项 | 说明 |
|---|---|
| 闭关时长 | 按「X时辰X刻」显示；若被闭关上限截断，明确提示「已达上限」 |
| 获得修为 | 本次离线累计 |
| 灵气收支 | 洞府产出量、实际吸收量、当前剩余储量 |
| 当前状态 | 结算后的境界与修为 |
| 可突破提示 | 若修为已达突破线，**在结算窗内直接给突破入口**，不让玩家再去找 |

**关闭结算窗后，界面停留在洞府打坐面板，角色已处于打坐状态**，玩家不需要任何额外操作即可继续修炼，见 §4.0。
