# 炼丹系统 · 第六版数值与配置工作框架 v1.3

**整理**：小G  
**日期**：2026-08-13  
**性质**：炼丹系统后续数值、配置、纸推、交互与经济工作的执行顺序。

## 一、文档职责

《炼丹系统·第六版设计定稿》保存全部正式规则、数值原则、配置归属和待定参数。

本文件只保存：

- 完成第六版所需的工作步骤；
- 各步骤的输入、工作内容和通过条件；
- 临时候选值、反推结果与正式配置值的施工状态；
- 参数变更后的回归范围；
- 最终交付清单。

规则、公式、数值原则或配置归属发生变化时，修改《炼丹系统·第六版设计定稿》；工作顺序、施工范围或通过条件发生变化时，修改本文件；同时影响两者的改动在同一次工作中同步更新内容、标题版本和文件名。

## 二、数值状态

| 状态 | 用途 |
|---|---|
| 临时候选值 | 只供垂直切片和纸推使用，单独保存 |
| 反推结果 | 由组合分布生成，等待回归验证 |
| 正式配置值 | 回归通过后写入权威配置表 |

判定类配置在反推前只建立字段结构；试跑数值不得写入正式配置。

## 三、工作顺序

### 第一步（贯穿全程）：维护正式设计文档

输入：讨论中已经确认的系统裁定。

工作：

- 将正式规则、公式、配置归属和待定参数写入《炼丹系统·第六版设计定稿》；
- 正式规则只记录已经确定的输入、条件、流程和结果；
- 删除公式可以直接推出的解释和重复内容；
- 检查每项规则是否只有一个完整出处。

通过条件：《炼丹系统·第六版设计定稿》能够独立说明系统如何运行，其他文档不补充规则。后续步骤形成新裁定时，同步回写该文档。

### 第二步：冻结数值关系

输入：《炼丹系统·第六版设计定稿》中的系统规则。

工作：

- 确定境界、品质、药力、药性、杂质、丹头、炉膛、剔杂、纯度、成丹率、升品和丹毒之间的输入输出关系；
- 固定单位、取整、上下限和数据归属；
- 将尚无数据依据的常数列入待定参数。

通过条件：每个数值只有一个职责和一个保存位置，全部公式可组成完整结算链。

#### 第二步输出：数学验收框架

本步同时建立后续切片、批量纸推和回调共用的验收指标，不提前填写通过阈值：

- 标准手算案例：覆盖炉膛边界、最低杂质生效、技能熟练、跨境除渣、最低纯度、成丹率、升品、批次和服丹；
- 配方指标：药力达成比`P/U`、丹头占用比`N/Nmax`、技能除渣比`A/Zf`、纯度余量`Q−Qmin`、剩余杂质占池比`D/Cpool`；
- 分布指标：最低杂质触底率、死方率、各类丹头和炉型覆盖率、代表路线成本与有效解数量；
- 经济指标：成丹与升品后的期望产量、单枚期望成本和参考售价；
- 稳定性指标：关键候选参数变动后，死方、全过、路线消失和大面积触底的变化。

各指标的目标区间在垂直切片和第一轮组合纸推后确定。

### 第三步：建立配置骨架

输入：《炼丹系统·第六版设计定稿》中的配置数据归属。

工作：

- 建立灵植表、丹方表、丹炉表、除渣力、丹毒池、成丹率描述、系统参数和属性配置接口；
- 君、臣、佐、使和丹头统一保存在灵植表；
- 每个基础丹方的每个开放品质使用一条完整丹方品质行，成丹条件、丹效、升品率和参考售价保存在同一行；
- 确定主键、引用、字段类型、合法范围、唯一性约束和运行页签；
- 使用中文显示名，同时保留稳定技术表ID和字段ID；
- 建立同方相邻启用品质、特殊丹头、默认材料、除渣来源、丹毒属性和系统参数的引用校验；
- 批次数量由神识与材料公式计算，不新增批次数量配置字段。

产出方式：字段结构和约束逐项人工确认；机械字段与基础行由脚本生成后人工校订。

通过条件：全部数据可沿引用关系导表，同一数据不存在重复保存，配置骨架与《配置表字段与程序使用说明》一致。

### 第四步：筑基境最小垂直切片

输入：配置骨架与临时候选值。

工作：

- 选择5～10个代表丹方品质行，覆盖不同五行、五味、正负药性、品质和炉型；
- 配置一小组臣佐使、君材、丹头和丹炉；
- 直接纸推组方、逐份投药、除渣、纯度、成丹率、升品、批次炼丹、剩余杂质与服用入池；
- 逐步记录每个输入、中间值、取整位置和结果，形成标准手算案例；
- 记录药力带、丹头容量、品质系数、炉膛边界和第二步验收指标暴露的问题。

通过条件：完整结算链可由手算复现，候选数值没有结构性矛盾。切片数据不冻结，标准手算案例作为后续计算脚本的对照答案。

### 第五步：全量配置普通灵植

输入：切片验证后的材料数值范围。

工作：

- 配置臣材的五行及固有数值；
- 配置使材的五味及固有数值；
- 配置佐材的药力、药性与绝对杂质；
- 检查同池材料的药力、药性易用度和杂质取舍；
- 检查各行、各味与正负药性覆盖；
- 价格字段保留，正式价格不冻结；
- 先按材料池规则脚本铺行，再逐池人工校订名称、分布和取舍。

通过条件：不存在同池全面支配材料，高药力、低杂质和易调性路线均有候选材料。

### 第六步：配置君材与丹头

输入：材料药力带和品质目标范围。

工作：

- 配置各境界、各基础品质君材的目标药力与固有数值；
- 配置丹头容量、稀有度和定位；
- 建立特殊丹头的丹方引用关系；
- 用代表坐标检查普通丹头与大丹头的覆盖差异；
- 价格字段保留，正式价格不冻结；
- 按境界与品质脚本建立基础行，再人工配置定位和特殊引用。

通过条件：基础容量支持常规路线，大容量能够提供独立配置空间。

### 第七步：配置丹炉与除渣、丹毒参数骨架

输入：切片结果和配置归属。

工作：

- 配置丹炉最高可炼境界、炉膛、神识门槛、价格字段、启用状态和定位；
- 在除渣力表建立炼丹术、灵植术和丹炉的同境六品质基础值结构；
- 在丹毒池建立各境界五味容量与每日消退率结构；
- 建立成丹率描述、四项炼丹系统参数和炼丹相关属性接口；
- 正式过滤率、技能除渣力、毒池容量、消退率和参数值在反推前保持候选或未冻结状态；
- 检查高境炉向下炼制的数据引用和覆盖统计。

通过条件：各数据只有一个保存位置；炉膛形成宽炉、偏性炉等定位；判定类正式数值保持未冻结。

### 第八步：配置丹方品质行

输入：全量材料、君材、丹头、丹炉和表结构。

工作：

- 脚本生成875个基础坐标及每方三个开放品质行，共用`recipe_id`；
- 每行完整配置境界、基础品质、君材品质、臣行、使味、成丹性值、启用状态和指定丹头；
- 人工配置正式丹名、规则小名、作用说明、丹效行为、参数、数值和持续时间；
- 建立跳档率、最低纯度、最低杂质、神识要求、基础成丹率、成丹率上限、默认投料和参考售价字段；
- 判定类字段使用切片候选值或留空，正式值不冻结；
- 默认投料在第十一步生成，不保存默认投药顺序。

通过条件：875个基础坐标与2625个丹方品质行结构完整；机械字段可重建，人工内容已校订，候选值与正式值状态明确。

### 第九步：第一轮组合纸推

输入：材料、君材、丹头、炉膛及试跑判定参数的候选值。

方法：

- 先建立读取正式表结构的批量结算与代表解搜索脚本，并用第四步标准手算案例逐项对照；
- 对全部启用丹方品质行执行约束求解，同时统计875个基础坐标的结构覆盖；
- 每行寻找最少份数、低剩余杂质、易配平和基础装备代表解；
- 用分层抽样观察解分布；
- 用剪枝状态搜索判定代表解的安全投药顺序；
- 不生成、保存或统计每行的全部配法。

份数指标：

- `N_struct`：不读取最低纯度，满足药力、药性与安全顺序的最少份数；
- `N_clean`：低剩余杂质代表路线的份数。

正式运行前确定求解变量边界、代表解目标函数、抽样规模和停止条件。

检查：

- 启用丹方品质行死方为0，每个代表解至少有一条安全顺序；
- 875个基础坐标均有启用品质行和合理炉型；
- 同池材料不存在全面支配；
- 高药力省位、低药力洁净和易调性路线均成立；
- 普通丹头、大丹头和各类炉型均有独立场景；
- 基础炉与高境炉覆盖符合设计定稿；
- 三种除渣来源的境界差结算正确，来源低境时贡献为0；
- 统计`P/U`、`N/Nmax`、`A/Zf`、最低杂质触底率、`Q−Qmin`和`D/Cpool`；
- 不存在单一选材、份数或炉型策略通吃；
- 整数取整与第四步手算一致，关键候选参数±10%不造成大面积死方、全过、路线消失或普遍触底。

通过条件：全部启用丹方品质行数学可行；脚本与标准手算一致；输出代表解、覆盖率、分布指标、边界问题和敏感性结果。

### 第十步：反推判定类数值

输入：第一轮组合分布。

工作：

- 反推各丹方品质行的最低纯度、最低杂质和神识要求；
- 反推炼丹术与灵植术的基础除渣力及熟练参数；
- 反推丹炉各品质过滤率与低境界炼丹倍率；
- 反推各丹方品质行的基础成丹率、成丹率上限与固定升品率；
- 反推五味毒池容量、每日消退率及每日消退点数取整规则；
- 计算`N_pass`：最低纯度确定后，满足全部硬条件的最少份数；
- 校验每行至少存在一套在最低杂质生效后仍达到最低纯度的合法配方；
- 校验普通丹门槛可弥补性：低一档炉＋该境满熟练技能＋同境最优材料配法的可达纯度不低于该行门槛；
- 用正式候选值重跑全部启用丹方品质行，并复查最低杂质触底率、`A/Zf`和`D/Cpool`。

通过条件：各品质产量进入目标区间；全部启用丹方品质行仍有合法解；普通丹门槛可弥补；没有因除渣量级导致路线消失或普遍触底。

### 第十一步：生成默认方并验证安全顺序

输入：正式候选判定类数值。

工作：

- 为每个启用丹方品质行选择教学可读、材料可得的默认投料；
- 搜索一条安全投药顺序，只把材料ID和数量写入丹方表；
- 将安全顺序与全链路验算结果保存到验证报告，不写入丹方表；
- 按最终药力、药性、炉膛、纯度、最低杂质和丹头条件复核；
- 验证当前“一种臣材＋一种佐材＋一种使材”的默认字段是否足够；不足时退回第三步扩展表结构并重跑第五至第十一步。

通过条件：全部默认方可由程序在运行时找到安全顺序并完成正式炼制；丹方表只保存默认材料与数量。

### 第十二步：交互原型与第二轮玩法纸推

输入：默认方、自由配方和正式结算链。

工作：

- 制作逐份投药、实时炉相、配置检查、确认扣料、正式失败、升品、批次选择、保存配方和自动炼制原型；
- 验证普通玩家使用默认方的成功体验；
- 验证熟手能否通过选材、设备和顺序改善结果；
- 验证玩家能否理解每个配置失败与正式结果；
- 检查是否存在简单操作策略通吃。

失败归因与回退：

- 规则或公式问题退回第一、二步；
- 字段或引用结构问题退回第三步；
- 材料、君材、丹头或丹炉分布问题退回第五至第七步；
- 判定类数值问题退回第十步；
- 默认方问题退回第十一步；
- 交互问题留在本步修改。

通过条件：操作流程可理解，默认玩法与进阶玩法均成立；发现的问题已按来源回退，不用参数调整掩盖规则或结构问题。

### 第十三步：第三轮经济与资源纸推

输入：通过玩法纸推的配置与产量分布。

工作：

- 核算灵植、君材、丹头、丹炉和代表配方成本；
- 核算默认方、洁净方、省位方和高风险方的收益；
- 将成丹失败率、升品率和剩余杂质折价纳入产值；
- 将神识与材料决定的批次上限纳入产量核算；
- 比较低品质炼制后升品与直接炼制高品质的期望产量、成本和利润；
- 确定灵植、君材、丹头、丹炉和各丹方品质行的正式价格；
- 验证六品自用、出售和稀缺定位；
- 验证稀有资源对高品产量的控制；
- 验证高境角色炼低境丹对低境经济的影响。

产出方式：成本、概率和产量由脚本计算；路线定位、稀缺度和价格由人工审定。

通过条件：主要路线均有经济定位，不出现单一路线垄断、低境经济失效或未经设计的升品套利。

### 第十四步：联合压力测试与回调

输入：数学、玩法和经济三轮结果。

工作：按第四部分回归矩阵重跑所有受影响环节，直到设计定稿、配置表、验证结果和交互案一致。

通过条件：不存在死方、失效默认方、无脑材料、统治炉型、异常产量或利润漏洞。

### 第十五步：正式交互案与最终审定

输入：通过联合回调的全部成果。

工作：

- 形成正式《炼丹系统交互案》；
- 回写经联合回调确认的正式配置值；
- 完成纸推与数值验证报告；
- 回查设计定稿、配置、交互与实现接口的一致性；
- 将仍未决定的内容保留在设计定稿“待定参数”。

通过条件：正式成果齐全，全部现行结论均能在设计定稿中找到唯一出处。

## 四、回归矩阵

| 改动 | 必须重跑 |
|---|---|
| 配置字段、引用或默认材料容量 | 从第三步重建骨架，并重跑全部受影响的生成与验证 |
| 普通灵植 | 组方、代表解、安全顺序、支配检查 |
| 君材目标药力 | 份数、路线、品质成功率、升品产量 |
| 丹头容量 | 高药力、低杂质、易调性路线 |
| 炉膛 | 安全顺序、丹炉覆盖 |
| 过滤率、技能除渣或境界差倍率 | 剩余杂质、纯度、成丹率、毒池 |
| 最低杂质 | 纯度、成丹率、毒池、售价 |
| 丹方神识要求 | 批次产量、成本与利润 |
| 最低纯度 | 死方、默认方、成丹率 |
| 成丹率 | 品质产量、成本与利润 |
| 升品率或每方开放品质 | 品质产量、售价、稀缺度与利润 |
| 毒池容量、消退率或取整 | 自用节奏与每日消退 |
| 丹效行为或数值 | 服用结果、价格、自用与出售定位 |
| 价格 | 成本、利润和高低境经济 |
| 交互流程 | 第二轮玩法纸推与正式交互案 |
