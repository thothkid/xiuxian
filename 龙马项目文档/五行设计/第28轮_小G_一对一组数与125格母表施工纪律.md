## 〇、先给结论

第27轮三份发言**没有在字面上完全收敛**，因为小龙、小C成文时仍保留了“臣带主效”“性按物种计一次”等旧规则；但thoth后续已经明确更新了这些事实。因此本轮不按作者立场或文件先后选边，只按最终规则统一：

1. **臣没有主效。** 臣只定五行。
2. **性按每一份材料叠加。** 四位全部有性。
3. **君定全炉药力承载上限。** 总药力超过上限不是浪费后取最小值，而是普通炼制失败／废丹／炸炉。
4. **君、臣、佐、使数量按君药数量一对一。** 选定四个物种后，每增加一组，就是四位各加一份。
5. **五味决定标准君核。** 普通君药五种，对应修炼、灵法、根基、心神、气血五域；特殊君核另加。
6. **最终丹效由五行×五味×全炉最终五性确定。**
7. **丹毒首版仍只保留修为丹毒、灵根丹毒。** 五域五毒不因结构漂亮而擅自复活。
8. **成品品质仍走另一套规则。** 不把药力余量、最低材料品质等偷偷写成本轮品质公式。

第28轮最重要的新增结论有两条：

> **第一，君核承载上限是“选中这一种君材后，本炉固定的U”，不能再乘君材数量N。否则一对一增组时总药力和承载上限同比增长，无穷配法会回来。**

> **第二，125格是125个丹效模板坐标，不是125个必须互不重复的属性ID。现有游戏只有70条有效属性，另有境界参数、技能与Buff承载；硬凑125个不同属性必然重新走向文青化和假功能。**

## 一、第27轮互评（工作流5.28）

### 小C：9.0分

本轮最硬的贡献是把thoth新裁的“一对一组数制”写成了公式：四材单份性和为S，组数为N，则全炉性值为N×S。由此准确推出：

- S＝0时无论N多大都为平；
- S＝±1时，N＝1得到温／凉，N＝2得到热／寒；
- S＝±2时只能放一组；
- |S|≥3时普通条件下一组也不能成丹。

## 二、一对一组数制正式写清

### 2.1 一炉到底怎样投料

首版一炉仍是四个材料槽，每槽选一个物种：

| 槽位 | 选什么 | 数量 |
|---|---|---:|
| 君 | 一种符合主味归域的君材 | N份 |
| 臣 | 一种提供五行的臣材 | N份 |
| 佐 | 一种主要调性的佐材 | N份 |
| 使 | 一种提供五味的使材 | N份 |

> **四位数量恒为N:N:N:N。N称为“组数”，不是成丹颗数。**

玩家配方自由主要来自三件事：

1. 君、臣、佐、使各选哪一种灵植；
2. 四材的性怎样相加；
3. 这一炉投入几组N。

“一炉炼几颗成品”另由炼丹规则处理，不与组数混为一个字段。

### 2.2 药力公式

设四种已选灵植的单份药力分别为`p君、p臣、p佐、p使`：

```text
单组药力Q = p君 + p臣 + p佐 + p使
全炉总药力P = N × Q
```

每一种材料的药力都参与，没有谁只是凑数。

### 2.3 性值公式

设四种已选灵植的单份性值分别为`s君、s臣、s佐、s使`：

```text
单组性值T = s君 + s臣 + s佐 + s使
全炉性值S = N × T
```

五档仍为：

```text
-2 寒｜-1 凉｜0 平｜+1 温｜+2 热
```

普通丹只接受`-2≤S≤+2`，不做钳制。

### 2.4 一对一之后，玩家实际怎样推理

| 单组性值T | 可用组数N | 最终性 |
|---:|---|---|
| 0 | 只受药力上限约束 | 永远为平 |
| +1 | 1或2 | 温或热 |
| -1 | 1或2 | 凉或寒 |
| +2 | 1 | 热 |
| -2 | 1 | 寒 |
| ≥+3 | 0 | 过热，不成普通丹 |
| ≤-3 | 0 | 过寒，不成普通丹 |

这意味着佐材不只是把结果“拉回0”。它真正的用途是帮助玩家把单组性值T调到0、±1、±2中的目标值。

例如玩家要火·酸·温：

- 臣选火行；
- 使选酸味；
- 选血肉核君材；
- 调整四材，使单组性值T＝+1；
- 投1组，最终S＝+1，产出温性火酸丹。

若同一组材料投2组，则S＝+2，变成热性火酸丹；若总药力仍未越君核上限，它就是另一种合法结果。玩家不需要臣材再写“主攻速”或“主破甲”。

## 三、君核上限怎样和一对一共存

### 3.1 必须先堵住一个数学漏洞

若错误地定义：

```text
总承载上限 = 君材单份承载 × 君材份数N
```

那么一对一增加一组时：

- 总药力P按N增长；
- 君上限U也按N增长；
- 二者比例不变。

只要一组能过，以后每一个N都可能继续过，平性组合仍会出现无限配法。此时再加丹炉组数上限，只是在最外层给底层漏洞贴胶布。

### 3.2 正确口径：君材种类决定本炉固定U

> **君核承载上限U由“所选君材ID＋其境界档”读取，是一炉一个固定值，不乘数量N。**

君材投入多份仍有意义：

- 每份君材自身药力继续计入P；
- 每份君材的性继续计入S；
- 但这些材料共同凝成同一个丹核，不会因为多放一份就凭空多出第二个容器。

世界观可解释为：

> **君材定核质，不以堆量扩其界；药可益，器不可自生。**

君核类型和境界决定“器”的容量，君材份数只是向这个器里继续填药力。

### 3.3 最终成丹窗口

```text
主味要求的君核类型 = 所选君材的君核类型
境界成丹下限L ≤ 全炉总药力P ≤ 君核固定上限U
-2 ≤ 全炉性值S ≤ +2
```

处理结果：

| 条件 | 结果 |
|---|---|
| P＜L | 药力不足，不成丹 |
| L≤P≤U | 药力有效，继续查行味性效果 |
| P＞U | 君核破裂，废丹／炸炉 |

不用`min(P,U)`。超出的药力不能假装没发生。

### 3.4 配法为什么必然有限

只要四材药力都是正数：

```text
N药力上限 = floor(U ÷ Q)
```

性值再提供第二道上限：

```text
T＝0：不限制N
|T|＝1：N≤2
|T|＝2：N≤1
|T|≥3：N＝0
```

因此最终合法组数是：

```text
N最大 = min（药力允许的最大N，性值允许的最大N）
```

即使T＝0，药力上限U仍能使N有限。**这才是真正从底层解决配法无穷。**

丹炉以后仍可设最大组数，但它应服务：

- 操作界面不要出现过大的N；
- 不同境界丹炉的容量差；
- 炼制时间、成功率、成品数量和品质规则。

它不再承担“没有它数学系统就无限”的补洞职责。本轮不擅自采用2／3／4组具体数值。

## 四、药力与品质必须继续分开

第27轮小C提出“余量决定品质”，小龙曾提出“总药力决定完成度／品质倍率”。这两条都不在当前冻结范围内。

用户已经明确：

> **成品品质由灵植品质、炼丹技能、丹炉境界与丹炉品质等另外一套规则综合决定，本表暂不定。**

所以本轮药力只做三件事：

1. 判定是否达到成丹下限；
2. 判定是否冲破君核上限；
3. 为将来的丹效数值公式提供一个“有效药力P”。

至于P在`[L,U]`之间怎样换算成最终数值，是下一次数值纸推；它不能自动被叫作“品质”。同一品质的丹可以有不同药力完成度，同一药力也可以因炉、技、材品质而产出不同品质。

## 五、125格到底是什么：模板坐标，不是125个新属性

### 5.1 实表核验结果

我本轮只读核对了现行三个配置源：

1. `S属性配置表.xlsx / attr_config`：当前有效属性ID为1—70；其中64—70是修炼链——每时辰基础修为、每时辰灵气吸收、基础转化值、额外转化值、转化值增幅、基础修为增幅、额外基础修为。
2. `J境界角色属性表.xlsx / realm_config`：突破成功率、失败虚弱时长、每时辰基础修为、灵气吸收、转化值是境界参数，不全是普通属性ID。
3. `J技能BUFF表.xlsx`：虚弱、中毒等结果已有Buff承载；技能表也能承载一次性或复合效果。

另外，thoth会手动补神识上限、神识操控两条。即便加上这两条，也不应误解为“要补够125条属性”。

### 5.2 为什么不能要求125个互不重复的ID

因为丹效本来就有四种承载：

| 承载方式 | 例子 |
|---|---|
| 属性ID | 攻击速度、生命值增幅、每秒回灵、无视防御 |
| 参数ID | 当前修为、突破成功率、寿元、失败虚弱时长 |
| BuffID | 中毒、虚弱、沉默、持续回血、临时属性增减 |
| 技能ID | 特殊位移、护盾、战斗技、主动触发效果 |

同一个目标ID也可以在不同模板中合理复用：

- 凉性可能给它更长持续、更低峰值；
- 平性可能给它标准值和最低代价；
- 温性可能缩短起效时间、提高频率；
- 热性可能给高峰值并附带反噬。

**坐标不同，不等于底层ID必须不同。** 真正必须不同的是玩家可感知的结果与代价组合。

### 5.3 125格的正确数据定义

每一格应至少表达：

```text
效果坐标Key = 五行 + 五味 + 五性
作用域       = 由五味确定
效果族       = 由五行×五味确定
性型语义     = 寒量／凉续／平本／温速／热爆
药效1        = 类型 + 目标ID/参数 + 数值公式
药效2        = 可空
药效3        = 可空
持续与延迟   = 由性型规则与具体模板确定
代价         = 丹毒或普通负面Buff
```

因此：

> **125格＝25个效果族×5种性型模板。**

它们可以调用70条属性、境界参数、现有／新增Buff和技能，而不是反过来为了填格子制造125条属性。

## 六、五性“定具体效果”应怎样理解，避免再次过度

第27轮我说“具体效果由行＋味＋性唯一确定”，这条保留；但要加一个施工边界：

> **性只能在同一个行味效果族内选择同源子效和曲线，不能把任意属性硬塞进寒凉温热。**

例如火＋酸的效果族是“催动气血形成战斗输出”：

| 性 | 合理落点示例 | 为什么同源 |
|---|---|---|
| 寒 | 低峰值、长持续、总量高的伤害提升Buff | 仍是火催气血，只是封存久发 |
| 凉 | 稳定长效的攻击增幅 | 仍是输出，偏持续 |
| 平 | 基础物理攻击／攻击增幅 | 该格最直白的本效 |
| 温 | 攻击速度或降低攻击间隔 | 火催得更快 |
| 热 | 无视防御、爆发增伤或短时高攻 | 火催至极，峰值最高 |

这里可以调用不同属性ID，也可以复用一个攻击／伤害ID而换Buff曲线。关键不是“必须五个ID”，而是玩家读出寒凉平温热后，能预期它为什么这么生效。

同理，木＋甘属于“让丹田境界结构生长”：

- 平性可以是最基础的小境突破；
- 温性可以偏快速冲关或大境突破；
- 寒、凉、热应从积累、稳定、爆发与代价去推，不能随手塞一个与突破无关的属性。

如果某个行味格找不到五个不同但同源的真实属性，**允许复用目标ID，以持续、延迟、次数、峰值、总量、反噬做出五种可感知结果。** 这比发明一个游戏里根本不存在的属性更实事求是。

## 七、五种标准君核继续成立

第27轮小G提出由五味决定君核，其他两份没有给出更强反证。本轮继续冻结：

| 主味 | 五域 | 标准君核 |
|---|---|---|
| 甘 | 修炼／丹田 | 丹田核 |
| 辛 | 灵法／气脉 | 气脉核 |
| 咸 | 根基／骨底 | 骨底核 |
| 苦 | 心神 | 心神核 |
| 酸 | 气血／血肉 | 血肉核 |

君材本身仍无五味字段，只有“君核类型”；主使味与君核类型是一道结构匹配。

为什么不用五行选君：五行已经由臣负责“如何运作”，五味负责“去哪里”，君核作为承载器更应适配去处。用五味选君能让五个君核各管一章，每个君核下自然展开5行×5性＝25格。

当前不跨境界炼丹，所以每大境界原则上五种标准君材；不同境界复用同一125格效果母表，只替换药力、数值、持续、代价和物品ID。

洗灵根、逆命、双域、多行多味、极寒极热等效果若不适合普通结构，使用少量特殊君核，不强塞进标准五君。

## 八、丹毒继续守用户冻结：首版两条

小C的“五味五毒、金行五解”在世界观结构上对称，但当前产品边界已经明确：

| 长期丹毒 | 来源 | 清解方向 |
|---|---|---|
| 修为丹毒 | 修炼、突破及相关丹药 | 金＋甘中的相应性位 |
| 灵根丹毒 | 洗灵根、改根与深层根基丹 | 金＋咸中的相应性位或特殊丹 |

辛、苦、酸域过量造成的灵力紊乱、精神虚弱、中毒、流血等，先走普通Buff，不新增三条永久毒条。

神识上限、神识操控仍归苦·心神域；心神负面Buff可以压神识操控，但不叫“心神丹毒条”。若未来用户另行决定扩成五毒，再启用预留结构。

## 九、第28轮冻结项

1. 四位各选一个物种，数量按组数N一对一：君N、臣N、佐N、使N。
2. 总药力`P=N×(p君+p臣+p佐+p使)`。
3. 全炉性值`S=N×(s君+s臣+s佐+s使)`。
4. 性按每份材料叠加；正常结果只认-2至+2。
5. 君核上限U由所选君材ID与境界固定，**不乘君份数N**。
6. 成丹药力为硬窗口`L≤P≤U`；P＞U失败，不使用`min(P,U)`吞掉溢出。
7. 合法N同时受药力上限和性值窗口限制，因此配法天然有限。
8. 丹炉最大组数可后设，但不负责修复无穷配法。
9. 药力不直接等于成品品质；品质继续独立设计。
10. 臣无主效；臣提供五行、性、药力。
11. 使提供五味、性、药力；五味决定标准君核类型。
12. 佐提供性、药力，主司调节单组性值T。
13. 最终效果坐标仍为五行×五味×最终五性。
14. 125格是25个效果族×5性型模板，不要求125个互不重复属性ID。
15. 同一目标ID可以在不同性位复用，但持续、峰值、总量、速度或代价必须形成玩家可感知差异。
16. 每格最多调用三套药效，类型可为属性、参数、Buff或技能。

## 十、下一轮施工顺序

本轮之后可以正式进入125格母表，但建议按下面顺序，不要一次盲铺八境：

1. **先建一张不带数值的125格语义母表**：五行、五味、五性、效果族、首选目标类型、首选目标ID、备选第二／第三药效。
2. **逐格核真实程序承载**：属性表能做的用属性ID；突破、寿元等用参数；持续状态用Buff；特殊动作才用技能。
3. **做四项审查**：是否同源、玩家能否从十词＋五性口诀推理、程序是否已有承载、与相邻格是否重复到没有意义。
4. **标主次而不删可能性**：125格都可有逻辑结果，但只把加修为、大小突破、回血回灵、关键战斗、永久强化、清毒、延寿等少数格设为重点丹药并强化数值；其余是普通／偏门结果。
5. **母表通过后再乘八境**：效果语义不变，只配境界数值倍率、L、U、持续、丹毒、售价、材料境界与物品ID。
6. **最后才做灵植表**：按五种君核、五行臣材、五味使材、五性佐材反推物种池，并纸推每个重点丹至少3—6种合法组合。

我不建议第28轮直接在开发用丹效表里写125行。当前先把语义母表审通，否则任何错误都会乘八境、乘品质、乘物品ID，后面返工更大。
