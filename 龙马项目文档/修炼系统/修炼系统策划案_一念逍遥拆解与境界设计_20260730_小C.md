# 第一部分 · 《一念逍遥》修炼与境界体系拆解

## 1.1 总架构：四层正交结构

这个游戏不是"一条境界线"，是四层正交结构叠出来的：

```
第 1 层 · 界域（三段）      人界 → 灵界 → 仙界        单向门，飞升不可逆
第 2 层 · 修炼方向（6 条）   法修/体修/剑修/鬼修/儒修/血修   每方向一套平行境界名表
第 3 层 · 大境界（14 阶）    炼气 … 大罗              各方向同阶对应，只换名不换骨架
第 4 层 · 小境界            期（前/中/后）× 重（N）      N 随大境界递增
```

- 六方向〔单〕：剑修（物理）、体修（物理）、鬼修（法术）、儒修（法术）、法修（法术）、血修（2026 新增，物理）。**每玩家至多同时修 4 个方向**，开血修后可能开五修。
- **各方向严格同阶对称**〔实〕。官方原话："体法各大境界几率时间一致"——只换名字，不换数值骨架。
- 官方对非法/体方向一律用"**对应境界**"措辞（如"太乙对应境界前期2重"），暗示共用同一阶位表。各方向的独立境界名表〔缺〕。

## 1.4 小境界命名规则：两级命名切换

游戏不是单一命名制，是**低阶用"层"、高阶切"期+重"**的两级结构〔实〕：

```
第 1 段（仅最低 1 阶）：  大境界 + N层        例：炼气十层、通脉10层
第 2 段（其余全部）：     大境界 + 期 + N重    例：太乙前期2重、化神后期15重
                        期 ∈ {前期, 中期, 后期}
                        该期最后一重称「圆满」，圆满是触发破境丹的独立节点
```

逐字证据：「炼气一共有十层」/「筑基后期」/「结丹中期」/「大乘中期开始」/「修为达太乙对应境界**前期2重**后」/「没瓶子好几天**一重小境界**很正常」/「**每个境界圆满后**都需要破境丹」/「前期突破到中期，中期突破到后期都需要元婴丹」。

**命名细节三条：**
- **不用"初期"，用"前期"**〔实〕。所有来源统一。
- **"圆满"是独立状态节点**〔实〕，不是形容词——它决定要不要吃破境丹。
- **"巅峰"不是小境界名**〔实〕。它是玩家称号/排名档位（"巅峰和至尊修士的名额限制"），与修为层级无关。
- UI 表现：炼气阶段"每个勾玉代表一个境界"——小境界在界面上以勾玉图标计数〔单〕。

## 1.5 修炼速度公式（本次最硬的一条数据）

**`修炼速度（修为/周天）= 洞府灵气 × 吸收率`**〔实〕，官方原文，四个独立来源重合。

**`洞府灵气 = 基础灵气 130 × (1 + Σ各项加成%)`** —— 全加区，无乘区〔实·数值自洽验证〕。

用玩家实测截图反推验证：

| 项 | 值 |
|---|---|
| 基础洞府灵气 | 130（固定，全阶段不变） |
| 聚灵阵 | +50% |
| 宗门等级增幅 | +9% |
| 功法增幅 | +23% |
| 飞仙铸剑增幅 | +10% |
| 古宝增幅 | +10.2% |
| 仙友增幅 | +3% |
| **合计洞府灵气** | **269.36** |
| 吸收率（境界决定） | 45% |
| **修炼速度** | **121.21 / 周天** |

验算：269.36 × 0.45 = 121.21 ✓ 精确吻合。
占领金色洞天后 +338 灵气（= 130 × 260%）：(269.36 + 338) × 0.45 = 273.31 ✓ 与帖中数字精确吻合。

→ **洞天福地加成也进同一个加区**，与官方"以加法的形式反映在修炼上"表述一致。

**加区明细（洞府灵气 %）：**

| 来源 | 数值 | 状态 |
|---|---|:--:|
| 基础洞府灵气 | 130（固定值，非百分比） | 〔实〕 |
| 聚灵阵 | 满级 51 级，+50% | 〔实〕 |
| 宗门等级 | 实测 +9%（早期版本记载 = 山头基础值 + 宗门等级×2，口径不同） | 〔冲·版本差异〕 |
| 宗门灵泉 | 有增幅，数值〔缺〕 | 〔单〕 |
| 功法 | 全 16 阶累计约 +69%；实测当前 +23% | 〔实〕 |
| 飞升铸剑 | 最高 +10%（化神后期飞升任务给） | 〔实〕 |
| 古宝（聚灵玉璧等） | 注灵每级 +0.2%，恒定不递增；实测总 +10.2% | 〔实〕 |
| 仙友（灵界后） | 实测 +3% | 〔实〕 |
| 洞天福地 | 金色洞天 +260%；蓝（灵居）/紫（福地）档位数值 | 〔缺〕 |
| 洞府耐久 | 总 100，被打一次 −30，**低于 80 时洞府灵气值下降** | 〔实〕 |
| 辅修方向（大罗版本） | 有灵气加成，数值〔缺〕 | 〔单〕 |

**时间单位**：1 道年 = 15 分钟现实时间〔实〕（交叉验证：洞天福地"每天可占领 4 道年（一小时）"→ 4×15=60min ✓）。1 周天 = 8 秒〔单·低权重，无法交叉，勿采信〕。

## 1.9 突破规则：小境界 vs 大境界

## 1.16 五条结构性判断〔判〕

以下是小C 的判断，不是竞品事实。

1. **层数递增是刻意的节奏工具，不是数值失控**。10 层 → 后期 6 重 → 8 重 → 15 重 → 20 重，后期大境界的小境界数量是前期的 2–3 倍。作用是：后期内容更新慢，用更细的小境界切分把同一段内容摊长，保证玩家每 1–3 天仍有一次"跳格子"的反馈。
2. **两级命名切换是为新手认知服务的**。炼气用"十层"（直觉、可数、有终点），此后切"期+重"（把长跑拆成三段，"前期"心理上比"第 37 层"轻）。**这是纯 UX 决策，零数值成本，可直接照搬。**
3. **吸收率是它最重要的一条设计**。加区（洞府灵气）随便堆，乘区（吸收率）只能靠境界抬。这一条同时解决三个问题：氪金不能跳过节奏、双修/多线自动受罚、老玩家和新玩家的差距有天花板。
4. **法/体双线严格同阶对称，只换名不换骨架**，极大降低数值维护成本。一张表配两条线。
5. **顶部必须留扩展位**。5 年内追加 3 个大境界（渡劫 2021 → 太乙 2024 → 大罗 2025）。境界枚举写死在代码里会死。

## 2.2 【核心提议】小境界层数：不等层递增制

**直接回答"是不是前后期不一样"：竞品实测答案是"不一样，后期是前期的 2–3 倍"（§1.3）。本案建议采纳这一结构。**

### 2.2.1 层数生成规则〔提〕

```
层数(序号 n) = 10 + 2 × max(0, n − 2)      n = 1..7
层数(渡劫)   = 上式结果 + 2                  即 24
```

前两个大境界不加长（新手期节奏不能拖），第 3 阶起每阶 +2 层，终局大境界额外 +2。

### 2.2.3 三案对比

| | 案A 等层制（现行） | **案B 递增制（本案推荐）** | 案C 分段递增制（竞品原教旨） |

**推荐案B 的理由**〔判〕：WAR3 ORPG 的后期内容产出速度必然低于前期（地图/怪物/秘境都是人工产能）。用更密的小境界把同一段内容摊长，是**零内容成本**换取反馈频率的手段。案C 的精细度对本项目体量过剩，收益不抵配表成本。

## 2.4 修炼速度与修为规则（沿用现行公式，补齐口径）

现行拍板公式（`打坐修炼_系统设计.md` §二），**不改**：

```
每3秒获得修为 = 境界基础速率(3秒) × (1 + ΣA类) × (1 + ΣB类) + Σ固定值
即时修为     ：修为 += effect_value（当场查当前境界列直接累加，不过速率公式）
```

### 2.4.1 ⚠ 关键补充：base_cult_speed 的乘区独占规则〔提〕

竞品最核心的一条数值设计是**吸收率乘区只能靠境界抬升，任何系统不得加成它**（§1.6）。

本项目公式里，`base_cult_speed` 承担的正是这个角色。**建议明文加一条硬规则：**

> **base_cult_speed 只由 realm_config 决定（即只由境界决定）。任何丹药/功法/装备/阵法/洞府/付费项目一律不得直接加成或替换 base_cult_speed，只能走 A/B/flat 三池。**

**这一条不新增任何字段，只是给已有字段加约束。**（依据主记忆「工程版奥卡姆四分类」§①：核心状态从紧；「现象不进元组」：能由已有结构表达的不得实体化为新字段。竞品的"吸收率"与本项目的 `base_cult_speed` 是同构的，不需要再开一个字段。）

它同时解决三个问题：
1. 氪金不能跳过境界节奏（钱只能堆 A/B 池，堆不动乘区底数）
2. 落后玩家的差距有天花板（乘区上限由境界锁死）
3. 未来若做多修方向/双修，摊薄修为 → 境界落后 → 底数低，自动形成惩罚闭环，不需要额外写惩罚逻辑

### 2.4.2 修为阈值曲线〔提〕

`cult_required`（realm_config 字段，已存在）建议按两级生成：

```
cult_required(境n, 层i) = 大境界基数(n) × 层内系数(i)

大境界基数(n) = 基准值 × 4^(n-1)         〔提〕倍率 4，待压测
层内系数(i)   = 1.0 + (i - 1) / (层数 - 1)   即层内从 1.0 线性升到 2.0
```

- 大境界间 4 倍跨度〔提〕：竞品同类数据〔缺〕，此值为本案自拟，**必须经模拟压测后再定**。
- 层内线性 1.0→2.0〔提〕：保证同一大境界内"越到后面越慢"，与阶段标签（前期快/后期慢）的体感一致。
- **圆满层的 cult_required = 大境界突破阈值**（现行设计已定，不改）。

### 2.4.3 修为溢出规则〔提〕

竞品此项〔缺〕，本案自拟：

| 场景 | 处理 |
|---|---|
| 小境界自动过（炼气/筑基） | 溢出修为**结转到下一层**，不浪费 |
| 小境界需判定突破（金丹起） | 修为满即封顶，**溢出部分丢弃**；封顶后 HUD 提示"修为已满，可尝试突破" |
| 大境界圆满 | 修为满即封顶，溢出丢弃；封顶后打坐不再产出，提示"需渡劫" |

理由〔判〕：封顶+丢弃是逼玩家去做突破/渡劫的动作，把"挂机躺赢"截断在境界门口。前两个大境界不封顶，是为了不打断新手期的连续感。

## 2.5 突破规则：三档分级

沿用现行 `need_breakthrough` 字段（`打坐修炼_系统设计.md` §九），**扩为三档**〔提〕：

| 档 | 适用范围 | need_breakthrough | 流程 |
|:--:|---|:--:|---|
| **档0 自动过** | 炼气 1→10、筑基 1→10 全层 | false | 修为满即自动升层，无判定、无消耗、无中断 |
| **档1 判定突破** | 金丹起，每个大境界的 1→(层数-1) | true | 修为满 → 出现【突破】按钮 → 消耗材料+灵石 → 概率判定 → 成功升层 / 失败进冷却 |
| **档2 渡劫** | 所有大境界的 **圆满 → 下一大境界** | true | 修为满 + 材料齐 → 前往**渡劫台** → 渡劫事件（见 §2.6） |

> 档0/档1 分界与现行设计一致（金丹起需要突破），本案只是把档2 从档1 里显式拆出来，因为两者的配置字段和表现完全不同。

### 2.5.1 突破消耗与成功率〔提〕

对齐竞品已验证的"本境界丹 vs 下境界丹"分工（§1.9）：

| 档 | 消耗品 | 命名规则 |
|:--:|---|---|
| 档1（升层） | **本境界**丹药 | 如金丹期升层用「金元丹」 |
| 档2（渡劫） | **下一境界**的突破丹 + 破境丹 | 如金丹圆满→元婴，用「元婴丹」 |

**基础成功率曲线**〔提〕（竞品实测 35%/15%/5% 呈锐减，本案取更缓的曲线，理由见下）：

| 大境界 | 档1 升层基础成功率 | 档2 渡劫基础成功率 |
|---|:--:|:--:|
| 炼气 / 筑基 | —（档0） | 90% |
| 金丹 | 85% | 70% |
| 元婴 | 80% | 60% |
| 化神 | 75% | 50% |
| 合体 | 70% | 40% |
| 大乘 | 65% | 35% |
| 渡劫 | 60% | 30% |

**〔判〕不照抄竞品的 35%/15%/5%**。竞品是放置手游，失败冷却 8.89 小时对它是正常节奏（玩家本来就不在线）；WAR3 ORPG 是一局制/在线制，把玩家挂在 8 小时冷却里等于劝退。**基础成功率必须显著高于放置游戏，惩罚必须显著轻于放置游戏。**

**丹药加成**〔提〕：突破丹提供固定 %加成，加法叠加到基础成功率，上限 95%（不做 100%，保留渡劫的不确定性）。

### 2.5.2 失败惩罚与保底〔提〕

竞品此项〔冲〕（掉不掉修为三说并存），本案自裁：

| 项 | 规则 |
|---|---|
| **档1 失败** | 扣除**当前层修为的 20%**，进入【元神受损】debuff，冷却 **3 分钟**，不掉层 |
| **档2 失败** | 扣除**圆满层修为的 30%**，进入【元神受损】，冷却 **30 分钟**，**不掉大境界、不掉层** |
| **境界倒退** | **本项目不做**。境界倒退在 ORPG 里是极高流失风险动作，收益不抵 |
| **保底** | 沿用现行 `guaranteed_after_fails` 字段。建议 **档1 连败 3 次必成，档2 连败 3 次必成** |
| **累积概率** | 每失败 1 次，下次成功率 **+10%**（累积，成功后清零）。与保底并存，双重兜底 |

> 现行 `breakthrough_config` 已有 `fail_penalty_cult_pct` / `fail_debuff_id` / `guaranteed_after_fails` 三个字段，上述规则不需要新增字段，只需要填值。**累积概率需新增 1 个字段**（见 §2.8）。

## 2.6 渡劫规则〔提〕

### 2.6.1 形式选择

竞品渡劫是**纯数值承伤，不是战斗**（9 段固定倍率伤害，气血+真元抗）〔单〕。

**本案建议改为实时战斗事件**，理由〔判〕：WAR3 是即时战斗引擎，纯数值承伤在 WAR3 里表现力接近于零（就是一串飘字），浪费引擎优势；而渡劫是整个修炼系统里唯一的仪式感节点，值得做成可操作的战斗。

### 2.6.2 渡劫台事件规则

| 项 | 规则 |
|---|---|
| 触发 | 圆满层修为满 + 材料齐 → 手动前往**渡劫台**（安全区内固定点）→ 主动开启 |
| 场景 | 独立小场景 / 圈定区域，渡劫期间不可被 PVP 打断 |
| 形式 | **9 道雷劫**，逐道降下，每道之间有 3 秒间隔（玩家可移动/走位/吃药/开盾） |
| **伤害倍率** | **1 / 1.2 / 1.5 / 2 / 3 / 4 / 5 / 7 / 10**（Σ = 34.7）——**直接借用竞品实测倍率**〔单·已自洽验证〕，这是一条现成的、经过 5 年线上验证的曲线，没有理由自己重造 |
| 单道伤害 | `雷劫基础伤害(大境界) × 该道倍率`。基础伤害由 `tribulation_config` 配置 |
| 抗性 | 生命值 + 灵力值共同承伤（对齐竞品"气血和真元共同抵抗"）；具体分摊比例〔提·待定〕 |
| 失败判定 | 生命值归零 = 渡劫失败，按 §2.5.2 档2 惩罚处理，**不死亡、不掉装备** |
| **辅助道具** | **劫盾（橙）：减免 60% 雷劫伤害；灵盾（紫）：减免 30%**——直接借用竞品数值〔实〕 |
| 前期难度 | **炼气→筑基、筑基→金丹 的雷劫必须"打不死人"**（竞品明确："突破到筑基的天劫很弱，不要浪费机缘买灵盾"〔实〕）。新手期渡劫是教学，不是筛选 |
| 时机 | 玩家自主选择渡劫时机，圆满后可无限期停留 |

### 2.6.3 渡劫的仪式感表现〔提〕

竞品此项〔缺〕（无任何来源记录突破动画/称号/公告），本案自拟：

| 层级 | 表现 |
|---|---|
| 小境界升层（档0/档1） | 角色身上一圈光效 + 一行飘字，无中断 |
| **大境界突破（档2 成功）** | 全屏光效 + 角色模型短暂放大 + **全服/全房间公告**："某某 突破至 金丹期" |
| 渡劫过程 | 天色变暗 + 雷云 + 每道雷有独立落雷特效与音效，第 9 道（10 倍）必须明显区别于前 8 道 |

> **公告只给大境界，不给小境界**。124 层每层都播报会变成噪音。

## 2.7 瓶颈与心魔〔提〕

### 2.7.1 瓶颈

竞品是**软瓶颈**（修为满了点突破就行，没有"必须做某事才能解锁"的硬瓶颈）〔实〕。

**本案建议：V2 只做软瓶颈，硬瓶颈挂待决。**

理由〔判〕：硬瓶颈（必须完成某任务/幻境才能突破）在竞品里是**后期大境界**才出现的（合体要炼化心魔、大乘要过荧惑守心、大罗要过天道试炼，§1.9）。它需要成体量的内容支撑，V2 阶段没有这些内容，硬加只会变成"卡在这里无事可做"。

**保留接口**：`breakthrough_config` 新增 `required_quest_id` 字段（见 §2.8），V2 全部留空，V5/V6 有任务/秘境内容后再填。

### 2.7.2 心魔

竞品的"心魔"是两套东西（§1.12）：心魔值（负向常驻资源）+ 荧惑守心（大境界前置玩法）。

**本案建议：V2 两套都不做，挂 V6。**

理由〔判〕：P01 已把"雷劫/心魔"整体归入 V2 的 Nope 之外，但心魔值的设计前提是**存在低境界修士可杀**（竞品：击败低级修士滋长心魔），这依赖 PVP，而 PVP 在 P01 路线里是 V7。没有 PVP 的心魔值是个空转系统。

**唯一建议在 V2 预埋的**：属性字段留 `heart_demon` 占位（int，V2 恒为 0，不参与任何计算），避免 V6 时改存档结构。**是否预埋由 thoth 定**——P01 的"存档一次定型"原则支持预埋，但奥卡姆四分类§①"核心状态从紧"反对，两条原则在此冲突，需要拍板。

## 2.10 境界收益：属性 + 容器双轨

现行设计已定"小境界同时做两件事：横向打开容器 + 给属性数值；大境界做数量级跃迁"（`打坐修炼_系统设计.md` §十一）。本案补齐落地口径〔提〕：

### 2.10.1 属性轨

`realm_config` 已有 `base_hp / base_mp / base_atk / base_def` 四列。**建议对齐 P02 属性体系的实际字段名**，避免 V2 时再做一次映射：

| realm_config 现字段 | P02 对应属性 | P02 ID |
|---|---|:--:|
| `base_hp` | 生命值 `jcxl` | 1 |
| `base_mp` | 灵力值 `jcmf` | 2 |
| `base_atk` | **应拆为** 攻击下限 `jcgj1` / 攻击上限 `jcgj2` | 3 / 4 |
| `base_def` | **应拆为** 物防下限 `jcfy1` / 物防上限 `jcfy2` | 7 / 8 |

> P02 的属性体系是**上下限制**（"下限 ≤ 上限，天运触发时取上限"），realm_config 用单值 `base_atk` 会与之不兼容。**这是一个必须在 V2 开工前修掉的口径不一致**，建议 realm_config 直接改为 6 列（hp / mp / atk_min / atk_max / def_min / def_max）。法攻/法防是否也随境界给基数，待 thoth 定。

**属性增长曲线**〔提〕：小境界线性、大境界跳变。
```
层内：base_attr(境n, 层i) = 大境界基数(n) × (1 + 0.08 × (i-1))
境间：大境界基数(n) = 大境界基数(n-1) × 2.5      〔提〕倍率待压测
```
竞品此项〔缺〕（无任何来源给出每层属性增量），本案值为自拟，**必须经战斗公式压测**（对齐 P03）。

### 2.10.2 容器轨〔提〕

小境界打开容器（不给数值，给"能装多少"），这是本项目区别于纯数值成长的设计点：

| 容器 | 由什么决定 | 建议节奏 |
|---|---|---|
| 法宝位 | 神识 | 竞品：元婴后期最高 6 个〔实〕。本项目建议同量级，元婴段封顶 |
| 术法品阶上限 | 大境界 | 每个大境界 +1 阶 |
| 丹药每日次数 | 大境界 | 每次**大境界**突破时刷新次数（借鉴竞品"每次提升大境界都会刷新"〔实〕——这是一个免费的突破正反馈） |
| 背包格数 | 大境界 | 竞品此项〔缺〕；本项目 P11 已有背包规则，是否挂境界待定 |

### 2.10.3 玩法解锁节点表〔提〕

竞品把**几乎所有玩法都挂在境界门槛上**（§1.14），且刻意留了一批**非境界驱动**的解锁（爬塔层数、法则值、轮回次数、开服天数）作为对照。这个混合结构值得照搬：**主线玩法挂境界，支线深度挂各自的独立进度**。

V2 阶段的建议节点（与 P01 版本路线对齐，只列 V2 能落地的）：

| 节点 | 解锁 | 备注 |
|---|---|---|
| 炼气 1 层 | 打坐（在线） | V2 核心闭环起点 |
| 炼气 圆满 | 离线闭关 | 先让玩家手动打坐几层，再给离线，否则离线会吃掉整个前期体验 |
| 筑基 前期 | 丹药服用 | 对齐 V4 炼丹，V2 只做"吃"不做"炼" |
| 金丹 前期 | 突破判定（档1 首次出现） | 前两阶全自动，此处是第一次"可能失败" |
| 金丹 前期 | 灵根生效（A 类加成启用） | P01 路线：V2 灵根生效 |
| 元婴 前期 | 洞府灵气（B 类主力来源） | 依赖 V5 洞府，V2 可先用区域灵气浓度顶替 |
| 化神 后期 | 人界→灵界准入 | V2 可只做标记，地图在 V5 |

> 上表中依赖 V4/V5 系统的节点，V2 阶段一律**做接口不做内容**（`area_qi_density` 表先只配灰盒区域）。

## 2.11 追赶机制〔提〕

竞品的**奋起 buff**（修为低于全服前十平均的 70% 即触发，境界越低 buff 越猛，§1.13）是一条低成本高收益的设计。

**本案建议 V2 不做，V5 有多人服务器后再做。** 单机/小房间下"全服前十"没有意义。

**但建议 V2 预埋一个 B 类来源 ID**（`cult_effect_config` 里加一行 `奋起`，全境界 value = 0），这样 V5 启用时不需要动代码，只改配置表数值。

## 2.12 与竞品的六条明确差异〔判〕

本案**不是**照抄一念逍遥。以下六处刻意背离，理由已写在各节：

| # | 竞品做法 | 本案做法 | 理由 |
|:--:|---|---|---|
| 1 | 突破成功率 35%/15%/5%，失败冷却 8.89h / 33.33h | 60%~90%，冷却 3~30 分钟 | 放置游戏 vs 在线 ORPG，玩家在线时的等待容忍度差一个数量级 |
| 2 | 渡劫 = 纯数值承伤 | 渡劫 = 实时战斗事件 | WAR3 是即时战斗引擎，纯数值浪费引擎优势 |
| 3 | 渡劫失败境界倒退 | 失败只扣修为，**不掉境界** | 倒退是极高流失风险，收益不抵 |
| 4 | 无保底、无累积概率 | 连败 3 次必成 + 每败 +10% | 同上，在线玩家承受不了长尾失败 |
| 5 | 无灵根系统 | 有灵根，且 V2 生效（P01 已定） | 本项目已有 `linggen_config` 和 `root_bonus` 表，是既定设计 |
| 6 | 6 个修炼方向 × 平行境界表 | 单线境界 | 本项目 V0–V2 体量不支持多方向；若 V6+ 要做，§2.1 的 realm_id 留位规则已为此预留 |
