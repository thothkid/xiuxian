# 修炼系统三表结构分析

范围：`J境界角色属性表.xlsx`、`L灵气源配置表.xlsx`、`修炼系统配置项总表.xlsx`。  
原则：仅讨论系统职责、字段归属、表间关系；不讨论任何数值。

## 一、表职责 / Table Responsibilities

| 文档 / Document | 当前职责 / Current Responsibility | 结论 / Conclusion |
|---|---|---|
| J境界角色属性表 / Realm Character Attributes | 角色等级对应的境界、阶段、突破、基础修炼、灵气吸收、属性、升级经验、技能。 | 应作为“角色等级成长”的唯一主表。 |
| L灵气源配置表 / Spirit Source Config | 洞府、秘境、宗门修炼室等可供吸收灵气地点的出厂参数。 | 应作为“灵气源型号”的唯一主表。 |
| 修炼系统配置项总表 / Cultivation Config Field Index | 记录修炼系统各配置表的字段口径。 | 应只做字段目录，不承载第二份业务配置。 |

## 二、已成立的表拆分 / Confirmed Separation

| 业务对象 / Business Object | 唯一配置归属 / Single Source of Truth | 运行时归属 / Runtime Ownership |
|---|---|---|
| 角色等级、境界、阶段、突破节点 / Character level, realm, phase, boundary | J境界角色属性表 / Realm Character Attributes | 角色存档 / Character Save |
| 洞府、秘境、修炼室的灵气基础参数 / Source base parameters | L灵气源配置表 / Spirit Source Config | 个人洞府存档或场景运行时状态 / Player Save or Scene Runtime State |
| 丹药效果 / Pill Effects | 丹药配置表 / Pill Config | 角色效果状态 / Character Effect State |
| 家具、阵法、功法等加成 / Facility, formation, technique modifiers | 各所属系统的效果字段 / Owning System Effect Fields | 角色或场景效果状态 / Character or Scene Effect State |

说明：L 表只配置灵气源的基础值，不配置家具、丹药、阵法、功法等对基础值的修正；这些修正留在各自所属系统中，统一使用修炼系统发布的效果目标枚举。

## 三、J境界角色属性表 / Realm Character Attributes

### 3.1 表职责

该表当前同时承载以下内容：

| 字段组 / Field Group | 字段 / Fields | 结构职责 / Structural Responsibility |
|---|---|---|
| 境界定位 / Realm Identity | `level`、`realm_id`、`realm_name`、`realm_sub_level`、`phase`、`display_name` | 将角色等级映射到大境界、小境界、阶段和显示名。 |
| 突破规则 / Breakthrough Rule | `boundary_type`、`base_success_rate`、`fail_weakness`、突破材料字段 | 定义当前等级节点是否需要突破及其基础规则。 |
| 修炼基础 / Cultivation Base | `base_cult_rate`、`spirit_cult_per_unit` | 定义角色等级提供的基础修为与灵气吸收能力。 |
| 成长属性 / Character Attributes | `attrs` | 定义等级成长带来的角色属性。 |
| 等级成长 / Level Progression | `exp_level_up`、`skill` | 定义升级所需修为及默认技能关联。 |

### 3.2 需要统一的结构口径

| 问题 / Issue | 现状 / Current State | 需要确定的唯一口径 / Required Single Definition |
|---|---|---|
| 逻辑表名 / Logical Table Name | 实体表工作表名为 `init_char_config`，总表使用 `realm_level_config`。 | 明确前者是否为物理导表名、后者是否为策划逻辑名；程序和总表必须有一套固定映射。 |
| `realm_id` / Realm ID | 字段已存在。 | 定义其是否为大境界唯一 ID，并确定由谁引用。 |
| `spirit_cult_per_unit` / Spirit Absorption | J 表中文为“灵气吸收”，总表中文为“单位灵气修为”。 | 该字段只能表示一种含义。按现有 J 表，应定义为“角色灵气吸收能力”，不能同时承担灵气转化。 |
| 灵气转化 / Spirit Conversion | 总表存在 `conversion_efficiency`，J、L 实表没有对应基础字段。 | 明确它是固定系统规则、角色字段、灵气源字段，还是仅允许作为外部效果目标。 |
| 突破归属 / Breakthrough Ownership | J 表已有成功率、虚弱时间、材料槽；总表另定义 `breakthrough_config`。 | 必须二选一：突破规则全部按等级放 J 表，或 J 表只保留突破 ID 并引用突破配置表。 |
| 材料结构 / Material Structure | J 表是固定材料槽；总表是 `material_group`。 | 固定槽位与材料组是两种不同表结构，只能保留一种为唯一来源。 |
| 未命名列 / Unnamed Columns | `skill` 后存在未命名列。 | 每一列必须具备变量名、类型和中文说明，或明确为导表工具的数组扩展列。 |

## 四、L灵气源配置表 / Spirit Source Config

### 4.1 表职责

| 字段 / Field | 中文含义 / Chinese Meaning | 结构定位 / Structural Role |
|---|---|---|
| `source_id` | 灵气源ID / Spirit Source ID | 所有灵气源型号的唯一 ID；被洞府、场景、宗门等外部配置引用。 |
| `source_name` | 灵气源名称 / Spirit Source Name | 策划识别与玩家展示。 |
| `source_type` | 个人或共享 / Personal or Shared | 决定灵气状态属于个人存档还是共享场景状态。 |
| `spirit_cap` | 灵气储量上限 / Spirit Storage Cap | 限制当前可积攒灵气。 |
| `spirit_total` | 灵气总产量上限 / Total Spirit Yield Cap | 定义灵气源是否可被产尽；空值表示无限产出。 |
| `spirit_rate` | 每时辰产出 / Spirit Output per Game Period | 定义灵气源自然产出节奏。 |
| `max_absorbers` | 可同时吸取人数 / Maximum Concurrent Absorbers | 限制共享灵气源同时参与吸收的角色数量。 |

### 4.2 结构结论

| 项目 / Item | 结论 / Conclusion |
|---|---|
| `source_id` / Spirit Source ID | 应是灵气源 ID，不应在中文说明中称为“场景 ID”；洞府不是场景。 |
| `spirit_cap` 与 `spirit_total` / Storage and Total Yield | 两者职责不同，应该同时保留：前者是当前可容纳量，后者是累计可产总量。 |
| 个人与共享 / Personal and Shared | `source_type` 的拆分正确；当前灵气值不进入配置表。 |
| 外部引用 / External References | 洞府等级表、场景表、宗门设施表应各自持有 `spirit_source_id`，单向引用 L 表。 |
| 共享分配 / Shared Allocation | `max_absorbers` 只解决并发人数，不解决灵气不足时的分配顺序或比例。该规则需要确定为固定系统规则或独立配置。 |
| 有限源枯竭 / Finite Source Exhaustion | 需要定义灵气池满时是否继续扣减总产量，以及总产量耗尽后的状态表达；这是运行规则，不必新增基础字段。 |

## 五、配置项总表 / Cultivation Config Field Index

该表当前不是完整字段总表，存在以下不一致：

| 总表项 / Index Entry | 实表情况 / Actual Table State | 结论 / Conclusion |
|---|---|---|
| `spirit_cult_per_unit` / Spirit Cult per Unit | J 表标注为“灵气吸收”。 | 中文说明需要与 J 表统一。 |
| `conversion_efficiency` / Conversion Efficiency | L 表无此字段。 | 需要明确该字段是否仍属于灵气源表。 |
| `breakthrough_config` / Breakthrough Config | J 表已直接承载部分突破字段。 | 需要明确突破的唯一配置归属。 |
| `material_group` / Material Group | J 表使用固定材料槽。 | 两种材料结构需要统一。 |
| `attrs`、`exp_level_up`、`skill` / Attributes, Experience, Skill | J 表存在，总表未收录。 | 若总表定义为完整字段目录，应补齐所有实体字段。 |

## 六、表间关系 / Table Relationships

```text
角色等级 / Character Level
  └─ J境界角色属性表 / Realm Character Attributes
       ├─ 境界与阶段 / Realm and Phase
       ├─ 突破节点 / Breakthrough Node
       ├─ 角色灵气吸收能力 / Character Spirit Absorption
       └─ 基础修为与属性 / Base Cultivation and Attributes

洞府、秘境、宗门修炼室 / Cave, Secret Realm, Sect Room
  └─ spirit_source_id
       └─ L灵气源配置表 / Spirit Source Config
            ├─ 储量上限 / Storage Cap
            ├─ 总产量上限 / Total Yield Cap
            ├─ 自然产出 / Natural Output
            └─ 并发吸取人数 / Concurrent Absorbers

丹药、功法、家具、阵法 / Pills, Techniques, Facilities, Formations
  └─ 各自配置表中的效果字段 / Effect Fields in Their Own Tables
       └─ 修炼系统固定效果目标 / Fixed Cultivation Effect Targets
```

## 七、当前优先级 / Current Priorities

1. 统一 `spirit_cult_per_unit` 与灵气转化字段的职责。
2. 确定突破规则是留在 J 表还是独立 `breakthrough_config`。
3. 统一材料的“固定槽位”与“材料组”结构。
4. 明确 L 表共享灵气不足时的分配规则。
5. 将配置项总表同步为所有实体表的真实字段目录。
