# 第05轮：修炼系统待改动项汇总

范围：第04轮审查文档、`J境界角色属性表.xlsx`、`L灵气源配置表.xlsx`、`修炼系统配置项总表.xlsx`。  
原则：仅讨论系统与表结构，不讨论数值。

## 一、结论 / Conclusion

第04轮提出的问题中，以下原则确定：

1. J 表保留为“境界等级 + 突破规则”的合并表，不拆出独立 `breakthrough_config`。
2. L 表保留为灵气源基础参数表；不承载家具、阵法、功法、丹药等外部加成。
3. `spirit_cult_per_unit` 保持“角色灵气吸收能力”的定义，不改成修为转化率。
4. `spirit_total` 是有限灵气源机制的基础字段，应保留；补运行规则，不因规则暂缺而删除。
5. 追赶表、修炼节奏表、虚弱表不恢复为独立游戏配置表。

## 二、直接改动项 / Direct Changes

| 改动项 / Change | 应如何改 / Required Change |
|---|---|
| 配置总表 / Config Index | 以 J、L 实表为唯一依据同步字段；总表只记录字段目录和字段口径，不承载第二套业务结构。 |
| J 表归属 / J Table Ownership | 明确 J 表为“境界等级 + 突破规则”合并表；总表删除独立 `breakthrough_config` 的重复归属。 |
| J 表字段目录 / J Field Index | 总表补齐 J 表实际存在的 `exp_level_up`、`attrs`、`skill`、突破材料槽等字段。 |
| 突破材料结构 / Material Structure | 固定使用“材料槽 + 数量槽”或材料组其中一种结构；总表与实表必须相同。 |
| 灵气吸收字段 / Spirit Absorption | `spirit_cult_per_unit` 中文说明统一为“角色灵气吸收能力”；删除“单位灵气修为”的旧说明。 |
| 灵气转化字段 / Spirit Conversion | `conversion_efficiency` 不再列为 L 表字段。其最终归属应为固定系统规则，或其他系统的效果目标；不得混入灵气源出厂参数。 |
| L 表中文表头 / L Chinese Header | `source_id` 中文说明统一为“灵气源ID”，不称为“场景ID”。 |
| L 表模板残留 / L Template Residue | 清理复制模板遗留的“突破”等无关文字。 |
| 类型与枚举 / Types and Enums | J、L 的 `##type` 行补全字段类型；`source_type`、`boundary_type` 等枚举有明确声明位。 |
| 单位声明 / Unit Declaration | 修为速率、灵气产出、灵气吸收、虚弱时长等字段在统一说明位标明单位；不依赖数值或口头约定推断。 |
| 自然精进行 / Natural Progression Rows | `boundary_type` 为空时，不读取成功率、虚弱、材料等突破字段；该约定写入表说明和导表校验规则。 |
| 无表头列 / Unnamed Columns | `skill` 后的未命名数据列，确认后补中英表头及类型；无用途则作为历史列清理。 |
| 属性槽位 / Attribute Slots | 属性槽位跳号应重排为连续槽，或在说明中声明保留槽位及用途。 |
| 属性基数与增量 / Attribute Base and Increment | 当前“首行绝对值、后续行增量”的隐含规则显式化；推荐拆分 `attr_base` 与 `attr_per_level`。 |
| 虚弱机制 / Weakness Mechanism | 策划案、总表同步为“虚弱行为固定、虚弱时长随突破节点配置”；虚弱恢复由 `pill_config` 效果目标承接。 |
| 共享灵气分配 / Shared Spirit Allocation | 将共享源灵气不足时的分配规则写入策划案，标为固定规则，不新增 `share_rule` 配置字段。 |
| 时间规则位置 / Time Rule Location | “刻、时辰、游戏日、显示换算”等规则写入策划案时间章节；配置表备注只保留字段说明。 |
| 总表表数量 / Config Table Count | 不恢复修炼追赶表、修炼节奏表、虚弱表；策划案与总表统一为当前实际保留的配置表结构。 |

## 三、需拍板项 / Decisions Needed

| 事项 / Decision | 要定什么 / What Must Be Defined |
|---|---|
| 灵气转化基数 / Spirit Conversion Base | `spirit_cult_per_unit` 已定义为吸收能力；需确定“灵气转修为”的基础规则是写死，还是使用独立字段。 |
| Lv80 终点 / Lv80 End State | 明确“大乘圆满 → 大成”的终局突破如何在 J 表表达；不能只有大突破而没有结果状态。 |
| `spirit_total` 运行规则 / Total Yield Runtime Rule | 定义累计产量何时扣除、耗尽后的状态、是否刷新、作用范围是单局还是跨局。 |
| 共享源单人限制 / Shared Source Per-player Limit | 决定是否限制单名角色从共享源吸取的速度，以避免高境界角色独占。 |
| 突破丹与挑战条件 / Pill and Challenge Conditions | 若小/大突破要限定可用丹药组或挑战条件，补回 J 表字段；若当前不做，从总表删除对应接口。 |
| 玩家展示名 / Display Name | 选择每级直接配置 `display_name`，或按境界名、层数、阶段自动生成。 |
| “刻” / Quarter Unit | 若保留刻级显示，则纳入固定时间体系；若不保留，从虚弱说明和显示规则删除。 |

## 四、推荐处理顺序 / Recommended Order

1. 确定灵气转化基数的规则落点。
2. 确定 Lv80 大乘大成的终局表达。
3. 确定 `spirit_total` 的有限灵气源运行规则。
4. 同步 J、L 与配置项总表。
5. 处理类型、枚举、单位、属性列和无表头列。
